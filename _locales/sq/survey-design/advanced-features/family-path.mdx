`family_path` është një fushë llogaritëse konvencionale që mban rrugën drejt direktorisë së mediave të bashkëngjitura të formularit. Çdo formular që kryen kërkime në bazat e të dhënave lokale me `rawquery`, `pulldata` ose `search()` duhet të përfshijë këtë fushë — pa të, rrugët e skedarëve nuk mund të zgjidhen dhe kërkimet kthejnë në heshtje rezultat bosh.

---

## Fusha calculate

Shtoni këtë rresht afër fillimit të fletës suaj survey, pas çdo fushe meta dhe para pyetjes së parë që përdor një skedar baze të dhënash:

| type | name | label | calculation |
|---|---|---|---|
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |

Fusha nuk ruan asnjë vlerë të dukshme dhe nuk kërkon etiketë (label). Është një parakusht i heshtur për të gjithë ndërtimin e rrugëve që vijon.

---

## Pse është e nevojshme

RTSurvey paketon mediat e formularit — baza të dhënash SQLite, imazhe, klipe audio — brenda një direktorie për çdo formular në pajisje. Rruga e saktë ndryshon midis platformave (Android, iOS, web) dhe midis pajisjeve.

Gjatë kohës së ekzekutimit aplikacioni plotëson `family_path` automatikisht. Një vlerë tipike e zgjidhur duket si:

```
resources/familyMedia/Phuong_Person_Test
```

Për shkak se rruga është specifike për platformën dhe përcaktohet në kohën e nisjes, ajo nuk mund të kododhet në mënyrë fikse në formular. `pulldata('app-api', 'family_path')` është e vetmja mënyrë e besueshme për ta marrë atë.

---

## Si ta përdorni në rrugë

Pasi të jetë përcaktuar `family_path`, ndërtoni një rrugë të plotë skedari me `concat()`:

```
concat(${family_path}, '/file.db::tableName')
```

Prapashtesa `::tableName` hiqet kur aplikacioni hap skedarin; emri i tabelës përdoret vetëm brenda kërkesës suaj SQL.

---

## Ku përdoret family_path

`family_path` kërkohet në argumentin e rrugës sa herë që referoni një skedar të bashkëngjitur:

- **Kërkimi në bazën e të dhënave lokale** — argumenti `db_path` i `search-autocomplete-noedit-v2('rawquery', ...)` duhet të ndërtohet me `concat(${family_path}, ...)`. Shih [Kërkimi në bazën e të dhënave lokale](local-database-search) për detajet e plota të përdorimit.
- **`pulldata` rawquery** — çdo thirrje `pulldata('rawquery', ...)` që lexon nga një skedar `.db` përdor të njëjtin model `concat()`.
- **`search()` me një skedar lokal** — pamjet (appearances) e kërkimit dinamik që ngarkojnë nga një skedar CSV ose DB i bashkëngjitur gjithashtu mbështeten te `family_path` për referencën e skedarit.

## Vendosja në formular

`family_path` duhet të shfaqet **përpara fushës së parë që e referon atë**. Pozicioni i rekomanduar është menjëherë pas grupit meta:

| type | name | label | calculation |
|---|---|---|---|
| begin_group | meta | | |
| deviceid | deviceid | | |
| start | start | | |
| end | end | | |
| end_group | | | |
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |
| select_one | province | Province | *(dukja rawquery që referon `${family_path}`)* |

<Callout type="warning">
Nëse `family_path` mungon në formular, ose vendoset pas fushës së parë `rawquery` / `search()` që e referon atë, të gjitha kërkimet ndaj skedarëve të bashkëngjitur do të kthejnë në heshtje rezultat bosh. Nuk ka asnjë mesazh gabimi — plotësimi automatik thjesht nuk tregon rezultate.
</Callout>

---

## Skedarë të shumtë të bazës së të dhënave

Një formular i vetëm mund të përdorë disa skedarë `.db`. Çdo rrugë ndërtohet në mënyrë të pavarur me `concat()`:

```
concat(${family_path}, '/locations.db::externalData')
concat(${family_path}, '/health_facilities.db::facilities')
concat(${family_path}, '/household_list.db::households')
```

Përcaktoni `family_path` një herë; referojeni atë në sa më shumë fusha të jetë e nevojshme.
