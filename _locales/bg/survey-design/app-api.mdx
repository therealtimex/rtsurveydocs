AppAPI позволява на потребителите да зареждат системни мета данни от приложението, използвайки различни методи във FormEngine и DMView. То осигурява достъп до различни ключове за данни за извличане на специфична информация от приложението.

В xlsform можете да използвате функцията `pulldata()` със следния синтаксис:


<Callout>pulldata('app-api', 'data-key')</Callout>

- `'app-api'`: Тази ключова дума информира FormEngine да зареди данните от App API.
- `'data-key'`: Това е ключът на данните, които искате да заредите от App API.
- Ако ключът за данни е невалиден или не се поддържа, изчислението ще върне "n/a".

Ето поддържаните ключове за данни, които можете да използвате с App-API:

`osPlatform`: Връща текущото име на ОС (Android или iOS) и версията на ОС. Уеб платформите ще върнат празна стойност.

`appPlatform`: Връща името на платформата на приложението, което е `rtSurvey`.

`appVersion`: Връща името на версията на приложението.

`getDisplayWidth`: Връща ширината на екрана на устройството в пиксели.

`getDisplayHeight`: Връща височината на екрана на устройството в пиксели.

`getScreenSize`: Връща размера на екрана на устройството в инчове.

`projectCode`: Връща текущия код на проекта на сайта, в който потребителят влиза.

`projectURL`: Връща текущия URL адрес на проекта на сайта, в който потребителят влиза. Стойността по подразбиране/резервна стойност е празен текст ("").

`startingPoint`: Връща пътя на точката, която стартира формата. Вижте "Начална точка на формата" за повече подробности.

`serverTime`: Връща най-добрата налична апроксимация на датата и часа на сървъра.

`user.[attribute]`: Връща текущите потребителски атрибути въз основа на посочения ключ на атрибута. Вижте таблицата "Потребителски атрибути" за наличните ключове на атрибути.

Комбинирайте посочените по-долу ключове на атрибути с "user." в параметрите на `pulldata()`, за да извлечете текущата потребителска информация. Например, използвайте `user.username`, `user.email` и т.н.

| Ключ на атрибут     | Описание                           |
|---------------------|------------------------------------|
| username            | Потребителско име на потребителя   |
| name                | Пълно име на потребителя           |
| staffCode           | Код на служител на потребителя     |
| phone               | Телефонен номер на потребителя     |
| email               | Имейл адрес на потребителя         |
| description         | Текст на описание в потребителска информация |
| organization_id     | ID на организация, към която принадлежи потребителят |
| organization_name   | Име на организация, към която принадлежи потребителят |
| team_id             | ID на екип, към който принадлежи потребителят |
| supervisor_id       | ID на ръководителя на потребителя  |
| is_supervisor       | 1, ако потребителят е ръководител, 0, ако не е |

`instancePath`: Връща текущия път на папката на екземпляра.

`appLanguage`: Връща текущия език на приложението, зададен в настройките на приложението (напр. vi, en).

`openArgs.[attribute]`: Връща аргумента за отваряне на форма, подаден от ActionButton (act_fill_form, act_get_instance). Стойността по подразбиране/резервна стойност е празен текст ("").

`primaryAppColor`: Извлича основния цвят на приложението.

## Примери за употреба

### Съхраняване на потребителското име и организацията на анкетьора

| type | name | label | calculation |
|------|------|-------|-------------|
| calculate | enumerator_name | | `pulldata('app-api', 'user.name')` |
| calculate | enumerator_org | | `pulldata('app-api', 'user.organization_name')` |
| calculate | enumerator_email | | `pulldata('app-api', 'user.email')` |

Използвайте ги в етикети за бележки за целите на одита:
```
note | interviewer_info | Анкетьор: ${enumerator_name} (${enumerator_org})
```

### Информация за устройството и екрана

| type | name | label | calculation |
|------|------|-------|-------------|
| calculate | device_platform | | `pulldata('app-api', 'osPlatform')` |
| calculate | app_ver | | `pulldata('app-api', 'appVersion')` |
| calculate | screen_w | | `pulldata('app-api', 'getDisplayWidth')` |

Полезно за отстраняване на проблеми: експортирайте `device_platform` и `app_ver` заедно с вашите данни, за да идентифицирате коя версия на устройството е използвана за всяко подаване.

### Време на сървъра вместо време на устройството

Часовниците на устройствата може да са грешни. Използвайте `serverTime` за по-надежден времеви печат:

| type | name | label | calculation |
|------|------|-------|-------------|
| calculate | server_ts | | `pulldata('app-api', 'serverTime')` |

### Условна логика въз основа на ролята на потребителя

Покажете секция само за ръководители само на ръководители:

| type | name | label | relevant |
|------|------|-------|----------|
| calculate | is_supervisor | | `pulldata('app-api', 'user.is_supervisor')` |
| begin_group | supervisor_section | Преглед от ръководител | `${is_supervisor} = '1'` |
| text | supervisor_notes | Бележки на ръководителя | |
| end_group | | | |

### Предаване на аргументи от бутон за действие

Когато формата се стартира от бутон за действие `act_fill_form` с персонализирани аргументи:

| type | name | label | calculation |
|------|------|-------|-------------|
| calculate | passed_hh_id | | `pulldata('app-api', 'openArgs.household_id')` |
| calculate | passed_task | | `pulldata('app-api', 'openArgs.task_code')` |

Бутонът за действие трябва да предава аргументите със съответстващи ключове (напр. `household_id`, `task_code`).

### Използване на информация за проекта

| type | name | label | calculation |
|------|------|-------|-------------|
| calculate | project | | `pulldata('app-api', 'projectCode')` |
| calculate | project_url | | `pulldata('app-api', 'projectURL')` |

## Бележки

- Всички извиквания на `pulldata('app-api', ...)` се оценяват при отваряне на формата и не се преоценяват динамично по време на сесията (с изключение на `serverTime` и `now()`).
- Ако ключът не се поддържа или данните не са налични, функцията връща `'n/a'` (не празен низ — тествайте с `!= 'n/a'`, а не с `!= ''`).
- Стойностите на `openArgs` са налични само когато формата се стартира от бутон за действие; в противен случай те връщат празен низ.
