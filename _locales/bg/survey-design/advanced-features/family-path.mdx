`family_path` е конвенционално изчислително поле, което съдържа пътя до директорията с мултимедия на формуляра. Всеки формуляр, който извършва локално търсене в база данни с `rawquery`, `pulldata` или `search()`, трябва да включва това поле — без него пътищата до файловете не могат да бъдат разпознати и търсенето връща празен резултат без съобщение.

---

## Изчислителното поле (calculate)

Добавете този ред близо до горната част на вашия лист за анкета (survey sheet), след всички мета полета и преди първия въпрос, който използва файл с база данни:

| type | name | label | calculation |
|---|---|---|---|
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |

Полето не съхранява видима стойност и не изисква етикет (label). То е мълчалива предпоставка за всяко следващо изграждане на пътища.

---

## Защо е необходимо

RTSurvey събира мултимедията на формуляра — бази данни SQLite, изображения, аудио клипове — в директория за конкретния формуляр на устройството. Точният път се различава между платформите (Android, iOS, уеб) и между устройствата.

По време на изпълнение приложението попълва `family_path` автоматично. Типична разпозната стойност изглежда по следния начин:

```
resources/familyMedia/Phuong_Person_Test
```

Тъй като пътят е специфичен за платформата и се определя по време на стартиране, той не може да бъде твърдо кодиран във формуляра. `pulldata('app-api', 'family_path')` е единственият надежден начин за неговото извличане.

---

## Как се използва в пътища

След като `family_path` е дефиниран, изградете пълен път до файл с `concat()`:

```
concat(${family_path}, '/file.db::tableName')
```

Суфиксът `::tableName` се премахва, когато приложението отвори файла; името на таблицата се използва само във вашата SQL заявка.

---

## Къде се използва family_path

`family_path` е необходим в аргумента за път винаги, когато препращате към включен файл:

- **Локално търсене в база данни** — аргументът `db_path` на `search-autocomplete-noedit-v2('rawquery', ...)` трябва да бъде изграден с `concat(${family_path}, ...)`. Вижте [Локално търсене в база данни](local-database-search) за пълни подробности относно използването.
- **`pulldata` rawquery** — всяко извикване на `pulldata('rawquery', ...)`, което чете от `.db` файл, използва същия модел с `concat()`.
- **`search()` с локален файл** — динамичните изгледи за търсене (appearances), които се зареждат от включен CSV или DB файл, също разчитат на `family_path` за препратка към файла.

---

## Разположение във формуляра

`family_path` трябва да се появи **преди първото поле, което го препраща**. Препоръчителната позиция е веднага след мета групата:

| type | name | label | calculation |
|---|---|---|---|
| begin_group | meta | | |
| deviceid | deviceid | | |
| start | start | | |
| end | end | | |
| end_group | | | |
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |
| select_one | province | Province | *(изглед rawquery, препращащ към `${family_path}`)* |

<Callout type="warning">
Ако `family_path` липсва във формуляра или е поставен след първото поле `rawquery` / `search()`, което го препраща, всички търсения в бази данни ще връщат празен резултат без съобщение. Няма съобщение за грешка — автоматичното довършване просто не показва резултати.
</Callout>

---

## Няколко файла с бази данни

Един формуляр може да използва няколко `.db` файла. Всеки път се изгражда независимо с `concat()`:

```
concat(${family_path}, '/locations.db::externalData')
concat(${family_path}, '/health_facilities.db::facilities')
concat(${family_path}, '/household_list.db::households')
```

Дефинирайте `family_path` веднъж; препращайте към него в толкова полета, колкото е необходимо.

---

## Проверка по време на разработка

Добавете временно поле `note` под `family_path`, за да инспектирате разпознатата стойност на устройството:

| type | name | label | calculation |
|---|---|---|---|
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |
| note | family_path_check | `Path: ${family_path}` | |

Бележката ще покаже действителния разпознат път по време на тестване. Премахнете я, преди да разгърнете финалния формуляр.
