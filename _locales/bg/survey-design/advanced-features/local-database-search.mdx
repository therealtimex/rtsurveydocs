**Търсене в локална база данни** позволява на полета от тип `select_one` или `text` да правят заявки към SQLite `.db` файл, който е вграден в медийния пакет на формуляра — изцяло офлайн, без връзка със сървъра. Това е правилният подход, когато списъкът с опции е голям и статичен (например национален списък със села, здравни заведения или административни граници) и не може да бъде гарантирана интернет свързаност.

| Подход | Източник на данни | Изисква свързаност |
|---|---|---|
| Търсене в локална база данни (`rawquery`) | Вграден `.db` файл (SQLite) | Не |
| `search-api()` | Отдалечен REST API | Да |
| `search()` | Вграден CSV файл | Не |

---

## Варианти на изглед

Полето за автоматично довършване се конфигурира чрез колоната `appearance`. Налични са три варианта:

| Вариант | Бележки |
|---|---|
| `search-autocomplete-noedit(...)` | Стандартно автоматично довършване — анкетьорът трябва да избере от списъка; въвеждането на свободен текст не се запазва |
| `search-autocomplete-noedit-v2(...)` | Препоръчителен вариант — същото поведение, но използва актуализиран механизъм за изобразяване с по-добра производителност при големи набори от резултати |
| `search(...)` | Обикновено съвпадение на базата на файл срещу вграден CSV; **не** поддържа необработен SQL — изброен тук само за сравнение |

<Callout type="info">
`search-autocomplete-noedit` е псевдоним — по време на обработка приложението го заменя с вътрешното име на функцията `searchAutocompleteNoedit`. Използвайте някое от двете изписвания във вашия XLSForm; и двете работят.
</Callout>

## Източник на данни `rawquery`

За да изпълните SQL заявка срещу `.db` файл, предайте `'rawquery'` като първи аргумент на функцията за изглед. Пълният синтаксис е:

```
search-autocomplete-noedit-v2(
  'rawquery',
  <db_path>,
  '[display_col]',
  'value_col',
  'SELECT ...',
  param1, param2, ...
)
```

### Параметри

| Позиция | Параметър | Описание |
|---|---|---|
| 1 | `'rawquery'` | Буквален низ — указва на приложението да изпълни SQL директно |
| 2 | `db_path` | Път към SQLite файла във формат `<dir>/<file>.db::tableName`. Суфиксът `::tableName` се премахва при отваряне на файла; името на таблицата се използва във вашия SQL |
| 3 | `'[display_col]'` | Колона, която да се показва в падащото меню. Ограждащите скоби `[ ]` се премахват по време на изпълнение |
| 4 | `'value_col'` | Колона, чиято стойност се съхранява, когато анкетьорът направи избор |
| 5 | `'SELECT ...'` | Всяка валидна SQLite SELECT инструкция. `SELECT DISTINCT` се инжектира автоматично, ако `DISTINCT` вече не присъства |
| 6+ | `param1, ...` | По избор. Стойности, обвързани с `?` маркери в SQL, по ред. Ако SQL съдържа `?`, но не са предоставени параметри, полето връща празен резултат (вградена защита срещу липсващи аргументи) |

### Конвенция за `db_path`

Файлът на базата данни се намира в директорията с вградени медии на формуляра. По време на изпълнение `pulldata('app-api', 'family_path')` връща пътя до тази директория. Вижте [family_path](family-path) за подробности относно настройките. Стандартният модел е:

```
concat(${family_path}, '/mydata.db::tableName')
```

Когато приложението отвори файла, то премахва частта `::tableName` и използва чистия път до файла. Името на таблицата се появява само във вашия SQL.

## Основен пример — търсене на провинция

Падащо меню за провинция само за четене, поддържано от вграден `vnxa3.db` файл:

| type | name | label | appearance | calculation |
|---|---|---|---|---|
| calculate | family_path | | | `pulldata('app-api', 'family_path')` |
| select_one | province | Провинция | `search-autocomplete-noedit-v2('rawquery', concat(${family_path}, '/vnxa3.db::externalData'), '[provv]', 'provid', 'SELECT provv, provid FROM externalData WHERE rta_filter = "1"')` | |

Колоната `appearance` (разширена за четливост):

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[provv]', 'provid',
  'SELECT provv, provid FROM externalData WHERE rta_filter = "1"')
```

- Показваният етикет идва от колона `provv`.
- Съхраняваната стойност идва от колона `provid`.
- Показват се само редове, където `rta_filter = "1"`.

## Параметризирани заявки

Използвайте `?` маркери във вашия SQL и предайте съответните референции към полета като допълнителни аргументи (от позиция 6 нататък). Това е стандартният модел за каскадни селекции — например зареждане на райони, които принадлежат към избраната по-горе провинция.

<Callout type="warning">
Ако вашият SQL съдържа поне един `?` и не са предоставени аргументи за параметри, полето връща празен набор от резултати. Това предотвратява появата на остарели или нефилтрирани данни преди да бъде направен родителски избор.
</Callout>

### Пример за каскада на район

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[distv]', 'distid',
  'SELECT distv, distid FROM externalData
   WHERE provid = ? AND rta_filter = "1"',
  ${province})
```

Стойността на `${province}` е обвързана с първия `?`. Полето е празно, докато анкетьорът не избере провинция.

### Пример с два параметъра — каскада на община

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[commv]', 'commid',
  'SELECT commv, commid FROM externalData
   WHERE provid = ? AND distid = ? AND rta_filter = "1"',
  ${province}, ${district})
```

Параметрите са обвързани по позиция: `${province}` → първи `?`, `${district}` → втори `?`.

## UNION SELECT за специални стойности

Инжектирайте синтетични редове — като "Не знам" или "Отказвам да отговоря" — директно в SQL чрез `UNION SELECT`:

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[provv]', 'provid',
  'SELECT provv, provid FROM externalData WHERE rta_filter = "1"
   UNION SELECT "<i>Не знам</i>", "888"')
```

Конвенции, използвани във формулярите на RTSurvey:

| Код | Значение |
|---|---|
| `888` | Не знам |
| `999` | Отказвам да отговоря |

HTML тагове като `<i>` в низа за показване се изобразяват от приложението — можете да ги използвате за визуално разграничаване на специалните опции.

## Многоезично показване

Съхранявайте специфични за езика етикети в отделни колони (например `label_vi`, `label_en`) и изберете подходящия въз основа на полето за език във вашия формуляр:

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[label_vi]', 'provid',
  'SELECT label_vi, label_en, provid FROM externalData
   WHERE rta_filter = "1"')
```

За да превключвате колоните динамично въз основа на поле `${language}`, използвайте `if()` израз за параметъра на колоната за показване, за да превключвате между езиковите колони:

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  if(${language} = 'vi', '[label_vi]', '[label_en]'),
  'provid',
  'SELECT label_vi, label_en, provid FROM externalData
   WHERE rta_filter = "1"')
```

<Callout type="info">
Параметърът на колоната за показване се оценява преди изпълнението на заявката. Само името на колоната (без скоби) се предава на SQL механизма; скобите са козметични маркери, премахвани по време на обработка.
</Callout>

## Валидиране на истински избор

Когато полето позволява специални стойности като 888 или 999, обикновената проверка `required = yes` е недостатъчна — тя е изпълнена дори ако анкетьорът избере "Не знам". Използвайте ограничението `selected-at(., 0) != -997`, за да потвърдите, че съхранената стойност е реален избор, а не вътрешния маркер "нищо не е избрано" `-997`:

| колона | стойност |
|---|---|
| constraint | `selected-at(., 0) != -997` |
| constraint_message | Моля, изберете валидна опция |

Стойността `-997` е вътрешният код, който RTSurvey съхранява, когато не е избран елемент от списъка за автоматично довършване. Изборът на 888 или 999 все пак е съзнателно решение и преминава тази проверка.

За да изисквате допълнително реална (неспециална) стойност, разширете ограничението:

```
selected-at(., 0) != -997 and selected-at(., 0) != '888' and selected-at(., 0) != '999'
```

## Сравнение: локална база данни срещу други методи за търсене

| Функция | `rawquery` автоматично довършване | `search-api()` | `search()` CSV | Обикновени CSV опции |
|---|---|---|---|---|
| Източник на данни | Вграден `.db` (SQLite) | Отдалечен REST API | Вграден CSV | Лист с опции |
| Работи офлайн | Да | Не | Да | Да |
| Поддържа необработен SQL | Да | Не | Не | Не |
| Каскадни филтри | Да — параметризиран `?` | Чрез тялото на заявката | Ограничено | Не |
| Размер на набора от данни | Много голям (милиони редове) | Неограничен (сървърен) | Среден (десетки хиляди) | Малък |
| Специални инжектирани редове | Да — `UNION SELECT` | Не | Не | Да (ръчно) |
| Сложност на настройка | Средна — изисква вграден `.db` | Висока — изисква API сървър | Ниска | Без |

## Ограничения

- `.db` файлът трябва да бъде вграден в медийния пакет на формуляра преди внедряване. Динамичните актуализации на базата данни изискват ново внедряване на формуляра.
- SQL се изпълнява във вида, в който е, на устройството. Няма сървърна защита — избягвайте конструиране на SQL от свободен текст, въведен от анкетьора.
- Поддържат се само `SELECT` инструкции. `INSERT`, `UPDATE` и `DELETE` не са разрешени.
- Много сложни заявки (големи `UNION` вериги, множество обединения) могат да бъдат бавни на бюджетни Android устройства.
- Вариантите на `search-autocomplete-noedit` не позволяват на анкетьора да запише стойност, която не е в набора от резултати. Ако се изисква въвеждане на свободен текст, използвайте отделно `text` поле.
- `SELECT DISTINCT` се инжектира автоматично само когато `DISTINCT` отсъства от заявката. Ако напишете `SELECT DISTINCT` изрично, той няма да бъде удвоен.
