Аудио записът позволява на формата безшумно или видимо да улавя аудио по време на раздел от анкетата. Той е полезен за записване на интервюта, околен звук по време на полеви наблюдения или изговорени отговори, които допълват структурираните отговори.

## Как работи

Аудио записът се контролира от две текстови (`text`) полета, действащи като **маркери**:

- Поле с изглед `audio-start` започва запис, когато анкетьорът го достигне.
- Поле с изглед `audio-end` спира записа и записва аудио файла към изпратените данни.

И двете маркерни полета са от тип `text`. Обикновено те са скрити от анкетьора (чрез `relevant = false` или поставени в неинтерактивна позиция), въпреки че могат да бъдат и видими. Записаното аудио се прикачва към изпратените данни като файл, свързан с полето `audio-end`.

---

## Основен пример

| type | name | label | appearance |
|------|------|-------|------------|
| text | audio_s_a1 | | `audio-start` |
| text | q_name | Respondent name | |
| text | q_occupation | Occupation | |
| integer | q_age | Age | |
| text | audio_e_a1 | | `audio-end` |

Приложението започва да записва, когато анкетьорът достигне `audio_s_a1`, и спира, когато достигне `audio_e_a1`. Всички въпроси между двата маркера се записват.

---

## Безшумен запис: `audio-start invisible`

По подразбиране мобилното приложение показва индикатор за запис, докато се улавя аудио. Добавянето на `invisible` към изгледа премахва този индикатор, така че записът се извършва без никакви видими знаци за респондента.

| type | name | label | appearance |
|------|------|-------|------------|
| text | audio_s_a1 | | `audio-start invisible` |
| text | q_consent | Do you agree to participate? | |
| text | q_feedback | Your feedback | |
| text | audio_e_a1 | | `audio-end` |

Използвайте `invisible` само когато изискванията за разкриване на информация са изпълнени чрез други средства (например отделно поле за писмено съгласие преди секцията за запис).

## Конвенция за именуване

Продукционните форми използват последователен модел на именуване за маркерните полета:

```
audio_s_{section}{n}   — начален маркер
audio_e_{section}{n}   — краен маркер
```

Където `{section}` е кратък етикет за секцията на формата, а `{n}` е последователен номер в рамките на тази секция.

| Field name | Role | Meaning |
|------------|------|---------|
| `audio_s_a1` | Start | First recording in section A |
| `audio_e_a1` | End | End of first recording in section A |
| `audio_s_b1` | Start | First recording in section B |
| `audio_e_b1` | End | End of first recording in section B |
| `audio_s_a2` | Start | Second recording in section A |
| `audio_e_a2` | End | End of second recording in section A |

Следването на тази конвенция улеснява идентифицирането на границите на записа при преглед на дефинициите на формите и данните от изпращанията.

## Съхранение и извличане

Когато анкетьорът достигне полето `audio-end`, приложението финализира аудио файла и го прикачва към изпратените данни. Файлът е:

- Съхранява се като аудио прикачен файл към изпратените данни, свързан с името на полето `audio-end`.
- Достъпен е в прегледа на изпращанията в бекенда на rtSurvey заедно с други медийни прикачени файлове.
- Може да се изтегли чрез стандартния експорт на изпращанията — аудио файловете се появяват в медийната колона, съответстваща на името на полето `audio-end`.

Файловият формат и битрейтът зависят от устройството и версията на приложението.

---

## Няколко секции за запис

Една форма може да съдържа няколко незастъпващи се секции за запис. Всяка двойка маркери `audio-start` / `audio-end` трябва да бъде напълно затворена — секциите не трябва да се преплитат.

| type | name | label | appearance |
|------|------|-------|------------|
| text | audio_s_a1 | | `audio-start` |
| text | q_intro | Introduction | |
| text | audio_e_a1 | | `audio-end` |
| note | section_break | — | |
| text | audio_s_b1 | | `audio-start invisible` |
| text | q_detail | Details | |
| text | audio_e_b1 | | `audio-end` |

Всяка секция създава отделен аудио файл, прикрепен към съответното му поле `audio-end`.

## Ограничения

- **Само за мобилно приложение.** Функцията не се поддържа в уеб формата. `audio-start` и `audio-end` се игнорират безшумно в браузъра.
- **Без вмъкване (nesting).** Секциите за запис не могат да се застъпват. Стартирането на нов запис преди достигането на предишния маркер `audio-end` не се поддържа.
- **Типът на полето трябва да бъде `text`.** Използването на `audio-start` или `audio-end` за всеки друг тип въпрос не се поддържа.
- **Размер за качване.** Дългите записи създават големи файлове. Имайте предвид ограниченията за размер на изпращаните данни и мрежовите условия на терен.
- **Без пауза по време на запис.** Записът работи непрекъснато от началния маркер до крайния маркер; няма механизъм за пауза и възобновяване в рамките на секция.
