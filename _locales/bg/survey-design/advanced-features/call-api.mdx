Функцията **Извикване на API** позволява на поле от анкета да прави HTTP заявка към външна услуга и да използва отговора за попълване на изчислена стойност или валидиране на потребителски вход. Това позволява търсене в реално време, проверка на ID, търсене на баркодове и всякакви други проверки от страна на сървъра по време на събирането на данни.

Има две функции:

- `callapi()` — извлича стойност от API и я съхранява в поле от тип `calculate` или `text`
- `callapi-verify()` — извиква API и блокира напредъка, ако отговорът не съответства на очакваната стойност (използва се в `constraint`)

---

## `callapi()` — Извличане и съхраняване на API отговор

### Синтаксис

Поставете `callapi()` в колоната **`calculation`** на поле от тип `calculate` или `text`:

```
callapi(method, url, allowed_auto, max_retry, no_overwrite, extract_expr, timeout, lifetime, response_q, call_type, post_body)
```

### Параметри

| # | Параметър      | Описание                                          |
|---|----------------|---------------------------------------------------|
| 1 | `method`       | HTTP метод: `'GET'` или `'POST'`                   |
| 2 | `url`          | URL адрес на API крайна точка                     |
| 3 | `allowed_auto` | `1` за автоматично извикване, когато се достигне до полето; `0` за изискване на ръчен бутон за задействане |
| 4 | `max_retry`    | Максимален брой опити за повторение при неуспех  |
| 5 | `no_overwrite` | `1` за запазване на съществуващата стойност, ако полето вече има такава; `0` за винаги презаписване |
| 6 | `extract_expr` | JSONPath израз за извличане на желаната стойност от отговора (напр. `$.data.name`) |
| 7 | `timeout`      | Таймаут на заявката в милисекунди                 |
| 8 | `lifetime`     | Колко дълго (мс) кешираният отговор остава валиден преди повторно извличане |
| 9 | `response_q`   | Име на поле за съхраняване на суровия HTTP код за отговор (напр. `${response_status}`) |
| 10 | `call_type`    | *(По избор)* Специален режим на извикване: `'lazy-upload'` или `'lazy-upload-multiple'` |
| 11 | `post_body`    | *(По избор)* Низ за POST тяло. Препращане към полета на формата с `##fieldname##` |

### Пример: GET заявка за търсене на домакинство по ID

| type | name | label | appearance | calculation |
|------|------|-------|------------|-------------|
| text | household_id | ID на домакинство | | |
| calculate | hh_name | | callapi | `callapi('GET', concat('https://api.example.com/households/', ${household_id}), 1, 3, 0, '$.name', 10000, 0, '')` |
| note | hh_display | Домакинство: `${hh_name}` | | |

### Пример: POST заявка с JSON тяло

```
callapi('POST', 'https://api.example.com/lookup', 1, 2, 0, '$.result.value', 15000, 0, '', '', '{"id": "##household_id##"}')
```

В `post_body` използвайте `##fieldname##`, за да инжектирате текущата стойност на всяко поле от формата.

### Външен вид: `callapi`

Добавете `callapi` към колоната `appearance` на полето, за да активирате интеграцията на API повикването:

| type | name | label | appearance | calculation |
|------|------|-------|------------|-------------|
| calculate | api_result | | callapi | `callapi('GET', ...)` |

Когато `allowed_auto` е `0`, rtSurvey показва **бутон "Извличане"**, който анкетьорът натиска ръчно.

## `callapi-verify()` — Валидиране на стойност спрямо API

`callapi-verify()` блокира изпращането на поле, докато API не потвърди, че въведената стойност е валидна. Използвайте го в колоната **`constraint`**.

### Синтаксис

```
callapi-verify(method, url, extract_expr, match_expr, timeout, constraint_mode, post_body, message)
```

### Параметри

| # | Параметър         | Описание                                          |
|---|-------------------|---------------------------------------------------|
| 1 | `method`          | HTTP метод: `'GET'` или `'POST'`                   |
| 2 | `url`             | API крайна точка за проверка                      |
| 3 | `extract_expr`    | JSONPath за извличане на очакваната стойност от отговора |
| 4 | `match_expr`      | Израз, сравняващ извлечената стойност със стойността на полето (напр. `$.status = 'valid'`) |
| 5 | `timeout`         | Таймаут на заявката в милисекунди                 |
| 6 | `constraint_mode` | `'soft'` само за предупреждение; `'hard'` за блокиране на напредъка |
| 7 | `post_body`       | *(По избор)* POST тяло със замествания `##fieldname##` |
| 8 | `message`         | *(По избор)* Съобщение за грешка. Поддържа многоезичност: `<en>Invalid!</en><vi>Không hợp lệ!</vi>` |

### Пример: Проверка на баркод спрямо регистър на активи

| type | name | label | appearance | constraint | constraint_message |
|------|------|-------|------------|------------|-------------------|
| barcode | asset_code | Сканирайте баркода на актива | callapi-verify | `callapi-verify('POST', 'https://api.example.com/assets/verify', '$.valid', ". = 'true'", 10000, 'hard', '{"code": "##asset_code##"}')` | Активът не е намерен в регистъра |

### Външен вид: `callapi-verify(...)`

Колоната `appearance` на поле с `callapi-verify()` в `constraint` трябва да съдържа `callapi-verify(params)` или `callapi-verify(dynamicParams)`, за да сигнализира на rtSurvey, че това поле използва API проверка.

## Използване на данни от App API заедно с callapi

Комбинирайте `callapi()` с `pulldata('app-api', 'user.token')`, за да инжектирате токена на удостоверения потребител във вашата API заявка:

```
callapi('POST', 'https://api.example.com/data', 1, 2, 0, '$.value', 10000, 0, '', '',
  concat('{"token":"', pulldata('app-api','user.token'), '","id":"##item_id##"}'))
```

## Най-добри практики

1. Винаги задавайте разумен `timeout` (5000–15000 ms) — не използвайте 0 или много високи стойности.
2. Задайте `allowed_auto=0` за проверки, които анкетьорът трябва да задейства съзнателно (напр. проверки на ID).
3. Задайте `no_overwrite=1`, когато полето може да бъде редактирано по-късно и не искате повторното извличане да презапише ръчните корекции.
4. Използвайте `extract_expr` със специфичен JSONPath, вместо да разчитате на суров текст за отговор.
5. Тествайте API повикванията в офлайн режим — `callapi` ще се провали грациозно и ще покаже грешка, но формата все пак трябва да може да бъде завършена за некритични полета.

## Ограничения

- Изисква мрежова свързаност по време на повикването — повикванията ще се провалят, когато устройството е офлайн.
- API отговорите трябва да са JSON — XML или текстови отговори изискват допълнителен анализ.
- Високата честота на повиквания (напр. едно API повикване на повторен екземпляр) може да забави навигацията във формата.
