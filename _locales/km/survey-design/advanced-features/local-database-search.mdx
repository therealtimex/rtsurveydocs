**ការស្វែងរកក្នុងមូលដ្ឋានទិន្នន័យក្នុងស្រុក (Local Database Search)** អនុញ្ញាតឱ្យវាល `select_one` ឬ `text` សាកសួរឯកសារ SQLite `.db` ដែលត្រូវបានភ្ជាប់មកជាមួយកញ្ចប់មេឌៀរបស់ទម្រង់បែបបទ — ទាំងស្រុងក្រៅប្រព័ន្ធ (offline) ដោយមិនចាំបាច់ឆ្លងកាត់ម៉ាស៊ីនបម្រើ (server)។ នេះគឺជាវិធីសាស្ត្រត្រឹមត្រូវ នៅពេលដែលបញ្ជីជម្រើសរបស់អ្នកមានទំហំធំ និងមានលក្ខណៈឋិតិវន្ត (ឧទាហរណ៍៖ បញ្ជីឈ្មោះភូមិ ទូទាំងប្រទេស មូលដ្ឋានសុខាភិបាល ឬព្រំប្រទល់រដ្ឋបាល) ហើយការភ្ជាប់អ៊ីនធឺណិតមិនអាចធានាបាន។

| វិធីសាស្ត្រ | ប្រភពទិន្នន័យ | ត្រូវការការភ្ជាប់អ៊ីនធឺណិត |
|---|---|---|
| ការស្វែងរកក្នុងមូលដ្ឋានទិន្នន័យក្នុងស្រុក (`rawquery`) | ឯកសារ `.db` ដែលបានភ្ជាប់មកជាមួយ (SQLite) | ទេ |
| `search-api()` | Remote REST API | បាទ/ចាស |
| `search()` | ឯកសារ CSV ដែលបានភ្ជាប់មកជាមួយ | ទេ |

## វ៉ារ្យ៉ង់នៃរូបរាង (Appearance variants)

វាលបំពេញស្វ័យប្រវត្តិត្រូវបានកំណត់រចនាសម្ព័ន្ធតាមរយៈជួរឈរ `appearance`។ មានវ៉ារ្យ៉ង់ចំនួនបីដែលអាចប្រើបាន៖

| វ៉ារ្យ៉ង់ | ចំណាំ |
|---|---|
| `search-autocomplete-noedit(...)` | ការបំពេញស្វ័យប្រវត្តិតាមស្តង់ដារ — អ្នកចុះអង្កេតត្រូវតែជ្រើសរើសពីបញ្ជី; ការបញ្ចូលអត្ថបទសេរីនឹងមិនត្រូវបានរក្សាទុកទេ |
| `search-autocomplete-noedit-v2(...)` | វ៉ារ្យ៉ង់ដែលត្រូវបានណែនាំ — មានឥរិយាបថដូចគ្នា ប៉ុន្តែប្រើប្រាស់ម៉ាស៊ីនបង្ហាញ (rendering engine) ដែលបានធ្វើបច្ចុប្បន្នភាពជាមួយនឹងដំណើរការល្អជាងមុនលើសំណុំលទ្ធផលធំៗ |
| `search(...)` | ការផ្គូផ្គងផ្អែកលើឯកសារសាមញ្ញធៀបនឹង CSV ដែលបានភ្ជាប់មកជាមួយ; **មិន** គាំទ្រ raw SQL ទេ — ចុះបញ្ជីនៅទីនេះសម្រាប់តែការប្រៀបធៀបប៉ុណ្ណោះ |

<Callout type="info">
`search-autocomplete-noedit` គឺជាឈ្មោះក្លែងក្លាយ (alias) — នៅពេលញែក (parse) កម្មវិធីនឹងជំនួសវាដោយឈ្មោះមុខងារខាងក្នុង `searchAutocompleteNoedit`។ ប្រើការសរសេរណាមួយនៅក្នុង XLSForm របស់អ្នក; ទាំងពីរដំណើរការដូចគ្នា។
</Callout>

## ប្រភពទិន្នន័យ `rawquery`

ដើម្បីដំណើរការសំណួរ SQL ធៀបនឹងឯកសារ `.db` សូមបញ្ជូន `'rawquery'` ជាអាគុយម៉ង់ដំបូងនៃមុខងាររូបរាង។ ទម្រង់ពេញលេញគឺ៖

```
search-autocomplete-noedit-v2(
  'rawquery',
  <db_path>,
  '[display_col]',
  'value_col',
  'SELECT ...',
  param1, param2, ...
)
```

### ប៉ារ៉ាម៉ែត្រ (Parameters)

| ទីតាំង | ប៉ារ៉ាម៉ែត្រ | ការពិពណ៌នា |
|---|---|---|
| 1 | `'rawquery'` | ខ្សែអក្សរជាក់លាក់ — ប្រាប់កម្មវិធីឱ្យអនុវត្ត SQL ដោយផ្ទាល់ |
| 2 | `db_path` | ផ្លូវទៅកាន់ឯកសារ SQLite ក្នុងទម្រង់ `<dir>/<file>.db::tableName`។ បច្ច័យ `::tableName` ត្រូវបានដកចេញនៅពេលបើកឯកសារ; ឈ្មោះតារាងត្រូវបានប្រើនៅក្នុង SQL របស់អ្នក |
| 3 | `'[display_col]'` | ជួរឈរដែលត្រូវបង្ហាញក្នុងបញ្ជីទម្លាក់ចុះ (dropdown)។ វង់ក្រចកការ៉េ `[ ]` ជុំវិញត្រូវបានដកចេញនៅពេលដំណើរការ |
| 4 | `'value_col'` | ជួរឈរដែលតម្លៃរបស់វាត្រូវបានរក្សាទុក នៅពេលអ្នកចុះអង្កេតធ្វើការជ្រើសរើស |
| 5 | `'SELECT ...'` | រាល់សេចក្តីថ្លែងការណ៍ SQLite SELECT ដែលមានសុពលភាព។ `SELECT DISTINCT` ត្រូវបានចាក់បញ្ចូលដោយស្វ័យប្រវត្តិ ប្រសិនបើ `DISTINCT` មិនទាន់មានវត្តមាន |
| 6+ | `param1, ...` | ជម្រើស។ តម្លៃដែលភ្ជាប់ទៅនឹងសញ្ញាសួរ `?` នៅក្នុង SQL តាមលំដាប់លំដោយ។ ប្រសិនបើ SQL មាន `?` ប៉ុន្តែគ្មានប៉ារ៉ាម៉ែត្រត្រូវបានផ្តល់ឱ្យ វាលនឹងត្រឡប់មកវិញទទេ (ការការពារដែលមានស្រាប់ប្រឆាំងនឹងអាគុយម៉ង់ដែលបាត់) |

### អនុសញ្ញា `db_path`

ឯកសារមូលដ្ឋានទិន្នន័យរស់នៅក្នុងថតមេឌៀដែលបានភ្ជាប់មកជាមួយរបស់ទម្រង់បែបបទ។ នៅពេលដំណើរការ `pulldata('app-api', 'family_path')` នឹងត្រឡប់ផ្លូវថតនោះមកវិញ។ សូមមើល [family_path](family-path) សម្រាប់ព័ត៌មានលម្អិតអំពីការរៀបចំ។ លំនាំស្តង់ដារគឺ៖

```
concat(${family_path}, '/mydata.db::tableName')
```

នៅពេលកម្មវិធីបើកឯកសារ វានឹងដកផ្នែក `::tableName` ចេញ ហើយប្រើផ្លូវឯកសារទទេរ។ ឈ្មោះតារាងបង្ហាញតែនៅក្នុង SQL របស់អ្នកប៉ុណ្ណោះ។

## ឧទាហរណ៍មូលដ្ឋាន — ការស្វែងរកខេត្ត

បញ្ជីទម្លាក់ចុះខេត្តសម្រាប់តែអាន ដែលគាំទ្រដោយឯកសារ `vnxa3.db` ដែលបានភ្ជាប់មកជាមួយ៖

| type | name | label | appearance | calculation |
|---|---|---|---|---|
| calculate | family_path | | | `pulldata('app-api', 'family_path')` |
| select_one | province | Province | `search-autocomplete-noedit-v2('rawquery', concat(${family_path}, '/vnxa3.db::externalData'), '[provv]', 'provid', 'SELECT provv, provid FROM externalData WHERE rta_filter = "1"')` | |

ជួរឈរ `appearance` (ពង្រីកដើម្បីងាយស្រួលអាន)៖

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[provv]', 'provid',
  'SELECT provv, provid FROM externalData WHERE rta_filter = "1"')
```

- ស្លាកដែលបានបង្ហាញបានមកពីជួរឈរ `provv`។
- តម្លៃដែលបានរក្សាទុកបានមកពីជួរឈរ `provid`។
- បង្ហាញតែជួរដេកណាដែលមាន `rta_filter = "1"` ប៉ុណ្ណោះ។

## សំណួរដែលមានប៉ារ៉ាម៉ែត្រ (Parameterized queries)

ប្រើសញ្ញាសួរ `?` នៅក្នុង SQL របស់អ្នក ហើយបញ្ជូនឯកសារយោងវាលដែលត្រូវគ្នាជាអាគុយម៉ង់បន្ថែម (ទីតាំងទី 6 តទៅ)។ នេះគឺជាលំនាំស្តង់ដារសម្រាប់ការជ្រើសរើសជាបន្តបន្ទាប់ (cascading selects) — ឧទាហរណ៍៖ ការទាញយកស្រុកដែលជាចំណុះឱ្យខេត្តដែលបានជ្រើសរើសពីមុន។

<Callout type="warning">
ប្រសិនបើ SQL របស់អ្នកមានយ៉ាងហោចណាស់សញ្ញាសួរ `?` មួយ ហើយគ្មានអាគុយម៉ង់ប៉ារ៉ាម៉ែត្រត្រូវបានផ្តល់ឱ្យទេ នោះវាលនឹងត្រឡប់សំណុំលទ្ធផលទទេរមកវិញ។ នេះការពារទិន្នន័យចាស់ ឬទិន្នន័យដែលមិនត្រូវបានត្រង ពីការបង្ហាញមុនពេលការជ្រើសរើសមេត្រូវបានធ្វើឡើង។
</Callout>

### ឧទាហរណ៍ការជ្រើសរើសស្រុកបន្តបន្ទាប់

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[distv]', 'distid',
  'SELECT distv, distid FROM externalData
   WHERE provid = ? AND rta_filter = "1"',
  ${province})
```

តម្លៃនៃ `${province}` ត្រូវបានភ្ជាប់ទៅនឹងសញ្ញាសួរ `?` ទីមួយ។ វាលនេះគឺទទេររហូតដល់អ្នកចុះអង្កេតជ្រើសរើសខេត្តមួយ។

### ឧទាហរណ៍ប៉ារ៉ាម៉ែត្រពីរ — ការជ្រើសរើសឃុំបន្តបន្ទាប់

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[commv]', 'commid',
  'SELECT commv, commid FROM externalData
   WHERE provid = ? AND distid = ? AND rta_filter = "1"',
  ${province}, ${district})
```

ប៉ារ៉ាម៉ែត្រត្រូវបានភ្ជាប់តាមទីតាំង៖ `${province}` → សញ្ញាសួរ `?` ទីមួយ, `${district}` → សញ្ញាសួរ `?` ទីពីរ។

## UNION SELECT សម្រាប់តម្លៃពិសេស

ចាក់បញ្ចូលជួរដេកសិប្បនិម្មិត — ដូចជា "មិនដឹង" ឬ "បដិសេធមិនឆ្លើយ" — ដោយផ្ទាល់នៅក្នុង SQL ដោយប្រើ `UNION SELECT`៖

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[provv]', 'provid',
  'SELECT provv, provid FROM externalData WHERE rta_filter = "1"
   UNION SELECT "<i>មិនដឹង</i>", "888"')
```

អនុសញ្ញាដែលបានប្រើក្នុងទម្រង់បែបបទ RTSurvey៖

| កូដ | អត្ថន័យ |
|---|---|
| `888` | មិនដឹង |
| `999` | បដិសេធមិនឆ្លើយ |

ស្លាក HTML ដូចជា `<i>` នៅក្នុងខ្សែអក្សរបង្ហាញ ត្រូវបានបង្ហាញដោយកម្មវិធី — អ្នកអាចប្រើពួកវាដើម្បីបែងចែកជម្រើសពិសេសៗដោយមើលឃើញ។

## ការបង្ហាញច្រើនភាសា

រក្សាទុកស្លាកតាមភាសានីមួយៗក្នុងជួរឈរដាច់ដោយឡែកពីគ្នា (ឧទាហរណ៍៖ `label_vi`, `label_en`) ហើយជ្រើសរើសយកមួយដែលសមស្របតាមវាលភាសានៅក្នុងទម្រង់បែបបទរបស់អ្នក៖

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[label_vi]', 'provid',
  'SELECT label_vi, label_en, provid FROM externalData
   WHERE rta_filter = "1"')
```

ដើម្បីប្តូរជួរឈរតាមលក្ខណៈថាមវន្តដោយផ្អែកលើវាល `${language}` សូមប្រើកន្សោម `if()` នៅលើប៉ារ៉ាម៉ែត្រជួរឈរបង្ហាញ ដើម្បីប្តូររវាងជួរឈរភាសា៖

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  if(${language} = 'vi', '[label_vi]', '[label_en]'),
  'provid',
  'SELECT label_vi, label_en, provid FROM externalData
   WHERE rta_filter = "1"')
```

<Callout type="info">
ប៉ារ៉ាម៉ែត្រជួរឈរបង្ហាញត្រូវបានវាយតម្លៃមុនពេលសំណួរដំណើរការ។ មានតែឈ្មោះជួរឈរ (ដោយគ្មានវង់ក្រចក) ប៉ុណ្ណោះដែលត្រូវបានបញ្ជូនទៅម៉ាស៊ីន SQL; វង់ក្រចកគឺជាសញ្ញាសម្គាល់សម្រាប់តែសោភ័ណភាពដែលត្រូវបានដកចេញនៅពេលញែក (parse)។
</Callout>

## ការផ្ទៀងផ្ទាត់ការជ្រើសរើសពិតប្រាកដ

នៅពេលដែលវាលអនុញ្ញាតឱ្យប្រើតម្លៃពិសេសដូចជា 888 ឬ 999 ការត្រួតពិនិត្យ `required = yes` ធម្មតាគឺមិនគ្រប់គ្រាន់ទេ — វាត្រូវបានបំពេញ សូម្បីតែអ្នកចុះអង្កេតជ្រើសរើស "មិនដឹង" ក៏ដោយ។ ប្រើលក្ខខណ្ឌបង្ខំ `selected-at(., 0) != -997` ដើម្បីផ្ទៀងផ្ទាត់ថាតម្លៃដែលបានរក្សាទុកគឺជាការជ្រើសរើសពិតប្រាកដ និងមិនមែនជាសញ្ញាសម្គាល់ផ្ទៃក្នុង "គ្មានអ្វីត្រូវបានជ្រើសរើស" `-997`៖

| ជួរឈរ | តម្លៃ |
|---|---|
| constraint | `selected-at(., 0) != -997` |
| constraint_message | សូមជ្រើសរើសជម្រើសដែលមានសុពលភាព |

តម្លៃ `-997` គឺជាកូដផ្ទៃក្នុងដែល RTSurvey រក្សាទុក នៅពេលដែលគ្មានធាតុណាមួយត្រូវបានជ្រើសរើសពីបញ្ជីបំពេញស្វ័យប្រវត្តិ។ ការជ្រើសរើសយក 888 ឬ 999 នៅតែជាជម្រើសដែលមានបំណងច្បាស់លាស់ ហើយឆ្លងកាត់ការត្រួតពិនិត្យនេះ។

ដើម្បីទាមទារបន្ថែមនូវតម្លៃពិតប្រាកដ (មិនមែនជាតម្លៃពិសេស) សូមពង្រីកលក្ខខណ្ឌបង្ខំ៖

```
selected-at(., 0) != -997 and selected-at(., 0) != '888' and selected-at(., 0) != '999'
```

## ដែនកំណត់

- ឯកសារ `.db` ត្រូវតែភ្ជាប់មកជាមួយកញ្ចប់មេឌៀរបស់ទម្រង់បែបបទមុនពេលដាក់ឱ្យប្រើប្រាស់។ ការធ្វើបច្ចុប្បន្នភាពថាមវន្តចំពោះមូលដ្ឋានទិន្នន័យ តម្រូវឱ្យមានការដាក់ឱ្យប្រើប្រាស់ទម្រង់បែបបទថ្មី។
- SQL ត្រូវបានអនុវត្តដូចដែលមាននៅលើឧបករណ៍។ គ្មានការសម្អាតខាងម៉ាស៊ីនបម្រើទេ — ចៀសវាងការបង្កើត SQL ពីការបញ្ចូលអត្ថបទសេរីរបស់អ្នកចុះអង្កេត។
- មានតែសេចក្តីថ្លែងការណ៍ `SELECT` ប៉ុណ្ណោះដែលត្រូវបានគាំទ្រ។ `INSERT`, `UPDATE`, និង `DELETE` មិនត្រូវបានអនុញ្ញាតទេ។
- សំណួរដែលស្មុគស្មាញខ្លាំង (ខ្សែសង្វាក់ `UNION` ធំ, ការតភ្ជាប់ច្រើន) អាចនឹងយឺតនៅលើឧបករណ៍ Android កម្រិតទាប។
- វ៉ារ្យ៉ង់ `search-autocomplete-noedit` មិនអនុញ្ញាតឱ្យអ្នកចុះអង្កេតរក្សាទុកតម្លៃដែលមិនមាននៅក្នុងសំណុំលទ្ធផលនោះទេ។ ប្រសិនបើត្រូវការបញ្ចូលអត្ថបទសេរី សូមប្រើវាល `text` ដាច់ដោយឡែក។
- `SELECT DISTINCT` ត្រូវបានចាក់បញ្ចូលដោយស្វ័យប្រវត្តិ លុះត្រាតែ `DISTINCT` អវត្តមានពីសំណួរ។ ប្រសិនបើអ្នកសរសេរ `SELECT DISTINCT` ច្បាស់លាស់ វានឹងមិនត្រូវបានបញ្ចូលស្ទួនទេ។
