---
title: "Rangfolge"
description: "Rangfolge-Fragen ermöglichen es den Befragten, eine Reihe von Auswahlmöglichkeiten nach Präferenz oder Priorität zu ordnen."
---

Der Fragetyp `rank` präsentiert eine Liste von Auswahlmöglichkeiten, die der Befragte nach Präferenz oder Priorität ordnet. Das Ergebnis wird als durch Leerzeichen getrennte Liste der Auswahlwerte in der Rangfolge gespeichert, wobei die Auswahl mit der höchsten Priorität zuerst steht.

> **rtSurvey-Webformular:** Das Drag-to-Rank-Widget ist derzeit nicht implementiert. Im Webformular wird `rank` als Auswahlliste dargestellt. Verwenden Sie diesen Typ, wenn Sie mobile Clients ansprechen, die das Rangfolgen-Widget unterstützen, oder wenn das Format des gespeicherten Wertes wichtiger ist als die Drag-to-Order-Interaktion.

## Grundlegende XLSForm-Spezifikation

| type | name | label |
|------|------|-------|
| rank priorities | main_priority | Ordnen Sie diese Gemeinschaftsbedürfnisse von am wichtigsten bis am wenigsten wichtig |

Die Auswahlmöglichkeiten werden im **Choices-Arbeitsblatt** genau wie bei `select_one` definiert:

**survey:**

| type | name | label |
|------|------|-------|
| rank priorities | main_priority | Ordnen Sie diese Bedürfnisse von am wichtigsten bis am wenigsten wichtig |

**choices:**

| list_name | name | label |
|-----------|------|-------|
| priorities | water | Sauberes Wasser |
| priorities | health | Gesundheitsversorgung |
| priorities | education | Bildung |
| priorities | roads | Straßen |
| priorities | electricity | Elektrizität |

## Format des gespeicherten Wertes

Der gespeicherte Wert ist eine **durch Leerzeichen getrennte Liste** von Auswahlwerten in der Rangfolge (zuerst = höchste Priorität):

```
water education health roads electricity
```

## Extrahieren von Rangpositionen

Verwenden Sie `selected-at()`, um die Auswahl an einem bestimmten Rang zu erhalten:

| type | name | label | calculation |
|------|------|-------|-------------|
| rank priorities | main_priority | Gemeinschaftsbedürfnisse ordnen | |
| calculate | top_priority | | selected-at(`${main_priority}`, 0) |
| calculate | second_priority | | selected-at(`${main_priority}`, 1) |

`selected-at(${main_priority}, 0)` gibt den Wert zurück, der an **erster** Stelle steht (Index 0 = oberster Rang).

## Verwendung von `rank-index()` mit Wiederholungsgruppen

Wenn `rank` innerhalb einer Wiederholungsgruppe (Repeat Group) verwendet wird, ermöglicht `rank-index()` den Zugriff auf den Ordinalrang von außerhalb der Wiederholung:

| type | name | label | calculation |
|------|------|-------|-------------|
| calculate | first_ranked | | rank-index(1, `${score}`) |

Siehe [Funktionen — Wiederholte Feld-Funktionen](../operators-and-functions/functions#repeated-field-functions) für vollständige Einzelheiten zu `rank-index()` und `rank-index-if()`.

## Anwendungen

Rangfolge-Fragen werden häufig verwendet für:

1. **Prioritätsranking** — Befragung von Gemeinschaften zur Einstufung von Entwicklungsbedarfen
2. **Präferenzordnung** — Einstufung von Produktmerkmalen, Dienstleistungsattributen oder Richtlinienoptionen
3. **Prüfungsreihenfolge** — Anordnung von Schritten in einem Prozess
4. **Top-N-Auswahl** — kombiniert mit `selected-at()`, um nur die ersten 1, 2 oder 3 Auswahlmöglichkeiten zu extrahieren

## Best Practices

1. Halten Sie die Liste kurz (3–7 Elemente) — das Ranking wird jenseits von 7–8 Auswahlmöglichkeiten kognitiv belastend.
2. Verwenden Sie klare, sich gegenseitig ausschließende Auswahlbeschriftungen, um Verwirrung darüber zu vermeiden, was „zuerst“ bedeutet.
3. Fügen Sie einen Hinweistext hinzu, der die Richtung der Rangfolge erklärt (z. B. „Ziehen zum Ordnen: zuerst = am wichtigsten“).
4. Validieren Sie mit `count-selected(.) = x`, wenn Sie sicherstellen müssen, dass alle Auswahlmöglichkeiten eingestuft wurden.

## Einschränkungen

- Das Drag-to-Rank-Widget ist im rtSurvey-Webformular nicht implementiert.
- Ein teilweises Ranking ist nicht möglich — alle Auswahlmöglichkeiten müssen geordnet werden.
- Halten Sie Listen auf 3–7 Elemente beschränkt; längere Listen werden unabhängig vom Client unhandlich.
