---
title: "Dynamische Suche"
description: "Die dynamische Suche lädt Antwortmöglichkeiten in Echtzeit von einer Remote-API, während der Enumerator tippt. Dies ermöglicht die Nutzung großer oder häufig aktualisierter Datensätze."
---

**Dynamische Suche** (auch Search API genannt) ermöglicht es einem `select_one`-, `select_multiple`- oder `text`-Feld, seine Antwortmöglichkeiten **während der Laufzeit** von einem Remote-Webdienst zu laden, während der Enumerator tippt. Dies ist der richtige Ansatz, wenn Ihre Auswahlliste zu groß ist, um sie in einer CSV-Datei zu bündeln, wenn sie häufig aktualisiert wird oder aus einer Live-Datenbank stammt.

---

## `search-api()` Erscheinungsbild (Appearance)

Die dynamische Suche wird über die Spalte `appearance` mit der Funktion `search-api()` konfiguriert:

```
search-api(method, url, post_body, value_column, display, data_path, save_path)
```

### Parameter

| Parameter | Beschreibung |
|-----------|-------------|
| `method` | Verwenden Sie immer `'POST'` |
| `url` | Der abzufragende API-Endpunkt |
| `post_body` | JSON-Body, der an die API gesendet wird. Verwenden Sie `%__input__%` als Platzhalter für den aktuellen Suchtext des Enumerators |
| `value_column` | Der Schlüssel im Antwortobjekt, der als gespeicherter **Wert** (Value) verwendet werden soll |
| `display` | Der Schlüssel (oder das Template), der als im Dropdown-Menü angezeigtes **Label** verwendet werden soll. Unterstützt `##key##`-Platzhalter und `@{func}`-Ausdrücke |
| `data_path` | JSONPath zum Array der Ergebnisobjekte in der Antwort (z. B. `$.data`, `$.hits.hits.*._source`) |
| `save_path` | Ein Name, unter dem die Rohantwort zur Verwendung durch andere Felder gespeichert wird |

---

## Basispiel

Suche nach einer Gesundheitseinrichtung, bei der der Enumerator einen Teil des Namens der Einrichtung eingibt:

| type | name | label | appearance |
|------|------|-------|------------|
| select_one | facility | Gesundheitseinrichtung auswählen | `search-api('POST', 'https://api.example.com/facilities/search', '{"query": "%__input__%"}', 'id', 'name', '$.results', 'facility_data')` |

Die API erhält `{"query": "nair"}`, wenn der Enumerator „nair“ eingibt, und gibt Folgendes zurück:

```json
{
  "results": [
    {"id": "HF001", "name": "Nairobi Central Clinic"},
    {"id": "HF002", "name": "Nairobi West Hospital"}
  ]
}
```

Das Dropdown-Menü zeigt `Nairobi Central Clinic` und `Nairobi West Hospital` an; der gespeicherte Wert ist `HF001` oder `HF002`.

## Erweiterte Formatierung der Anzeige

### Verwendung von `##key##`-Templates

Mehrere Felder im Label anzeigen:

```
search-api('POST', 'https://api.example.com/search', '{"q": "%__input__%"}', 'id', '##name## (##district##)', '$.data', 'res')
```

Anzeige als: `Nairobi Central Clinic (Nairobi)`.

### Verwendung von `@{func}`-Ausdrücken

Bedingte Logik im Anzeige-Label anwenden:

```
search-api('POST', 'https://api.example.com/search', '{"q": "%__input__%"}', 'id',
  '@{if_else(eq("##status##", "active"), "✓ ##name##", "✗ ##name##")}',
  '$.data', 'res')
```

Aktive Ergebnisse zeigen `✓ Clinic Name`; inaktive zeigen `✗ Clinic Name`.

## Einen Standardwert festlegen: `search-default-api()`

Verwenden Sie `search-default-api()` nach `search-api()`, um das Feld mit einer Standardauswahl vorzubereiten, die aus einem separaten API-Aufruf geladen wird (z. B. beim Bearbeiten eines vorhandenen Datensatzes):

```
appearance: search-api(...) search-default-api('POST', 'https://api.example.com/get', '{"id": "##saved_id##"}', 'id', 'name', '$.item')
```

---

## Benutzerdefiniertes Trennzeichen für select_multiple: `search-default-separator()`

Geben Sie für `select_multiple`-Felder an, wie mehrere ausgewählte Werte in der gespeicherten Zeichenfolge verbunden werden sollen:

```
appearance: search-api(...) search-default-separator(' || ')
```

Das Standard-Trennzeichen ist ein Leerzeichen.

## Unterstützte Fragetypen

| Fragetyp | Anwendungsfall |
|---------------|----------|
| `select_one` | Einzelauswahl aus Suchergebnissen |
| `select_multiple` | Mehrfachauswahl aus Suchergebnissen |
| `text` | Autovervollständigung — der Enumerator tippt frei, kann aber einen Vorschlag auswählen |

## Verwendung gespeicherter Antwortdaten

Wenn der Enumerator ein Ergebnis auswählt, speichert rtSurvey das vollständige passende Objekt aus der Antwort unter dem Namen `save_path`. Andere Felder können auf zwei Arten daraus lesen.

### Methode 1 — `pulldata()`-Abfrage

Verwenden Sie `pulldata('save_path', 'key')`, um ein Feld der obersten Ebene aus dem gespeicherten Objekt zu lesen:

| type | name | label | calculation |
|------|------|-------|-------------|
| select_one | facility | Einrichtung auswählen | |
| calculate | facility_district | | `pulldata('facility_data', 'district')` |
| calculate | facility_type | | `pulldata('facility_data', 'type')` |
| calculate | facility_beds | | `pulldata('facility_data', 'beds')` |

Das Erscheinungsbild (`appearance`) in der `select_one`-Zeile muss `search-api(..., 'facility_data')` mit dem passenden `save_path` enthalten.

Für **verschachtelte JSON-Felder** kombinieren Sie dies mit `substr-jsonpath()`:

```
substr-jsonpath(pulldata('facility_data', 'location'), '$.district')
```

## Lokale Dateisuche mit search()

`search()` führt Offline-Abfragen auf Spaltengleichheit gegen eine mitgelieferte SQLite-`.db`-Datei durch — keine Netzwerkverbindung und keine SQL-Abfragen erforderlich. Verwenden Sie dies, wenn Ihre Referenzdaten mit dem Formular paketiert sind und Sie eine einfache Suche nach dem Motto „Finde alle Zeilen, in denen die Spalte dem Wert entspricht“ benötigen.

### Signatur

```
search(path, 'matches', 'list_name', ${field})
```

### Parameter

| Parameter | Beschreibung |
|-----------|-------------|
| `path` | Pfad zur SQLite-Tabelle: `concat(${family_path}, '/file.db::table')` |
| `'matches'` | Match-Operator — gibt Zeilen zurück, in denen die Spalte dem Wert entspricht |
| `'list_name'` | Spaltenname, gegen den gematcht werden soll |
| `${field}` | Wert, der gematcht werden soll; normalerweise eine Feldreferenz |

### Beispiel

Befüllen eines `select_one`-Feldes aus einer lokalen Datenbank, indem der Wert von `${d307}` mit der Spalte `list_name` in der Tabelle `externalData` von `d307.db` abgeglichen wird:

| type | name | label | appearance |
|------|------|-------|------------|
| select_one | facility | Einrichtung auswählen | `search(concat(${family_path}, '/d307.db::externalData'), 'matches', 'list_name', ${d307})` |

Wenn `${d307}` gleich `"HF001"` ist, gibt `search()` jede Zeile in `externalData` zurück, in der `list_name = 'HF001'` ist — vollständig aus der mitgelieferten Datei, ohne Netzwerkaufruf.

### search() vs. rawquery Autovervollständigung

| Funktion | `search()` | `rawquery` Autovervollständigung |
|---------|-----------|------------------------|
| SQL-Abfragen | Nein — nur Spaltengleichheit | Ja — vollständiges `SELECT … FROM …` |
| Parametrisierte Eingabe | Spaltenwert-Match | In SQL-String eingebettet |
| Freitext-Eingabe | Ja — Enumerator kann frei tippen | Nein — muss aus Liste auswählen |
| UNION / Multi-Tabelle | Nicht unterstützt | Unterstützt |

### Wann welches Tool zu verwenden ist

- Verwenden Sie **`search()`**, wenn Sie einen einfachen Gleichheitsabgleich gegen eine mitgelieferte `.db`-Datei benötigen, das Formular offline funktionieren muss und Sie Freitext-Eingaben zulassen möchten.
- Verwenden Sie **`rawquery` Autovervollständigung**, wenn Sie SQL-Flexibilität benötigen (JOINs, UNIONs, berechnete Spalten) oder über mehrere Tabellen hinweg abfragen müssen und das Formular über eine zuverlässige Verbindung verfügt.

## Best Practices

1. Stellen Sie sicher, dass Ihr API-Endpunkt innerhalb von 1–2 Sekunden antwortet — langsame APIs lassen die Suche träge erscheinen.
2. Verwenden Sie `%__input__%` im `post_body`, damit die API nur passende Ergebnisse zurückgibt und nicht den gesamten Datensatz.
3. Indizieren Sie das Suchfeld serverseitig (z. B. Elasticsearch, Datenbank-Volltextindex) für schnelle Antworten.
4. Begrenzen Sie die Ergebnisse auf 20–50 Einträge pro Abfrage — die Rückgabe von Tausenden von Ergebnissen macht den Zweck der Suche zunichte.
5. Fügen Sie eine Anforderung für eine Mindesteingabelänge in der API hinzu, um zu vermeiden, dass bei einstelligen Eingaben umfangreiche Abfragen ausgelöst werden.

## Einschränkungen

- Die dynamische Suche erfordert eine Netzwerkverbindung — sie funktioniert nicht offline.
- Der Platzhalter `%__input__%` wird so wie er ist injiziert; bereinigen Sie Eingaben serverseitig, um Injection-Angriffe zu verhindern.
- Komplexe `@{func}`-Anzeigeausdrücke haben möglicherweise nur begrenzte Unterstützung über alle rtSurvey-Client-Versionen hinweg.
