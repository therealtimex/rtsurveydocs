---
title: "Geotrace"
description: "Les questions Geotrace capturent une série de points GPS formant une ligne ou un chemin."
---

Le type de question `geotrace` capture une séquence de coordonnées géographiques formant une ligne ou un chemin (polyline). Dans le formulaire web de rtSurvey, cela se présente sous la forme d'un **champ de texte** où l'enquêteur (énumérateur) saisit ou colle directement la chaîne de coordonnées.

## Spécification de base XLSForm

| type     | name        | label                        |
|----------|-------------|------------------------------|
| geotrace | river_path  | Tracer le chemin de la rivière |
| geotrace | road_route  | Enregistrer l'itinéraire de la route |

Pour la spécification standard, voir la [documentation XLSForm](https://xlsform.org/en/#question-types).

---

## Format des données (Data Format)

Stocké sous forme d'une liste de points séparés par des points-virgules **sans espaces autour des points-virgules**. Chaque point est composé de quatre valeurs séparées par des espaces :

```
lat lon alt acc;lat lon alt acc;lat lon alt acc
```

| Component | Description |
|-----------|-------------|
| `lat` | Latitude en degrés décimaux |
| `lon` | Longitude en degrés décimaux |
| `alt` | Altitude en mètres (`0` si inconnue) |
| `acc` | Précision GPS en mètres (`0` si inconnue) |

**Exemple — un chemin à trois points :**
```
13.756331 100.501762 15 8;13.758000 100.503000 14 6;13.760000 100.505000 13 5
```

Un minimum de deux points est requis pour former un chemin valide.

---

## Comment il s'affiche dans rtSurvey

Dans le formulaire web de rtSurvey, `geotrace` s'affiche comme un simple **champ de texte**. L'enquêteur tape ou colle la chaîne de coordonnées. Il n'y a pas de sélecteur de carte interactif intégré pour ce type dans le formulaire web actuel.

### Collecte de points de manière interactive

Le modèle recommandé pour la collecte sur le terrain est un **groupe de répétition (repeat group) de questions `geopoint`** — chaque point utilise le sélecteur de carte GPS complet — combiné à un `calculate` pour produire la chaîne geotrace :

| type | name | label | calculation |
|------|------|-------|-------------|
| begin repeat | path_points | Enregistrer chaque point de passage | |
| geopoint | point | Appuyer pour enregistrer le point | |
| end repeat | path_points | | |
| calculate | geotrace_value | | `join(';', ${path_points/point})` |

La chaîne calculée peut ensuite être stockée dans une question de type `text` ou utilisée dans `geotrace`.

## Exemple d'utilisation

| type | name | label | hint | required |
|------|------|-------|------|----------|
| geotrace | farm_boundary_path | Enregistrer le chemin d'accès à la ferme | Saisir chaque point de passage séparé par des points-virgules | yes |

---

## Bonnes pratiques

1. Utilisez un groupe de répétition de questions `geopoint` pour une collecte interactive basée sur une carte, puis joignez les valeurs — cela donne aux enquêteurs un sélecteur GPS pour chaque point individuel.
2. Incluez le format attendu dans la colonne `hint` lorsqu'une saisie manuelle des coordonnées est requise.
3. Validez la présence avec `required = yes` lorsque le chemin est obligatoire.
4. Prévoyez le nettoyage des données — les chemins saisis manuellement peuvent avoir une précision incohérente.

## Limites (Limitations)

- Il n'y a pas de sélecteur de carte interactif intégré pour `geotrace` dans le formulaire web de rtSurvey.
- La chaîne de coordonnées peut être longue pour des chemins complexes — gardez cela à l'esprit pour la performance du formulaire et le stockage.
- La validation de la topologie du chemin (ex: nombre minimum de points, auto-intersection) nécessite un post-traitement en dehors des contraintes XLSForm.
