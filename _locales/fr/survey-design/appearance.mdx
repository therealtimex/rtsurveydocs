La colonne `appearance` dans rtSurvey vous permet de personnaliser la présentation visuelle et le comportement des questions dans vos enquêtes. Cette fonctionnalité améliore l'expérience utilisateur et peut considérablement améliorer l'efficacité de la collecte de données. rtSurvey prend en charge les attributs d'apparence standard de XLSForm et les étend avec des options supplémentaires.

## Attributs d'apparence standard de XLSForm

rtSurvey prend en charge les attributs d'apparence standard de XLSForm suivants :

| Attribut d'apparence | Types de questions | Description |
|----------------------|--------------------|-------------|
| multiline | text | Crée une zone de texte multiligne (idéal pour les clients web) |
| minimal | select_one, select_multiple | Affiche les choix dans un menu déroulant |
| quick | select_one | Passe automatiquement à la question suivante après la sélection (mobile uniquement) |
| no-calendar | date | Supprime l'affichage du calendrier (mobile uniquement) |
| month-year | date | Permet de sélectionner uniquement le mois et l'année |
| year | date | Permet de sélectionner uniquement l'année |
| horizontal-compact | select_one, select_multiple | Affiche les choix horizontalement (web uniquement) |
| horizontal | select_one, select_multiple | Affiche les choix horizontalement en colonnes (web uniquement) |
| likert | select_one | Présente les choix sous forme d'échelle de Likert |
| compact | select_one, select_multiple | Affiche les choix côte à côte avec un espacement minimal |
| quickcompact | select_one | Combine l'affichage compact avec l'avance automatique (mobile uniquement) |
| field-list | groups | Affiche tout le groupe sur un seul écran (mobile uniquement) |
| label | select_one, select_multiple | Affiche les étiquettes de choix sans champs de saisie |
| list-nolabel | select_one, select_multiple | Affiche les champs de saisie sans étiquettes (à utiliser avec `label`) |
| table-list | groups | Affiche les questions sous forme de tableau |
| signature | image | Permet la capture de signature (mobile uniquement) |
| draw | image | Permet le dessin à main levée (mobile uniquement) |
| map, quick map | select_one, select_one_from_file | Permet la sélection à partir d'éléments de carte |

## Bonnes pratiques pour l'utilisation de l'apparence

1. **Cohérence** : Utilisez les attributs d'apparence de manière cohérente dans toute votre enquête pour un aspect uniforme.
2. **Mobile vs Web** : Réfléchissez au rendu des apparences sur différents appareils et plateformes.
3. **Performance** : Soyez prudent avec les attributs d'apparence qui pourraient ralentir le chargement du formulaire (ex: `table-list` pour les grands groupes).
4. **Expérience utilisateur** : Choisissez des apparences qui facilitent la saisie des données et la rendent plus intuitive pour les répondants.
5. **Test** : Testez toujours votre formulaire sur les appareils cibles pour vous assurer que les apparences fonctionnent comme prévu.

## Techniques avancées

### Combinaison d'apparences

Certains attributs d'apparence peuvent être combinés pour des mises en page plus complexes :

```
| type | name | label | appearance |
|------|------|-------|------------|
| select_one options | choice | Select one: | minimal compact |
```

### Apparences dynamiques

rtSurvey permet des changements d'apparence dynamiques basés sur la logique du formulaire :

```
| type | name | label | appearance | relevant |
|------|------|-------|------------|----------|
| text | time | Enter time: | inline-[%H:%M] | ${show_time} = 'yes' |
```

## Considérations relatives aux applications mobiles

- Certaines apparences (ex: `quick`, `signature`) sont spécifiques aux appareils mobiles.
- Testez rigoureusement sur Android et iOS pour garantir un comportement cohérent.

## Attributs d'apparence étendus de rtSurvey

En plus des apparences standard de XLSForm, rtSurvey prend en charge les options spécifiques à la plateforme suivantes :

### Contrôle des données et de l'affichage

| Attribut d'apparence | Types de questions | Description |
|----------------------|--------------------|-------------|
| `invisible` | n'importe lequel | Masque le champ de la vue tout en continuant à collecter ou à calculer sa valeur. Différent du type `hidden` — le champ participe toujours à la logique. |
| `displaytitle` | n'importe lequel | Force l'affichage de l'étiquette/titre du champ même lorsqu'il serait autrement supprimé. |
| `autopull` | select_one, select_multiple | Récupère automatiquement des données externes pour remplir les choix lors du chargement du formulaire ou du changement d'un champ déclencheur. |
| `floating_hint` | text, integer, decimal | Affiche le texte d'aide (hint) sous forme d'étiquette flottante au-dessus du champ de saisie plutôt qu'en dessous. |
| `calculate-button` | calculate | Ajoute un bouton visible qui déclenche le recalcul du champ à la demande, plutôt qu'un calcul automatique. |

### Mise en page (Layout)

| Attribut d'apparence | Types de questions | Description |
|----------------------|--------------------|-------------|
| `1screen` | group | Force l'affichage de tout le groupe sur un seul écran, quelle que soit la taille du groupe. |
| `columns(n)` | select_one, select_multiple | Affiche les choix sur `n` colonnes. Exemple : `columns(3)` affiche trois colonnes de boutons radio. |
| `gridformat<row=R col=C colspan=S align=center>` | n'importe lequel | Positionne le champ dans une mise en page CSS-grid à la ligne `R`, colonne `C`, sur `S` colonnes. Utilisé avec `advanced-extension/grid-layout`. |
| `ignore-simplify` | n'importe lequel | Indique au moteur de rendu du formulaire d'ignorer la simplification ou la condensation automatique de la mise en page de ce champ. |

### Widgets

| Attribut d'apparence | Types de questions | Description |
|----------------------|--------------------|-------------|
| `likert` | select_one | Présente les choix sous forme de ligne d'échelle de Likert (déjà présent dans le tableau standard ci-dessus ; prise en charge confirmée). |
| `distress` | select_one | Affiche les choix sous la forme du widget visuel de l'échelle de détresse psychologique de Kessler (K10) avec des icônes émotionnelles. |

### Intégration API

| Attribut d'apparence | Types de questions | Description |
|----------------------|--------------------|-------------|
| `callapi` | text, integer, decimal, select_one | Active l'intégration des appels API pour ce champ. La colonne de calcul (calculation) doit contenir une expression `callapi()`. Voir [Call API](advanced-features/call-api). |
| `callapi-verify(params)` | text, integer, decimal | Déclenche un appel de vérification API à l'aide de paramètres statiques. Le formulaire bloque la progression jusqu'à ce que l'API confirme la valeur. |
| `callapi-verify(dynamicParams)` | text, integer, decimal | Identique à `callapi-verify` mais avec des paramètres dérivés d'autres valeurs de champ au moment de l'exécution. |

### Format de date/heure en ligne (inline)

Pour les champs `date`, `time` et `datetime`, vous pouvez spécifier un format d'affichage personnalisé à l'aide d'une chaîne de format ajoutée à l'apparence :

```
inline-[%d/%m/%Y]
inline-1line-[%d/%m/%Y %H:%M]
```

Les jetons de format sont les mêmes que `format-date()` et `format-date-time()`. Voir [Fonctions — Fonctions de date et d'heure](operators-and-functions/functions#date-and-time-functions).

Exemple :

| type | name | label | appearance |
|------|------|-------|------------|
| datetime | event_time | Date et heure de l'événement | inline-[%d/%m/%Y %I:%M %p] |
| date | birth_date | Date de naissance | inline-[%d/%m/%Y] |

### Disposition des boutons en ligne — `display{}` et `results{}`

Pour les types de questions qui s'affichent sous forme de bouton d'icône en ligne (`date`, `time`, `datetime`, `image`, `audio`, `video`, `file`, `barcode`, `geopoint`), deux modificateurs d'apparence contrôlent la position du bouton et le comportement après la capture.

#### `display{...}` — position du bouton avant la capture

```
display{<align>, <size>, <color>}
```

| Paramètre | Valeurs | Par défaut |
|-----------|---------|------------|
| Align (Alignement) | `left`, `right`, `top`, `center`, `bottom` | `right` |
| Size (Taille) | `small`, `medium`, `large` | `small` |
| Color (Couleur) | hex ex: `#FF5500` | couleur principale du thème |
| Flag | `inline-icon` | force le mode icône |

| Valeur d'Align | Mise en page |
|----------------|--------------|
| `right` | Bouton à droite de l'étiquette |
| `left` | Bouton à gauche de l'étiquette |
| `top` | Bouton au-dessus de l'étiquette, centré sur toute la largeur |
| `center` / `bottom` | Bouton au-dessous de l'étiquette, centré sur toute la largeur |

#### `results{...}` — mise en page et visibilité après la capture

Hérite des paramètres de `display{}`. À utiliser pour déplacer le bouton ou masquer des éléments une fois qu'une valeur a été capturée.

```
results{<align>, hide(<element>)}
```

| Valeur de `hide` | Effet |
|---|---|
| `hide(capture)` | Masque le bouton de capture une fois qu'un fichier/une valeur existe |
| `hide(review)` | Masque la vignette de révision / le bouton de lecture |
| `hide(filename)` | Masque le nom du fichier affiché après le téléchargement |
| `hide(camera)` | Masque le bouton de déclenchement de l'appareil photo après la capture |
| `hide(scanner)` | Masque le bouton de lecture du code-barres après la lecture d'une valeur |
| `hide(value)` | Masque le texte de la valeur lue (barcode / geopoint) |

Le widget passe automatiquement de la mise en page `display{}` à `results{}` au moment où une valeur est capturée.

**Exemples :**

```
inline display{right}                                    → icône à droite de l'étiquette
inline display{left, large}                              → grande icône sur la gauche
inline display{center, large, #FF5500}                   → grande icône orange sous l'étiquette
inline display{right} results{left}                      → l'icône se déplace vers la gauche après capture
inline display{right} results{hide(capture)}             → l'icône disparaît après capture
inline display{center} results{hide(capture), hide(filename)}
```

## Limitations connues

- Les apparences complexes peuvent ne pas s'afficher de manière identique sur toutes les plateformes.
- Certaines apparences rtSurvey avancées peuvent ne pas être prises en charge en mode hors connexion (offline).

## Dépannage des problèmes d'apparence

1. **L'apparence n'est pas appliquée** : Vérifiez s'il y a des fautes de frappe dans la colonne appearance.
2. **Rendu incohérent** : Vérifiez la compatibilité avec le type de question et la plateforme.
3. **Problèmes de performance** : Envisagez de simplifier les apparences complexes, en particulier pour les grandes enquêtes.
