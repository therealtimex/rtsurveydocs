La columna `appearance` en rtSurvey le permite personalizar la presentación visual y el comportamiento de las preguntas en sus encuestas. Esta característica mejora la experiencia del usuario y puede mejorar significativamente la eficiencia en la recolección de datos. rtSurvey admite los atributos de apariencia estándar de XLSForm y los extiende con opciones adicionales.

## Atributos de Apariencia Estándar de XLSForm

rtSurvey admite los siguientes atributos de apariencia estándar de XLSForm:

| Atributo de Apariencia (Appearance Attribute) | Tipos de Pregunta (Question Types) | Descripción |
|----------------------|----------------|-------------|
| multiline | text | Crea un cuadro de texto de varias líneas (ideal para clientes web) |
| minimal | select_one, select_multiple | Muestra las opciones en un menú desplegable |
| quick | select_one | Avanza automáticamente a la siguiente pregunta después de la selección (solo móvil) |
| no-calendar | date | Suprime la visualización del calendario (solo móvil) |
| month-year | date | Permite la selección de mes y año solamente |
| year | date | Permite la selección de año solamente |
| horizontal-compact | select_one, select_multiple | Muestra las opciones horizontalmente (solo web) |
| horizontal | select_one, select_multiple | Muestra las opciones horizontalmente en columnas (solo web) |
| likert | select_one | Presenta las opciones como una escala de Likert |
| compact | select_one, select_multiple | Muestra las opciones una al lado de la otra con un relleno mínimo |
| quickcompact | select_one | Combina la visualización compacta con el avance automático (solo móvil) |
| field-list | groups | Muestra el grupo completo en una sola pantalla (solo móvil) |
| label | select_one, select_multiple | Muestra las etiquetas de las opciones sin campos de entrada |
| list-nolabel | select_one, select_multiple | Muestra los campos de entrada sin etiquetas (usar con `label`) |
| table-list | groups | Muestra las preguntas en formato de tabla |
| signature | image | Permite la captura de firmas (solo móvil) |
| draw | image | Permite el dibujo a mano alzada (solo móvil) |
| map, quick map | select_one, select_one_from_file | Permite la selección desde características del mapa |

## Mejores Prácticas para el Uso de Appearance

1. **Consistencia**: Use los atributos de apariencia de manera consistente en toda su encuesta para una apariencia uniforme.
2. **Móvil vs. Web**: Considere cómo se representarán las apariencias en diferentes dispositivos y plataformas.
3. **Rendimiento**: Tenga cuidado con los atributos de apariencia que podrían ralentizar la carga del formulario (por ejemplo, `table-list` para grupos grandes).
4. **Experiencia del Usuario**: Elija apariencias que faciliten la entrada de datos y sean más intuitivas para los encuestados.
5. **Pruebas**: Siempre pruebe su formulario en los dispositivos de destino para asegurarse de que las apariencias funcionen como se espera.

## Técnicas Avanzadas

### Combinación de Apariencias

Algunos atributos de apariencia se pueden combinar para diseños más complejos:

```
| type | name | label | appearance |
|------|------|-------|------------|
| select_one options | choice | Seleccione uno: | minimal compact |
```

### Apariencias Dinámicas

rtSurvey permite cambios de apariencia dinámicos basados en la lógica del formulario:

```
| type | name | label | appearance | relevant |
|------|------|-------|------------|----------|
| text | time | Ingrese la hora: | inline-[%H:%M] | ${show_time} = 'yes' |
```

## Consideraciones para la Aplicación Móvil

- Algunas apariencias (por ejemplo, `quick`, `signature`) son específicas para dispositivos móviles.
- Pruebe minuciosamente tanto en Android como en iOS para garantizar un comportamiento consistente.

## Atributos de Apariencia Extendidos de rtSurvey

Además de las apariencias estándar de XLSForm, rtSurvey admite las siguientes opciones específicas de la plataforma:

### Control de datos y visualización

| Atributo de Apariencia (Appearance Attribute) | Tipos de Pregunta (Question Types) | Descripción |
|----------------------|----------------|-------------|
| `invisible` | any | Oculta el campo de la vista mientras sigue recolectando o calculando su valor. Diferente del tipo `hidden`: el campo sigue participando en la lógica. |
| `displaytitle` | any | Fuerza la visualización de la etiqueta/título del campo incluso cuando de otro modo estaría suprimido. |
| `autopull` | select_one, select_multiple | Obtiene automáticamente datos externos para completar las opciones cuando se carga el formulario o cambia un campo activador. |
| `floating_hint` | text, integer, decimal | Muestra el texto de sugerencia (hint) como una etiqueta flotante sobre el campo de entrada en lugar de debajo de él. |
| `calculate-button` | calculate | Agrega un botón visible que activa el recálculo del campo a pedido, en lugar de calcularlo automáticamente. |

### Grupo y navegación

| Atributo de Apariencia (Appearance Attribute) | Tipos de Pregunta (Question Types) | Descripción |
|----------------------|----------------|-------------|
| `section` | group | Representa el grupo como una tarjeta de sección colapsable. Nota: solo para la aplicación móvil. |
| `toc-hide` | any | Excluye la pregunta del panel de navegación de la tabla de contenido (TOC). |
| `minilog` | begin_repeat | Muestra las entradas de repetición completadas como una lista de mini-registro compacta en lugar de expandir cada entrada en línea. |

### Comportamiento de entrada

| Atributo de Apariencia (Appearance Attribute) | Tipos de Pregunta (Question Types) | Descripción |
|----------------------|----------------|-------------|
| `proper` | text | Capitaliza automáticamente la primera letra de cada palabra a medida que el encuestado escribe (comportamiento de tipo título). |
| `text-nolabel` | text, integer, decimal | Representa el campo de entrada sin una etiqueta visible. |
| `inline-1line` | text | Fuerza que la entrada de texto se muestre en una sola línea, incluso cuando la etiqueta de la pregunta es larga. |
| `popup` | any | Representa el campo dentro de una ventana emergente / superposición modal en lugar de en línea en la página. |

### Diseño (Layout)

| Atributo de Apariencia (Appearance Attribute) | Tipos de Pregunta (Question Types) | Descripción |
|----------------------|----------------|-------------|
| `1screen` | group | Fuerza a que todo el grupo se muestre en una sola pantalla, independientemente del tamaño del grupo. |
| `columns(n)` | select_one, select_multiple | Muestra las opciones en `n` columnas. Ejemplo: `columns(3)` muestra tres columnas de botones de radio. |
| `gridformat<row=R col=C colspan=S align=center>` | any | Posiciona el campo en un diseño de cuadrícula CSS en la fila `R`, columna `C`, abarcando `S` columnas. Se usa con `advanced-extension/grid-layout`. |
| `ignore-simplify` | any | Indica al renderizador del formulario que omita la simplificación o condensación automática del diseño de este campo. |
| `horizontal(N)` | select_one, select_multiple | Establece que cada opción ocupe el `N` por ciento del ancho de la fila. Ejemplo: `horizontal(50)` coloca dos opciones por fila. |
| `scroll-view(N%)` | group, repeat | Restringe el contenedor a una altura máxima del `N%` del viewport (o del padre), agregando una barra de desplazamiento cuando el contenido se desborda. Ejemplo: `scroll-view(60%)`. |

### Widgets

| Atributo de Apariencia (Appearance Attribute) | Tipos de Pregunta (Question Types) | Descripción |
|----------------------|----------------|-------------|
| `likert` | select_one | Presenta las opciones como una fila de escala de Likert (ya está en la tabla estándar anterior; soporte confirmado). |
| `distress` | select_one | Representa las opciones como el widget visual de la Escala de Distrés Psicológico de Kessler (K10) con iconos emocionales. |
| `rating_box-fill-{c1}-{c2}-{c3}-{c4}-{c5}` | select_one | Representa las opciones como cuadros de calificación estilizados con cinco ranuras de color. `c1` = borde exterior del contenedor, `c2` = borde no marcado, `c3` = borde marcado y relleno, `c4` = color de texto no marcado, `c5` = color de texto marcado. Ejemplo: `rating_box-fill-grey-blue-green-black-white`. |
| `tagging-choices-noshow-v2-{c1}-{c2}-{c3}-{c4}-{c5}` | select_multiple | Representa las opciones como etiquetas de colores (tag chips). Las cinco ranuras de color siguen el mismo orden que `rating_box-fill`. Las opciones seleccionadas se resaltan; las opciones no seleccionadas se suprimen de la vista de resumen. |

### Integración de API

| Atributo de Apariencia (Appearance Attribute) | Tipos de Pregunta (Question Types) | Descripción |
|----------------------|----------------|-------------|
| `callapi` | text, integer, decimal, select_one | Habilita la integración de llamadas a API para este campo. La columna de cálculo debe contener una expresión `callapi()`. Consulte [Llamar API (Call API)](advanced-features/call-api). |
| `callapi-verify(params)` | text, integer, decimal | Activa una llamada de verificación de API utilizando parámetros estáticos. El formulario bloquea el progreso hasta que la API confirma el valor. |
| `callapi-verify(dynamicParams)` | text, integer, decimal | Igual que `callapi-verify` pero con parámetros derivados de otros valores de campo en tiempo de ejecución. |

### Selector de idioma (Language switcher)

| Atributo de Apariencia (Appearance Attribute) | Tipos de Pregunta (Question Types) | Descripción |
|----------------------|----------------|-------------|
| `change_language-{colors} default('lang')` | note, text | Representa un widget selector de idioma estilizado con los códigos de color dados. El token `default('lang')` establece el idioma inicial (por ejemplo, `default('en')`); se reescribe a `rtDefault('lang')` internamente durante el procesamiento. Ejemplo: `change_language-blue-white default('vi')`. |

### Formato de fecha/hora en línea (Inline)

Para los campos `date`, `time` y `datetime`, puede especificar un formato de visualización personalizado utilizando una cadena de formato añadida a la apariencia:

```
inline-[%d/%m/%Y]
inline-1line-[%d/%m/%Y %H:%M]
```

Los tokens de formato son los mismos que en `format-date()` y `format-date-time()`. Consulte [Funciones — Funciones de fecha y hora](operators-and-functions/functions#date-and-time-functions).

Ejemplo:

| tipo (type) | nombre (name) | etiqueta (label) | apariencia (appearance) |
|------|------|-------|------------|
| datetime | event_time | Fecha y hora del evento | inline-[%d/%m/%Y %I:%M %p] |
| date | birth_date | Fecha de nacimiento | inline-[%d/%m/%Y] |

### Diseño de botones en línea — `display{}` y `results{}`

Para los tipos de preguntas que se representan como un botón de icono en línea (`date`, `time`, `datetime`, `image`, `audio`, `video`, `file`, `barcode`, `geopoint`), dos modificadores de apariencia controlan la posición del botón y el comportamiento posterior a la captura.

#### `display{...}` — posición del botón antes de la captura

```
display{<align>, <size>, <color>}
```

| Parámetro | Valores | Por defecto |
|-----------|--------|---------|
| Alineación (Align) | `left`, `right`, `top`, `center`, `bottom` | `right` |
| Tamaño (Size) | `small`, `medium`, `large` | `small` |
| Color | hex p. ej. `#FF5500` | color primario del tema |
| Indicador (Flag) | `inline-icon` | fuerza el modo de icono |

| Valor de alineación (Align) | Diseño |
|-------------|--------|
| `right` | Botón a la derecha de la etiqueta |
| `left` | Botón a la izquierda de la etiqueta |
| `top` | Botón arriba de la etiqueta, centrado en todo el ancho |
| `center` / `bottom` | Botón debajo de la etiqueta, centrado en todo el ancho |

#### `results{...}` — diseño y visibilidad después de la captura

Hereda la configuración de `display{}`. Se usa para mover el botón u ocultar elementos una vez que se ha capturado un valor.

```
results{<align>, hide(<element>)}
```

| Valor de `hide` | Efecto |
|---|---|
| `hide(capture)` | Oculta el botón de captura una vez que existe un archivo/valor |
| `hide(review)` | Oculta la miniatura de revisión / botón de reproducción |
| `hide(filename)` | Oculta el nombre del archivo que se muestra después de la carga |
| `hide(camera)` | Oculta el botón disparador de la cámara después de la captura |
| `hide(scanner)` | Oculta el botón de escaneo de código de barras después de escanear un valor |
| `hide(value)` | Oculta el texto del valor escaneado (código de barras / geopunto) |

El widget cambia automáticamente del diseño `display{}` al diseño `results{}` en el momento en que se captura un valor.

**Ejemplos:**

```
inline display{right}                                    → icono a la derecha de la etiqueta
inline display{left, large}                              → icono grande a la izquierda
inline display{center, large, #FF5500}                   → icono grande naranja debajo de la etiqueta
inline display{right} results{left}                      → el icono se mueve a la izquierda después de la captura
inline display{right} results{hide(capture)}             → el icono desaparece después de la captura
inline display{center} results{hide(capture), hide(filename)}
```

## Limitaciones Conocidas

- Las apariencias complejas pueden no representarse de manera idéntica en todas las plataformas.
- Es posible que algunas apariencias avanzadas de rtSurvey no sean compatibles en el modo fuera de línea (offline).

## Solución de Problemas de Apariencia

1. **La apariencia no se aplica**: Verifique si hay errores tipográficos en la columna de apariencia.
2. **Representación inconsistente**: Verifique la compatibilidad con el tipo de pregunta y la plataforma.
3. **Problemas de rendimiento**: Considere simplificar las apariencias complejas, especialmente para encuestas grandes.
