เรียกใช้ rtCloud บนโครงสร้างพื้นฐานของคุณเองโดยใช้ Docker Compose การโฮสต์ด้วยตนเองให้ความเป็นเจ้าของข้อมูล เครือข่าย และสภาพแวดล้อมการติดตั้งใช้งานของคุณอย่างสมบูรณ์ เหมาะสำหรับองค์กรที่มีข้อกำหนดด้านการพำนักอาศัยของข้อมูล เครือข่ายที่ปิดจากภายนอก หรือความต้องการโครงสร้างพื้นฐานที่กำหนดเอง

## rtCloud Self-Hosting คืออะไร?

rtCloud Self-Hosting เป็น Docker image อย่างเป็นทางการที่แพ็คเกจแพลตฟอร์ม rtCloud ทั้งหมดเป็นสแตกคอนเทนเนอร์แบบพกพาที่คุณสามารถเรียกใช้บนเซิร์ฟเวอร์ Linux ใดก็ได้ สแตกประกอบด้วย:

| บริการ | คำอธิบาย |
|---------|-------------|
| **rtCloud App** | เว็บแอปพลิเคชัน Apache 2.4 + PHP 7.4 พร้อมคิวพื้นหลังในตัว (Beanstalkd) เซิร์ฟเวอร์วิเคราะห์ (Shiny) และงานตามกำหนดเวลา |
| **MySQL 8.0** | ฐานข้อมูลเชิงสัมพันธ์สำหรับข้อมูลแอปพลิเคชันและแบบสำรวจทั้งหมด |
| **Keycloak** *(ไม่บังคับ)* | เซิร์ฟเวอร์ Single Sign-On แบบฝังสำหรับการจัดการตัวตนองค์กร |

## เมื่อใดควรโฮสต์ด้วยตนเอง

การโฮสต์ด้วยตนเองเป็นทางเลือกที่ถูกต้องเมื่อคุณ:

- ต้องการ **อธิปไตยของข้อมูล** — ข้อมูลทั้งหมดอยู่ภายในโครงสร้างพื้นฐานของคุณเอง
- ดำเนินการในเครือข่าย **ที่ปิดจากภายนอกหรือถูกจำกัด** โดยไม่มีการเข้าถึงคลาวด์ภายนอก
- มี **ข้อกำหนดด้านการปฏิบัติตามกฎระเบียบ** (GDPR, HIPAA, นโยบายข้อมูลของรัฐบาล) ที่บังคับให้จัดเก็บในสถานที่
- ต้องการรวมเข้ากับ **ผู้ให้บริการตัวตนภายใน** (Active Directory, LDAP, SAML)
- ต้องการ **ปรับแต่งทรัพยากร** — การจัดสรร CPU, RAM และพื้นที่จัดเก็บตามเงื่อนไขของคุณ

## ภาพรวมสถาปัตยกรรม

การติดตั้งใช้งานทำงานเป็นชุดคอนเทนเนอร์ Docker ที่เชื่อมต่อบนเครือข่ายภายใน:

```
┌────────────────────────────────────────┐
│            rtcloud-app                 │
│  Apache 2.4 (port 80)                  │
│  PHP 7.4 application                   │
│  Beanstalkd queue (internal)           │
│  Shiny Server (port 3838)              │
│  Cron scheduler                        │
└─────────────────┬──────────────────────┘
                  │ rtcloud-net (bridge)
┌─────────────────▼──────────────────────┐
│            rtcloud-mysql               │
│  MySQL 8.0 (port 3306, internal only)  │
└────────────────────────────────────────┘
```

เมื่อเปิดใช้งาน SSO คอนเทนเนอร์ที่สามจะทำงานควบคู่กัน:

```
┌─────────────────────────────────────────┐
│            rtcloud-keycloak             │
│  Keycloak (port 8080, internal only)    │
│  Admin UI (port 9000, internal only)    │
└─────────────────────────────────────────┘
```

คอนเทนเนอร์ทั้งหมดสื่อสารผ่านเครือข่ายบริดจ์ Docker ที่แยกต่างหาก มีเพียงพอร์ตแอปพลิเคชันเว็บและ (ไม่บังคับ) พอร์ตการวิเคราะห์ Shiny เท่านั้นที่เปิดเผยต่อโฮสต์
