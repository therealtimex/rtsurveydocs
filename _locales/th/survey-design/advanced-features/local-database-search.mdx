import { Callout } from 'nextra/components'

**การค้นหาฐานข้อมูลในตัวเครื่อง (Local Database Search)** ช่วยให้ฟิลด์ `select_one` หรือ `text` สามารถค้นหาไฟล์ SQLite `.db` ที่รวมอยู่ในแพ็กเกจสื่อของแบบฟอร์มได้ — แบบออฟไลน์ทั้งหมด โดยไม่ต้องเชื่อมต่อกับเซิร์ฟเวอร์ นี่เป็นวิธีที่เหมาะสมเมื่อรายการตัวเลือกของคุณมีขนาดใหญ่และคงที่ (เช่น รายชื่อหมู่บ้านทั่วประเทศ สถานพยาบาล หรือเขตการปกครอง) และไม่สามารถรับประกันการเชื่อมต่ออินเทอร์เน็ตได้

| วิธีการ | แหล่งข้อมูล | ต้องใช้การเชื่อมต่อ |
|---|---|---|
| การค้นหาฐานข้อมูลในตัวเครื่อง (`rawquery`) | ไฟล์ `.db` ที่รวมมาให้ (SQLite) | ไม่ |
| `search-api()` | REST API ภายนอก | ใช่ |
| `search()` | ไฟล์ CSV ที่รวมมาให้ | ไม่ |

---

## รูปแบบ Appearance

ฟิลด์เติมข้อความอัตโนมัติจะถูกกำหนดค่าผ่านคอลัมน์ `appearance` โดยมี 3 รูปแบบให้เลือกใช้:

| รูปแบบ | หมายเหตุ |
|---|---|
| `search-autocomplete-noedit(...)` | การเติมข้อความอัตโนมัติมาตรฐาน — ผู้สำรวจต้องเลือกจากรายการเท่านั้น ไม่สามารถบันทึกข้อความที่พิมพ์เองได้ |
| `search-autocomplete-noedit-v2(...)` | รูปแบบที่แนะนำ — มีพฤติกรรมเหมือนกันแต่ใช้เอนจินการแสดงผลที่อัปเดตใหม่ซึ่งมีประสิทธิภาพดีกว่าสำหรับชุดผลลัพธ์ขนาดใหญ่ |
| `search(...)` | การจับคู่ตามไฟล์อย่างง่ายกับไฟล์ CSV ที่รวมมาให้ โดย**ไม่**รองรับ raw SQL — แสดงไว้ที่นี่เพื่อการเปรียบเทียบเท่านั้น |

<Callout type="info">
`search-autocomplete-noedit` เป็นชื่อแทน (alias) — ในขณะที่ประมวลผล แอปจะแทนที่ด้วยชื่อฟังก์ชันภายในคือ `searchAutocompleteNoedit` คุณสามารถใช้ชื่อใดก็ได้ใน XLSForm ของคุณ ทั้งสองแบบทำงานได้เหมือนกัน
</Callout>

## แหล่งข้อมูล `rawquery`

หากต้องการรันคำสั่ง SQL กับไฟล์ `.db` ให้ส่งค่า `'rawquery'` เป็นอาร์กิวเมนต์แรกของฟังก์ชัน appearance โดยมีรูปแบบเต็มดังนี้:

```
search-autocomplete-noedit-v2(
  'rawquery',
  <db_path>,
  '[display_col]',
  'value_col',
  'SELECT ...',
  param1, param2, ...
)
```

### พารามิเตอร์ (Parameters)

| ตำแหน่ง | พารามิเตอร์ | คำอธิบาย |
|---|---|---|
| 1 | `'rawquery'` | ข้อความตายตัว — บอกแอปให้รัน SQL โดยตรง |
| 2 | `db_path` | เส้นทางไปยังไฟล์ SQLite ในรูปแบบ `<dir>/<file>.db::tableName` โดยส่วนต่อท้าย `::tableName` จะถูกตัดออกเมื่อเปิดไฟล์ และจะใช้ชื่อตารางภายในคำสั่ง SQL ของคุณ |
| 3 | `'[display_col]'` | คอลัมน์ที่จะแสดงในรายการดรอปดาวน์ โดยเครื่องหมายวงเล็บ `[ ]` จะถูกตัดออกในขณะทำงาน |
| 4 | `'value_col'` | คอลัมน์ที่ค่าจะถูกบันทึกเมื่อผู้สำรวจเลือกรายการ |
| 5 | `'SELECT ...'` | คำสั่ง SQLite SELECT ใดๆ ที่ถูกต้อง โดย `SELECT DISTINCT` จะถูกแทรกโดยอัตโนมัติหากไม่มี `DISTINCT` อยู่แล้ว |
| 6+ | `param1, ...` | (ไม่บังคับ) ค่าที่ผูกกับตัวแทน `?` ใน SQL ตามลำดับ หาก SQL มี `?` แต่ไม่มีพารามิเตอร์ส่งไป ฟิลด์จะคืนค่าว่าง (เป็นการป้องกันข้อผิดพลาดในกรณีที่อาร์กิวเมนต์ไม่ครบ) |

### รูปแบบ `db_path`

ไฟล์ฐานข้อมูลจะอยู่ในไดเรกทอรีสื่อที่รวมอยู่ในแบบฟอร์ม ในขณะทำงาน `pulldata('app-api', 'family_path')` จะคืนค่าเส้นทางไดเรกทอรีนั้น ดูรายละเอียดการตั้งค่าได้ที่ [family_path](family-path) รูปแบบมาตรฐานคือ:

```
concat(${family_path}, '/mydata.db::tableName')
```

เมื่อแอปเปิดไฟล์ จะทำการตัดส่วน `::tableName` ออกและใช้เส้นทางไฟล์ปกติ ส่วนชื่อตารางจะปรากฏเฉพาะในคำสั่ง SQL ของคุณเท่านั้น

## ตัวอย่างพื้นฐาน — การค้นหาจังหวัด

ดรอปดาวน์จังหวัดแบบอ่านอย่างเดียวที่ดึงข้อมูลจากไฟล์ `vnxa3.db` ที่รวมมาให้:

| type | name | label | appearance | calculation |
|---|---|---|---|---|
| calculate | family_path | | | `pulldata('app-api', 'family_path')` |
| select_one | province | จังหวัด | `search-autocomplete-noedit-v2('rawquery', concat(${family_path}, '/vnxa3.db::externalData'), '[provv]', 'provid', 'SELECT provv, provid FROM externalData WHERE rta_filter = "1"')` | |

คอลัมน์ `appearance` (ขยายเพื่อให้อ่านง่ายขึ้น):

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[provv]', 'provid',
  'SELECT provv, provid FROM externalData WHERE rta_filter = "1"')
```

- ป้ายชื่อ (label) ที่แสดงมาจากคอลัมน์ `provv`
- ค่าที่บันทึกมาจากคอลัมน์ `provid`
- แสดงเฉพาะแถวที่ `rta_filter = "1"`

## การใช้ตัวแปรในคำสั่ง Query (Parameterized queries)

ใช้ตัวแทน `?` ในคำสั่ง SQL ของคุณ และส่งการอ้างอิงฟิลด์ที่เกี่ยวข้องเป็นอาร์กิวเมนต์เพิ่มเติม (ตั้งแต่ตำแหน่งที่ 6 เป็นต้นไป) นี่เป็นรูปแบบมาตรฐานสำหรับตัวเลือกแบบลำดับชั้น (cascading selects) เช่น การโหลดอำเภอที่อยู่ในจังหวัดที่เลือกไว้ก่อนหน้า

<Callout type="warning">
หากคำสั่ง SQL ของคุณมีเครื่องหมาย `?` อย่างน้อยหนึ่งตัว และไม่มีอาร์กิวเมนต์พารามิเตอร์ส่งไป ฟิลด์จะคืนค่าว่าง ซึ่งจะช่วยป้องกันไม่ให้ข้อมูลเก่าหรือข้อมูลที่ไม่เกี่ยวข้องแสดงขึ้นมาก่อนที่จะมีการเลือกข้อมูลหลัก
</Callout>

### ตัวอย่างลำดับชั้นของอำเภอ (District cascade)

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[distv]', 'distid',
  'SELECT distv, distid FROM externalData
   WHERE provid = ? AND rta_filter = "1"',
  ${province})
```

ค่าของ `${province}` จะถูกผูกกับ `?` ตัวแรก ฟิลด์จะว่างเปล่าจนกว่าผู้สำรวจจะเลือกจังหวัด

### ตัวอย่างสองพารามิเตอร์ — ลำดับชั้นของตำบล (Commune cascade)

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[commv]', 'commid',
  'SELECT commv, commid FROM externalData
   WHERE provid = ? AND distid = ? AND rta_filter = "1"',
  ${province}, ${district})
```

พารามิเตอร์จะถูกผูกตามตำแหน่ง: `${province}` → `?` ตัวแรก, `${district}` → `?` ตัวที่สอง

## UNION SELECT สำหรับค่าพิเศษ

แทรกแถวจำลอง เช่น "ไม่ทราบ" หรือ "ปฏิเสธการตอบ" ลงใน SQL โดยตรงโดยใช้ `UNION SELECT`:

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[provv]', 'provid',
  'SELECT provv, provid FROM externalData WHERE rta_filter = "1"
   UNION SELECT "<i>ไม่ทราบ</i>", "888"')
```

ค่าคงที่ที่ใช้ในแบบฟอร์ม RTSurvey:

| รหัส | ความหมาย |
|---|---|
| `888` | ไม่ทราบ |
| `999` | ปฏิเสธการตอบ |

แท็ก HTML เช่น `<i>` ในข้อความที่แสดงจะถูกประมวลผลโดยแอป — คุณสามารถใช้เพื่อแยกตัวเลือกพิเศษให้เห็นชัดเจนทางสายตา

## การแสดงผลหลายภาษา

เก็บป้ายชื่อเฉพาะภาษาไว้ในคอลัมน์แยกกัน (เช่น `label_vi`, `label_en`) และเลือกคอลัมน์ที่เหมาะสมตามฟิลด์ภาษาในแบบฟอร์มของคุณ:

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[label_vi]', 'provid',
  'SELECT label_vi, label_en, provid FROM externalData
   WHERE rta_filter = "1"')
```

หากต้องการเปลี่ยนคอลัมน์โดยอัตโนมัติตามฟิลด์ `${language}` ให้ใช้คำสั่ง `if()` ในพารามิเตอร์คอลัมน์ที่แสดงเพื่อสลับระหว่างคอลัมน์ภาษา:

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  if(${language} = 'vi', '[label_vi]', '[label_en]'),
  'provid',
  'SELECT label_vi, label_en, provid FROM externalData
   WHERE rta_filter = "1"')
```

<Callout type="info">
พารามิเตอร์คอลัมน์ที่แสดงจะถูกประมวลผลก่อนที่จะรันคำสั่ง Query โดยจะส่งเฉพาะชื่อคอลัมน์ (ไม่มีเครื่องหมายวงเล็บ) ไปยังเอนจิน SQL ส่วนเครื่องหมายวงเล็บเป็นเพียงเครื่องหมายระบุที่จะถูกตัดออกในขณะประมวลผล
</Callout>

## การตรวจสอบความถูกต้องของการเลือกข้อมูลจริง

เมื่อฟิลด์อนุญาตให้เลือกค่าพิเศษ เช่น 888 หรือ 999 การตรวจสอบเพียง `required = yes` จะไม่เพียงพอ — เนื่องจากเงื่อนไขจะเป็นจริงแม้ว่าผู้สำรวจจะเลือก "ไม่ทราบ" ก็ตาม ให้ใช้เงื่อนไข `selected-at(., 0) != -997` เพื่อตรวจสอบว่าค่าที่บันทึกเป็นการเลือกข้อมูลจริง ไม่ใช่ค่าคงที่ภายใน "ไม่ได้เลือกอะไรเลย" คือ `-997`:

| คอลัมน์ | ค่า |
|---|---|
| constraint | `selected-at(., 0) != -997` |
| constraint_message | โปรดเลือกตัวเลือกที่ถูกต้อง |

ค่า `-997` เป็นรหัสภายในที่ RTSurvey บันทึกไว้เมื่อไม่มีการเลือกรายการใดๆ จากรายการเติมข้อความอัตโนมัติ การเลือก 888 หรือ 999 ยังถือเป็นการเลือกโดยตั้งใจและจะผ่านการตรวจสอบนี้

หากต้องการกำหนดเพิ่มเติมให้ต้องเป็นค่าจริง (ไม่ใช่ค่าพิเศษ) ให้ขยายเงื่อนไขดังนี้:

```
selected-at(., 0) != -997 and selected-at(., 0) != '888' and selected-at(., 0) != '999'
```

## การเปรียบเทียบ: ฐานข้อมูลในตัวเครื่อง vs วิธีการค้นหาอื่นๆ

| คุณสมบัติ | `rawquery` autocomplete | `search-api()` | `search()` CSV | ตัวเลือก CSV ทั่วไป |
|---|---|---|---|---|
| แหล่งข้อมูล | ไฟล์ `.db` (SQLite) ที่รวมมา | REST API ภายนอก | ไฟล์ CSV ที่รวมมา | แผ่นงาน Choices |
| ทำงานแบบออฟไลน์ | ใช่ | ไม่ | ใช่ | ใช่ |
| รองรับ raw SQL | ใช่ | ไม่ | ไม่ | ไม่ |
| ตัวกรองแบบลำดับชั้น | ใช่ — ใช้ `?` | ผ่านเนื้อหาคำขอ (Request body) | จำกัด | ไม่ |
| ขนาดชุดข้อมูล | ใหญ่มาก (หลายล้านแถว) | ไม่จำกัด (ฝั่งเซิร์ฟเวอร์) | ปานกลาง (หลายหมื่น) | เล็ก |
| แถวพิเศษที่แทรกได้ | ใช่ — `UNION SELECT` | ไม่ | ไม่ | ใช่ (ทำเอง) |
| ความซับซ้อนในการตั้งค่า | ปานกลาง — ต้องมีไฟล์ `.db` | สูง — ต้องมีเซิร์ฟเวอร์ API | ต่ำ | ไม่มี |

## ข้อจำกัด

- ไฟล์ `.db` ต้องรวมอยู่ในแพ็กเกจสื่อของแบบฟอร์มก่อนการติดตั้ง การอัปเดตฐานข้อมูลจำเป็นต้องติดตั้งแบบฟอร์มใหม่
- คำสั่ง SQL จะถูกรันตามที่เขียนไว้บนอุปกรณ์ ไม่มีการกรองคำสั่ง (sanitization) ฝั่งเซิร์ฟเวอร์ — หลีกเลี่ยงการสร้างคำสั่ง SQL จากการพิมพ์ข้อความเองของผู้สำรวจ
- รองรับเฉพาะคำสั่ง `SELECT` เท่านั้น ไม่อนุญาตให้ใช้ `INSERT`, `UPDATE` และ `DELETE`
- คำสั่ง Query ที่ซับซ้อนมาก (มีการใช้ `UNION` หลายตัว, การ Join หลายตาราง) อาจทำงานช้าบนอุปกรณ์ Android รุ่นประหยัด
- รูปแบบ `search-autocomplete-noedit` ไม่อนุญาตให้ผู้สำรวจบันทึกค่าที่ไม่มีอยู่ในชุดผลลัพธ์ หากจำเป็นต้องบันทึกข้อความที่พิมพ์เอง ให้ใช้ฟิลด์ `text` แยกต่างหาก
- `SELECT DISTINCT` จะถูกแทรกโดยอัตโนมัติเฉพาะเมื่อไม่มี `DISTINCT` ในคำสั่ง หากคุณเขียน `SELECT DISTINCT` เอง จะไม่มีการเพิ่มซ้ำซ้อน
