import { Callout } from 'nextra/components'

`family_path` คือฟิลด์ calculate ตามข้อตกลงที่เก็บพาธไปยังไดเรกทอรีสื่อที่รวมมากับฟอร์ม ทุกฟอร์มที่มีการค้นหาฐานข้อมูลในเครื่องด้วย `rawquery`, `pulldata` หรือ `search()` จะต้องรวมฟิลด์นี้ไว้ — หากไม่มีฟิลด์นี้ พาธไฟล์จะไม่สามารถแก้ไขได้ และการค้นหาจะคืนค่าว่างโดยไม่มีการแจ้งเตือน

---

## ฟิลด์ calculate

เพิ่มแถวนี้ไว้ที่ส่วนบนของชีต survey ของคุณ หลังจากฟิลด์ meta ใดๆ และก่อนคำถามแรกที่ใช้ไฟล์ฐานข้อมูล:

| type | name | label | calculation |
|---|---|---|---|
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |

ฟิลด์นี้จะไม่เก็บค่าที่มองเห็นได้และไม่ต้องการ label เป็นข้อกำหนดเบื้องต้นสำหรับการสร้างพาธทั้งหมดที่จะตามมา

---

## ทำไมจึงจำเป็น

RTSurvey จะรวมสื่อของฟอร์ม — ฐานข้อมูล SQLite, รูปภาพ, คลิปเสียง — ไว้ในไดเรกทอรีเฉพาะฟอร์มบนอุปกรณ์ พาธที่แน่นอนจะแตกต่างกันไปตามแพลตฟอร์ม (Android, iOS, เว็บ) และระหว่างอุปกรณ์

ในขณะรันไทม์ แอปจะเติม `family_path` ให้โดยอัตโนมัติ ค่าที่แก้ไขแล้วโดยทั่วไปจะมีลักษณะดังนี้:

```
resources/familyMedia/Phuong_Person_Test
```

เนื่องจากพาธเป็นแบบเฉพาะแพลตฟอร์มและถูกกำหนดในเวลาที่เปิดแอป จึงไม่สามารถกำหนดค่าตายตัวในฟอร์มได้ `pulldata('app-api', 'family_path')` เป็นวิธีเดียวที่เชื่อถือได้ในการดึงข้อมูลนี้

---

## วิธีใช้ในพาธ

เมื่อกำหนด `family_path` แล้ว ให้สร้างพาธไฟล์แบบเต็มด้วย `concat()`:

```
concat(${family_path}, '/file.db::tableName')
```

ส่วนต่อท้าย `::tableName` จะถูกตัดออกเมื่อแอปเปิดไฟล์ ชื่อตารางจะถูกใช้ภายในแบบสอบถาม SQL ของคุณเท่านั้น

---

## family_path ถูกใช้ที่ไหนบ้าง

จำเป็นต้องมี `family_path` ในอาร์กิวเมนต์พาธเมื่อใดก็ตามที่คุณอ้างอิงถึงไฟล์ที่รวมมาด้วย:

- **การค้นหาฐานข้อมูลในเครื่อง** — อาร์กิวเมนต์ `db_path` ของ `search-autocomplete-noedit-v2('rawquery', ...)` ต้องสร้างด้วย `concat(${family_path}, ...)` ดู [การค้นหาฐานข้อมูลในเครื่อง](local-database-search) สำหรับรายละเอียดการใช้งานฉบับเต็ม
- **`pulldata` rawquery** — การเรียกใช้ `pulldata('rawquery', ...)` ใดๆ ที่อ่านจากไฟล์ `.db` จะใช้รูปแบบ `concat()` เดียวกัน
- **`search()` พร้อมไฟล์ในเครื่อง** — การแสดงผลแบบการค้นหาแบบไดนามิกที่โหลดจากไฟล์ CSV หรือ DB ที่รวมมาด้วยนั้นยังขึ้นอยู่กับ `family_path` สำหรับการอ้างอิงไฟล์ด้วย

---

## การจัดวางในฟอร์ม

`family_path` จะต้องปรากฏ **ก่อนฟิลด์แรกที่อ้างอิงถึง** ตำแหน่งที่แนะนำคือทันทีหลังจากกลุ่ม meta:

| type | name | label | calculation |
|---|---|---|---|
| begin_group | meta | | |
| deviceid | deviceid | | |
| start | start | | |
| end | end | | |
| end_group | | | |
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |
| select_one | province | Province | *(การแสดงผล rawquery ที่อ้างอิงถึง `${family_path}`)* |

<Callout type="warning">
หากฟอร์มไม่มี `family_path` หรือวางไว้หลังฟิลด์ `rawquery` / `search()` แรกที่อ้างอิงถึง การค้นหาไฟล์ที่รวมมาด้วยทั้งหมดจะคืนค่าว่างโดยไม่มีการแจ้งเตือน จะไม่มีข้อความแสดงข้อผิดพลาด — การเติมข้อความอัตโนมัติจะไม่แสดงผลลัพธ์ใดๆ
</Callout>

---

## ไฟล์ฐานข้อมูลหลายไฟล์

ฟอร์มเดียวสามารถใช้ไฟล์ `.db` ได้หลายไฟล์ แต่ละพาธจะถูกสร้างขึ้นแยกกันด้วย `concat()`:

```
concat(${family_path}, '/locations.db::externalData')
concat(${family_path}, '/health_facilities.db::facilities')
concat(${family_path}, '/household_list.db::households')
```

กำหนด `family_path` เพียงครั้งเดียว และอ้างอิงในฟิลด์ต่างๆ ตามต้องการ

## การตรวจสอบระหว่างการพัฒนา

เพิ่มฟิลด์ `note` ชั่วคราวใต้ `family_path` เพื่อตรวจสอบค่าที่แก้ไขแล้วบนอุปกรณ์:

| type | name | label | calculation |
|---|---|---|---|
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |
| note | family_path_check | `Path: ${family_path}` | |

บันทึกจะแสดงพาธที่แก้ไขแล้วจริงในระหว่างการทดสอบ ให้ลบออกก่อนที่จะปรับใช้ฟอร์มขั้นสุดท้าย
