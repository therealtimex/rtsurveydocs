การบันทึกเสียงช่วยให้แบบฟอร์มสามารถบันทึกเสียงได้ทั้งแบบเงียบหรือแบบที่มองเห็นได้ในระหว่างช่วงหนึ่งของการสำรวจ ซึ่งมีประโยชน์สำหรับการบันทึกการสัมภาษณ์ เสียงบรรยากาศระหว่างการสังเกตการณ์ภาคสนาม หรือการตอบด้วยเสียงที่ช่วยเสริมคำตอบแบบโครงสร้าง

---

<Callout type="warning">
**แอปมือถือเท่านั้น** การบันทึกเสียงต้องใช้แอปมือถือ rtSurvey ในแบบฟอร์มเว็บ appearance `audio-start` และ `audio-end` จะถูกละเว้นไปเฉยๆ โดยไม่มีการบันทึกเสียงและไม่มีการแสดงข้อผิดพลาด ให้ทดสอบบนอุปกรณ์จริงเสมอเมื่อจำเป็นต้องใช้การบันทึกเสียง
</Callout>

## วิธีการทำงาน

การบันทึกเสียงถูกควบคุมโดยฟิลด์ `text` สองฟิลด์ที่ทำหน้าที่เป็น **ตัวกำกับ (markers)**:

- ฟิลด์ที่มี appearance `audio-start` จะเริ่มบันทึกเสียงเมื่อผู้เก็บข้อมูลมาถึงฟิลด์นี้
- ฟิลด์ที่มี appearance `audio-end` จะหยุดบันทึกเสียงและบันทึกไฟล์เสียงลงในข้อมูลที่ส่ง (submission)

ฟิลด์กำกับทั้งสองเป็นประเภท `text` โดยปกติจะถูกซ่อนจากผู้เก็บข้อมูล (โดยใช้ `relevant = false` หรือวางในตำแหน่งที่ไม่มีการโต้ตอบ) แม้ว่าจะสามารถตั้งค่าให้มองเห็นได้ก็ตาม เสียงที่บันทึกไว้จะถูกแนบไปกับ submission เป็นไฟล์ที่เชื่อมโยงกับฟิลด์ `audio-end`

---

## ตัวอย่างพื้นฐาน

| type | name | label | appearance |
|------|------|-------|------------|
| text | audio_s_a1 | | `audio-start` |
| text | q_name | ชื่อผู้ตอบแบบสอบถาม | |
| text | q_occupation | อาชีพ | |
| integer | q_age | อายุ | |
| text | audio_e_a1 | | `audio-end` |

แอปจะเริ่มบันทึกเมื่อผู้เก็บข้อมูลมาถึง `audio_s_a1` และหยุดเมื่อมาถึง `audio_e_a1` คำถามทั้งหมดที่อยู่ระหว่างตัวกำกับทั้งสองจะถูกบันทึกเสียงไว้

---

## การบันทึกแบบเงียบ: `audio-start invisible`

โดยปกติ แอปมือถือจะแสดงตัวบ่งชี้การบันทึกในขณะที่มีการจับเสียง การเพิ่ม `invisible` ลงใน appearance จะช่วยปิดตัวบ่งชี้นี้ เพื่อให้การบันทึกเกิดขึ้นโดยไม่มีสัญญาณที่มองเห็นได้สำหรับผู้ตอบแบบสอบถาม

| type | name | label | appearance |
|------|------|-------|------------|
| text | audio_s_a1 | | `audio-start invisible` |
| text | q_consent | คุณยินยอมที่จะเข้าร่วมหรือไม่? | |
| text | q_feedback | ความคิดเห็นของคุณ | |
| text | audio_e_a1 | | `audio-end` |

ใช้ `invisible` เฉพาะเมื่อได้ปฏิบัติตามข้อกำหนดการเปิดเผยข้อมูลผ่านวิธีอื่นแล้วเท่านั้น (เช่น ฟิลด์คำยินยอมเป็นลายลักษณ์อักษรที่แยกต่างหากก่อนถึงส่วนที่มีการบันทึก)

## หลักการตั้งชื่อ

แบบฟอร์มที่ใช้งานจริงจะใช้รูปแบบการตั้งชื่อที่สอดคล้องกันสำหรับฟิลด์กำกับ:

```
audio_s_{section}{n}   — ตัวกำกับเริ่มต้น
audio_e_{section}{n}   — ตัวกำกับสิ้นสุด
```

โดยที่ `{section}` คือป้ายกำกับสั้นๆ สำหรับส่วนของแบบฟอร์ม และ `{n}` คือลำดับหมายเลขภายในส่วนนั้น

| Field name | Role | Meaning |
|------------|------|---------|
| `audio_s_a1` | Start | การบันทึกครั้งแรกในส่วน A |
| `audio_e_a1` | End | สิ้นสุดการบันทึกครั้งแรกในส่วน A |
| `audio_s_b1` | Start | การบันทึกครั้งแรกในส่วน B |
| `audio_e_b1` | End | สิ้นสุดการบันทึกครั้งแรกในส่วน B |
| `audio_s_a2` | Start | การบันทึกครั้งที่สองในส่วน A |
| `audio_e_a2` | End | สิ้นสุดการบันทึกครั้งที่สองในส่วน A |

การปฏิบัติตามหลักการนี้ช่วยให้ระบุขอบเขตการบันทึกได้ง่ายเมื่อตรวจสอบคำนิยามของแบบฟอร์มและข้อมูล submission

---

## การจัดเก็บและการเรียกใช้

เมื่อผู้เก็บข้อมูลมาถึงฟิลด์ `audio-end` แอปจะสรุปไฟล์เสียงและแนบไปกับ submission ไฟล์นั้นจะ:

- ถูกจัดเก็บเป็นไฟล์แนบเสียงใน submission โดยเชื่อมโยงกับชื่อฟิลด์ `audio-end`
- เข้าถึงได้ในส่วนแสดงผล submission ของ rtSurvey back-end พร้อมกับไฟล์แนบสื่ออื่นๆ
- สามารถดาวน์โหลดได้ผ่านการส่งออก submission มาตรฐาน โดยไฟล์เสียงจะปรากฏในคอลัมน์สื่อที่ตรงกับชื่อฟิลด์ `audio-end`

รูปแบบไฟล์และบิตเรตขึ้นอยู่กับอุปกรณ์และเวอร์ชันของแอป

---

## ส่วนการบันทึกหลายส่วน

แบบฟอร์มหนึ่งสามารถมีส่วนการบันทึกหลายส่วนที่ไม่ซ้อนทับกัน ตัวกำกับ `audio-start` / `audio-end` แต่ละคู่จะต้องอยู่ภายในขอบเขตของตัวเองอย่างสมบูรณ์ โดยแต่ละส่วนต้องไม่เหลื่อมกัน

| type | name | label | appearance |
|------|------|-------|------------|
| text | audio_s_a1 | | `audio-start` |
| text | q_intro | บทนำ | |
| text | audio_e_a1 | | `audio-end` |
| note | section_break | — | |
| text | audio_s_b1 | | `audio-start invisible` |
| text | q_detail | รายละเอียด | |
| text | audio_e_b1 | | `audio-end` |

แต่ละส่วนจะสร้างไฟล์เสียงแยกกันแนบไปกับฟิลด์ `audio-end` ที่เกี่ยวข้อง

## ข้อจำกัด

- **แอปมือถือเท่านั้น** ฟีเจอร์นี้ไม่รองรับในแบบฟอร์มเว็บ `audio-start` และ `audio-end` จะถูกละเว้นไปเฉยๆ เมื่อเปิดในเบราว์เซอร์
- **ห้ามซ้อนทับ (No nesting)** ส่วนการบันทึกไม่สามารถซ้อนทับกันได้ ไม่รองรับการเริ่มบันทึกใหม่ก่อนที่จะถึงตัวกำกับ `audio-end` ก่อนหน้า
- **ประเภทฟิลด์ต้องเป็น `text`** ไม่รองรับการใช้ `audio-start` หรือ `audio-end` กับคำถามประเภทอื่น
- **ขนาดการอัปโหลด** การบันทึกที่ยาวจะทำให้ไฟล์มีขนาดใหญ่ โปรดคำนึงถึงขีดจำกัดขนาดของ submission และสภาพเครือข่ายในพื้นที่ปฏิบัติงาน
- **ไม่มีการหยุดชั่วคราวระหว่างบันทึก** การบันทึกจะดำเนินไปอย่างต่อเนื่องจากตัวกำกับเริ่มต้นไปยังตัวกำกับสิ้นสุด ไม่มีกลไกในการหยุดชั่วคราวและเริ่มใหม่ภายในส่วนเดียวกัน
