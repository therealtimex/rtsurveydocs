**స్థానిక డేటాబేస్ సెర్చ్ (Local Database Search)** అనేది ఫారమ్ యొక్క మీడియా ప్యాకేజీతో కూడిన SQLite `.db` ఫైల్‌ను క్వెరీ చేయడానికి `select_one` లేదా `text` ఫీల్డ్‌ను అనుమతిస్తుంది — ఇది పూర్తిగా ఆఫ్‌లైన్‌లో, సర్వర్ కమ్యూనికేషన్ అవసరం లేకుండా జరుగుతుంది. మీ ఎంపికల జాబితా పెద్దదిగా మరియు స్టాటిక్ (ఉదాహరణకు, గ్రామల జాతీయ జాబితా, ఆరోగ్య కేంద్రాలు లేదా పరిపాలనా సరిహద్దులు) ఉండి, ఇంటర్నెట్ కనెక్టివిటీకి గ్యారెంటీ లేనప్పుడు ఇది సరైన పద్ధతి.

| పద్ధతి | డేటా మూలం | కనెక్టివిటీ అవసరమా |
|---|---|---|
| స్థానిక డేటాబేస్ సెర్చ్ (`rawquery`) | బండిల్డ్ `.db` ఫైల్ (SQLite) | లేదు |
| `search-api()` | రిమోట్ REST API | అవును |
| `search()` | బండిల్డ్ CSV ఫైల్ | లేదు |

## అప్పియరెన్స్ వేరియంట్లు (Appearance variants)

ఆటోకంప్లీట్ ఫీల్డ్ `appearance` కాలమ్ ద్వారా కాన్ఫిగర్ చేయబడుతుంది. మూడు వేరియంట్లు అందుబాటులో ఉన్నాయి:

| వేరియంట్ | గమనికలు |
|---|---|
| `search-autocomplete-noedit(...)` | ప్రామాణిక ఆటోకంప్లీట్ — ఎన్యూమరేటర్ జాబితా నుండి ఎంచుకోవాలి; ఫ్రీ-టెక్స్ట్ ఎంట్రీ సేవ్ చేయబడదు |
| `search-autocomplete-noedit-v2(...)` | సిఫార్సు చేయబడిన వేరియంట్ — అదే ప్రవర్తనను కలిగి ఉంటుంది కానీ పెద్ద ఫలితాల సెట్‌లపై మెరుగైన పనితీరు కోసం అప్‌డేట్ చేయబడిన రెండరింగ్ ఇంజిన్‌ను ఉపయోగిస్తుంది |
| `search(...)` | బండిల్డ్ CSVతో సాధారణ ఫైల్-ఆధారిత మ్యాచ్; రా SQLకి **మద్దతు ఇవ్వదు** — కేవలం పోలిక కోసం ఇక్కడ జాబితా చేయబడింది |

<Callout type="info">
`search-autocomplete-noedit` అనేది ఒక అలియాస్ — పార్సింగ్ సమయంలో యాప్ దీనిని అంతర్గత ఫంక్షన్ పేరు `searchAutocompleteNoedit`తో భర్తీ చేస్తుంది. మీ XLSFormలో ఏ స్పెల్లింగ్‌నైనా ఉపయోగించవచ్చు; రెండూ పనిచేస్తాయి.
</Callout>

## `rawquery` డేటా మూలం

`.db` ఫైల్‌పై SQL క్వెరీని అమలు చేయడానికి, అప్పియరెన్స్ ఫంక్షన్ యొక్క మొదటి ఆర్గ్యుమెంట్‌గా `'rawquery'`ని పంపండి. పూర్తి సిగ్నేచర్ ఇలా ఉంటుంది:

```
search-autocomplete-noedit-v2(
  'rawquery',
  <db_path>,
  '[display_col]',
  'value_col',
  'SELECT ...',
  param1, param2, ...
)
```

### పారామితులు (Parameters)

| స్థానం | పారామితి | వివరణ |
|---|---|---|
| 1 | `'rawquery'` | లిటరల్ స్ట్రింగ్ — SQLని నేరుగా అమలు చేయమని యాప్‌కి చెబుతుంది |
| 2 | `db_path` | SQLite ఫైల్‌కి పాత్, `<dir>/<file>.db::tableName` రూపంలో ఉంటుంది. ఫైల్‌ను ఓపెన్ చేసినప్పుడు `::tableName` సఫిక్స్ తొలగించబడుతుంది; టేబుల్ పేరు మీ SQL లోపల ఉపయోగించబడుతుంది |
| 3 | `'[display_col]'` | డ్రాప్‌డౌన్‌లో ప్రదర్శించాల్సిన కాలమ్. చుట్టూ ఉన్న `[ ]` బ్రాకెట్లు రన్‌టైమ్‌లో తొలగించబడతాయి |
| 4 | `'value_col'` | ఎన్యూమరేటర్ ఎంపిక చేసినప్పుడు సేవ్ చేయబడే విలువ గల కాలమ్ |
| 5 | `'SELECT ...'` | ఏదైనా చెల్లుబాటు అయ్యే SQLite SELECT స్టేట్‌మెంట్. `DISTINCT` ఇప్పటికే లేకపోతే `SELECT DISTINCT` ఆటోమేటిక్‌గా ఇంజెక్ట్ చేయబడుతుంది |
| 6+ | `param1, ...` | ఐచ్ఛికం. SQLలోని `?` ప్లేస్‌హోల్డర్‌లకు క్రమ పద్ధతిలో బైండ్ చేయబడిన విలువలు. ఒకవేళ SQLలో `?` ఉండి, పారామితులు ఇవ్వకపోతే, ఫీల్డ్ ఖాళీగా ఉంటుంది (తప్పిపోయిన ఆర్గ్యుమెంట్‌లకు వ్యతిరేకంగా ఇది ఒక అంతర్నిర్మిత రక్షణ) |

### `db_path` విధానం

డేటాబేస్ ఫైల్ ఫారమ్ యొక్క బండిల్డ్ మీడియా డైరెక్టరీ లోపల ఉంటుంది. రన్‌టైమ్‌లో, `pulldata('app-api', 'family_path')` ఆ డైరెక్టరీ పాత్‌ను తిరిగి ఇస్తుంది. సెటప్ వివరాల కోసం [family_path](family-path) చూడండి. ప్రామాణిక నమూనా ఇలా ఉంటుంది:

```
concat(${family_path}, '/mydata.db::tableName')
```

యాప్ ఫైల్‌ను ఓపెన్ చేసినప్పుడు అది `::tableName` భాగాన్ని తొలగించి, కేవలం ఫైల్ పాత్‌ను ఉపయోగిస్తుంది. టేబుల్ పేరు మీ SQL లోపల మాత్రమే కనిపిస్తుంది.

## ప్రాథమిక ఉదాహరణ — ప్రావిన్స్ లుకప్

బండిల్డ్ `vnxa3.db` ఫైల్ ద్వారా సపోర్ట్ చేయబడిన రీడ్-ఓన్లీ ప్రావిన్స్ డ్రాప్‌డౌన్:

| type | name | label | appearance | calculation |
|---|---|---|---|---|
| calculate | family_path | | | `pulldata('app-api', 'family_path')` |
| select_one | province | ప్రావిన్స్ | `search-autocomplete-noedit-v2('rawquery', concat(${family_path}, '/vnxa3.db::externalData'), '[provv]', 'provid', 'SELECT provv, provid FROM externalData WHERE rta_filter = "1"')` | |

`appearance` కాలమ్ (చదవడానికి వీలుగా విస్తరించబడింది):

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[provv]', 'provid',
  'SELECT provv, provid FROM externalData WHERE rta_filter = "1"')
```

- ప్రదర్శించబడే లేబుల్ `provv` కాలమ్ నుండి వస్తుంది.
- సేవ్ చేయబడిన విలువ `provid` కాలమ్ నుండి వస్తుంది.
- `rta_filter = "1"` ఉన్న రోస్ (rows) మాత్రమే చూపబడతాయి.

## పారామీటరైజ్డ్ క్వెరీలు (Parameterized queries)

మీ SQLలో `?` ప్లేస్‌హోల్డర్‌లను ఉపయోగించండి మరియు సంబంధిత ఫీల్డ్ రిఫరెన్స్‌లను అదనపు ఆర్గ్యుమెంట్‌లుగా (6వ స్థానం నుండి) పంపండి. కాస్కేడింగ్ సెలెక్ట్‌ల కోసం ఇది ప్రామాణిక నమూనా — ఉదాహరణకు, ముందుగా ఎంచుకున్న ప్రావిన్స్‌కు చెందిన జిల్లాలను లోడ్ చేయడం.

<Callout type="warning">
మీ SQLలో కనీసం ఒక `?` ఉండి, పారామీటర్ ఆర్గ్యుమెంట్‌లు ఇవ్వకపోతే, ఫీల్డ్ ఖాళీ ఫలితాల సెట్‌ను ఇస్తుంది. పేరెంట్ సెలెక్షన్ జరగకముందే పాత లేదా సంబంధం లేని డేటా కనిపించకుండా ఇది నిరోధిస్తుంది.
</Callout>

### జిల్లా కాస్కేడ్ ఉదాహరణ

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[distv]', 'distid',
  'SELECT distv, distid FROM externalData
   WHERE provid = ? AND rta_filter = "1"',
  ${province})
```

`${province}` యొక్క విలువ మొదటి `?` కి బైండ్ చేయబడుతుంది. ఎన్యూమరేటర్ ఒక ప్రావిన్స్‌ని ఎంచుకునే వరకు ఫీల్డ్ ఖాళీగా ఉంటుంది.

### రెండు పారామితుల ఉదాహరణ — కమ్యూన్ కాస్కేడ్

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[commv]', 'commid',
  'SELECT commv, commid FROM externalData
   WHERE provid = ? AND distid = ? AND rta_filter = "1"',
  ${province}, ${district})
```

పారామితులు స్థానబద్ధంగా బైండ్ చేయబడతాయి: `${province}` → మొదటి `?`, `${district}` → రెండవ `?`.

## ప్రత్యేక విలువల కోసం UNION SELECT

`UNION SELECT` ఉపయోగించి SQLలో నేరుగా "తెలియదు" లేదా "సమాధానం చెప్పడానికి నిరాకరించారు" వంటి సింథటిక్ రోస్‌ను ఇంజెక్ట్ చేయండి:

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[provv]', 'provid',
  'SELECT provv, provid FROM externalData WHERE rta_filter = "1"
   UNION SELECT "<i>తెలియదు</i>", "888"')
```

RTSurvey ఫారమ్‌లలో ఉపయోగించే పద్ధతులు:

| కోడ్ | అర్థం |
|---|---|
| `888` | తెలియదు |
| `999` | సమాధానం చెప్పడానికి నిరాకరించారు |

డిస్ప్లే స్ట్రింగ్‌లోని `<i>` వంటి HTML ట్యాగ్‌లు యాప్ ద్వారా రెండర్ చేయబడతాయి — ప్రత్యేక ఎంపికలను దృశ్యపరంగా గుర్తించడానికి మీరు వాటిని ఉపయోగించవచ్చు.

## బహుభాషా ప్రదర్శన

భాషా-నిర్దిష్ట లేబుల్‌లను వేర్వేరు కాలమ్‌లలో (ఉదాహరణకు, `label_vi`, `label_en`) స్టోర్ చేయండి మరియు మీ ఫారమ్‌లోని లాంగ్వేజ్ ఫీల్డ్ ఆధారంగా తగిన దానిని ఎంచుకోండి:

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[label_vi]', 'provid',
  'SELECT label_vi, label_en, provid FROM externalData
   WHERE rta_filter = "1"')
```

`${language}` ఫీల్డ్ ఆధారంగా డైనమిక్‌గా కాలమ్‌లను మార్చడానికి, లాంగ్వేజ్ కాలమ్‌ల మధ్య మారడానికి డిస్ప్లే కాలమ్ పారామీటర్‌పై `if()` ఎక్స్‌ప్రెషన్‌ని ఉపయోగించండి:

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  if(${language} = 'vi', '[label_vi]', '[label_en]'),
  'provid',
  'SELECT label_vi, label_en, provid FROM externalData
   WHERE rta_filter = "1"')
```

<Callout type="info">
డిస్ప్లే కాలమ్ పారామీటర్ క్వెరీ అమలు కావడానికి ముందే మూల్యాంకనం చేయబడుతుంది. కేవలం కాలమ్ పేరు (బ్రాకెట్లు లేకుండా) మాత్రమే SQL ఇంజిన్‌కు పంపబడుతుంది; బ్రాకెట్లు అనేవి కేవలం పార్సింగ్ సమయంలో తొలగించబడే కాస్మెటిక్ మార్కర్లు.
</Callout>

## నిజమైన ఎంపికను ధృవీకరించడం

ఫీల్డ్ 888 లేదా 999 వంటి ప్రత్యేక విలువలని అనుమతించినప్పుడు, సాధారణ `required = yes` చెక్ సరిపోదు — ఎన్యూమరేటర్ "తెలియదు" అని ఎంచుకున్నా అది సంతృప్తి చెందుతుంది. సేవ్ చేయబడిన విలువ నిజమైన ఎంపిక అని మరియు అంతర్గత "ఏమీ ఎంచుకోలేదు" అనే సెంటనెల్ `-997` కాదని ధృవీకరించడానికి `selected-at(., 0) != -997` కన్‌స్ట్రైంట్‌ని ఉపయోగించండి:

| కాలమ్ | విలువ |
|---|---|
| constraint | `selected-at(., 0) != -997` |
| constraint_message | దయచేసి సరైన ఎంపికను ఎంచుకోండి |

ఆటోకంప్లీట్ జాబితా నుండి ఏ ఐటెమ్ ఎంచుకోనప్పుడు RTSurvey `-997` అనే అంతర్గత కోడ్‌ని సేవ్ చేస్తుంది. 888 లేదా 999ని ఎంచుకోవడం అనేది ఉద్దేశపూర్వక ఎంపిక కాబట్టి ఈ చెక్ పాస్ అవుతుంది.

అదనంగా నిజమైన (ప్రత్యేకమైనది కాని) విలువను కోరడానికి, కన్‌స్ట్రైంట్‌ని ఇలా విస్తరించండి:

```
selected-at(., 0) != -997 and selected-at(., 0) != '888' and selected-at(., 0) != '999'
```

## పరిమితులు

- డిప్లాయ్‌మెంట్‌కు ముందే `.db` ఫైల్ ఫారమ్ యొక్క మీడియా ప్యాకేజీలో బండిల్ చేయబడాలి. డేటాబేస్‌కు డైనమిక్ అప్‌డేట్‌లు కావాలంటే కొత్త ఫారమ్ డిప్లాయ్‌మెంట్ అవసరం.
- SQL పరికరంలో ఉన్నది ఉన్నట్లుగా అమలు చేయబడుతుంది. సర్వర్ సైడ్ శానిటైజేషన్ (sanitisation) ఉండదు — ఎన్యూమరేటర్ ఇచ్చే ఫ్రీ-టెక్స్ట్ ఇన్‌పుట్ నుండి SQLని నిర్మించడం నివారించండి.
- కేవలం `SELECT` స్టేట్‌మెంట్‌లు మాత్రమే సపోర్ట్ చేయబడతాయి. `INSERT`, `UPDATE`, మరియు `DELETE` అనుమతించబడవు.
- చాలా క్లిష్టమైన క్వెరీలు (పెద్ద `UNION` చైన్‌లు, మల్టిపుల్ జాయిన్‌లు) తక్కువ-స్థాయి ఆండ్రాయిడ్ పరికరాలలో నెమ్మదిగా ఉండవచ్చు.
- `search-autocomplete-noedit` వేరియంట్లు ఫలితాల సెట్‌లో లేని విలువను సేవ్ చేయడానికి ఎన్యూమరేటర్‌ను అనుమతించవు. ఒకవేళ ఫ్రీ-టెక్స్ట్ ఎంట్రీ కావాలంటే, విడిగా `text` ఫీల్డ్‌ని ఉపయోగించండి.
- క్వెరీలో `DISTINCT` లేనప్పుడు మాత్రమే `SELECT DISTINCT` ఆటోమేటిక్‌గా ఇంజెక్ట్ చేయబడుతుంది. మీరు స్వయంగా `SELECT DISTINCT` అని రాస్తే, అది రెండుసార్లు రాదు.
