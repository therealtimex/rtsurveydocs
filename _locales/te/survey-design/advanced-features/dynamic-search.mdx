**డైనమిక్ సెర్చ్** (దీనిని సెర్చ్ API అని కూడా పిలుస్తారు) అనేది ఎన్యుమరేటర్ టైప్ చేస్తున్నప్పుడు **రన్‌టైమ్** లో రిమోట్ వెబ్ సర్వీస్ నుండి ఎంపికలను లోడ్ చేయడానికి `select_one`, `select_multiple` లేదా `text` ఫీల్డ్‌ను అనుమతిస్తుంది. మీ ఎంపికల జాబితా CSV ఫైల్‌లో ఉంచడానికి చాలా పెద్దదిగా ఉన్నప్పుడు, తరచుగా అప్‌డేట్ అవుతున్నప్పుడు లేదా లైవ్ డేటాబేస్ నుండి వస్తున్నప్పుడు ఇది సరైన విధానం.

---

## `search-api()` అప్పియరెన్స్

డైనమిక్ సెర్చ్ అనేది `appearance` కాలమ్ ద్వారా `search-api()` ఫంక్షన్‌ని ఉపయోగించి కాన్ఫిగర్ చేయబడుతుంది:

```
search-api(method, url, post_body, value_column, display, data_path, save_path)
```

### పారామితులు

| పారామితి | వివరణ |
|-----------|-------------|
| `method` | ఎల్లప్పుడూ `'POST'`ని ఉపయోగించండి |
| `url` | ప్రశ్న పంపాల్సిన API ఎండ్‌పాయింట్ |
| `post_body` | APIకి పంపబడే JSON బాడీ. ఎన్యుమరేటర్ టైప్ చేసే ప్రస్తుత సెర్చ్ టెక్స్ట్ కోసం `%__input__%`ని ప్లేస్‌హోల్డర్‌గా ఉపయోగించండి |
| `value_column` | స్టోర్ చేయబడిన **వాల్యూ** (value)గా ఉపయోగించడానికి రెస్పాన్స్ ఆబ్జెక్ట్‌లోని కీ |
| `display` | డ్రాప్‌డౌన్‌లో చూపబడే **లేబుల్** (label)గా ఉపయోగించడానికి కీ (లేదా టెంప్లేట్). ఇది `##key##` ప్లేస్‌హోల్డర్‌లను మరియు `@{func}` ఎక్స్‌ప్రెషన్స్‌ను సపోర్ట్ చేస్తుంది |
| `data_path` | రెస్పాన్స్‌లోని రిజల్ట్ ఆబ్జెక్ట్స్ శ్రేణికి JSONPath (ఉదాహరణకు, `$.data`, `$.hits.hits.*._source`) |
| `save_path` | ఇతర ఫీల్డ్‌లు ఉపయోగించుకోవడానికి ముడి రెస్పాన్స్ సేవ్ చేయబడే పేరు |

## ప్రాథమిక ఉదాహరణ

ఎన్యుమరేటర్ హెల్త్ ఫెసిలిటీ పేరులో కొంత భాగాన్ని టైప్ చేసే హెల్త్ ఫెసిలిటీ లుకప్:

| type | name | label | appearance |
|------|------|-------|------------|
| select_one | facility | ఆరోగ్య కేంద్రాన్ని ఎంచుకోండి | `search-api('POST', 'https://api.example.com/facilities/search', '{"query": "%__input__%"}', 'id', 'name', '$.results', 'facility_data')` |

ఎన్యుమరేటర్ "nair" అని టైప్ చేసినప్పుడు APIకి `{"query": "nair"}` వెళ్తుంది మరియు ఇది క్రింది వాటిని రిటర్న్ చేస్తుంది:

```json
{
  "results": [
    {"id": "HF001", "name": "Nairobi Central Clinic"},
    {"id": "HF002", "name": "Nairobi West Hospital"}
  ]
}
```

డ్రాప్‌డౌన్ `Nairobi Central Clinic` మరియు `Nairobi West Hospital` అని చూపిస్తుంది; స్టోర్ చేయబడిన వాల్యూ `HF001` లేదా `HF002`.

## అధునాతన డిస్‌ప్లే ఫార్మాటింగ్

### `##key##` టెంప్లేట్‌లను ఉపయోగించడం

లేబుల్‌లో బహుళ ఫీల్డ్‌లను చూపండి:

```
search-api('POST', 'https://api.example.com/search', '{"q": "%__input__%"}', 'id', '##name## (##district##)', '$.data', 'res')
```

ఇది ఇలా కనిపిస్తుంది: `Nairobi Central Clinic (Nairobi)`.

### `@{func}` ఎక్స్‌ప్రెషన్స్‌ను ఉపయోగించడం

డిస్‌ప్లే లేబుల్‌లో కండిషనల్ లాజిక్‌ను అప్లై చేయండి:

```
search-api('POST', 'https://api.example.com/search', '{"q": "%__input__%"}', 'id',
  '@{if_else(eq("##status##", "active"), "✓ ##name##", "✗ ##name##")}',
  '$.data', 'res')
```

యాక్టివ్ ఫలితాలు `✓ Clinic Name` అని; ఇన్యాక్టివ్ ఫలితాలు `✗ Clinic Name` అని చూపిస్తాయి.

---

## డిఫాల్ట్ వాల్యూని సెట్ చేయడం: `search-default-api()`

ఒక విడిగా ఉన్న API కాల్ నుండి లోడ్ చేయబడిన డిఫాల్ట్ ఎంపికతో ఫీల్డ్‌ను ముందుగానే నింపడానికి (ఉదాహరణకు, ఇప్పటికే ఉన్న రికార్డును ఎడిట్ చేస్తున్నప్పుడు) `search-api()` తర్వాత `search-default-api()`ని ఉపయోగించండి:

```
appearance: search-api(...) search-default-api('POST', 'https://api.example.com/get', '{"id": "##saved_id##"}', 'id', 'name', '$.item')
```

---

## select_multiple కోసం కస్టమ్ సెపరేటర్: `search-default-separator()`

`select_multiple` ఫీల్డ్‌ల కోసం, స్టోర్ చేయబడిన స్ట్రింగ్‌లో బహుళ ఎంచుకున్న విలువలు ఎలా కలపాలో పేర్కొనండి:

```
appearance: search-api(...) search-default-separator(' || ')
```

డిఫాల్ట్ సెపరేటర్ స్పేస్.

|---------------|----------|

## సేవ్ చేసిన రెస్పాన్స్ డేటాను ఉపయోగించడం

ఎన్యుమరేటర్ ఒక ఫలితాన్ని ఎంచుకున్నప్పుడు, rtSurvey రెస్పాన్స్ నుండి పూర్తిగా సరిపోలే ఆబ్జెక్ట్‌ను `save_path` పేరుతో సేవ్ చేస్తుంది. ఇతర ఫీల్డ్‌లు దాని నుండి రెండు విధాలుగా చదవగలవు.

### పద్ధతి 1 — `pulldata()` లుకప్

సేవ్ చేసిన ఆబ్జెక్ట్ నుండి టాప్-లెవల్ ఫీల్డ్‌ను చదవడానికి `pulldata('save_path', 'key')`ని ఉపయోగించండి:

| type | name | label | calculation |
|------|------|-------|-------------|
| select_one | facility | కేంద్రాన్ని ఎంచుకోండి | |
| calculate | facility_district | | `pulldata('facility_data', 'district')` |
| calculate | facility_type | | `pulldata('facility_data', 'type')` |
| calculate | facility_beds | | `pulldata('facility_data', 'beds')` |

`select_one` వరుసలోని అప్పియరెన్స్ తప్పనిసరిగా సరిపోలే `save_path`తో `search-api(..., 'facility_data')`ని కలిగి ఉండాలి.

**నెస్టెడ్ JSON ఫీల్డ్స్** కోసం, `substr-jsonpath()`తో కలపండి:

```
substr-jsonpath(pulldata('facility_data', 'location'), '$.district')
```

## search() తో లోకల్ ఫైల్ సెర్చ్

`search()` అనేది నెట్‌వర్క్ కనెక్షన్ మరియు SQL క్వెరీల అవసరం లేకుండా బండిల్ చేయబడిన SQLite `.db` ఫైల్‌పై ఆఫ్‌లైన్, కాలమ్-ఈక్వాలిటీ లుకప్‌లను నిర్వహిస్తుంది. మీ రిఫరెన్స్ డేటా ఫారమ్‌తో పాటు ప్యాక్ చేయబడినప్పుడు మరియు మీకు సాధారణ "కాలమ్ విలువకు సమానంగా ఉన్న అన్ని వరుసలను కనుగొనండి" అనే లుకప్ అవసరమైనప్పుడు దీనిని ఉపయోగించండి.

### సంతకం (Signature)

```
search(path, 'matches', 'list_name', ${field})
```

### పారామితులు

| పారామితి | వివరణ |
|-----------|-------------|
| `path` | SQLite టేబుల్‌కి పాత్: `concat(${family_path}, '/file.db::table')` |
| `'matches'` | మ్యాచ్ ఆపరేటర్ — కాలమ్ విలువకు సమానంగా ఉన్న వరుసలను రిటర్న్ చేస్తుంది |
| `'list_name'` | సరిపోల్చాల్సిన కాలమ్ పేరు |
| `${field}` | సరిపోల్చాల్సిన విలువ; సాధారణంగా ఒక ఫీల్డ్ రిఫరెన్స్ |

### ఉదాహరణ

`d307.db` యొక్క `externalData` టేబుల్‌లోని `list_name` కాలమ్‌తో `${d307}` విలువను సరిపోల్చడం ద్వారా లోకల్ డేటాబేస్ నుండి `select_one`ని నింపండి:

| type | name | label | appearance |
|------|------|-------|------------|
| select_one | facility | కేంద్రాన్ని ఎంచుకోండి | `search(concat(${family_path}, '/d307.db::externalData'), 'matches', 'list_name', ${d307})` |

`${d307}` విలువ `"HF001"`కి సమానంగా ఉన్నప్పుడు, `search()` అనేది `externalData`లో `list_name = 'HF001'` ఉన్న ప్రతి వరుసను రిటర్న్ చేస్తుంది — ఇది నెట్‌వర్క్ కాల్ లేకుండా పూర్తిగా బండిల్ చేయబడిన ఫైల్ నుండి జరుగుతుంది.

### search() వర్సెస్ rawquery ఆటో కంప్లీట్

| ఫీచర్ | `search()` | `rawquery` ఆటో కంప్లీట్ |
|---------|-----------|------------------------|
| SQL క్వెరీలు | లేదు — కాలమ్ ఈక్వాలిటీ మాత్రమే | అవును — పూర్తి `SELECT … FROM …` |
| పారామీటరైజ్డ్ ఇన్‌పుట్ | కాలమ్ వాల్యూ మ్యాచ్ | SQL స్ట్రింగ్‌లో పొందుపరచబడింది |
| ఫ్రీ-టెక్స్ట్ ఎంట్రీ | అవును — ఎన్యుమరేటర్ స్వేచ్ఛగా టైప్ చేయవచ్చు | లేదు — జాబితా నుండి ఎంచుకోవాలి |
| UNION / మల్టీ-టేబుల్ | సపోర్ట్ చేయదు | సపోర్ట్ చేస్తుంది |

### దేనిని ఎప్పుడు ఉపయోగించాలి

- బండిల్ చేయబడిన `.db` ఫైల్‌తో మీకు సరళమైన ఈక్వాలిటీ మ్యాచ్ అవసరమైనప్పుడు, ఫారమ్ ఆఫ్‌లైన్‌లో పని చేయాల్సి ఉన్నప్పుడు మరియు మీరు ఫ్రీ-టెక్స్ట్ ఎంట్రీని అనుమతించాలనుకున్నప్పుడు **`search()`**ని ఉపయోగించండి.
- మీకు SQL ఫ్లెక్సిబిలిటీ (JOINs, UNIONs, కంప్యూటెడ్ కాలమ్స్) అవసరమైనప్పుడు లేదా బహుళ టేబుల్స్‌లో క్వెరీ చేయాల్సి వచ్చినప్పుడు మరియు ఫారమ్‌కి స్థిరమైన కనెక్టివిటీ ఉన్నప్పుడు **`rawquery` ఆటో కంప్లీట్** ని ఉపయోగించండి.

## ఉత్తమ పద్ధతులు

1. మీ API ఎండ్‌పాయింట్ 1-2 సెకన్లలోపు స్పందిస్తుందని నిర్ధారించుకోండి — నెమ్మదిగా ఉండే APIలు సెర్చ్ సరిగ్గా పని చేయడం లేదని అనిపించేలా చేస్తాయి.
2. API మొత్తం డేటాసెట్‌ను కాకుండా సరిపోలే ఫలితాలను మాత్రమే రిటర్న్ చేసేలా `post_body`లో `%__input__%`ని ఉపయోగించండి.
3. వేగవంతమైన ప్రతిస్పందనల కోసం సర్వర్ సైడ్‌లో సెర్చ్ ఫీల్డ్‌ను ఇండెక్స్ చేయండి (ఉదాహరణకు, Elasticsearch, డేటాబేస్ ఫుల్-టెక్స్ట్ ఇండెక్స్).
4. ప్రతి క్వెరీకి ఫలితాలను 20-50 ఐటమ్స్‌కు పరిమితం చేయండి — వేలకొద్దీ ఫలితాలను రిటర్న్ చేయడం వల్ల సెర్చ్ ఉద్దేశ్యం నెరవేరదు.
5. సింగిల్-క్యారెక్టర్ ఇన్‌పుట్‌లపై పెద్ద క్వెరీలను నివారించడానికి APIలో మినిమమ్ ఇన్‌పుట్ లెంగ్త్ రిక్వైర్మెంట్‌ను చేర్చండి.

## పరిమితులు

- డైనమిక్ సెర్చ్‌కి నెట్‌వర్క్ కనెక్టివిటీ అవసరం — ఇది ఆఫ్‌లైన్‌లో పని చేయదు.
- `%__input__%` ప్లేస్‌హోల్డర్ నేరుగా ఇంజెక్ట్ చేయబడుతుంది; ఇంజెక్షన్ అటాక్స్‌ను నిరోధించడానికి సర్వర్ సైడ్‌లో ఇన్‌పుట్‌లను శానిటైజ్ చేయండి.
- సంక్లిష్టమైన `@{func}` డిస్‌ప్లే ఎక్స్‌ప్రెషన్స్‌కి అన్ని rtSurvey క్లయింట్ వెర్షన్‌లలో పరిమిత సపోర్ట్ ఉండవచ్చు.
