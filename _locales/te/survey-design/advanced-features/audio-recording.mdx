ఆడియో రికార్డింగ్ సర్వేలోని ఒక విభాగంలో నిశ్శబ్దంగా లేదా కనిపించేలా ఆడియోను క్యాప్చర్ చేయడానికి ఫారమ్‌ను అనుమతిస్తుంది. ఇంటర్వ్యూలను రికార్డ్ చేయడానికి, ఫీల్డ్ అబ్జర్వేషన్ల సమయంలో పరిసర ధ్వనిని లేదా నిర్మాణాత్మక సమాధానాలకు అనుబంధంగా ఉండే మాట్లాడే ప్రతిస్పందనలను రికార్డ్ చేయడానికి ఇది ఉపయోగపడుతుంది.

## ఇది ఎలా పని చేస్తుంది

ఆడియో రికార్డింగ్ **మార్కర్లు**గా పనిచేసే రెండు `text` ఫీల్డ్‌ల ద్వారా నియంత్రించబడుతుంది:

- `audio-start` అప్పియరెన్స్‌తో ఉన్న ఫీల్డ్, ఎన్యూమరేటర్ దానికి చేరుకున్నప్పుడు రికార్డింగ్‌ను ప్రారంభిస్తుంది.
- `audio-end` అప్పియరెన్స్‌తో ఉన్న ఫీల్డ్ రికార్డింగ్‌ను ఆపివేసి, ఆడియో ఫైల్‌ను సబ్మిషన్‌కు సేవ్ చేస్తుంది.

రెండు మార్కర్ ఫీల్డ్‌లు `text` రకానికి చెందినవి. అవి సాధారణంగా ఎన్యూమరేటర్ నుండి దాచబడతాయి (`relevant = false` ఉపయోగించి లేదా ఇంటరాక్టివ్ కాని స్థానంలో ఉంచడం ద్వారా), అయితే అవి కనిపించేలా కూడా ఉండవచ్చు. రికార్డ్ చేయబడిన ఆడియో `audio-end` ఫీల్డ్‌కు లింక్ చేయబడిన ఫైల్‌గా సబ్మిషన్‌కు జోడించబడుతుంది.

## నిశ్శబ్ద రికార్డింగ్: `audio-start invisible`

డిఫాల్ట్‌గా, ఆడియో క్యాప్చర్ చేయబడుతున్నప్పుడు మొబైల్ యాప్ రికార్డింగ్ ఇండికేటర్‌ను ప్రదర్శిస్తుంది. అప్పియరెన్స్‌కు `invisible` ని జోడించడం వల్ల ఈ ఇండికేటర్ నిరోధించబడుతుంది, తద్వారా ప్రతివాదికి ఎటువంటి కనిపించే సూచన లేకుండా రికార్డింగ్ జరుగుతుంది.

| type | name | label | appearance |
|------|------|-------|------------|
| text | audio_s_a1 | | `audio-start invisible` |
| text | q_consent | మీరు పాల్గొనడానికి అంగీకరిస్తున్నారా? | |
| text | q_feedback | మీ అభిప్రాయం | |
| text | audio_e_a1 | | `audio-end` |

వెల్లడి అవసరాలు ఇతర మార్గాల ద్వారా (ఉదాహరణకు, రికార్డింగ్ విభాగానికి ముందు ప్రత్యేక వ్రాతపూర్వక సమ్మతి ఫీల్డ్) తీర్చబడినప్పుడు మాత్రమే `invisible` ని ఉపయోగించండి.

## నామకరణ పద్ధతి (Naming convention)

ప్రొడక్షన్ ఫారమ్‌లు మార్కర్ ఫీల్డ్‌ల కోసం స్థిరమైన నామకరణ పద్ధతిని ఉపయోగిస్తాయి:

```
audio_s_{section}{n}   — ప్రారంభ మార్కర్
audio_e_{section}{n}   — ముగింపు మార్కర్
```

ఇక్కడ `{section}` అనేది ఫారమ్ విభాగం కోసం ఒక చిన్న లేబుల్ మరియు `{n}` అనేది ఆ విభాగంలోని వరుస సంఖ్య.

| Field name | Role | Meaning |
|------------|------|---------|
| `audio_s_a1` | Start | విభాగం A లో మొదటి రికార్డింగ్ |
| `audio_e_a1` | End | విభాగం A లో మొదటి రికార్డింగ్ ముగింపు |
| `audio_s_b1` | Start | విభాగం B లో మొదటి రికార్డింగ్ |
| `audio_e_b1` | End | విభాగం B లో మొదటి రికార్డింగ్ ముగింపు |
| `audio_s_a2` | Start | విభాగం A లో రెండవ రికార్డింగ్ |
| `audio_e_a2` | End | విభాగం A లో రెండవ రికార్డింగ్ ముగింపు |

ఈ పద్ధతిని అనుసరించడం వల్ల ఫారమ్ డెఫినిషన్లు మరియు సబ్మిషన్ డేటాను సమీక్షించేటప్పుడు రికార్డింగ్ సరిహద్దులను గుర్తించడం సులభం అవుతుంది.

## నిల్వ మరియు పునరుద్ధరణ (Storage and retrieval)

ఎన్యూమరేటర్ `audio-end` ఫీల్డ్‌కు చేరుకున్నప్పుడు, యాప్ ఆడియో ఫైల్‌ను పూర్తి చేసి సబ్మిషన్‌కు జోడిస్తుంది. ఆ ఫైల్:

- సబ్మిషన్‌పై ఆడియో అటాచ్‌మెంట్‌గా నిల్వ చేయబడుతుంది, ఇది `audio-end` ఫీల్డ్ పేరుతో అనుబంధించబడి ఉంటుంది.
- ఇతర మీడియా అటాచ్‌మెంట్‌లతో పాటు rtSurvey బ్యాక్-ఎండ్ సబ్మిషన్ వ్యూయర్‌లో అందుబాటులో ఉంటుంది.
- ప్రామాణిక సబ్మిషన్ ఎగుమతి ద్వారా డౌన్‌లోడ్ చేసుకోవచ్చు — `audio-end` ఫీల్డ్ పేరుకు అనుగుణంగా మీడియా కాలమ్‌లో ఆడియో ఫైల్‌లు కనిపిస్తాయి.

ఫైల్ ఫార్మాట్ మరియు బిట్రేట్ పరికరం మరియు యాప్ వెర్షన్‌పై ఆధారపడి ఉంటాయి.

## బహుళ రికార్డింగ్ విభాగాలు

ఒక ఫారమ్‌లో ఒకదానికొకటి సంబంధం లేని అనేక రికార్డింగ్ విభాగాలు ఉండవచ్చు. ప్రతి `audio-start` / `audio-end` మార్కర్ల జంట పూర్తిగా ఒకదానిలో ఒకటి ఉండాలి — విభాగాలు ఒకదానితో ఒకటి కలవకూడదు.

| type | name | label | appearance |
|------|------|-------|------------|
| text | audio_s_a1 | | `audio-start` |
| text | q_intro | పరిచయం | |
| text | audio_e_a1 | | `audio-end` |
| note | section_break | — | |
| text | audio_s_b1 | | `audio-start invisible` |
| text | q_detail | వివరాలు | |
| text | audio_e_b1 | | `audio-end` |

ప్రతి విభాగం దాని సంబంధిత `audio-end` ఫీల్డ్‌కు జోడించబడిన ప్రత్యేక ఆడియో ఫైల్‌ను ఉత్పత్తి చేస్తుంది.

## పరిమితులు

- **మొబైల్ యాప్ మాత్రమే.** ఈ ఫీచర్ వెబ్ ఫారమ్‌లో మద్దతు ఇవ్వబడదు. బ్రౌజర్‌లో `audio-start` మరియు `audio-end` నిశ్శబ్దంగా విస్మరించబడతాయి.
- **నెస్టెడ్ రికార్డింగ్ లేదు.** రికార్డింగ్ విభాగాలు ఒకదానిపై ఒకటి రాకూడదు. మునుపటి `audio-end` మార్కర్‌కు చేరుకోకముందే కొత్త రికార్డింగ్‌ను ప్రారంభించడం మద్దతు ఇవ్వబడదు.
- **ఫీల్డ్ రకం తప్పనిసరిగా `text` అయి ఉండాలి.** మరే ఇతర ప్రశ్న రకంపై అయినా `audio-start` లేదా `audio-end` ఉపయోగించడం మద్దతు ఇవ్వబడదు.
- **అప్‌లోడ్ పరిమాణం.** సుదీర్ఘ రికార్డింగ్‌లు పెద్ద ఫైల్‌లను ఉత్పత్తి చేస్తాయి. ఫీల్డ్‌లో సబ్మిషన్ సైజు పరిమితులు మరియు నెట్‌వర్క్ పరిస్థితుల గురించి అవగాహన కలిగి ఉండండి.
- **రికార్డింగ్ మధ్యలో పాజ్ లేదు.** రికార్డింగ్ ప్రారంభ మార్కర్ నుండి ముగింపు మార్కర్ వరకు నిరంతరంగా నడుస్తుంది; ఒక విభాగంలో పాజ్ చేసి మళ్లీ ప్రారంభించే విధానం లేదు.
