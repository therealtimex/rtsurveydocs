`file` प्रश्न प्रकार उत्तरदाताओं को अपने डिवाइस से **कोई भी फ़ाइल अपलोड करने** की अनुमति देता है — दस्तावेज़, स्प्रेडशीट, पीडीएफ, या अन्य फ़ाइल प्रकार। `image`, `audio`, और `video` के विपरीत जो विशिष्ट कैप्चर टूल लॉन्च करते हैं, `file` एक सामान्य-उद्देश्य फ़ाइल पिकर खोलता है।

## मूल XLSForm विनिर्देश

| type | name      | label                        |
|------|-----------|------------------------------|
| file | document  | कृपया अपना दस्तावेज़ अपलोड करें |

मानक फ़ाइल प्रश्न प्रकार पर अधिक जानकारी के लिए, [XLSForm विनिर्देश](https://xlsform.org/en/#question-types) देखें।

## उपयोग

फ़ाइल प्रश्नों का आमतौर पर उपयोग किया जाता है:

1. सहायक दस्तावेज़ (रसीदें, प्रमाणपत्र, अनुबंध, रिपोर्ट) एकत्र करना
2. स्कैन किए गए पूर्ण पेपर फ़ॉर्म अपलोड करना
3. अन्य प्रणालियों से स्प्रेडशीट या डेटा निर्यात एकत्र करना
4. कोई भी डिजिटल फ़ाइल प्रकार जिसे छवि/ऑडियो/वीडियो कवर नहीं करता है

## डेटा प्रारूप

अपलोड की गई फ़ाइलें बाइनरी अटैचमेंट के रूप में संग्रहीत की जाती हैं:

- **प्रारूप:** मूल प्रारूप में संरक्षित (पीडीएफ, एक्सएलएसएक्स, डीओसीएक्स, आदि)
- **नामकरण:** `{instanceID}-{fieldname}.{extension}`
- **भंडारण:** सबमिशन के साथ सर्वर मीडिया फ़ोल्डर में अपलोड किया गया
- **पहुँच:** सबमिशन प्रबंधन इंटरफ़ेस से डाउनलोड करने योग्य

## rtSurvey एक्सटेंशन

### स्वीकृत फ़ाइल प्रकार

यह प्रतिबंधित करने के लिए `parameters` कॉलम का उपयोग करें कि कौन से फ़ाइल प्रकारों का चयन किया जा सकता है:

| type | name | label | parameters |
|------|------|-------|------------|
| file | report | निरीक्षण रिपोर्ट अपलोड करें | `accept=.pdf` |
| file | spreadsheet | डेटा फ़ाइल अपलोड करें | `accept=.xlsx,.csv` |

`accept` पैरामीटर मानक फ़ाइल एक्सटेंशन सिंटैक्स (कॉमा-पृथक) का उपयोग करता है।

### फ़ाइल आकार मार्गदर्शन

rtSurvey प्रश्न स्तर पर हार्ड फ़ाइल-आकार सीमा लागू नहीं करता है, लेकिन सर्वर अपलोड सीमा लागू होती है। प्रगणक को अपेक्षाएँ संप्रेषित करने के लिए `hint` का उपयोग करें:

| type | name | label | hint |
|------|------|-------|------|
| file | receipt | भुगतान रसीद अपलोड करें | स्वीकृत: PDF या छवि। अधिकतम फ़ाइल आकार: 5 MB |

### डिवाइस फ़ाइल सिस्टम और क्लाउड स्टोरेज के साथ एकीकरण

Android और iOS पर, `file` प्रश्न डिवाइस के नेटिव फ़ाइल पिकर को खोलता है, जिसमें निम्न तक पहुँच शामिल हो सकती है:
- स्थानीय डिवाइस स्टोरेज
- SD कार्ड (Android)
- iCloud Drive (iOS)
- Google Drive, Dropbox (यदि स्थापित हो)

वेब पर, यह ब्राउज़र का मानक फ़ाइल अपलोड डायलॉग खोलता है।

### इनलाइन बटन लेआउट

पूर्ण-चौड़ाई वाले फ़ाइल पिकर के बजाय लेबल के बगल में अपलोड को **गोलाकार आइकन बटन** के रूप में प्रस्तुत करने के लिए `inline` जोड़ें।

```
| type | name | label           | appearance                              |
|------|------|-----------------|-----------------------------------------|
| file | doc  | दस्तावेज़ अपलोड करें | inline display{right}                   |
| file | doc  | दस्तावेज़ अपलोड करें | inline display{left, large}             |
| file | doc  | दस्तावेज़ अपलोड करें | inline display{center, large, <0099FF/>} |
```

**बटन की स्थिति** — `left`, `right` *(डिफ़ॉल्ट)*, `top`, `center`, `bottom`

**बटन का आकार** — `small` *(डिफ़ॉल्ट)*, `medium`, `large`

**बटन का रंग** — प्राथमिक रंग को ओवरराइड करने के लिए `display{}` के अंदर एक हेक्स रंग जोड़ें:

```
inline display{right, large, <FF5500/>}
```

**कैप्चर के बाद नियंत्रण — `results{}`:**

| Appearance | प्रभाव |
|---|---|
| `results{hide(capture)}` | फ़ाइल संलग्न होने के बाद अपलोड बटन को छिपाता है |
| `results{hide(review)}` | अपलोड के बाद समीक्षा/पूर्वावलोकन बटन को छिपाता है |
| `results{hide(filename)}` | अपलोड के बाद दिखाए गए फ़ाइल नाम को छिपाता है |
| `results{left}` | अपलोड के बाद आइकन को बाईं ओर ले जाता है |

उदाहरण — फ़ाइल संलग्न होने के बाद अपलोड बटन छिपाएँ:
```
inline display{right} results{hide(capture)}
```

### लेबल को दबाएं

```
inline text-nolabel display{center, large}
```

## सर्वोत्तम अभ्यास

1. फ़ाइल प्रकारों को प्रतिबंधित करने के लिए `accept` का उपयोग करें — यह प्रगणकों को गलती से गलत फ़ाइलें अपलोड करने से रोकता है।
2. `hint` कॉलम में हमेशा आकार और प्रारूप मार्गदर्शन शामिल करें।
3. फ़ोटो और छवियों के लिए, इसके बजाय `image` प्रकार का उपयोग करें — यह बेहतर संपीड़न और सुसंगत प्रारूप हैंडलिंग प्रदान करता है।
4. फ़ाइल अटैचमेंट वाले बड़े सर्वेक्षणों के लिए, अपने डेटा स्टोरेज और डाउनलोड बैंडविड्थ की तदनुसार योजना बनाएं।
5. तैनाती से पहले लक्ष्य डिवाइस प्रकार (Android बनाम iOS बनाम वेब) पर फ़ाइल पिकर का परीक्षण करें — क्लाउड ड्राइव तक पहुँच भिन्न होती है।

## डेटा हैंडलिंग विचार

- फ़ाइलें अपने मूल प्रारूप में संग्रहीत की जाती हैं; उन्हें rtSurvey द्वारा परिवर्तित या संपीड़ित नहीं किया जाता है।
- डाउनलोड के बाद फ़ाइलों का विश्लेषण करें — rtSurvey फ़ाइल सामग्री को निकालता या अनुक्रमित नहीं करता है।
- बड़े फ़ाइल अटैचमेंट एक पूर्ण डेटासेट डाउनलोड करने के लिए आवश्यक समय को काफी बढ़ा देते हैं।

## सीमाएँ

- फ़ाइल प्रश्न फ़ाइल सामग्री को मान्य नहीं करते हैं — UI स्तर पर केवल `accept` के माध्यम से फ़ाइल एक्सटेंशन जाँच लागू की जाती है।
- बहुत बड़ी फ़ाइलें (100 MB+) कम-कनेक्टिविटी वाले वातावरण में अपलोड पर टाइम आउट हो सकती हैं।
- ऑफ़लाइन प्रगणक फ़ाइलें संलग्न कर सकते हैं लेकिन कनेक्टिविटी बहाल होने तक वे अपलोड नहीं होंगी।
- कुछ डिवाइस कॉन्फ़िगरेशन कुछ स्टोरेज स्थानों तक पहुँच को प्रतिबंधित करते हैं (उदाहरण के लिए, कॉर्पोरेट एमडीएम नीतियां)।
