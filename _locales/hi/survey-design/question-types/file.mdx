`file` प्रश्न प्रकार उत्तरदाताओं को अपने डिवाइस से **कोई भी फ़ाइल अपलोड** करने की अनुमति देता है — दस्तावेज़, स्प्रेडशीट, PDF, या अन्य फ़ाइल प्रकार। `image`, `audio`, और `video` के विपरीत जो विशिष्ट कैप्चर टूल लॉन्च करते हैं, `file` एक सामान्य-उद्देश्य वाला फ़ाइल पिकर खोलता है।

## बुनियादी XLSForm विनिर्देश (Specification)

| type | name      | label                        |
|------|-----------|------------------------------|
| file | document  | कृपया अपना दस्तावेज़ अपलोड करें |

मानक फ़ाइल प्रश्न प्रकार पर अधिक विवरण के लिए, [XLSForm विनिर्देश](https://xlsform.org/en/#question-types) देखें।

## उपयोग

फ़ाइल प्रश्नों का उपयोग आमतौर पर इनके लिए किया जाता है:

1. सहायक दस्तावेज़ एकत्र करना (रसीदें, प्रमाण पत्र, अनुबंध, रिपोर्ट)
2. स्कैन किए गए पूर्ण पेपर फॉर्म अपलोड करना
3. अन्य प्रणालियों से स्प्रेडशीट या डेटा निर्यात एकत्र करना
4. कोई भी डिजिटल फ़ाइल प्रकार जिसे इमेज/ऑडियो/वीडियो कवर नहीं करता है

## डेटा प्रारूप (Data format)

अपलोड की गई फ़ाइलें बाइनरी अटैचमेंट के रूप में संग्रहीत की जाती हैं:

- **प्रारूप:** मूल प्रारूप (PDF, XLSX, DOCX, आदि) में सुरक्षित
- **नामकरण:** `{instanceID}-{fieldname}.{extension}`
- **भंडारण:** सबमिशन के साथ सर्वर मीडिया फ़ोल्डर में अपलोड किया गया
- **पहुँच:** सबमिशन प्रबंधन इंटरफ़ेस से डाउनलोड करने योग्य

## rtSurvey विस्तार (Extensions)

### स्वीकृत फ़ाइल प्रकार

किन फ़ाइल प्रकारों को चुना जा सकता है, इसे प्रतिबंधित करने के लिए `parameters` कॉलम का उपयोग करें:

| type | name | label | parameters |
|------|------|-------|------------|
| file | report | निरीक्षण रिपोर्ट अपलोड करें | `accept=.pdf` |
| file | spreadsheet | डेटा फ़ाइल अपलोड करें | `accept=.xlsx,.csv` |

`accept` पैरामीटर मानक फ़ाइल एक्सटेंशन सिंटैक्स (कॉमा-सेपरेटेड) का उपयोग करता है।

### फ़ाइल आकार मार्गदर्शन

rtSurvey प्रश्न स्तर पर कोई कठोर फ़ाइल-आकार सीमा लागू नहीं करता है, लेकिन सर्वर अपलोड सीमा लागू होती है। गणनाकर्ता (enumerator) को अपेक्षाओं को संप्रेषित करने के लिए `hint` का उपयोग करें:

| type | name | label | hint |
|------|------|-------|------|
| file | receipt | भुगतान रसीद अपलोड करें | स्वीकृत: PDF या इमेज। अधिकतम फ़ाइल आकार: 5 MB |

### डिवाइस फ़ाइल सिस्टम और क्लाउड स्टोरेज के साथ एकीकरण

Android और iOS पर, `file` प्रश्न डिवाइस का नेटिव फ़ाइल पिकर खोलता है, जिसमें इनकी पहुँच शामिल हो सकती है:
- स्थानीय डिवाइस स्टोरेज
- SD कार्ड (Android)
- iCloud Drive (iOS)
- Google Drive, Dropbox (यदि स्थापित है)

वेब पर, यह ब्राउज़र का मानक फ़ाइल अपलोड डायलॉग खोलता है।

### इनलाइन बटन लेआउट (Inline button layout)

फुल-विड्थ फ़ाइल पिकर के बजाय लेबल के बगल में **सर्कुलर आइकन बटन** के रूप में अपलोड रेंडर करने के लिए `inline` जोड़ें।

```
| type | name | label           | appearance                              |
|------|------|-----------------|-----------------------------------------|
| file | doc  | दस्तावेज़ अपलोड करें | inline display{right}                   |
| file | doc  | दस्तावेज़ अपलोड करें | inline display{left, large}             |
| file | doc  | दस्तावेज़ अपलोड करें | inline display{center, large, <0099FF/>} |
```

**बटन स्थिति** — `left`, `right` *(डिफ़ॉल्ट)*, `top`, `center`, `bottom`

**बटन आकार** — `small` *(डिफ़ॉल्ट)*, `medium`, `large`

**बटन रंग** — प्राथमिक रंग को ओवरराइड करने के लिए `display{}` के अंदर एक हेक्स रंग जोड़ें:

```
inline display{right, large, <FF5500/>}
```

**कैप्चर के बाद का नियंत्रण — `results{}`:**

| Appearance | Effect |
|---|---|
| `results{hide(capture)}` | फ़ाइल अटैच होने के बाद अपलोड बटन को छिपाता है |
| `results{hide(review)}` | अपलोड के बाद समीक्षा/पूर्वावलोकन बटन को छिपाता है |
| `results{hide(filename)}` | अपलोड के बाद दिखाए गए फ़ाइल नाम को छिपाता है |
| `results{left}` | अपलोड के बाद आइकन को बाईं ओर ले जाता है |

उदाहरण — फ़ाइल अटैच होने के बाद अपलोड बटन छिपाएँ:
```
inline display{right} results{hide(capture)}
```

### लेबल दबाएँ (Suppress the label)

```
inline text-nolabel display{center, large}
```

## उदाहरण उपयोग

### आवश्यक PDF अपलोड

| type | name | label | hint | required | required_message |
|------|------|-------|------|----------|-----------------|
| file | signed_consent | हस्ताक्षरित सहमति फॉर्म अपलोड करें | केवल PDF, अधिकतम 2MB | yes | सहमति फॉर्म आवश्यक है |

### सशर्त दस्तावेज़ अपलोड

| type | name | label | relevant |
|------|------|-------|----------|

## सर्वोत्तम प्रथाएं

1. फ़ाइल प्रकारों को प्रतिबंधित करने के लिए `accept` का उपयोग करें — यह गणनाकर्ताओं को गलती से गलत फ़ाइलें अपलोड करने से रोकता है।
2. हमेशा `hint` कॉलम में आकार और प्रारूप मार्गदर्शन शामिल करें।
3. फोटो और इमेज के लिए, इसके बजाय `image` प्रकार का उपयोग करें — यह बेहतर संपीड़न और सुसंगत प्रारूप प्रबंधन प्रदान करता है।
4. फ़ाइल अटैचमेंट वाले बड़े सर्वेक्षणों के लिए, उसके अनुसार अपने डेटा स्टोरेज और डाउनलोड बैंडविड्थ की योजना बनाएं।
5. परिनियोजन से पहले लक्ष्य डिवाइस प्रकार (Android बनाम iOS बनाम वेब) पर फ़ाइल पिकर का परीक्षण करें — क्लाउड ड्राइव तक पहुँच अलग-अलग होती है।

## डेटा हैंडलिंग विचार

- फ़ाइलें उनके मूल प्रारूप में संग्रहीत की जाती हैं; वे rtSurvey द्वारा परिवर्तित या संपीड़ित नहीं की जाती हैं।
- डाउनलोड के बाद फ़ाइलों का विश्लेषण करें — rtSurvey फ़ाइल सामग्री को निकालता या अनुक्रमित (index) नहीं करता है।
- बड़े फ़ाइल अटैचमेंट पूर्ण डेटासेट डाउनलोड करने के लिए आवश्यक समय को महत्वपूर्ण रूप से बढ़ा देते हैं।

## सीमाएं (Limitations)

- फ़ाइल प्रश्न फ़ाइल सामग्री को सत्यापित नहीं करते हैं — UI स्तर पर केवल `accept` के माध्यम से फ़ाइल एक्सटेंशन जांच लागू की जाती है।
- बहुत बड़ी फ़ाइलें (100 MB+) कम-कनेक्टिविटी वाले वातावरण में अपलोड पर टाइम आउट हो सकती हैं।
- ऑफ़लाइन गणनाकर्ता फ़ाइलें अटैच कर सकते हैं लेकिन वे तब तक अपलोड नहीं होंगी जब तक कनेक्टिविटी बहाल नहीं हो जाती।
- कुछ डिवाइस कॉन्फ़िगरेशन कुछ स्टोरेज स्थानों (जैसे, कॉर्पोरेट MDM नीतियां) तक पहुँच को प्रतिबंधित करते हैं।
