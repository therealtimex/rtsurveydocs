`family_path` एक कन्वेंशन calculate फ़ील्ड है जो फ़ॉर्म की बंडल की गई मीडिया डायरेक्टरी का पाथ रखता है। हर फ़ॉर्म जो `rawquery`, `pulldata`, या `search()` के साथ स्थानीय डेटाबेस लुकअप करता है, उसमें यह फ़ील्ड शामिल होना चाहिए — इसके बिना, फ़ाइल पाथ हल नहीं किए जा सकते और लुकअप चुपचाप खाली परिणाम लौटाते हैं।

---

## calculate फ़ील्ड

इस पंक्ति को अपनी survey शीट के शीर्ष के पास जोड़ें, किसी भी मेटा फ़ील्ड के बाद और डेटाबेस फ़ाइल का उपयोग करने वाले पहले प्रश्न से पहले:

| type | name | label | calculation |
|---|---|---|---|
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |

यह फ़ील्ड कोई दृश्य मान संग्रहीत नहीं करता है और इसके लिए किसी label की आवश्यकता नहीं है। यह बाद में आने वाले सभी पाथ निर्माण के लिए एक अदृश्य पूर्व शर्त है।

---

## इसकी आवश्यकता क्यों है

RTSurvey फ़ॉर्म मीडिया — SQLite डेटाबेस, चित्र, ऑडियो क्लिप — को डिवाइस पर प्रति-फ़ॉर्म डायरेक्टरी के अंदर बंडल करता है। सटीक पाथ अलग-अलग प्लेटफ़ॉर्म (Android, iOS, वेब) और अलग-अलग डिवाइस के बीच भिन्न होता है।

रनटाइम पर ऐप `family_path` को स्वचालित रूप से भर देता है। एक विशिष्ट हल किया गया मान इस तरह दिखता है:

```
resources/familyMedia/Phuong_Person_Test
```

क्योंकि पाथ प्लेटफ़ॉर्म-विशिष्ट है और लॉन्च के समय निर्धारित होता है, इसे फ़ॉर्म में हार्ड-कोड नहीं किया जा सकता है। इसे प्राप्त करने का एकमात्र विश्वसनीय तरीका `pulldata('app-api', 'family_path')` है।

---

## पाथ में इसका उपयोग कैसे करें

एक बार `family_path` परिभाषित हो जाने के बाद, `concat()` के साथ एक पूर्ण फ़ाइल पाथ बनाएं:

```
concat(${family_path}, '/file.db::tableName')
```

जब ऐप फ़ाइल खोलता है तो `::tableName` प्रत्यय हटा दिया जाता है; टेबल नाम का उपयोग केवल आपके SQL क्वेरी के अंदर किया जाता है।

---

## जहाँ family_path का उपयोग किया जाता है

जब भी आप किसी बंडल की गई फ़ाइल का संदर्भ देते हैं, तो पाथ तर्क में `family_path` आवश्यक होता है:

- **स्थानीय डेटाबेस खोज** — `search-autocomplete-noedit-v2('rawquery', ...)` का `db_path` तर्क `concat(${family_path}, ...)` के साथ बनाया जाना चाहिए। पूर्ण उपयोग विवरण के लिए [स्थानीय डेटाबेस खोज](local-database-search) देखें।
- **`pulldata` rawquery** — कोई भी `pulldata('rawquery', ...)` कॉल जो `.db` फ़ाइल से पढ़ती है, उसी `concat()` पैटर्न का उपयोग करती है।
- **स्थानीय फ़ाइल के साथ `search()`** — डायनेमिक-सर्च अपीयरेंस जो बंडल की गई CSV या DB फ़ाइल से लोड होते हैं, वे भी फ़ाइल संदर्भ के लिए `family_path` पर निर्भर करते हैं।

## फ़ॉर्म में प्लेसमेंट

`family_path` उस पहले फ़ील्ड से **पहले दिखाई देना चाहिए जो इसे संदर्भित करता है**। अनुशंसित स्थिति मेटा समूह के तुरंत बाद है:

| type | name | label | calculation |
|---|---|---|---|
| begin_group | meta | | |
| deviceid | deviceid | | |
| start | start | | |
| end | end | | |
| end_group | | | |
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |
| select_one | province | प्रांत | *(rawquery appearance referencing `${family_path}`)* |

<Callout type="warning">
यदि फ़ॉर्म से `family_path` गायब है, या इसे संदर्भित करने वाले पहले `rawquery` / `search()` फ़ील्ड के बाद रखा गया है, तो बंडल की गई फ़ाइलों के विरुद्ध सभी लुकअप चुपचाप खाली लौट आएंगे। कोई त्रुटि संदेश नहीं आता है — ऑटो-कम्प्लीट बस कोई परिणाम नहीं दिखाता है।
</Callout>

---

## एकाधिक डेटाबेस फ़ाइलें

एक ही फ़ॉर्म कई `.db` फ़ाइलों का उपयोग कर सकता है। प्रत्येक पाथ `concat()` के साथ स्वतंत्र रूप से बनाया गया है:

```
concat(${family_path}, '/locations.db::externalData')
concat(${family_path}, '/health_facilities.db::facilities')
concat(${family_path}, '/household_list.db::households')
```

`family_path` को एक बार परिभाषित करें; जितने आवश्यक हो उतने फ़ील्ड में इसका संदर्भ दें।

---

## विकास के दौरान सत्यापन

डिवाइस पर हल किए गए मान का निरीक्षण करने के लिए `family_path` के नीचे एक अस्थायी `note` फ़ील्ड जोड़ें:

| type | name | label | calculation |
|---|---|---|---|
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |
| note | family_path_check | `पाथ: ${family_path}` | |

नोट परीक्षण के दौरान वास्तविक हल किए गए पाथ को प्रदर्शित करेगा। अंतिम फ़ॉर्म को तैनात करने से पहले इसे हटा दें।
