**डायनेमिक सर्च** (जिसे सर्च API भी कहा जाता है) एक `select_one`, `select_multiple`, या `text` फ़ील्ड को प्रगणक के टाइप करते समय **रनटाइम पर** रिमोट वेब सेवा से अपने विकल्पों को लोड करने की अनुमति देता है। यह तब सही दृष्टिकोण है जब आपकी पसंद की सूची CSV फ़ाइल में बंडल करने के लिए बहुत बड़ी हो, बार-बार अपडेट की जाती हो, या लाइव डेटाबेस से आती हो।

---

## `search-api()` अपीयरेंस (Appearance)

डायनेमिक सर्च को `search-api()` फ़ंक्शन का उपयोग करके `appearance` कॉलम के माध्यम से कॉन्फ़िगर किया गया है:

```
search-api(method, url, post_body, value_column, display, data_path, save_path)
```

### पैरामीटर्स (Parameters)

| पैरामीटर | विवरण |
|-----------|-------------|
| `method` | हमेशा `'POST'` का उपयोग करें |
| `url` | क्वेरी करने के लिए API एंडपॉइंट |
| `post_body` | API को भेजी गई JSON बॉडी। प्रगणक के वर्तमान खोज टेक्स्ट के लिए प्लेसहोल्डर के रूप में `%__input__%` का उपयोग करें |
| `value_column` | रिस्पॉन्स ऑब्जेक्ट की वह की (key) जिसे संग्रहीत **मान** (value) के रूप में उपयोग किया जाना है |
| `display` | ड्रॉपडाउन में दिखाए गए **लेबल** (label) के रूप में उपयोग की जाने वाली की (key) या टेम्पलेट। `##key##` प्लेसहोल्डर्स और `@{func}` एक्सप्रेशन का समर्थन करता है |
| `data_path` | रिस्पॉन्स में परिणाम ऑब्जेक्ट्स के एरे (array) के लिए JSONPath (जैसे, `$.data`, `$.hits.hits.*._source`) |
| `save_path` | एक नाम जिसके तहत अन्य फ़ील्ड द्वारा उपयोग के लिए रॉ रिस्पॉन्स (raw response) सहेजा जाता है |

## बुनियादी उदाहरण

एक स्वास्थ्य सुविधा खोज जहाँ प्रगणक सुविधा के नाम का हिस्सा टाइप करता है:

| type | name | label | appearance |
|------|------|-------|------------|
| select_one | facility | स्वास्थ्य सुविधा चुनें | `search-api('POST', 'https://api.example.com/facilities/search', '{"query": "%__input__%"}', 'id', 'name', '$.results', 'facility_data')` |

जब प्रगणक "nair" टाइप करता है तो API को `{"query": "nair"}` प्राप्त होता है और वह वापस करता है:

```json
{
  "results": [
    {"id": "HF001", "name": "Nairobi Central Clinic"},
    {"id": "HF002", "name": "Nairobi West Hospital"}
  ]
}
```

ड्रॉपडाउन में `Nairobi Central Clinic` और `Nairobi West Hospital` दिखाई देता है; संग्रहीत मान `HF001` या `HF002` है।

## उन्नत डिस्प्ले फॉर्मेटिंग

### `##key##` टेम्पलेट्स का उपयोग करना

लेबल में कई फ़ील्ड दिखाएं:

```
search-api('POST', 'https://api.example.com/search', '{"q": "%__input__%"}', 'id', '##name## (##district##)', '$.data', 'res')
```

इस तरह प्रदर्शित होता है: `Nairobi Central Clinic (Nairobi)`।

### `@{func}` एक्सप्रेशन का उपयोग करना

डिस्प्ले लेबल में कंडीशनल लॉजिक लागू करें:

```
search-api('POST', 'https://api.example.com/search', '{"q": "%__input__%"}', 'id',
  '@{if_else(eq("##status##", "active"), "✓ ##name##", "✗ ##name##")}',
  '$.data', 'res')
```

सक्रिय परिणामों में `✓ Clinic Name` दिखता है; निष्क्रिय में `✗ Clinic Name` दिखता है।

---

## डिफ़ॉल्ट मान सेट करना: `search-default-api()`

किसी अलग API कॉल से लोड किए गए डिफ़ॉल्ट विकल्प के साथ फ़ील्ड को पहले से भरने के लिए `search-api()` के बाद `search-default-api()` का उपयोग करें (उदाहरण के लिए, किसी मौजूदा रिकॉर्ड को संपादित करते समय):

```
appearance: search-api(...) search-default-api('POST', 'https://api.example.com/get', '{"id": "##saved_id##"}', 'id', 'name', '$.item')
```

---

## select_multiple के लिए कस्टम सेपरेटर: `search-default-separator()`

`select_multiple` फ़ील्ड के लिए, निर्दिष्ट करें कि संग्रहीत स्ट्रिंग में कई चयनित मान कैसे जुड़े हैं:

```
appearance: search-api(...) search-default-separator(' || ')
```

डिफ़ॉल्ट सेपरेटर एक स्पेस (space) है।

---

## समर्थित प्रश्न प्रकार

| प्रश्न प्रकार | उपयोग का मामला |
|---------------|----------|
| `select_one` | खोज परिणामों से एकल चयन |
| `select_multiple` | खोज परिणामों से बहु-चयन |
| `text` | ऑटो-कम्प्लीट (Autocomplete) — प्रगणक स्वतंत्र रूप से टाइप करता है लेकिन सुझाव चुन सकता है |

## सहेजे गए रिस्पॉन्स डेटा का उपयोग करना

जब प्रगणक एक परिणाम चुनता है, तो rtSurvey रिस्पॉन्स से मेल खाने वाले पूरे ऑब्जेक्ट को `save_path` नाम के तहत सहेजता है। अन्य फ़ील्ड इसमें से दो तरीकों से पढ़ सकते हैं।

### तरीका 1 — `pulldata()` लुकअप

सहेजे गए ऑब्जेक्ट से टॉप-लेवल फ़ील्ड को पढ़ने के लिए `pulldata('save_path', 'key')` का उपयोग करें:

| type | name | label | calculation |
|------|------|-------|-------------|
| select_one | facility | सुविधा चुनें | |
| calculate | facility_district | | `pulldata('facility_data', 'district')` |
| calculate | facility_type | | `pulldata('facility_data', 'type')` |
| calculate | facility_beds | | `pulldata('facility_data', 'beds')` |

`select_one` पंक्ति पर अपीयरेंस में मैचिंग `save_path` के साथ `search-api(..., 'facility_data')` शामिल होना चाहिए।

**नेस्टेड (Nested) JSON फ़ील्ड** के लिए, `substr-jsonpath()` के साथ संयोजित करें:

```
substr-jsonpath(pulldata('facility_data', 'location'), '$.district')
```

## search() के साथ लोकल फ़ाइल सर्च

`search()` बंडल की गई SQLite `.db` फ़ाइल के विरुद्ध ऑफ़लाइन, कॉलम-इक्वलिटी लुकअप करता है — किसी नेटवर्क कनेक्शन और SQL क्वेरी की आवश्यकता नहीं होती है। इसका उपयोग तब करें जब आपका संदर्भ डेटा फ़ॉर्म के साथ पैक किया गया हो और आपको एक सरल "वे सभी पंक्तियाँ खोजें जहाँ कॉलम मान के बराबर है" लुकअप की आवश्यकता हो।

### सिग्नेचर (Signature)

```
search(path, 'matches', 'list_name', ${field})
```

### पैरामीटर्स (Parameters)

| पैरामीटर | विवरण |
|-----------|-------------|
| `path` | SQLite टेबल का पाथ (path): `concat(${family_path}, '/file.db::table')` |
| `'matches'` | मैच ऑपरेटर — उन पंक्तियों को लौटाता है जहाँ कॉलम मान के बराबर होता है |
| `'list_name'` | मैच करने के लिए कॉलम का नाम |
| `${field}` | मैच करने के लिए मान; आमतौर पर एक फ़ील्ड संदर्भ |

### उदाहरण

`d307.db` की `externalData` टेबल में `list_name` कॉलम के विरुद्ध `${d307}` के मान का मिलान करके लोकल डेटाबेस से `select_one` भरें:

| type | name | label | appearance |
|------|------|-------|------------|
| select_one | facility | सुविधा चुनें | `search(concat(${family_path}, '/d307.db::externalData'), 'matches', 'list_name', ${d307})` |

जब `${d307}` `"HF001"` के बराबर होता है, तो `search()` `externalData` में प्रत्येक पंक्ति लौटाता है जहाँ `list_name = 'HF001'` — पूरी तरह से बंडल की गई फ़ाइल से, बिना किसी नेटवर्क कॉल के।

### search() बनाम rawquery ऑटो-कम्प्लीट

| विशेषता | `search()` | `rawquery` ऑटो-कम्प्लीट |
|---------|-----------|------------------------|
| SQL क्वेरी | नहीं — केवल कॉलम इक्वलिटी | हाँ — पूर्ण `SELECT … FROM …` |
| पैरामीट्रिज्ड इनपुट | कॉलम मान मिलान | SQL स्ट्रिंग में एम्बेडेड |
| फ्री-टेक्स्ट प्रविष्टि | हाँ — प्रगणक स्वतंत्र रूप से टाइप कर सकता है | नहीं — सूची से चुनना होगा |
| UNION / बहु-टेबल | समर्थित नहीं | समर्थित |

### प्रत्येक का उपयोग कब करें

- **`search()`** का उपयोग तब करें जब आपको बंडल की गई `.db` फ़ाइल के विरुद्ध सीधे इक्वलिटी मैच की आवश्यकता हो, फ़ॉर्म को ऑफ़लाइन काम करना चाहिए, और आप फ्री-टेक्स्ट प्रविष्टि की अनुमति देना चाहते हैं।
- **`rawquery` ऑटो-कम्प्लीट** का उपयोग तब करें जब आपको SQL लचीलेपन (JOINs, UNIONs, गणना किए गए कॉलम) की आवश्यकता हो या कई टेबल में क्वेरी करनी हो, और फ़ॉर्म में विश्वसनीय कनेक्टिविटी हो।

## सर्वोत्तम अभ्यास (Best Practices)

1. सुनिश्चित करें कि आपका API एंडपॉइंट 1-2 सेकंड के भीतर जवाब देता है — धीमे API खोज को अनुत्तरदायी महसूस कराते हैं।
2. `post_body` में `%__input__%` का उपयोग करें ताकि API केवल मिलान करने वाले परिणाम लौटाए, न कि पूरा डेटासेट।
3. तेज़ प्रतिक्रियाओं के लिए सर्वर साइड (जैसे, Elasticsearch, डेटाबेस फुल-टेक्स्ट इंडेक्स) पर सर्च फ़ील्ड को इंडेक्स करें।
4. प्रति क्वेरी परिणामों को 20-50 आइटम तक सीमित करें — हजारों परिणाम लौटाना खोज के उद्देश्य को विफल कर देता है।
5. एकल-वर्ण इनपुट पर व्यापक प्रश्नों को ट्रिगर करने से बचने के लिए API में न्यूनतम इनपुट लंबाई की आवश्यकता शामिल करें।

## सीमाएँ (Limitations)

- डायनेमिक सर्च के लिए नेटवर्क कनेक्टिविटी की आवश्यकता होती है — यह ऑफ़लाइन काम नहीं करता है।
- `%__input__%` प्लेसहोल्डर जैसा है वैसा ही इंजेक्ट किया जाता है; इंजेक्शन हमलों को रोकने के लिए सर्वर साइड पर इनपुट को सैनिटाइज़ (sanitise) करें।
- जटिल `@{func}` डिस्प्ले एक्सप्रेशन का सभी rtSurvey क्लाइंट संस्करणों में सीमित समर्थन हो सकता है।
