ऑडियो रिकॉर्डिंग एक फ़ॉर्म को सर्वेक्षण के एक अनुभाग के दौरान चुपचाप या स्पष्ट रूप से ऑडियो कैप्चर करने की अनुमति देती है। यह साक्षात्कार, क्षेत्र अवलोकन के दौरान परिवेशी ध्वनि, या बोले गए उत्तरों को रिकॉर्ड करने के लिए उपयोगी है जो संरचित उत्तरों के पूरक हैं।

</Callout>

## यह कैसे काम करता है

ऑडियो रिकॉर्डिंग दो `text` फ़ील्ड द्वारा नियंत्रित की जाती है जो **मार्कर** के रूप में कार्य करते हैं:

- `audio-start` दिखावट वाला फ़ील्ड तब रिकॉर्डिंग शुरू करता है जब प्रगणक उस पर पहुँचता है।
- `audio-end` दिखावट वाला फ़ील्ड रिकॉर्डिंग बंद कर देता है और सबमिशन में ऑडियो फ़ाइल सहेजता है।

दोनों मार्कर फ़ील्ड `text` प्रकार के हैं। वे आमतौर पर प्रगणक से छिपे होते हैं (`relevant = false` का उपयोग करके या गैर-संवादात्मक स्थिति में रखकर), हालांकि वे दृश्यमान हो सकते हैं। रिकॉर्ड किया गया ऑडियो सबमिशन के साथ `audio-end` फ़ील्ड से जुड़ी फ़ाइल के रूप में संलग्न होता है।

जब प्रगणक `audio_s_a1` पर पहुँचता है तो ऐप रिकॉर्डिंग शुरू कर देता है और जब वे `audio_e_a1` पर पहुँचते हैं तो बंद कर देता है। दो मार्करों के बीच के सभी प्रश्न रिकॉर्ड किए जाते हैं।

## मूक रिकॉर्डिंग: `audio-start invisible`

डिफ़ॉल्ट रूप से, मोबाइल ऐप ऑडियो कैप्चर किए जाने के दौरान रिकॉर्डिंग संकेतक प्रदर्शित करता है। दिखावट में `invisible` जोड़ने से यह संकेतक दब जाता है, इसलिए रिकॉर्डिंग प्रतिवादी को बिना किसी दृश्य संकेत के होती है।

| type | name | label | appearance |
|------|------|-------|------------|
| text | audio_s_a1 | | `audio-start invisible` |
| text | q_consent | क्या आप भाग लेने के लिए सहमत हैं? | |
| text | q_feedback | आपकी प्रतिक्रिया | |
| text | audio_e_a1 | | `audio-end` |

`invisible` का उपयोग केवल तभी करें जब प्रकटीकरण आवश्यकताओं को अन्य माध्यमों (जैसे, रिकॉर्डिंग अनुभाग से पहले एक अलग लिखित सहमति फ़ील्ड) के माध्यम से संतुष्ट किया गया हो।

## नामकरण परंपरा

उत्पादन फ़ॉर्म मार्कर फ़ील्ड के लिए एक सुसंगत नामकरण पैटर्न का उपयोग करते हैं:

```
audio_s_{section}{n}   — प्रारंभ मार्कर
audio_e_{section}{n}   — अंत मार्कर
```

जहाँ `{section}` फ़ॉर्म अनुभाग के लिए एक छोटा लेबल है और `{n}` उस अनुभाग के भीतर एक अनुक्रमिक संख्या है।

| फ़ील्ड का नाम | भूमिका | अर्थ |
|------------|------|---------|
| `audio_s_a1` | प्रारंभ | अनुभाग A में पहली रिकॉर्डिंग |
| `audio_e_a1` | अंत | अनुभाग A में पहली रिकॉर्डिंग का अंत |
| `audio_s_b1` | प्रारंभ | अनुभाग B में पहली रिकॉर्डिंग |
| `audio_e_b1` | अंत | अनुभाग B में पहली रिकॉर्डिंग का अंत |
| `audio_s_a2` | प्रारंभ | अनुभाग A में दूसरी रिकॉर्डिंग |
| `audio_e_a2` | अंत | अनुभाग A में दूसरी रिकॉर्डिंग का अंत |

इस परंपरा का पालन करने से फ़ॉर्म परिभाषाओं और सबमिशन डेटा की समीक्षा करते समय रिकॉर्डिंग सीमाओं की पहचान करना आसान हो जाता् है।

---

## भंडारण और पुनर्प्राप्ति

जब प्रगणक `audio-end` फ़ील्ड पर पहुँचता है, तो ऐप ऑडियो फ़ाइल को अंतिम रूप देता है और इसे सबमिशन के साथ संलग्न करता है। फ़ाइल है:

- सबमिशन पर ऑडियो अटैचमेंट के रूप में संग्रहीत, जो `audio-end` फ़ील्ड नाम से जुड़ा है।
- अन्य मीडिया अटैचमेंट के साथ rtSurvey बैक-एंड सबमिशन व्यूअर में सुलभ।
- मानक सबमिशन निर्यात के माध्यम से डाउनलोड करने योग्य — ऑडियो फ़ाइलें `audio-end` फ़ील्ड नाम के अनुरूप मीडिया कॉलम में दिखाई देती हैं।

फ़ाइल स्वरूप और बिटरेट डिवाइस और ऐप संस्करण पर निर्भर करते हैं।

## एकाधिक रिकॉर्डिंग अनुभाग

एक फ़ॉर्म में कई गैर-अतिव्यापी रिकॉर्डिंग अनुभाग हो सकते हैं। `audio-start` / `audio-end` मार्करों की प्रत्येक जोड़ी पूरी तरह से निहित होनी चाहिए — अनुभागों को आपस में नहीं मिलना चाहिए।

| type | name | label | appearance |
|------|------|-------|------------|
| text | audio_s_a1 | | `audio-start` |
| text | q_intro | परिचय | |
| text | audio_e_a1 | | `audio-end` |
| note | section_break | — | |
| text | audio_s_b1 | | `audio-start invisible` |
| text | q_detail | विवरण | |
| text | audio_e_b1 | | `audio-end` |

प्रत्येक अनुभाग अपने संबंधित `audio-end` फ़ील्ड से जुड़ी एक अलग ऑडियो फ़ाइल तैयार करता है।

## सीमाएँ

- **केवल मोबाइल ऐप।** यह सुविधा वेब फ़ॉर्म में समर्थित नहीं है। ब्राउज़र में `audio-start` और `audio-end` को चुपचाप अनदेखा कर दिया जाता है।
- **कोई नेस्टिंग नहीं।** रिकॉर्डिंग अनुभाग ओवरलैप नहीं हो सकते। पिछला `audio-end` मार्कर पहुँचने से पहले नई रिकॉर्डिंग शुरू करना समर्थित नहीं है।
- **फ़ील्ड प्रकार `text` होना चाहिए।** किसी अन्य प्रश्न प्रकार पर `audio-start` या `audio-end` का उपयोग करना समर्थित नहीं है।
- **अपलोड आकार।** लंबी रिकॉर्डिंग बड़ी फ़ाइलें बनाती हैं। क्षेत्र में सबमिशन आकार सीमा और नेटवर्क स्थितियों के बारे में जागरूक रहें।
- **कोई मध्य-रिकॉर्डिंग विराम नहीं।** रिकॉर्डिंग प्रारंभ मार्कर से अंत मार्कर तक लगातार चलती है; एक अनुभाग के भीतर रुकने और फिर से शुरू करने का कोई तंत्र नहीं है।
