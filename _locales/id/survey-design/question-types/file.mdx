Tipe pertanyaan `file` memungkinkan responden untuk **mengunggah berkas apa pun** dari perangkat mereka — dokumen, lembar kerja, PDF, atau tipe berkas lainnya. Berbeda dengan `image`, `audio`, dan `video` yang meluncurkan alat penangkap khusus, `file` membuka pemilih berkas tujuan umum.

## Spesifikasi Dasar XLSForm

| type | name      | label                        |
|------|-----------|------------------------------|
| file | document  | Silakan unggah dokumen Anda |

Untuk detail lebih lanjut tentang tipe pertanyaan berkas standar, lihat [spesifikasi XLSForm](https://xlsform.org/en/#question-types).

## Kegunaan

Pertanyaan berkas biasanya digunakan untuk:

1. Mengumpulkan dokumen pendukung (kuitansi, sertifikat, kontrak, laporan)
2. Mengunggah formulir kertas yang telah diisi dan dipindai
3. Mengumpulkan lembar kerja atau ekspor data dari sistem lain
4. Tipe berkas digital apa pun yang tidak dicakup oleh gambar/audio/video

## Format data

Berkas yang diunggah disimpan sebagai lampiran biner:

- **Format:** Dipertahankan dalam format asli (PDF, XLSX, DOCX, dll.)
- **Penamaan:** `{instanceID}-{fieldname}.{extension}`
- **Penyimpanan:** Diunggah ke folder media server bersama dengan pengiriman
- **Akses:** Dapat diunduh dari antarmuka manajemen pengiriman

## ekstensi rtSurvey

### Tipe berkas yang diterima

Gunakan kolom `parameters` untuk membatasi tipe berkas mana yang dapat dipilih:

| type | name | label | parameters |
|------|------|-------|------------|
| file | report | Unggah laporan inspeksi | `accept=.pdf` |
| file | spreadsheet | Unggah berkas data | `accept=.xlsx,.csv` |

Parameter `accept` menggunakan sintaks ekstensi berkas standar (dipisahkan koma).

### Panduan ukuran berkas

rtSurvey tidak memberlakukan batas ukuran berkas yang ketat di tingkat pertanyaan, tetapi batas unggahan server berlaku. Gunakan `hint` untuk mengomunikasikan harapan kepada enumerator:

| type | name | label | hint |
|------|------|-------|------|
| file | receipt | Unggah kuitansi pembayaran | Diterima: PDF atau gambar. Ukuran berkas maksimal: 5 MB |

### Integrasi dengan sistem berkas perangkat dan penyimpanan cloud

Pada Android dan iOS, pertanyaan `file` membuka pemilih berkas bawaan perangkat, yang mungkin mencakup akses ke:
- Penyimpanan perangkat lokal
- Kartu SD (Android)
- iCloud Drive (iOS)
- Google Drive, Dropbox (jika terpasang)

Pada web, ini membuka dialog unggah berkas standar browser.

### Tata letak tombol inline (Inline button layout)

Tambahkan `inline` untuk merender unggahan sebagai **tombol ikon melingkar** di samping label, bukan pemilih berkas lebar penuh.

```
| type | name | label           | appearance                              |
|------|------|-----------------|-----------------------------------------|
| file | doc  | Unggah dokumen | inline display{right}                   |
| file | doc  | Unggah dokumen | inline display{left, large}             |
| file | doc  | Unggah dokumen | inline display{center, large, <0099FF/>} |
```

**Posisi tombol** — `left`, `right` *(default)*, `top`, `center`, `bottom`

**Ukuran tombol** — `small` *(default)*, `medium`, `large`

**Warna tombol** — tambahkan warna hex di dalam `display{}` untuk mengganti warna utama:

```
inline display{right, large, <FF5500/>}
```

**Kontrol pasca-penangkapan — `results{}`:**

| Appearance | Effect |
|---|---|
| `results{hide(capture)}` | Menyembunyikan tombol unggah setelah berkas dilampirkan |
| `results{hide(review)}` | Menyembunyikan tombol tinjau/pratinjau setelah unggahan |
| `results{hide(filename)}` | Menyembunyikan nama berkas yang ditampilkan setelah unggahan |
| `results{left}` | Memindahkan ikon ke kiri setelah unggahan |

Contoh — sembunyikan tombol unggah setelah berkas dilampirkan:
```
inline display{right} results{hide(capture)}
```

### Menghilangkan label (Suppress the label)

```
inline text-nolabel display{center, large}
```

## Praktik Terbaik

1. Gunakan `accept` untuk membatasi tipe berkas — ini mencegah enumerator mengunggah berkas yang salah secara tidak sengaja.
2. Selalu sertakan panduan ukuran dan format di kolom `hint`.
3. Untuk foto dan gambar, gunakan tipe `image` saja — tipe ini menawarkan kompresi yang lebih baik dan penanganan format yang konsisten.
4. Untuk survei besar dengan lampiran berkas, rencanakan penyimpanan data dan bandwidth unduhan Anda sesuai dengan kebutuhan tersebut.
5. Uji pemilih berkas pada tipe perangkat target (Android vs. iOS vs. web) sebelum penyebaran — akses ke drive cloud bervariasi.

## Pertimbangan penanganan data

- Berkas disimpan dalam format aslinya; berkas tidak dikonversi atau dikompresi oleh rtSurvey.
- Analisis berkas setelah diunduh — rtSurvey tidak mengekstrak atau mengindeks konten berkas.
- Lampiran berkas yang besar secara signifikan meningkatkan waktu yang diperlukan untuk mengunduh kumpulan data lengkap.

## Keterbatasan (Limitations)

- Pertanyaan berkas tidak memvalidasi konten berkas — hanya pemeriksaan ekstensi berkas melalui `accept` yang diberlakukan di tingkat UI.
- Berkas yang sangat besar (100 MB+) mungkin mengalami waktu habis saat mengunggah di lingkungan dengan konektivitas rendah.
- Enumerator luring dapat melampirkan berkas, tetapi berkas tersebut tidak akan diunggah hingga konektivitas pulih.
- Beberapa konfigurasi perangkat membatasi akses ke lokasi penyimpanan tertentu (misalnya, kebijakan MDM perusahaan).
