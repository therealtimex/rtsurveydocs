Tipe pertanyaan `file` memungkinkan responden untuk **mengunggah file apa pun** dari perangkat mereka — dokumen, spreadsheet, PDF, atau tipe file lainnya. Tidak seperti `image`, `audio`, dan `video` yang meluncurkan alat pengambilan spesifik, `file` membuka pemilih file serbaguna.

## Spesifikasi Dasar XLSForm

| type | name      | label                         |
|------|-----------|-------------------------------|
| file | document  | Mohon unggah dokumen Anda     |

Untuk detail lebih lanjut tentang tipe pertanyaan file standar, lihat [spesifikasi XLSForm](https://xlsform.org/en/#question-types).

## Penggunaan

Pertanyaan file umumnya digunakan untuk:

1.  Mengumpulkan dokumen pendukung (struk, sertifikat, kontrak, laporan)
2.  Mengunggah formulir kertas yang telah diisi dan dipindai
3.  Mengumpulkan spreadsheet atau ekspor data dari sistem lain
4.  Semua jenis file digital yang tidak tercakup oleh gambar/audio/video

## Format data

File yang diunggah disimpan sebagai lampiran biner:

-   **Format:** Dipertahankan dalam format asli (PDF, XLSX, DOCX, dll.)
-   **Penamaan:** `{instanceID}-{fieldname}.{extension}`
-   **Penyimpanan:** Diunggah ke folder media server bersama dengan pengiriman
-   **Akses:** Dapat diunduh dari antarmuka manajemen pengiriman

## Ekstensi rtSurvey

### Jenis file yang diterima

Gunakan kolom `parameters` untuk membatasi jenis file yang dapat dipilih:

| type | name        | label                           | parameters            |
|------|-------------|---------------------------------|-----------------------|
| file | report      | Unggah laporan inspeksi         | `accept=.pdf`         |
| file | spreadsheet | Unggah file data              | `accept=.xlsx,.csv` |

Parameter `accept` menggunakan sintaks ekstensi file standar (dipisahkan koma).

### Panduan ukuran file

rtSurvey tidak menerapkan batasan ukuran file yang ketat pada tingkat pertanyaan, tetapi batasan unggah server berlaku. Gunakan `hint` untuk mengkomunikasikan ekspektasi kepada enumerator:

| type | name | label                      | hint                                             |
|------|------|----------------------------|--------------------------------------------------|
| file | receipt | Unggah tanda terima pembayaran | Diterima: PDF atau gambar. Ukuran file maksimum: 5 MB |

### Integrasi dengan sistem file perangkat dan penyimpanan cloud

Di Android dan iOS, pertanyaan `file` membuka pemilih file native perangkat, yang mungkin menyertakan akses ke:
-   Penyimpanan perangkat lokal
-   Kartu SD (Android)
-   iCloud Drive (iOS)
-   Google Drive, Dropbox (jika terinstal)

Di web, ini membuka dialog unggah file standar browser.

### Tata letak tombol inline

Tambahkan `inline` untuk merender unggahan sebagai **tombol ikon melingkar** di sebelah label, bukan pemilih file selebar penuh.

```
| type | name | label           | appearance                              |
|------|------|-----------------|-----------------------------------------|
| file | doc  | Unggah dokumen  | inline display{right}                   |
| file | doc  | Unggah dokumen  | inline display{left, large}             |
| file | doc  | Unggah dokumen  | inline display{center, large, <0099FF/>} |
```

**Posisi tombol** — `left`, `right` *(default)*, `top`, `center`, `bottom`

**Ukuran tombol** — `small` *(default)*, `medium`, `large`

**Warna tombol** — tambahkan warna hex di dalam `display{}` untuk menimpa warna primer:

```
inline display{right, large, <FF5500/>}
```

**Kontrol pasca-rekaman — `results{}`:**

| Appearance | Efek                                     |
|------------|------------------------------------------|
| `results{hide(capture)}` | Menyembunyikan tombol unggah setelah file dilampirkan |
| `results{hide(review)}` | Menyembunyikan tombol tinjau/pratinjau setelah unggah |
| `results{hide(filename)}` | Menyembunyikan nama file yang ditampilkan setelah unggah |
| `results{left}` | Memindahkan ikon ke kiri setelah unggah |

Contoh — sembunyikan tombol unggah setelah file dilampirkan:
```
inline display{right} results{hide(capture)}
```

### Menekan label

```
inline text-nolabel display{center, large}
```

## Contoh penggunaan

### Unggah PDF yang diperlukan

| type | name | label                        | hint                    | required | required_message            |
|------|------|------------------------------|-------------------------|----------|-----------------------------|
| file | signed_consent | Unggah formulir persetujuan yang ditandatangani | Hanya PDF, maksimal 2MB | yes      | Formulir persetujuan diperlukan |

### Unggah dokumen kondisional

| type           | name          | label                                | relevant                  |
|----------------|---------------|--------------------------------------|---------------------------|
| select_one yesno | has_land_title | Apakah rumah tangga memiliki sertifikat tanah? |                           |
| file           | land_title_doc | Unggah foto atau scan sertifikat tanah       | `${has_land_title} = 'yes'` |

## Praktik Terbaik

1.  Gunakan `accept` untuk membatasi jenis file — ini mencegah enumerator secara tidak sengaja mengunggah file yang salah.
2.  Selalu sertakan panduan ukuran dan format di kolom `hint`.
3.  Untuk foto dan gambar, gunakan tipe `image` sebagai gantinya — ini menawarkan kompresi yang lebih baik dan penanganan format yang konsisten.
4.  Untuk survei besar dengan lampiran file, rencanakan penyimpanan data dan bandwidth unduhan Anda dengan tepat.
5.  Uji pemilih file pada tipe perangkat target (Android vs. iOS vs. web) sebelum deployment — akses ke drive cloud bervariasi.

## Pertimbangan penanganan data

-   File disimpan dalam format aslinya; file tidak dikonversi atau dikompresi oleh rtSurvey.
-   Analisis file setelah diunduh — rtSurvey tidak mengekstrak atau mengindeks konten file.
-   Lampiran file yang besar secara signifikan meningkatkan waktu yang diperlukan untuk mengunduh set data lengkap.

## Keterbatasan

-   Pertanyaan file tidak memvalidasi konten file — hanya pemeriksaan ekstensi file melalui `accept` yang diberlakukan pada tingkat UI.
-   File yang sangat besar (100 MB+) dapat mengalami batas waktu unggah di lingkungan dengan konektivitas rendah.
-   Enumerator offline dapat melampirkan file tetapi tidak akan mengunggah hingga konektivitas dipulihkan.
-   Beberapa konfigurasi perangkat membatasi akses ke lokasi penyimpanan tertentu (misalnya, kebijakan MDM perusahaan).
