import { Callout, Steps } from 'nextra/components'

公開 Docker イメージ `rtawebteam/rtcloud:survey-public` を使用して、独自のサーバー（VPS、ベアメタル、またはローカルマシン）で rtSurvey を実行したい場合はこのガイドをご使用ください。

**Docker Hub ログイン不要** — イメージは公開されています。

コンテナは単一のイメージにすべてをバンドルしています：
- Apache + PHP（アプリケーションサーバー）
- Shiny Server（分析ダッシュボード、ポート 3838）
- Beanstalkd（バックグラウンドジョブキュー）

---

## 要件

### サーバー

| リソース | 最小 | 推奨 |
|----------|---------|-------------|
| RAM | 4 GB | 8 GB |
| ディスク | 50 GB | 100 GB SSD |
| CPU | 2 vCPU | 4 vCPU |
| OS | Ubuntu 22.04 LTS | Ubuntu 22.04 LTS |

### ソフトウェア

- **Docker Engine 24.0+** — [インストールガイド](https://docs.docker.com/engine/install/ubuntu/)
- **Docker Compose v2.0+** — Docker Desktop に含まれています。Linux の場合：`apt install docker-compose-plugin`

## セットアップ

<Steps>

### 作業ディレクトリの作成

```bash
mkdir -p /opt/rtsurvey && cd /opt/rtsurvey
```

### `docker-compose.yml` の作成

```yaml
services:
  mysql:
    image: mysql:8.0
    container_name: rtsurvey-mysql
    restart: unless-stopped
    command: >
      --default-authentication-plugin=mysql_native_password
      --character-set-server=utf8
      --collation-server=utf8_unicode_ci
      --sql-mode=NO_ENGINE_SUBSTITUTION
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: ${MYSQL_DATABASE:-smartsurvey}
      MYSQL_USER: ${MYSQL_USER:-smartsurvey}
      MYSQL_PASSWORD: ${MYSQL_PASSWORD}
      MYSQL_ROOT_HOST: '%'
    volumes:
      - mysql_data:/var/lib/mysql
    networks:
      - rtsurvey-net
    healthcheck:
      test: ["CMD-SHELL", "mysqladmin ping -h localhost -u root -p$$MYSQL_ROOT_PASSWORD"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 30s

  rtsurvey:
    image: rtawebteam/rtcloud:survey-public
    container_name: rtsurvey-app
    restart: unless-stopped
    entrypoint: ["/bin/entrypoint-production.sh"]
    depends_on:
      mysql:
        condition: service_healthy
    ports:
      - "${APP_PORT:-8080}:80"
      - "${SHINY_PORT:-3838}:3838"
    env_file:
      - .env
    volumes:
      - app_uploads:/var/www/html/smartsurvey/uploads
      - app_audios:/var/www/html/smartsurvey/audios
      - app_downloads:/var/www/html/smartsurvey/downloads
      - app_gallery:/var/www/html/smartsurvey/gallery
      - app_tmp:/var/www/html/smartsurvey/tmp
      - app_cache:/var/www/html/smartsurvey/cache
      - app_runtime:/var/www/html/smartsurvey/protected/runtime
      - app_assets:/var/www/html/smartsurvey/assets
      - app_aggregate:/var/www/html/smartsurvey/aggregate
    networks:
      - rtsurvey-net
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 90s

  # オプション：組み込み Keycloak SSO
  # 起動方法：docker compose --profile embed-keycloak up -d
  keycloak:
    image: quay.io/keycloak/keycloak:latest
    container_name: rtsurvey-keycloak
    restart: unless-stopped
    profiles:
      - embed-keycloak
    command: start --import-realm
    environment:
      KEYCLOAK_ADMIN: ${KEYCLOAK_ADMIN_USER:-admin}
      KEYCLOAK_ADMIN_PASSWORD: ${KEYCLOAK_ADMIN_PASSWORD}
      KC_HTTP_ENABLED: "true"
      KC_HTTP_RELATIVE_PATH: /auth
      KC_PROXY_HEADERS: xforwarded
      KC_HOSTNAME: ${KC_HOSTNAME}
      KC_HOSTNAME_STRICT: "false"
      KC_DB: mysql
      KC_DB_URL_DATABASE: ${KEYCLOAK_DB:-keycloak}
      KC_DB_URL_HOST: mysql
      KC_DB_USERNAME: ${KEYCLOAK_DB_USER:-keycloak}
      KC_DB_PASSWORD: ${KEYCLOAK_DB_PASSWORD}
    volumes:
      - ./keycloak-import:/opt/keycloak/data/import
    ports:
      - "${KEYCLOAK_PORT:-8091}:8080"
    depends_on:
      mysql:
        condition: service_healthy
    networks:
      - rtsurvey-net
    healthcheck:
      test: ["CMD-SHELL", "curl -f http://localhost:9000/health/ready || exit 1"]
      interval: 30s
      timeout: 10s
      retries: 10
      start_period: 120s

volumes:
  mysql_data:
  app_uploads:
  app_audios:
  app_downloads:
  app_gallery:
  app_tmp:
  app_cache:
  app_runtime:
  app_assets:
  app_aggregate:

networks:
  rtsurvey-net:
    driver: bridge
```

### `.env` の作成

```bash
# Project
PROJECT_ID=mysurvey
PROJECT_TYPE=rtsurvey
PROJECT_URL=your-server-ip-or-domain
HTTP_PROTOCOL=http
TZ=UTC

# Database
MYSQL_HOST=mysql
MYSQL_DATABASE=smartsurvey
MYSQL_USER=smartsurvey
MYSQL_ROOT_PASSWORD=change-this-root-password
MYSQL_PASSWORD=change-this-app-password

# Admin (set before first startup — cannot change via env after DB is created)
ADMIN_PASSWORD=change-this-admin-password

# Runtime
RUN_ENV=prod
RUN_MODE=admin
GII_ENABLED=false
CSRF_VALIDATION_ENABLED=true

# Ports (optional — defaults shown)
APP_PORT=8080
SHINY_PORT=3838
```

<Callout type="warning">
起動前に `MYSQL_ROOT_PASSWORD` と `MYSQL_PASSWORD` を変更してください。本番環境では強力なランダム文字列（32文字以上）を使用してください。
</Callout>

### スタックの起動

```bash
docker compose up -d
```

最初の起動には約 60〜90 秒かかります — MySQL が初回実行時にデータベースを初期化します。

### 確認

```bash
# すべてのコンテナが実行中か確認
docker compose ps

# アプリケーションのヘルスを確認
curl http://localhost:8080/health
```

</Steps>

## 初回ログイン

ヘルスチェックが通過したら、ブラウザを開いてください：

```
http://your-server:8080/cpms/cpmsSite/login
```

| フィールド | 値 |
|-------|-------|
| ユーザー名 | `admin` |
| パスワード | `.env` の `ADMIN_PASSWORD` の値（デフォルト：`admin`） |

<Callout type="warning">
初回起動前に `.env` で `ADMIN_PASSWORD` を設定してください。エントリポイントは初回実行時に設定します — データベース初期化後に変更しても効果はありません。
</Callout>

## 環境変数

### アプリコンテナが必要とする変数

これらが不足している場合、エントリポイントは起動を拒否します：

| 変数 | 説明 |
|----------|-------------|
| `PROJECT_ID` | このインスタンスの一意の識別子（英数字、スペースなし） |
| `PROJECT_URL` | アプリにアクセスするドメインまたは IP（`http://` プレフィックスなし） |
| `MYSQL_HOST` | MySQL ホスト名 — Docker サービス名を使用（例：`mysql`） |
| `MYSQL_DATABASE` | データベース名 |
| `MYSQL_PASSWORD` | データベースユーザーのパスワード |

### MySQL コンテナが必要とする変数

| 変数 | 説明 |
|----------|-------------|
| `MYSQL_ROOT_PASSWORD` | MySQL root パスワード（`mysql` コンテナが使用、アプリではない） |

### 推奨変数

| 変数 | デフォルト | 説明 |
|----------|---------|-------------|
| `MYSQL_USER` | `smartsurvey` | データベースユーザー名 |
| `ADMIN_PASSWORD` | `admin` | 初期管理者パスワード — **初回起動前に設定**、DB 作成後は env で変更不可 |
| `HTTP_PROTOCOL` | `https` | SSL を使用しない場合は `http` に設定 |
| `PROJECT_PORT` | `80` | ユーザーが接続する外部ポート（内部 Docker ポートではない） |
| `PROJECT_TYPE` | `rtwork` | プラットフォームの種類 — アンケートプラットフォームには `rtsurvey` を使用 |
| `TZ` | `UTC` | タイムゾーン（例：`Asia/Bangkok`、`America/New_York`） |

### ランタイム

| 変数 | デフォルト | 説明 |
|----------|---------|-------------|
| `RUN_ENV` | `prod` | 環境モード（`prod` または `dev`） |
| `RUN_MODE` | `admin` | サービスの役割 — シングルサーバー設定には `admin` を使用 |
| `GII_ENABLED` | `false` | 本番環境では `false` を維持（Yii コードジェネレーター） |
| `CSRF_VALIDATION_ENABLED` | `true` | CSRF 保護 — `true` を維持 |

### ライセンス

| 変数 | デフォルト | 説明 |
|----------|---------|-------------|
| `REQUIRE_LICENSE` | `false` | ライセンス検証を強制する場合は `true` に設定 |
| `RTCLOUD_LICENSE_KEY` | — | ライセンスキー — `REQUIRE_LICENSE=true` の場合に必要 |

## データの永続化

すべてのユーザーデータは名前付き Docker ボリュームに保存されます。これらはコンテナの再起動やイメージの更新後も保持されます。

| ボリューム | 内容 |
|--------|----------|
| `mysql_data` | データベース（アンケート、ユーザー、回答） |
| `app_uploads` | アンケートからのファイルアップロード |
| `app_gallery` | メディアライブラリ |
| `app_downloads` | 生成されたエクスポートファイル |
| `app_audios` | 音声録音 |
| `app_runtime` | PHP セッションとキャッシュファイル |
| `app_aggregate` | 集計された分析データ |

## 一般的な操作

### ログの表示

```bash
docker compose logs -f rtsurvey
docker compose logs -f mysql
```

### アプリの再起動

```bash
docker compose restart rtsurvey
```

### シェルへのアクセス

```bash
docker compose exec rtsurvey bash
```

### データベースマイグレーションの手動実行

```bash
docker compose exec rtsurvey php /var/www/html/smartsurvey/protected/yiic migrate
```

## アップグレード

イメージには `survey-public` タグが付いています。最新バージョンに更新するには：

```bash
docker compose pull
docker compose up -d
```

データベースのマイグレーションは、本番エントリポイントを通じて起動時に自動的に実行されます。

## バックアップと復元

### データベースのバックアップ

```bash
docker compose exec mysql \
  mysqldump -u root -p"${MYSQL_ROOT_PASSWORD}" smartsurvey \
  > backup-$(date +%Y%m%d).sql
```

### データベースの復元

```bash
docker compose exec -T mysql \
  mysql -u root -p"${MYSQL_ROOT_PASSWORD}" smartsurvey \
  < backup-20240101.sql
```

### アップロードファイルのバックアップ

```bash
docker run --rm \
  -v rtsurvey_app_uploads:/data \
  -v $(pwd):/backup \
  alpine tar czf /backup/uploads-$(date +%Y%m%d).tar.gz -C /data .
```

## 組み込み Keycloak（オプション SSO）

本番の compose ファイルには、SSO 用のオプション Keycloak コンテナが含まれています。同じ MySQL インスタンスを共有し、Docker Compose プロファイルで有効化されます。

<Callout type="info">
組み込み Keycloak には少なくとも **4 GB の RAM** が必要です。SSO が不要な場合はスキップしてください。
</Callout>

### `.env` に Keycloak 変数を追加する

```bash
# Keycloak admin
KEYCLOAK_ADMIN_USER=admin
KEYCLOAK_ADMIN_PASSWORD=change-this-keycloak-password

# Keycloak database (created automatically in the shared MySQL on first run)
KEYCLOAK_DB=keycloak
KEYCLOAK_DB_USER=keycloak
KEYCLOAK_DB_PASSWORD=change-this-keycloak-db-password

# KC_HOSTNAME: full public URL of your server (Keycloak appends /auth automatically)
KC_HOSTNAME=http://your-server:8091

# Port Keycloak listens on (host)
KEYCLOAK_PORT=8091

# Tell the rtCloud app to connect to embedded Keycloak
EMBED_KEYCLOAK=true
KEYCLOAK_URL=http://your-server:8091
KEYCLOAK_REALM=rtsurvey
KEYCLOAK_CLIENT_ID=rtsurvey
KEYCLOAK_CLIENT_SECRET=your-client-secret
```

`keycloak` サービスは上記の `docker-compose.yml` にすでに含まれています（`embed-keycloak` プロファイル下 — `--profile embed-keycloak` を使用しない限り起動しません）。

インポートディレクトリを作成します（Keycloak はなくても起動しますが、レルムの自動プロビジョニングは機能しません）：

```bash
mkdir -p /opt/rtsurvey/keycloak-import
```

### Keycloak で起動する

```bash
docker compose --profile embed-keycloak up -d
```

Keycloak なしで起動する場合（デフォルト）：

```bash
docker compose up -d
```

### Keycloak 管理コンソール

正常に起動したら、Keycloak 管理 UI にアクセスします：

```
http://your-server:8091/auth/admin
```

`KEYCLOAK_ADMIN_USER` / `KEYCLOAK_ADMIN_PASSWORD` でログインしてください。
