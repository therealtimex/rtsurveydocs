import { Callout, Steps } from 'nextra/components'

Skorzystaj z tego przewodnika, jeśli chcesz uruchomić rtSurvey na własnym serwerze (VPS, bare metal lub maszyna lokalna) przy użyciu publicznego obrazu Docker `rtawebteam/rtcloud:survey-public`.

**Logowanie do Docker Hub nie jest wymagane** — obraz jest publiczny.

Kontener zawiera wszystko w jednym obrazie:
- Apache + PHP (serwer aplikacji)
- Shiny Server (dashboardy analityczne, port 3838)
- Beanstalkd (kolejka zadań w tle)

---

## Wymagania

### Serwer

| Zasób | Minimum | Zalecane |
|-------|---------|---------|
| RAM | 4 GB | 8 GB |
| Dysk | 50 GB | 100 GB SSD |
| CPU | 2 vCPU | 4 vCPU |
| System operacyjny | Ubuntu 22.04 LTS | Ubuntu 22.04 LTS |

### Oprogramowanie

- **Docker Engine 24.0+** — [przewodnik instalacji](https://docs.docker.com/engine/install/ubuntu/)
- **Docker Compose v2.0+** — dołączony do Docker Desktop; na Linux: `apt install docker-compose-plugin`

## Konfiguracja

<Steps>

### Utwórz katalog roboczy

```bash
mkdir -p /opt/rtsurvey && cd /opt/rtsurvey
```

### Utwórz plik `docker-compose.yml`

```yaml
services:
  mysql:
    image: mysql:8.0
    container_name: rtsurvey-mysql
    restart: unless-stopped
    command: >
      --default-authentication-plugin=mysql_native_password
      --character-set-server=utf8
      --collation-server=utf8_unicode_ci
      --sql-mode=NO_ENGINE_SUBSTITUTION
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: ${MYSQL_DATABASE:-smartsurvey}
      MYSQL_USER: ${MYSQL_USER:-smartsurvey}
      MYSQL_PASSWORD: ${MYSQL_PASSWORD}
      MYSQL_ROOT_HOST: '%'
    volumes:
      - mysql_data:/var/lib/mysql
    networks:
      - rtsurvey-net
    healthcheck:
      test: ["CMD-SHELL", "mysqladmin ping -h localhost -u root -p$$MYSQL_ROOT_PASSWORD"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 30s

  rtsurvey:
    image: rtawebteam/rtcloud:survey-public
    container_name: rtsurvey-app
    restart: unless-stopped
    entrypoint: ["/bin/entrypoint-production.sh"]
    depends_on:
      mysql:
        condition: service_healthy
    ports:
      - "${APP_PORT:-8080}:80"
      - "${SHINY_PORT:-3838}:3838"
    env_file:
      - .env
    volumes:
      - app_uploads:/var/www/html/smartsurvey/uploads
      - app_audios:/var/www/html/smartsurvey/audios
      - app_downloads:/var/www/html/smartsurvey/downloads
      - app_gallery:/var/www/html/smartsurvey/gallery
      - app_tmp:/var/www/html/smartsurvey/tmp
      - app_cache:/var/www/html/smartsurvey/cache
      - app_runtime:/var/www/html/smartsurvey/protected/runtime
      - app_assets:/var/www/html/smartsurvey/assets
      - app_aggregate:/var/www/html/smartsurvey/aggregate
    networks:
      - rtsurvey-net
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 90s

  # Optional: Embedded Keycloak SSO
  # Start with: docker compose --profile embed-keycloak up -d
  keycloak:
    image: quay.io/keycloak/keycloak:latest
    container_name: rtsurvey-keycloak
    restart: unless-stopped
    profiles:
      - embed-keycloak
    command: start --import-realm
    environment:
      KEYCLOAK_ADMIN: ${KEYCLOAK_ADMIN_USER:-admin}
      KEYCLOAK_ADMIN_PASSWORD: ${KEYCLOAK_ADMIN_PASSWORD}
      KC_HTTP_ENABLED: "true"
      KC_HTTP_RELATIVE_PATH: /auth
      KC_PROXY_HEADERS: xforwarded
      KC_HOSTNAME: ${KC_HOSTNAME}
      KC_HOSTNAME_STRICT: "false"
      KC_DB: mysql
      KC_DB_URL_DATABASE: ${KEYCLOAK_DB:-keycloak}
      KC_DB_URL_HOST: mysql
      KC_DB_USERNAME: ${KEYCLOAK_DB_USER:-keycloak}
      KC_DB_PASSWORD: ${KEYCLOAK_DB_PASSWORD}
    volumes:
      - ./keycloak-import:/opt/keycloak/data/import
    ports:
      - "${KEYCLOAK_PORT:-8091}:8080"
    depends_on:
      mysql:
        condition: service_healthy
    networks:
      - rtsurvey-net
    healthcheck:
      test: ["CMD-SHELL", "curl -f http://localhost:9000/health/ready || exit 1"]
      interval: 30s
      timeout: 10s
      retries: 10
      start_period: 120s

volumes:
  mysql_data:
  app_uploads:
  app_audios:
  app_downloads:
  app_gallery:
  app_tmp:
  app_cache:
  app_runtime:
  app_assets:
  app_aggregate:

networks:
  rtsurvey-net:
    driver: bridge
```

### Utwórz plik `.env`

```bash
# Project
PROJECT_ID=mysurvey
PROJECT_TYPE=rtsurvey
PROJECT_URL=your-server-ip-or-domain
HTTP_PROTOCOL=http
TZ=UTC

# Database
MYSQL_HOST=mysql
MYSQL_DATABASE=smartsurvey
MYSQL_USER=smartsurvey
MYSQL_ROOT_PASSWORD=change-this-root-password
MYSQL_PASSWORD=change-this-app-password

# Admin (set before first startup — cannot change via env after DB is created)
ADMIN_PASSWORD=change-this-admin-password

# Runtime
RUN_ENV=prod
RUN_MODE=admin
GII_ENABLED=false
CSRF_VALIDATION_ENABLED=true

# Ports (optional — defaults shown)
APP_PORT=8080
SHINY_PORT=3838
```

<Callout type="warning">
Zmień `MYSQL_ROOT_PASSWORD` i `MYSQL_PASSWORD` przed uruchomieniem. Używaj mocnych losowych ciągów znaków (32+ znaki) w środowisku produkcyjnym.
</Callout>

### Uruchom stack

```bash
docker compose up -d
```

Pierwsze uruchomienie zajmuje około 60–90 sekund — MySQL inicjalizuje bazę danych przy pierwszym starcie.

### Weryfikacja

```bash
# Check all containers are running
docker compose ps

# Check application health
curl http://localhost:8080/health
```

</Steps>

## Pierwsze logowanie

Po pomyślnym przejściu kontroli zdrowia otwórz przeglądarkę:

```
http://your-server:8080/cpms/cpmsSite/login
```

| Pole | Wartość |
|------|---------|
| Nazwa użytkownika | `admin` |
| Hasło | wartość `ADMIN_PASSWORD` z pliku `.env` (domyślnie `admin`) |

<Callout type="warning">
Ustaw `ADMIN_PASSWORD` w pliku `.env` przed pierwszym uruchomieniem. Punkt wejścia ustawia je przy pierwszym uruchomieniu — zmiana po inicjalizacji bazy danych nie ma żadnego efektu.
</Callout>

## Zmienne środowiskowe

### Wymagane przez kontener aplikacji

Punkt wejścia odmówi uruchomienia, jeśli którakolwiek z nich brakuje:

| Zmienna | Opis |
|---------|------|
| `PROJECT_ID` | Unikalny identyfikator tej instancji (alfanumeryczny, bez spacji) |
| `PROJECT_URL` | Domena lub IP, pod którym dostępna jest aplikacja (bez przedrostka `http://`) |
| `MYSQL_HOST` | Nazwa hosta MySQL — użyj nazwy usługi Docker (np. `mysql`) |
| `MYSQL_DATABASE` | Nazwa bazy danych |
| `MYSQL_PASSWORD` | Hasło użytkownika bazy danych |

### Wymagane przez kontener MySQL

| Zmienna | Opis |
|---------|------|
| `MYSQL_ROOT_PASSWORD` | Hasło roota MySQL (używane przez kontener `mysql`, nie przez aplikację) |

### Zalecane

| Zmienna | Domyślnie | Opis |
|---------|-----------|------|
| `MYSQL_USER` | `smartsurvey` | Nazwa użytkownika bazy danych |
| `ADMIN_PASSWORD` | `admin` | Początkowe hasło administratora — **ustaw przed pierwszym uruchomieniem**, nie można zmienić przez env po utworzeniu bazy danych |
| `HTTP_PROTOCOL` | `https` | Ustaw na `http`, jeśli nie używasz SSL |
| `PROJECT_PORT` | `80` | Zewnętrzny port, z którym łączą się użytkownicy (nie wewnętrzny port Docker) |
| `PROJECT_TYPE` | `rtwork` | Typ platformy — użyj `rtsurvey` dla platformy ankiet |
| `TZ` | `UTC` | Strefa czasowa (np. `Asia/Bangkok`, `America/New_York`) |

### Środowisko wykonawcze

| Zmienna | Domyślnie | Opis |
|---------|-----------|------|
| `RUN_ENV` | `prod` | Tryb środowiska (`prod` lub `dev`) |
| `RUN_MODE` | `admin` | Rola usługi — użyj `admin` dla konfiguracji jednoserwisowej |
| `GII_ENABLED` | `false` | Ustaw na `false` w produkcji (generator kodu Yii) |
| `CSRF_VALIDATION_ENABLED` | `true` | Ochrona CSRF — pozostaw `true` |

### Licencja

| Zmienna | Domyślnie | Opis |
|---------|-----------|------|
| `REQUIRE_LICENSE` | `false` | Ustaw na `true`, aby wymusić weryfikację licencji |
| `RTCLOUD_LICENSE_KEY` | — | Twój klucz licencyjny — wymagany gdy `REQUIRE_LICENSE=true` |

## Trwałość danych

Wszystkie dane użytkowników są przechowywane w nazwanych wolumenach Docker. Przeżywają restarty kontenerów i aktualizacje obrazów.

| Wolumen | Zawartość |
|---------|-----------|
| `mysql_data` | Baza danych (ankiety, użytkownicy, odpowiedzi) |
| `app_uploads` | Przesłane pliki z ankiet |
| `app_gallery` | Biblioteka multimediów |
| `app_downloads` | Wygenerowane pliki eksportu |
| `app_audios` | Nagrania audio |
| `app_runtime` | Sesja PHP i pliki cache |
| `app_aggregate` | Zagregowane dane analityczne |

## Typowe operacje

### Przeglądanie logów

```bash
docker compose logs -f rtsurvey
docker compose logs -f mysql
```

### Restart aplikacji

```bash
docker compose restart rtsurvey
```

### Dostęp do powłoki

```bash
docker compose exec rtsurvey bash
```

### Ręczne uruchamianie migracji bazy danych

```bash
docker compose exec rtsurvey php /var/www/html/smartsurvey/protected/yiic migrate
```

## Aktualizacje

Obraz jest oznaczony tagiem `survey-public`. Aby zaktualizować do najnowszej wersji:

```bash
docker compose pull
docker compose up -d
```

Migracje bazy danych uruchamiają się automatycznie przy starcie przez produkcyjny punkt wejścia.

## Kopia zapasowa i przywracanie

### Kopia zapasowa bazy danych

```bash
docker compose exec mysql \
  mysqldump -u root -p"${MYSQL_ROOT_PASSWORD}" smartsurvey \
  > backup-$(date +%Y%m%d).sql
```

### Przywracanie bazy danych

```bash
docker compose exec -T mysql \
  mysql -u root -p"${MYSQL_ROOT_PASSWORD}" smartsurvey \
  < backup-20240101.sql
```

### Kopia zapasowa przesłanych plików

```bash
docker run --rm \
  -v rtsurvey_app_uploads:/data \
  -v $(pwd):/backup \
  alpine tar czf /backup/uploads-$(date +%Y%m%d).tar.gz -C /data .
```

## Wbudowany Keycloak (opcjonalne SSO)

Produkcyjny plik compose zawiera opcjonalny kontener Keycloak dla SSO. Współdzieli tę samą instancję MySQL i jest aktywowany przez profil Docker Compose.

<Callout type="info">
Wbudowany Keycloak wymaga co najmniej **4 GB RAM**. Jest opcjonalny — pomiń go, jeśli nie potrzebujesz SSO.
</Callout>

### Dodaj zmienne Keycloak do pliku `.env`

```bash
# Keycloak admin
KEYCLOAK_ADMIN_USER=admin
KEYCLOAK_ADMIN_PASSWORD=change-this-keycloak-password

# Keycloak database (created automatically in the shared MySQL on first run)
KEYCLOAK_DB=keycloak
KEYCLOAK_DB_USER=keycloak
KEYCLOAK_DB_PASSWORD=change-this-keycloak-db-password

# KC_HOSTNAME: full public URL of your server (Keycloak appends /auth automatically)
KC_HOSTNAME=http://your-server:8091

# Port Keycloak listens on (host)
KEYCLOAK_PORT=8091

# Tell the rtCloud app to connect to embedded Keycloak
EMBED_KEYCLOAK=true
KEYCLOAK_URL=http://your-server:8091
KEYCLOAK_REALM=rtsurvey
KEYCLOAK_CLIENT_ID=rtsurvey
KEYCLOAK_CLIENT_SECRET=your-client-secret
```

Usługa `keycloak` jest już zawarta w pliku `docker-compose.yml` powyżej (pod profilem `embed-keycloak` — nie uruchomi się, chyba że użyjesz `--profile embed-keycloak`).

Utwórz katalog importu (Keycloak uruchomi się bez niego, ale automatyczne przydzielanie realm nie zadziała):

```bash
mkdir -p /opt/rtsurvey/keycloak-import
```

### Uruchom z Keycloak

```bash
docker compose --profile embed-keycloak up -d
```

Aby uruchomić bez Keycloak (domyślnie):

```bash
docker compose up -d
```

### Konsola administratora Keycloak

Po pomyślnym uruchomieniu, uzyskaj dostęp do interfejsu administratora Keycloak pod adresem:

```
http://your-server:8091/auth/admin
```

Zaloguj się przy użyciu `KEYCLOAK_ADMIN_USER` / `KEYCLOAK_ADMIN_PASSWORD`.
