`family_path` è un campo calculate di convenzione che contiene il percorso della directory multimediale in bundle del modulo. Ogni modulo che esegue ricerche in database locali con `rawquery`, `pulldata` o `search()` deve includere questo campo — senza di esso, i percorsi dei file non possono essere risolti e le ricerche restituiscono silenziosamente un risultato vuoto.

---

## Il campo calculate

Aggiungi questa riga nella parte superiore del foglio survey, dopo eventuali campi meta e prima della prima domanda che utilizza un file di database:

| type | name | label | calculation |
|---|---|---|---|
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |

Il campo non memorizza alcun valore visibile e non richiede un label. È un prerequisito silenzioso per tutta la costruzione del percorso che segue.

---

## Perché è necessario

RTSurvey raggruppa i media del modulo — database SQLite, immagini, clip audio — all'interno di una directory per modulo sul dispositivo. Il percorso esatto differisce tra le piattaforme (Android, iOS, web) e tra i dispositivi.

In fase di esecuzione, l'app compila automaticamente `family_path`. Un tipico valore risolto appare come:

```
resources/familyMedia/Phuong_Person_Test
```

Poiché il percorso è specifico della piattaforma e viene determinato al momento del lancio, non può essere codificato nel modulo. `pulldata('app-api', 'family_path')` è l'unico modo affidabile per recuperarlo.

---

## Come usarlo nei percorsi

Una volta definito `family_path`, costruisci un percorso file completo con `concat()`:

```
concat(${family_path}, '/file.db::tableName')
```

Il suffisso `::tableName` viene rimosso quando l'app apre il file; il nome della tabella viene utilizzato solo all'interno della query SQL.

---

## Dove viene utilizzato family_path

`family_path` è richiesto nell'argomento del percorso ogni volta che si fa riferimento a un file in bundle:

- **Ricerca nel database locale** — l'argomento `db_path` di `search-autocomplete-noedit-v2('rawquery', ...)` deve essere costruito con `concat(${family_path}, ...)`. Vedere [Ricerca nel database locale](local-database-search) per i dettagli completi sull'utilizzo.
- **`pulldata` rawquery** — qualsiasi chiamata `pulldata('rawquery', ...)` che legge da un file `.db` utilizza lo stesso pattern `concat()`.
- **`search()` con un file locale** — le apparenze di ricerca dinamica che caricano da un file CSV o DB in bundle si affidano anche a `family_path` per il riferimento al file.

---

## Posizionamento nel modulo

`family_path` deve apparire **prima del primo campo che lo richiama**. La posizione consigliata è immediatamente dopo il gruppo meta:

| type | name | label | calculation |
|---|---|---|---|
| begin_group | meta | | |
| deviceid | deviceid | | |
| start | start | | |
| end | end | | |
| end_group | | | |
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |
| select_one | province | Provincia | *(rawquery appearance che fa riferimento a `${family_path}`)* |

<Callout type="warning">
Se `family_path` manca nel modulo, o è posizionato dopo il primo campo `rawquery` / `search()` che lo richiama, tutte le ricerche nei file in bundle restituiranno silenziosamente un risultato vuoto. Non viene visualizzato alcun messaggio di errore — l'autocompletamento semplicemente non mostra risultati.
</Callout>

---

## File di database multipli

Un singolo modulo può utilizzare diversi file `.db`. Ogni percorso è costruito indipendentemente con `concat()`:

```
concat(${family_path}, '/locations.db::externalData')
concat(${family_path}, '/health_facilities.db::facilities')
concat(${family_path}, '/household_list.db::households')
```

Definisci `family_path` una volta; fai riferimento ad esso in tutti i campi necessari.

---

## Verifica durante lo sviluppo

Aggiungi un campo `note` temporaneo sotto `family_path` per ispezionare il valore risolto sul dispositivo:

| type | name | label | calculation |
|---|---|---|---|
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |
| note | family_path_check | `Percorso: ${family_path}` | |

La nota visualizzerà il percorso effettivo risolto durante il test. Rimuovila prima di distribuire il modulo finale.
