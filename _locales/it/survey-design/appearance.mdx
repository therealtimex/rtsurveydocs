La colonna `appearance` in rtSurvey consente di personalizzare la presentazione visiva e il comportamento delle domande nei sondaggi. Questa funzione migliora l'esperienza dell'utente e può migliorare significativamente l'efficienza della raccolta dei dati. rtSurvey supporta gli attributi di aspetto standard di XLSForm e li estende con opzioni aggiuntive.

## Attributi di Aspetto Standard di XLSForm

rtSurvey supporta i seguenti attributi di aspetto standard di XLSForm:

| Attributo di Aspetto | Tipi di Domanda | Descrizione |
|----------------------|-----------------|-------------|
| multiline | text | Crea una casella di testo riga multipla (ideale per i client web) |
| minimal | select_one, select_multiple | Visualizza le scelte in un menu a discesa |
| quick | select_one | Passa automaticamente alla domanda successiva dopo la selezione (solo per dispositivi mobili) |
| no-calendar | date | Sopprime la visualizzazione del calendario (solo per dispositivi mobili) |
| month-year | date | Consente la selezione solo di mese e anno |
| year | date | Consente la selezione solo dell'anno |
| horizontal-compact | select_one, select_multiple | Visualizza le scelte orizzontalmente (solo web) |
| horizontal | select_one, select_multiple | Visualizza le scelte orizzontalmente in colonne (solo web) |
| likert | select_one | Presenta le scelte come una scala Likert |
| compact | select_one, select_multiple | Visualizza le scelte affiancate con spaziatura minima |
| quickcompact | select_one | Combina la visualizzazione compatta con l'avanzamento automatico (solo per dispositivi mobili) |
| field-list | groups | Visualizza l'intero gruppo in un'unica schermata (solo per dispositivi mobili) |
| label | select_one, select_multiple | Mostra le etichette delle scelte senza input |
| list-nolabel | select_one, select_multiple | Mostra gli input senza etichette (da usare con `label`) |
| table-list | groups | Visualizza le domande in formato tabella |
| signature | image | Consente l'acquisizione della firma (solo per dispositivi mobili) |
| draw | image | Consente il disegno a mano libera (solo per dispositivi mobili) |
| map, quick map | select_one, select_one_from_file | Consente la selezione dalle caratteristiche della mappa |

## Migliori Pratiche per l'Uso dell'Aspetto

1. **Coerenza**: Usa gli attributi di aspetto in modo coerente in tutto il sondaggio per un look uniforme.
2. **Mobile vs. Web**: Considera come gli aspetti verranno renderizzati su diversi dispositivi e piattaforme.
3. **Prestazioni**: Sii cauto con gli attributi di aspetto che potrebbero rallentare il caricamento del modulo (ad esempio, `table-list` per gruppi numerosi).
4. **Esperienza Utente**: Scegli aspetti che rendano l'inserimento dei dati più facile e intuitivo per i rispondenti.
5. **Test**: Testa sempre il tuo modulo sui dispositivi di destinazione per assicurarti che gli aspetti funzionino come previsto.

## Tecniche Avanzate

### Combinazione di Aspetti

Alcuni attributi di aspetto possono essere combinati per layout più complessi:

```
| type | name | label | appearance |
|------|------|-------|------------|
| select_one options | choice | Select one: | minimal compact |
```

### Aspetti Dinamici

rtSurvey consente modifiche dinamiche dell'aspetto basate sulla logica del modulo:

```
| type | name | label | appearance | relevant |
|------|------|-------|------------|----------|
| text | time | Enter time: | inline-[%H:%M] | ${show_time} = 'yes' |
```

## Considerazioni sull'App Mobile

- Alcuni aspetti (ad esempio, `quick`, `signature`) sono specifici per i dispositivi mobili.
- Testare accuratamente sia su Android che su iOS per garantire un comportamento coerente.

## Attributi di Aspetto Estesi di rtSurvey

Oltre agli aspetti standard di XLSForm, rtSurvey supporta le seguenti opzioni specifiche della piattaforma:

### Controllo dei dati e della visualizzazione

| Attributo di Aspetto | Tipi di Domanda | Descrizione |
|----------------------|-----------------|-------------|
| `invisible` | qualsiasi | Nasconde il campo dalla vista pur continuando a raccogliere o calcolare il suo valore. Diverso dal tipo `hidden`: il campo partecipa comunque alla logica. |
| `displaytitle` | qualsiasi | Forza la visualizzazione dell'etichetta/titolo del campo anche quando verrebbe normalmente soppresso. |
| `autopull` | select_one, select_multiple | Recupera automaticamente i dati esterni per popolare le scelte al caricamento del modulo o quando cambia un campo trigger. |
| `floating_hint` | text, integer, decimal | Mostra il testo del suggerimento come un'etichetta fluttuante sopra il campo di input anziché sotto di esso. |
| `calculate-button` | calculate | Aggiunge un pulsante visibile che attiva il ricalcolo del campo su richiesta, anziché calcolare automaticamente. |

### Gruppo e navigazione

| Attributo di Aspetto | Tipi di Domanda | Descrizione |
|----------------------|-----------------|-------------|
| `section` | group | Renderizza il gruppo come una scheda di sezione comprimibile. Nota: solo app mobile. |
| `toc-hide` | qualsiasi | Esclude la domanda dal pannello di navigazione dell'indice (TOC). |
| `minilog` | begin_repeat | Visualizza le voci di ripetizione completate come un elenco mini-log compatto anziché espandere ogni voce in linea. |

### Comportamento dell'input

| Attributo di Aspetto | Tipi di Domanda | Descrizione |
|----------------------|-----------------|-------------|
| `proper` | text | Scrive automaticamente in maiuscolo la prima lettera di ogni parola mentre il rispondente digita (comportamento title-case). |
| `text-nolabel` | text, integer, decimal | Renderizza il campo di input senza un'etichetta visibile. |
| `inline-1line` | text | Forza l'input di testo a essere visualizzato su una singola riga anche quando l'etichetta della domanda è lunga. |
| `popup` | qualsiasi | Renderizza il campo all'interno di un popup / overlay modale anziché in linea nella pagina. |

### Layout

| Attributo di Aspetto | Tipi di Domanda | Descrizione |
|----------------------|-----------------|-------------|
| `1screen` | group | Forza l'intero gruppo a essere visualizzato in un'unica schermata, indipendentemente dalle dimensioni del gruppo. |
| `columns(n)` | select_one, select_multiple | Visualizza le scelte in `n` colonne. Esempio: `columns(3)` mostra tre colonne di pulsanti di opzione. |
| `gridformat<row=R col=C colspan=S align=center>` | qualsiasi | Posiziona il campo in un layout CSS-grid alla riga `R`, colonna `C`, occupando `S` colonne. Usato con `advanced-extension/grid-layout`. |
| `ignore-simplify` | qualsiasi | Istruisce il renderer del modulo a saltare la semplificazione o la condensazione automatica del layout di questo campo. |
| `horizontal(N)` | select_one, select_multiple | Imposta ogni scelta in modo che occupi l' `N` percento della larghezza della riga. Esempio: `horizontal(50)` posiziona due scelte per riga. |
| `scroll-view(N%)` | group, repeat | Vincola il contenitore a un'altezza massima dell' `N%` del viewport (o del genitore), aggiungendo una barra di scorrimento quando il contenuto trabocca. Esempio: `scroll-view(60%)`. |

### Widget

| Attributo di Aspetto | Tipi di Domanda | Descrizione |
|----------------------|-----------------|-------------|
| `likert` | select_one | Presenta le scelte come una riga di scala Likert (già nella tabella standard sopra; supporto confermato). |
| `distress` | select_one | Renderizza le scelte come il widget visivo della Kessler Psychological Distress Scale (K10) con icone emotive. |
| `rating_box-fill-{c1}-{c2}-{c3}-{c4}-{c5}` | select_one | Renderizza le scelte come caselle di valutazione stilizzate con cinque slot di colore. `c1` = bordo del contenitore esterno, `c2` = bordo non selezionato, `c3` = bordo selezionato e riempimento, `c4` = colore del testo non selezionato, `c5` = colore del testo selezionato. Esempio: `rating_box-fill-grey-blue-green-black-white`. |
| `tagging-choices-noshow-v2-{c1}-{c2}-{c3}-{c4}-{c5}` | select_multiple | Renderizza le scelte come chip di tag colorati. I cinque slot di colore seguono lo stesso ordine di `rating_box-fill`. Le scelte selezionate sono evidenziate; le scelte non selezionate sono soppresse dalla vista di riepilogo. |

### Integrazione API

| Attributo di Aspetto | Tipi di Domanda | Descrizione |
|----------------------|-----------------|-------------|
| `callapi` | text, integer, decimal, select_one | Consente l'integrazione delle chiamate API per questo campo. La colonna di calcolo deve contenere un'espressione `callapi()`. Vedi [Chiamata API](advanced-features/call-api). |
| `callapi-verify(params)` | text, integer, decimal | Attiva una chiamata di verifica API utilizzando parametri statici. Il modulo blocca il progresso finché l'API non conferma il valore. |
| `callapi-verify(dynamicParams)` | text, integer, decimal | Uguale a `callapi-verify` ma con parametri derivati da altri valori di campo in fase di runtime. |

### Selettore della lingua

| Attributo di Aspetto | Tipi di Domanda | Descrizione |
|----------------------|-----------------|-------------|
| `change_language-{colors} default('lang')` | note, text | Renderizza un widget per il cambio della lingua stilizzato con i codici colore forniti. Il token `default('lang')` imposta la lingua iniziale (ad esempio `default('en')`); viene riscritto internamente in `rtDefault('lang')` durante il parsing. Esempio: `change_language-blue-white default('vi')`. |

### Formato data/ora in linea

Per i campi `date`, `time` e `datetime`, è possibile specificare un formato di visualizzazione personalizzato utilizzando una stringa di formato aggiunta all'aspetto:

```
inline-[%d/%m/%Y]
inline-1line-[%d/%m/%Y %H:%M]
```

I token di formato sono gli stessi di `format-date()` e `format-date-time()`. Vedi [Funzioni — Funzioni di data e ora](operators-and-functions/functions#date-and-time-functions).

Esempio:

| type | name | label | appearance |
|------|------|-------|------------|
| datetime | event_time | Data e ora dell'evento | inline-[%d/%m/%Y %I:%M %p] |
| date | birth_date | Data di nascita | inline-[%d/%m/%Y] |

### Layout dei pulsanti in linea — `display{}` e `results{}`

Per i tipi di domande che vengono renderizzati come un pulsante con icona in linea (`date`, `time`, `datetime`, `image`, `audio`, `video`, `file`, `barcode`, `geopoint`), due modificatori di aspetto controllano la posizione del pulsante e il comportamento post-acquisizione.

#### `display{...}` — posizione del pulsante prima dell'acquisizione

```
display{<align>, <size>, <color>}
```

| Parametro | Valori | Predefinito |
|-----------|--------|-------------|
| Align | `left`, `right`, `top`, `center`, `bottom` | `right` |
| Size | `small`, `medium`, `large` | `small` |
| Color | hex ad es. `#FF5500` | colore del tema primario |
| Flag | `inline-icon` | forza la modalità icona |

| Valore Align | Layout |
|--------------|--------|
| `right` | Pulsante a destra dell'etichetta |
| `left` | Pulsante a sinistra dell'etichetta |
| `top` | Pulsante sopra l'etichetta, centrato a larghezza intera |
| `center` / `bottom` | Pulsante sotto l'etichetta, centrato a larghezza intera |

#### `results{...}` — layout e visibilità dopo l'acquisizione

Eredita le impostazioni di `display{}`. Usalo per spostare il pulsante o nascondere elementi una volta acquisito un valore.

```
results{<align>, hide(<element>)}
```

| Valore `hide` | Effetto |
|---|---|
| `hide(capture)` | Nasconde il pulsante di acquisizione una volta che esiste un file/valore |
| `hide(review)` | Nasconde la miniatura di revisione / il pulsante di riproduzione |
| `hide(filename)` | Nasconde il nome del file mostrato dopo il caricamento |
| `hide(camera)` | Nasconde il pulsante di attivazione della fotocamera dopo l'acquisizione |
| `hide(scanner)` | Nasconde il pulsante di scansione del codice a barre dopo la scansione di un valore |
| `hide(value)` | Nasconde il testo del valore scansionato (codice a barre / geopoint) |

Il widget passa automaticamente dal layout `display{}` a quello `results{}` nel momento in cui viene acquisito un valore.

**Esempi:**

```
inline display{right}                                    → icona a destra dell'etichetta
inline display{left, large}                              → icona grande a sinistra
inline display{center, large, #FF5500}                   → icona arancione grande sotto l'etichetta
inline display{right} results{left}                      → l'icona si sposta a sinistra dopo l'acquisizione
inline display{right} results{hide(capture)}             → l'icona scompare dopo l'acquisizione
inline display{center} results{hide(capture), hide(filename)}
```

## Limitazioni Noto

- Gli aspetti complessi potrebbero non essere renderizzati in modo identico su tutte le piattaforme.
- Alcuni aspetti avanzati di rtSurvey potrebbero non essere supportati in modalità offline.

## Risoluzione dei Problemi di Aspetto

1. **Aspetto Non Applicato**: Controlla eventuali errori di battitura nella colonna appearance.
2. **Rendering Incoerente**: Verifica la compatibilità con il tipo di domanda e la piattaforma.
3. **Problemi di Prestazioni**: Considera la possibilità di semplificare gli aspetti complessi, specialmente per sondaggi di grandi dimensioni.
