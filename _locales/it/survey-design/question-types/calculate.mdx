Il tipo di domanda `calculate` esegue una formula silenziosamente in background. Memorizza il risultato in un campo denominato a cui altre domande possono fare riferimento, ma non mostra alcun input o etichetta all'intervistatore. Usalo per derivare valori, concatenare stringhe, eseguire logica condizionale o cercare dati necessari in seguito nel modulo.

---

## Sintassi di base

| type | name | label | calculation |
|------|------|-------|-------------|
| calculate | total | | `${price} * ${quantity}` |

- **type**: Sempre `calculate`.
- **name**: Un nome di campo univoco. Altre domande fanno riferimento a questo con `${name}`.
- **label**: Lasciare vuoto — i campi calculate non vengono mai mostrati all'intervistatore.
- **calculation**: La formula da valutare. Supporta tutte le [funzioni XLSForm](../operators-and-functions/functions) e i riferimenti ai campi.

---

## Modelli comuni

### Aritmetica

| type | name | label | calculation |
|------|------|-------|-------------|
| integer | price | Unit price | |
| integer | quantity | Quantity | |
| calculate | total | | `${price} * ${quantity}` |
| note | total_note | Total: `${total}` | |

### Concatenazione di stringhe

| type | name | label | calculation |
|------|------|-------|-------------|
| text | first_name | First name | |
| text | last_name | Last name | |
| calculate | full_name | | `concat(${first_name}, ' ', ${last_name})` |

### Valore condizionale

| type | name | label | calculation |
|------|------|-------|-------------|
| integer | score | Score (0–100) | |
| calculate | grade | | `if(${score} >= 90, 'A', if(${score} >= 75, 'B', if(${score} >= 60, 'C', 'F')))` |

### Età dalla data di nascita

| type | name | label | calculation |
|------|------|-------|-------------|
| date | dob | Date of birth | |
| calculate | age_years | | `int((today() - ${dob}) div 365.25)` |

## Usare `once()` per bloccare il valore

Per impostazione predefinita, `calculate` viene rivalutato ogni volta che cambia un campo a cui si fa riferimento. Avvolgi la formula in `once()` per valutarla solo al primo caricamento e congelare il risultato:

| type | name | label | calculation |
|------|------|-------|-------------|
| calculate | interview_start | | `once(now())` |

Usa `once()` per timestamp, valori iniziali o qualsiasi caso in cui il ricalcolo al variare dei dati non sia desiderabile.

## Recupero di dati da fonti esterne

### Da un file CSV

```
pulldata('staff.csv', 'department', 'name', ${staff_id})
```

Vedere [pulldata()](../operators-and-functions/pulldata) per il riferimento completo.

### Da un database SQLite pacchettizzato

```
pulldata('rawquery',
  concat(${family_path}, '/locations.db::provinces'),
  'SELECT name FROM provinces WHERE id = ?',
  ${province_id})
```

Vedere [Ricerca nel database locale](../advanced-features/local-database-search) per i dettagli sulla costruzione del percorso.

### Dal contesto dell'app

```
pulldata('app-api', 'user.username')
pulldata('app-api', 'family_path')
```

Vedere [App API](../app-api) per tutte le chiavi disponibili.

## Usare calculate in relevant e constraint

Altri campi possono fare riferimento a un risultato `calculate` proprio come a qualsiasi altro campo:

| type | name | label | relevant | constraint |
|------|------|-------|----------|------------|
| calculate | bmi | | | `${weight} div (${height} * ${height}) * 10000` |
| note | bmi_warning | BMI is very high — please verify weight and height. | `${bmi} > 40` | |

## Best Practice

1. Assegna ai campi calculate nomi significativi — `total_cost` è più chiaro di `calc1` e più facile da tracciare nelle esportazioni.
2. Scomponi le formule complesse in più campi calculate concatenati anziché in un'unica espressione profondamente nidificata.
3. Usa `once()` per timestamp e snapshot iniziali per evitare che i valori cambino dopo la prima acquisizione.
4. Posiziona i campi `calculate` prima della prima domanda che fa riferimento ad essi — l'ordine di valutazione segue l'ordine del modulo.
5. Mantieni vuota la colonna `label`. Alcuni strumenti visualizzano l'etichetta; lasciarla vuota evita output confusi.

## Limitazioni

- I campi Calculate non vengono mai visualizzati direttamente all'intervistatore — usa un campo `note` per mostrare il risultato.
- La colonna `calculation` è obbligatoria; una riga `calculate` senza formula memorizza sempre una stringa vuota.
- I risultati vengono rivalutati ad ogni modifica del modulo a meno che non siano racchiusi in `once()` — formule molto complesse in moduli di grandi dimensioni possono influire sulle prestazioni di rendering su dispositivi di fascia bassa.
- I valori calcolati vengono memorizzati come stringhe nell'invio. Usa `number()`, `int()` o `boolean()` per eseguire il cast del tipo quando passi il risultato a espressioni aritmetiche o logiche.
