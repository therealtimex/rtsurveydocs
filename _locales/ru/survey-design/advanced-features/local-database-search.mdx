**Поиск в локальной базе данных** позволяет полям `select_one` или `text` опрашивать файл SQLite `.db`, который включен в медиа-пакет формы — полностью в автономном режиме, без обращения к серверу. Это правильный подход, если ваш список вариантов большой и статический (например, национальный список деревень, медицинских учреждений или административных границ), а связь не может быть гарантирована.

| Подход | Источник данных | Требуется подключение |
|---|---|---|
| Поиск в локальной базе данных (`rawquery`) | Встроенный файл `.db` (SQLite) | Нет |
| `search-api()` | Удаленный REST API | Да |
| `search()` | Встроенный CSV-файл | Нет |

---

## Варианты отображения (Appearance)

Поле автозаполнения настраивается через колонку `appearance`. Доступны три варианта:

| Вариант | Примечания |
|---|---|
| `search-autocomplete-noedit(...)` | Стандартное автозаполнение — интервьюер должен выбрать из списка; ввод произвольного текста не сохраняется |
| `search-autocomplete-noedit-v2(...)` | Рекомендуемый вариант — то же поведение, но используется обновленный движок рендеринга с лучшей производительностью на больших наборах результатов |
| `search(...)` | Простое сопоставление на основе встроенного CSV-файла; **не** поддерживает чистый SQL — приведено здесь только для сравнения |

<Callout type="info">
`search-autocomplete-noedit` — это псевдоним; во время парсинга приложение заменяет его внутренним именем функции `searchAutocompleteNoedit`. Используйте любое написание в вашей XLS-форме; оба работают.
</Callout>

## Источник данных `rawquery`

Чтобы запустить SQL-запрос к файлу `.db`, передайте `'rawquery'` в качестве первого аргумента функции appearance. Полная сигнатура:

```
search-autocomplete-noedit-v2(
  'rawquery',
  <db_path>,
  '[display_col]',
  'value_col',
  'SELECT ...',
  param1, param2, ...
)
```

### Параметры

| Позиция | Параметр | Описание |
|---|---|---|
| 1 | `'rawquery'` | Литеральная строка — указывает приложению выполнять SQL напрямую |
| 2 | `db_path` | Путь к файлу SQLite в формате `<dir>/<file>.db::tableName`. Суффикс `::tableName` отсекается при открытии файла; имя таблицы используется внутри вашего SQL-запроса |
| 3 | `'[display_col]'` | Колонка для отображения в выпадающем списке. Окружающие квадратные скобки `[ ]` отсекаются во время выполнения |
| 4 | `'value_col'` | Колонка, значение которой сохраняется, когда интервьюер делает выбор |
| 5 | `'SELECT ...'` | Любой допустимый оператор SQLite SELECT. `SELECT DISTINCT` внедряется автоматически, если `DISTINCT` еще не присутствует |
| 6+ | `param1, ...` | Необязательно. Значения, привязанные к плейсхолдерам `?` в SQL по порядку. Если SQL содержит `?`, но параметры не указаны, поле возвращает пустое значение (встроенная защита от отсутствующих аргументов) |

### Соглашение `db_path`

Файл базы данных находится внутри встроенного медиа-каталога формы. Во время выполнения `pulldata('app-api', 'family_path')` возвращает путь к этому каталогу. См. [family_path](family-path) для получения подробной информации о настройке. Стандартный шаблон:

```
concat(${family_path}, '/mydata.db::tableName')
```

Когда приложение открывает файл, оно отсекает часть `::tableName` и использует чистый путь к файлу. Имя таблицы появляется только внутри вашего SQL-запроса.

## Базовый пример — поиск провинции

Выпадающий список провинций только для чтения, работающий на базе встроенного файла `vnxa3.db`:

| type | name | label | appearance | calculation |
|---|---|---|---|---|
| calculate | family_path | | | `pulldata('app-api', 'family_path')` |
| select_one | province | Провинция | `search-autocomplete-noedit-v2('rawquery', concat(${family_path}, '/vnxa3.db::externalData'), '[provv]', 'provid', 'SELECT provv, provid FROM externalData WHERE rta_filter = "1"')` | |

Колонка `appearance` (развернута для удобства чтения):

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[provv]', 'provid',
  'SELECT provv, provid FROM externalData WHERE rta_filter = "1"')
```

- Отображаемая метка берется из колонки `provv`.
- Сохраненное значение берется из колонки `provid`.
- Показываются только строки, где `rta_filter = "1"`.

## Параметризованные запросы

Используйте плейсхолдеры `?` в SQL и передавайте соответствующие ссылки на поля в качестве дополнительных аргументов (начиная с 6-й позиции). Это стандартный шаблон для каскадных выборов — например, загрузка районов, принадлежащих ранее выбранной провинции.

<Callout type="warning">
Если ваш SQL содержит хотя бы один знак `?` и аргументы параметров не указаны, поле возвращает пустой набор результатов. Это предотвращает появление устаревших или неактуальных данных до того, как будет сделан родительский выбор.
</Callout>

### Пример каскада районов

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[distv]', 'distid',
  'SELECT distv, distid FROM externalData
   WHERE provid = ? AND rta_filter = "1"',
  ${province})
```

Значение `${province}` привязывается к первому знаку `?`. Поле остается пустым, пока интервьюер не выберет провинцию.

### Пример с двумя параметрами — каскад коммун

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[commv]', 'commid',
  'SELECT commv, commid FROM externalData
   WHERE provid = ? AND distid = ? AND rta_filter = "1"',
  ${province}, ${district})
```

Параметры привязываются позиционно: `${province}` → первый `?`, `${district}` → второй `?`.

## UNION SELECT для специальных значений

Внедряйте синтетические строки, такие как «Не знаю» или «Отказ от ответа», непосредственно в SQL с помощью `UNION SELECT`:

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[provv]', 'provid',
  'SELECT provv, provid FROM externalData WHERE rta_filter = "1"
   UNION SELECT "<i>Не знаю</i>", "888"')
```

Соглашения, используемые в формах RTSurvey:

| Код | Значение |
|---|---|
| `888` | Не знаю |
| `999` | Отказ от ответа |

HTML-теги, такие как `<i>`, в строке отображения рендерятся приложением — вы можете использовать их для визуального выделения специальных опций.

## Многоязычное отображение

Храните языковые метки в отдельных колонках (например, `label_vi`, `label_en`) и выбирайте подходящую на основе поля языка в вашей форме:

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[label_vi]', 'provid',
  'SELECT label_vi, label_en, provid FROM externalData
   WHERE rta_filter = "1"')
```

Чтобы динамически переключать колонки на основе поля `${language}`, используйте выражение `if()` в параметре колонки отображения для переключения между языковыми колонками:

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  if(${language} = 'vi', '[label_vi]', '[label_en]'),
  'provid',
  'SELECT label_vi, label_en, provid FROM externalData
   WHERE rta_filter = "1"')
```

<Callout type="info">
Параметр колонки отображения вычисляется перед запуском запроса. В SQL-движок передается только имя колонки (без скобок); скобки являются косметическими маркерами, отсекаемыми во время парсинга.
</Callout>

## Проверка реального выбора

Если поле допускает специальные значения, такие как 888 или 999, обычной проверки `required = yes` недостаточно — она выполняется, даже если интервьюер выбирает «Не знаю». Используйте ограничение `selected-at(., 0) != -997`, чтобы убедиться, что сохраненное значение является реальным выбором, а не внутренним маркером «ничего не выбрано» `-997`:

| колонка | значение |
|---|---|
| constraint | `selected-at(., 0) != -997` |
| constraint_message | Пожалуйста, выберите корректный вариант |

Значение `-997` — это внутренний код, который RTSurvey сохраняет, когда ни один элемент не был выбран из списка автозаполнения. Выбор 888 или 999 по-прежнему является сознательным выбором и проходит эту проверку.

Чтобы дополнительно потребовать реальное (не специальное) значение, расширьте ограничение:

```
selected-at(., 0) != -997 and selected-at(., 0) != '888' and selected-at(., 0) != '999'
```

## Сравнение: локальная база данных и другие методы поиска

| Функция | Автозаполнение `rawquery` | `search-api()` | `search()` CSV | Обычные CSV-варианты |
|---|---|---|---|---|
| Источник данных | Встроенный `.db` (SQLite) | Удаленный REST API | Встроенный CSV | Лист Choices |
| Работает офлайн | Да | Нет | Да | Да |
| Поддержка чистого SQL | Да | Нет | Нет | Нет |
| Каскадные фильтры | Да — параметризованный `?` | Через тело запроса | Ограниченно | Нет |
| Размер набора данных | Очень большой (миллионы строк) | Неограниченно (на стороне сервера) | Средний (десятки тысяч) | Маленький |
| Специальные внедренные строки | Да — `UNION SELECT` | Нет | Нет | Да (вручную) |
| Сложность настройки | Средняя — требуется встроенный `.db` | Высокая — требуется API-сервер | Низкая | Нет |

## Ограничения

- Файл `.db` должен быть включен в медиа-пакет формы перед развертыванием. Динамические обновления базы данных требуют нового развертывания формы.
- SQL выполняется на устройстве «как есть». На стороне сервера очистка (sanitization) не производится — избегайте создания SQL-запросов на основе произвольного текстового ввода интервьюера.
- Поддерживаются только операторы `SELECT`. `INSERT`, `UPDATE` и `DELETE` не разрешены.
- Очень сложные запросы (большие цепочки `UNION`, множественные присоединения) могут медленно работать на бюджетных Android-устройствах.
- Варианты `search-autocomplete-noedit` не позволяют интервьюеру сохранить значение, которого нет в наборе результатов. Если требуется ввод произвольного текста, используйте отдельное поле `text`.
- `SELECT DISTINCT` внедряется автоматически только в том случае, если `DISTINCT` отсутствует в запросе. Если вы напишете `SELECT DISTINCT` явно, оно не будет дублироваться.
