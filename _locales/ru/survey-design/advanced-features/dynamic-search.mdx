---

**Динамический поиск** (также называемый Search API) позволяет полям `select_one`, `select_multiple` или `text` загружать варианты из удаленного веб-сервиса **во время выполнения** по мере того, как переписчик вводит текст. Это правильный подход, если ваш список вариантов слишком велик для включения в CSV-файл, часто обновляется или поступает из живой базы данных.

---

## Внешний вид `search-api()`

Динамический поиск настраивается в столбце `appearance` с помощью функции `search-api()`:

```
search-api(method, url, post_body, value_column, display, data_path, save_path)
```

### Параметры

| Параметр | Описание |
|-----------|-------------|
| `method` | Всегда используйте `'POST'` |
| `url` | Конечная точка API (endpoint) для запроса |
| `post_body` | Тело JSON, отправляемое в API. Используйте `%__input__%` как заполнитель для текущего текста поиска переписчика |
| `value_column` | Ключ в объекте ответа, который будет использоваться как сохраненное **значение** (`value`) |
| `display` | Ключ (или шаблон), который будет использоваться в качестве **метки** (`label`), отображаемой в выпадающем списке. Поддерживает заполнители `##key##` и выражения `@{func}` |
| `data_path` | JSONPath к массиву результирующих объектов в ответе (например, `$.data`, `$.hits.hits.*._source`) |
| `save_path` | Имя, под которым необработанный ответ сохраняется для использования в других полях |

## Базовый пример

Поиск медицинского учреждения, где переписчик вводит часть названия учреждения:

| type | name | label | appearance |
|------|------|-------|------------|
| select_one | facility | Выберите медицинское учреждение | `search-api('POST', 'https://api.example.com/facilities/search', '{"query": "%__input__%"}', 'id', 'name', '$.results', 'facility_data')` |

API получает `{"query": "nair"}`, когда переписчик вводит «nair», и возвращает:

```json
{
  "results": [
    {"id": "HF001", "name": "Nairobi Central Clinic"},
    {"id": "HF002", "name": "Nairobi West Hospital"}
  ]
}
```

В выпадающем списке отображаются `Nairobi Central Clinic` и `Nairobi West Hospital`; сохраненное значение — `HF001` или `HF002`.

## Расширенное форматирование отображения

### Использование шаблонов `##key##`

Отображение нескольких полей в метке:

```
search-api('POST', 'https://api.example.com/search', '{"q": "%__input__%"}', 'id', '##name## (##district##)', '$.data', 'res')
```

Отображается как: `Nairobi Central Clinic (Nairobi)`.

### Использование выражений `@{func}`

Применение условной логики в метке отображения:

```
search-api('POST', 'https://api.example.com/search', '{"q": "%__input__%"}', 'id',
  '@{if_else(eq("##status##", "active"), "✓ ##name##", "✗ ##name##")}',
  '$.data', 'res')
```

Для активных результатов отображается `✓ Clinic Name`; для неактивных — `✗ Clinic Name`.

## Установка значения по умолчанию: `search-default-api()`

Используйте `search-default-api()` после `search-api()`, чтобы предварительно заполнить поле вариантом по умолчанию, загруженным из отдельного вызова API (например, при редактировании существующей записи):

```
appearance: search-api(...) search-default-api('POST', 'https://api.example.com/get', '{"id": "##saved_id##"}', 'id', 'name', '$.item')
```

---

## Пользовательский разделитель для select_multiple: `search-default-separator()`

Для полей `select_multiple` укажите, как несколько выбранных значений объединяются в сохраненной строке:

```
appearance: search-api(...) search-default-separator(' || ')
```

Разделитель по умолчанию — пробел.

## Поддерживаемые типы вопросов

| Тип вопроса | Вариант использования |
|---------------|----------|
| `select_one` | Одиночный выбор из результатов поиска |
| `select_multiple` | Множественный выбор из результатов поиска |
| `text` | Автозаполнение — переписчик вводит текст свободно, но может выбрать предложение |

## Использование сохраненных данных ответа

Когда переписчик выбирает результат, rtSurvey сохраняет полный соответствующий объект из ответа под именем `save_path`. Другие поля могут считывать данные из него двумя способами.

### Метод 1 — поиск `pulldata()`

Используйте `pulldata('save_path', 'key')` для чтения поля верхнего уровня из сохраненного объекта:

| type | name | label | calculation |
|------|------|-------|-------------|
| select_one | facility | Выберите учреждение | |
| calculate | facility_district | | `pulldata('facility_data', 'district')` |
| calculate | facility_type | | `pulldata('facility_data', 'type')` |
| calculate | facility_beds | | `pulldata('facility_data', 'beds')` |

Свойство `appearance` в строке `select_one` должно включать `search-api(..., 'facility_data')` с соответствующим `save_path`.

Для **вложенных полей JSON** используйте в сочетании с `substr-jsonpath()`:

```
substr-jsonpath(pulldata('facility_data', 'location'), '$.district')
```

## Поиск в локальном файле с помощью search()

`search()` выполняет офлайн-поиск по равенству столбцов в прикрепленном файле SQLite `.db` — без сетевого подключения и без SQL-запросов. Используйте его, когда ваши справочные данные упакованы вместе с формой и вам нужен простой поиск «найти все строки, где столбец равен значению».

### Сигнатура

```
search(path, 'matches', 'list_name', ${field})
```

### Параметры

| Параметр | Описание |
|-----------|-------------|
| `path` | Путь к таблице SQLite: `concat(${family_path}, '/file.db::table')` |
| `'matches'` | Оператор совпадения — возвращает строки, в которых столбец равен значению |
| `'list_name'` | Имя столбца для сопоставления |
| `${field}` | Значение для сопоставления; обычно ссылка на поле |

### Пример

Заполнение поля `select_one` из локальной базы данных путем сопоставления значения `${d307}` со столбцом `list_name` в таблице `externalData` файла `d307.db`:

| type | name | label | appearance |
|------|------|-------|------------|
| select_one | facility | Выберите учреждение | `search(concat(${family_path}, '/d307.db::externalData'), 'matches', 'list_name', ${d307})` |

Когда `${d307}` равно `"HF001"`, `search()` возвращает каждую строку в `externalData`, где `list_name = 'HF001'` — полностью из прикрепленного файла, без сетевого вызова.

### search() против автозаполнения rawquery

| Функция | `search()` | Автозаполнение `rawquery` |
|---------|-----------|------------------------|
| SQL-запросы | Нет — только равенство столбцов | Да — полный `SELECT … FROM …` |
| Параметризованный ввод | Сопоставление значений столбцов | Встроено в строку SQL |
| Свободный ввод текста | Да — переписчик может писать свободно | Нет — необходимо выбрать из списка |
| UNION / несколько таблиц | Не поддерживается | Поддерживается |

### Когда использовать каждый из них

- Используйте **`search()`**, когда вам нужно простое сопоставление по равенству в прикрепленном файле `.db`, форма должна работать в офлайн-режиме, и вы хотите разрешить свободный ввод текста.
- Используйте **автозаполнение `rawquery`**, когда вам нужна гибкость SQL (JOIN, UNION, вычисляемые столбцы) или необходимо выполнять запросы к нескольким таблицам, а форма имеет надежное соединение.

## Лучшие практики

1. Убедитесь, что конечная точка вашего API отвечает в течение 1–2 секунд — медленные API делают поиск не отзывчивым.
2. Используйте `%__input__%` в `post_body`, чтобы API возвращал только соответствующие результаты, а не весь набор данных.
3. Индексируйте поле поиска на стороне сервера (например, Elasticsearch, полнотекстовый индекс базы данных) для быстрых ответов.
4. Ограничьте результаты 20–50 элементами на запрос — возврат тысяч результатов лишает поиск смысла.
5. Включите требование к минимальной длине ввода в API, чтобы избежать запуска широких запросов при вводе одного символа.

## Ограничения

- Динамический поиск требует сетевого подключения — он не работает в офлайн-режиме.
- Заполнитель `%__input__%` вставляется «как есть»; очищайте входные данные на стороне сервера для предотвращения атак типа «инъекция».
- Сложные выражения отображения `@{func}` могут иметь ограниченную поддержку во всех версиях клиента rtSurvey.
