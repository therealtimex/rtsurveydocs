Аудиозапись позволяет форме скрыто или явно записывать звук во время прохождения раздела опроса. Это полезно для записи интервью, фонового звука во время полевых наблюдений или устных ответов, которые дополняют структурированные данные.

---

<Callout type="warning">
**Только для мобильного приложения.** Аудиозапись требует мобильного приложения rtSurvey. В веб-форме параметры `audio-start` и `audio-end` просто игнорируются — запись не ведется, и ошибка не выводится. Всегда тестируйте на устройстве, если требуется аудиозапись.

## Как это работает

Аудиозапись управляется двумя полями типа `text`, которые выступают в роли **маркеров**:

- Поле с параметром `audio-start` начинает запись, когда интервьюер доходит до него.
- Поле с параметром `audio-end` останавливает запись и прикрепляет аудиофайл к отправляемым данным.

Оба маркерных поля имеют тип `text`. Обычно они скрыты от интервьюера (с помощью `relevant = false` или размещения в неинтерактивном месте), хотя могут быть и видимыми. Записанное аудио прикрепляется к отправке как файл, связанный с полем `audio-end`.

---

## Базовый пример

| type | name | label | appearance |
|------|------|-------|------------|
| text | audio_s_a1 | | `audio-start` |
| text | q_name | Имя респондента | |
| text | q_occupation | Род занятий | |
| integer | q_age | Возраст | |
| text | audio_e_a1 | | `audio-end` |

Приложение начинает запись, когда интервьюер доходит до `audio_s_a1`, и останавливает, когда доходит до `audio_e_a1`. Все вопросы между этими двумя маркерами будут записаны.

---

## Скрытая запись: `audio-start invisible`

По умолчанию мобильное приложение отображает индикатор записи во время захвата звука. Добавление `invisible` в параметр appearance скрывает этот индикатор, так что запись происходит без каких-либо видимых признаков для респондента.

| type | name | label | appearance |
|------|------|-------|------------|
| text | audio_s_a1 | | `audio-start invisible` |
| text | q_consent | Вы согласны принять участие? | |
| text | q_feedback | Ваш отзыв | |
| text | audio_e_a1 | | `audio-end` |

Используйте `invisible` только тогда, когда требования к информированию были выполнены другими способами (например, отдельное поле письменного согласия перед разделом записи).

## Правила именования

В рабочих формах используется последовательный шаблон именования полей-маркеров:

```
audio_s_{section}{n}   — начальный маркер
audio_e_{section}{n}   — конечный маркер
```

Где `{section}` — это краткое обозначение раздела формы, а `{n}` — порядковый номер внутри этого раздела.

| Field name | Role | Meaning |
|------------|------|---------|
| `audio_s_a1` | Start | Первая запись в разделе A |
| `audio_e_a1` | End | Конец первой записи в разделе A |
| `audio_s_b1` | Start | Первая запись в разделе B |
| `audio_e_b1` | End | Конец первой записи в разделе B |
| `audio_s_a2` | Start | Вторая запись в разделе A |
| `audio_e_a2` | End | Конец второй записи в разделе A |

Соблюдение этого правила позволяет легко определять границы записи при просмотре определений форм и данных опросов.

---

## Хранение и получение

Когда интервьюер доходит до поля `audio-end`, приложение завершает создание аудиофайла и прикрепляет его к отправляемым данным. Файл:

- Хранится как аудиоприложение к отправленным данным, связанное с именем поля `audio-end`.
- Доступен в окне просмотра данных rtSurvey вместе с другими медиафайлами.
- Доступен для загрузки через стандартный экспорт — аудиофайлы появляются в столбце медиа, соответствующем имени поля `audio-end`.

Формат файла и битрейт зависят от устройства и версии приложения.

---

## Несколько разделов записи

Форма может содержать несколько неперекрывающихся разделов записи. Каждая пара маркеров `audio-start` / `audio-end` должна быть полностью завершена — разделы не должны пересекаться.

| type | name | label | appearance |
|------|------|-------|------------|
| text | audio_s_a1 | | `audio-start` |
| text | q_intro | Введение | |
| text | audio_e_a1 | | `audio-end` |
| note | section_break | — | |
| text | audio_s_b1 | | `audio-start invisible` |
| text | q_detail | Подробности | |
| text | audio_e_b1 | | `audio-end` |

Каждый раздел создает отдельный аудиофайл, прикрепленный к соответствующему полю `audio-end`.

---

## Ограничения

- **Только для мобильного приложения.** Эта функция не поддерживается в веб-форме. Параметры `audio-start` и `audio-end` в браузере просто игнорируются.
- **Никакой вложенности.** Разделы записи не могут перекрываться. Запуск новой записи до достижения предыдущего маркера `audio-end` не поддерживается.
- **Тип поля должен быть `text`.** Использование `audio-start` или `audio-end` в вопросах любого другого типа не поддерживается.
- **Размер загрузки.** Длительные записи создают большие файлы. Помните об ограничениях на размер отправляемых данных и условиях сети в полевых условиях.
- **Нет паузы во время записи.** Запись ведется непрерывно от начального маркера до конечного; механизм паузы и возоновления записи внутри раздела отсутствует.
