import { Callout } from 'nextra/components'

**로컬 데이터베이스 검색**을 사용하면 `select_one` 또는 `text` 필드가 양식의 미디어 패키지와 함께 번들로 제공되는 SQLite `.db` 파일을 쿼리할 수 있습니다. 이는 서버를 거치지 않고 완전히 오프라인으로 작동합니다. 이 방법은 선택 목록이 크고 정적이며(예: 전국 마을 목록, 의료 시설 또는 행정 구역) 연결을 보장할 수 없는 경우에 적합한 접근 방식입니다.

| 접근 방식 | 데이터 소스 | 연결 필요 여부 |
|---|---|---|
| 로컬 데이터베이스 검색 (`rawquery`) | 내장된 `.db` 파일 (SQLite) | 아니요 |
| `search-api()` | 원격 REST API | 예 |
| `search()` | 내장된 CSV 파일 | 아니요 |

---

## 디자인 변형 (Appearance variants)

자동 완성 필드는 `appearance` 열을 통해 구성됩니다. 세 가지 변형을 사용할 수 있습니다.

| 변형 | 참고 |
|---|---|
| `search-autocomplete-noedit(...)` | 표준 자동 완성 — 조사원은 목록에서 선택해야 하며, 자유 텍스트 입력은 저장되지 않습니다. |
| `search-autocomplete-noedit-v2(...)` | 권장 변형 — 동작은 동일하지만 대규모 결과 세트에서 더 나은 성능을 제공하는 업데이트된 렌더링 엔진을 사용합니다. |
| `search(...)` | 내장된 CSV에 대한 단순 파일 기반 일치. raw SQL을 지원하지 **않으며**, 여기서는 비교 목적으로만 나열됩니다. |

<Callout type="info">
`search-autocomplete-noedit`은 별칭(alias)입니다. 구문 분석 시 앱은 이를 내부 함수 이름인 `searchAutocompleteNoedit`으로 바꿉니다. XLSForm에서 두 가지 철자 중 하나를 사용하면 되며, 둘 다 작동합니다.
</Callout>

---

## `rawquery` 데이터 소스

`.db` 파일에 대해 SQL 쿼리를 실행하려면 appearance 함수의 첫 번째 인수로 `'rawquery'`를 전달합니다. 전체 시그니처는 다음과 같습니다.

```
search-autocomplete-noedit-v2(
  'rawquery',
  <db_path>,
  '[display_col]',
  'value_col',
  'SELECT ...',
  param1, param2, ...
)
```

### 매개변수

| 위치 | 매개변수 | 설명 |
|---|---|---|
| 1 | `'rawquery'` | 리터럴 문자열 — 앱에 SQL을 직접 실행하도록 지시합니다. |
| 2 | `db_path` | SQLite 파일의 경로로, `<dir>/<file>.db::tableName` 형식입니다. 파일을 열 때 `::tableName` 접미사는 제거되며, 테이블 이름은 SQL 내부에서 사용됩니다. |
| 3 | `'[display_col]'` | 드롭다운에 표시할 열입니다. 주변의 `[ ]` 대괄호는 런타임에 제거됩니다. |
| 4 | `'value_col'` | 조사원이 선택할 때 값이 저장되는 열입니다. |
| 5 | `'SELECT ...'` | 유효한 모든 SQLite SELECT 문입니다. `DISTINCT`가 이미 존재하지 않는 경우 `SELECT DISTINCT`가 자동으로 주입됩니다. |
| 6+ | `param1, ...` | 선택 사항. SQL의 `?` 자리 표시자에 순서대로 바인딩되는 값입니다. SQL에 `?`가 포함되어 있지만 매개변수가 제공되지 않으면 필드는 빈 결과를 반환합니다(누락된 인수에 대한 내장 가드). |

### `db_path` 규칙

데이터베이스 파일은 양식의 번들 미디어 디렉터리 내에 위치합니다. 런타임에 `pulldata('app-api', 'family_path')`는 해당 디렉터리 경로를 반환합니다. 설정 세부 정보는 [family_path](family-path)를 참조하세요. 표준 패턴은 다음과 같습니다.

```
concat(${family_path}, '/mydata.db::tableName')
```

앱이 파일을 열 때 `::tableName` 부분을 잘라내고 순수 파일 경로를 사용합니다. 테이블 이름은 SQL 내부에만 나타납니다.

## 기본 예제 — 도/시 조회

내장된 `vnxa3.db` 파일로 뒷받침되는 읽기 전용 도/시 드롭다운:

| type | name | label | appearance | calculation |
|---|---|---|---|---|
| calculate | family_path | | | `pulldata('app-api', 'family_path')` |
| select_one | province | Province | `search-autocomplete-noedit-v2('rawquery', concat(${family_path}, '/vnxa3.db::externalData'), '[provv]', 'provid', 'SELECT provv, provid FROM externalData WHERE rta_filter = "1"')` | |

`appearance` 열(가독성을 위해 확장됨):

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[provv]', 'provid',
  'SELECT provv, provid FROM externalData WHERE rta_filter = "1"')
```

- 표시되는 레이블은 `provv` 열에서 가져옵니다.
- 저장되는 값은 `provid` 열에서 가져옵니다.
- `rta_filter = "1"`인 행만 표시됩니다.

## 매개변수화된 쿼리 (Parameterized queries)

SQL에서 `?` 자리 표시자를 사용하고 해당 필드 참조를 추가 인수(6번 위치부터)로 전달합니다. 이는 계층적 선택(cascading selects)을 위한 표준 패턴입니다. 예를 들어 이전에 선택한 도/시에 속하는 구/군을 로드하는 경우입니다.

<Callout type="warning">
SQL에 `?`가 하나 이상 포함되어 있고 매개변수 인수가 제공되지 않으면 필드는 빈 결과 세트를 반환합니다. 이는 상위 선택이 이루어지기 전에 오래되거나 범위가 지정되지 않은 데이터가 나타나는 것을 방지합니다.
</Callout>

### 구/군 계층 예제

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[distv]', 'distid',
  'SELECT distv, distid FROM externalData
   WHERE provid = ? AND rta_filter = "1"',
  ${province})
```

`${province}`의 값은 첫 번째 `?`에 바인딩됩니다. 조사원이 도/시를 선택할 때까지 필드는 비어 있습니다.

### 두 개의 매개변수 예제 — 읍/면/동 계층

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[commv]', 'commid',
  'SELECT commv, commid FROM externalData
   WHERE provid = ? AND distid = ? AND rta_filter = "1"',
  ${province}, ${district})
```

매개변수는 위치에 따라 바인딩됩니다. `${province}` → 첫 번째 `?`, `${district}` → 두 번째 `?`.

## 특별한 값을 위한 UNION SELECT

`UNION SELECT`를 사용하여 "모름" 또는 "응답 거부"와 같은 인공적인 행을 SQL에 직접 주입합니다.

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[provv]', 'provid',
  'SELECT provv, provid FROM externalData WHERE rta_filter = "1"
   UNION SELECT "<i>Không biết</i>", "888"')
```

RTSurvey 양식에서 사용되는 규칙:

| 코드 | 의미 |
|---|---|
| `888` | 모름 |
| `999` | 응답 거부 |

표시 문자열의 `<i>`와 같은 HTML 태그는 앱에서 렌더링되므로, 특별한 옵션을 시각적으로 구분하는 데 사용할 수 있습니다.

## 다국어 표시

언어별 레이블을 별도의 열(예: `label_vi`, `label_en`)에 저장하고 양식의 언어 필드에 따라 적절한 열을 선택합니다.

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[label_vi]', 'provid',
  'SELECT label_vi, label_en, provid FROM externalData
   WHERE rta_filter = "1"')
```

`${language}` 필드에 따라 열을 동적으로 전환하려면 표시 열 매개변수에서 `if()` 표현식을 사용하여 언어 열 간에 전환합니다.

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  if(${language} = 'vi', '[label_vi]', '[label_en]'),
  'provid',
  'SELECT label_vi, label_en, provid FROM externalData
   WHERE rta_filter = "1"')
```

<Callout type="info">
표시 열 매개변수는 쿼리가 실행되기 전에 평가됩니다. 열 이름(대괄호 제외)만 SQL 엔진으로 전달됩니다. 대괄호는 구문 분석 시 제거되는 장식용 마커입니다.
</Callout>

## 실제 선택 항목 유효성 검사

필드에서 888 또는 999와 같은 특별한 값을 허용하는 경우 단순한 `required = yes` 검사만으로는 부족합니다. 조사원이 "모름"을 선택해도 조건이 충족되기 때문입니다. 저장된 값이 실제 선택 항목이고 내부의 "선택 안 함" 감시값인 `-997`이 아닌지 확인하려면 `selected-at(., 0) != -997` 제약 조건을 사용하세요.

| 열 | 값 |
|---|---|
| constraint | `selected-at(., 0) != -997` |
| constraint_message | 유효한 옵션을 선택해 주세요. |

값 `-997`은 자동 완성 목록에서 항목을 선택하지 않았을 때 RTSurvey가 저장하는 내부 코드입니다. 888 또는 999를 선택하는 것은 여전히 의도적인 선택이며 이 검사를 통과합니다.

추가로 실제(특별하지 않은) 값을 요구하려면 제약 조건을 확장하세요.

```
selected-at(., 0) != -997 and selected-at(., 0) != '888' and selected-at(., 0) != '999'
```

## 비교: 로컬 데이터베이스 vs 기타 검색 방법

| 기능 | `rawquery` 자동 완성 | `search-api()` | `search()` CSV | 일반 CSV 선택지 |
|---|---|---|---|---|
| 데이터 소스 | 내장된 `.db` (SQLite) | 원격 REST API | 내장된 CSV | Choices 시트 |
| 오프라인 작동 | 예 | 아니요 | 예 | 예 |
| raw SQL 지원 | 예 | 아니요 | 아니요 | 아니요 |
| 계층적 필터 | 예 — 매개변수화된 `?` | 요청 본문을 통해 | 제한적 | 아니요 |
| 데이터 세트 크기 | 매우 큼 (수백만 행) | 무제한 (서버 측) | 중간 (수만 개) | 작음 |
| 특별 주입 행 | 예 — `UNION SELECT` | 아니요 | 아니요 | 예 (수동) |
| 설정 복잡성 | 중간 — 내장된 `.db` 필요 | 높음 — API 서버 필요 | 낮음 | 없음 |

## 제한 사항

- `.db` 파일은 배포 전에 양식의 미디어 패키지 내부에 포함되어야 합니다. 데이터베이스의 동적 업데이트에는 새 양식 배포가 필요합니다.
- SQL은 장치에서 있는 그대로 실행됩니다. 서버 측 새니타이제이션(sanitisation)이 없으므로 조사원의 자유 텍스트 입력으로 SQL을 구성하지 마십시오.
- `SELECT` 문만 지원됩니다. `INSERT`, `UPDATE`, `DELETE`는 허용되지 않습니다.
- 매우 복잡한 쿼리(대규모 `UNION` 체인, 다중 조인)는 저사양 Android 장치에서 느릴 수 있습니다.
- `search-autocomplete-noedit` 변형은 조사원이 결과 세트에 없는 값을 저장하는 것을 허용하지 않습니다. 자유 텍스트 입력이 필요한 경우 별도의 `text` 필드를 사용하십시오.
- `SELECT DISTINCT`는 쿼리에 `DISTINCT`가 없는 경우에만 자동으로 주입됩니다. `SELECT DISTINCT`를 명시적으로 작성하면 중복되지 않습니다.
