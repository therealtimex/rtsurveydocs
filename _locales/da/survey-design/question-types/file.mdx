---

Spørgsmålstypen `file` gør det muligt for respondenter at **uploade enhver fil** fra deres enhed — dokumenter, regneark, PDF'er eller andre filtyper. I modsætning til `image`, `audio` og `video`, der starter specifikke optagelsesværktøjer, åbner `file` en generel filvælger.

## Grundlæggende XLSForm-specifikation

| type | name | label |
|---|---|---|
| file | document | Venligst upload dit dokument |

For flere detaljer om standard filspørgsmålstypen, se [XLSForm specification](https://xlsform.org/en/#question-types).

## Anvendelser

Filspørgsmål bruges ofte til:

1. Indsamling af understøttende dokumenter (kvitteringer, certifikater, kontrakter, rapporter)
2. Upload af udfyldte papirformularer, der blev scannet
3. Indsamling af regneark eller dataeksporter fra andre systemer
4. Enhver digital filtype, som billede/lyd/video ikke dækker

## Dataformat

Uploadede filer gemmes som binære vedhæftninger:

- **Format:** Bevares i originalt format (PDF, XLSX, DOCX osv.)
- **Navngivning:** `{instanceID}-{fieldname}.{extension}`
- **Opbevaring:** Uploades til serverens mediemappe sammen med indsendelsen
- **Adgang:** Kan downloades fra grænsefladen til administration af indsendelser

## rtSurvey udvidelser

### Accepterede filtyper

Brug kolonnen `parameters` til at begrænse, hvilke filtyper der kan vælges:

| type | name | label | parameters |
|---|---|---|---|
| file | report | Upload inspektionsrapporten | `accept=.pdf` |
| file | spreadsheet | Upload datafilen | `accept=.xlsx,.csv` |

Parameteren `accept` bruger standard filendelsessyntaks (komma-separeret).

### Vejledning til filstørrelse

rtSurvey håndhæver ikke en hård filstørrelsesbegrænsning på spørgsmålsniveau, men serverens uploadgrænse gælder. Brug `hint` til at kommunikere forventninger til intervieweren:

| type | name | label | hint |
|---|---|---|---|
| file | receipt | Upload betalingskvitteringen | Accepteret: PDF eller billede. Maksimal filstørrelse: 5 MB |

### Integration med enhedens filsystem og cloud-lagring

På Android og iOS åbner `file`-spørgsmålet enhedens native filvælger, som kan inkludere adgang til:
- Lokal enhedslagring
- SD-kort (Android)
- iCloud Drive (iOS)
- Google Drive, Dropbox (hvis installeret)

På web åbner den browserens standard filupload-dialog.

### Inline knaplayout

Tilføj `inline` for at gengive upload-knappen som en **cirkulær ikonknap** ved siden af etiketten i stedet for en fuld-bredde filvælger.

```
| type | name | label | appearance |
|---|---|---|---|
| file | doc | Upload dokument | inline display{right} |
| file | doc | Upload dokument | inline display{left, large} |
| file | doc | Upload dokument | inline display{center, large, <0099FF/>} |
```

**Knapposition** – `left`, `right` *(standard)*, `top`, `center`, `bottom`

**Knapstørrelse** – `small` *(standard)*, `medium`, `large`

**Knapfarve** – tilføj en hex-farve inde i `display{}` for at overskrive primærfarven:

```
inline display{right, large, <FF5500/>}
```

**Kontrol efter optagelse — `results{}`:**

| Appearance | Effekt |
|---|---|
| `results{hide(capture)}` | Skjuler upload-knappen, når en fil er vedhæftet |
| `results{hide(review)}` | Skjuler gennemgangs-/forhåndsvisningsknappen efter upload |
| `results{hide(filename)}` | Skjuler filnavnet vist efter upload |
| `results{left}` | Flytter ikon til venstre efter upload |

Eksempel – skjul upload-knappen efter filen er vedhæftet:
```
inline display{right} results{hide(capture)}
```

### Undertryk etiketten

```
inline text-nolabel display{center, large}
```

## Bedste praksis

1. Brug `accept` til at begrænse filtyper — dette forhindrer interviewere i ved et uheld at uploade forkerte filer.
2. Inkluder altid vejledning om størrelse og format i `hint`-kolonnen.
3. For fotos og billeder, brug `image`-typen i stedet — den tilbyder bedre komprimering og konsekvent formatbehandling.
4. For store undersøgelser med filvedhæftninger, planlæg din datalagring og downloadbåndbredde derefter.
5. Test filvælgeren på den tilsigtede enhedstype (Android vs. iOS vs. web) før udrulning — adgang til cloud-drev varierer.

## Datahåndteringsovervejelser

- Filer gemmes i deres originale format; de konverteres eller komprimeres ikke af rtSurvey.
- Analyser filer efter download — rtSurvey udtrækker eller indekserer ikke filindhold.
- Store filvedhæftninger øger betydeligt den tid, det tager at downloade et komplet datasæt.

## Begrænsninger

- Filspørgsmål validerer ikke filindhold — kun filendelseskontrol via `accept` håndhæves på UI-niveau.
- Meget store filer (100 MB+) kan give timeout ved upload i miljøer med lav forbindelse.
- Offline interviewere kan vedhæfte filer, men de uploades ikke, før der er genoprettet forbindelse.
- Nogle enhedskonfigurationer begrænser adgangen til visse lagerplaceringer (f.eks. virksomheds MDM-politikker).
