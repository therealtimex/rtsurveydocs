import { Callout } from 'nextra/components'

`family_path` er et konventionelt calculate-felt, der indeholder stien til formularens bundled mediedirectory. Enhver formular, der udfører lokale databaseopslag med `rawquery`, `pulldata` eller `search()`, skal inkludere dette felt — uden det kan filstier ikke løses, og opslag returnerer lydløst tomme resultater.

---

## Feltet calculate

Tilføj denne række nær toppen af dit survey-ark, efter eventuelle metafeltet og før det første spørgsmål, der bruger en databasefil:

| type | name | label | calculation |
|---|---|---|---|
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |

Feltet gemmer ingen synlig værdi og kræver intet label. Det er en lydløs forudsætning for al efterfølgende konstruktion af stier.

---

## Hvorfor det er nødvendigt

RTSurvey bundler formularmedier — SQLite-databaser, billeder, lydklip — inde i et per-formular directory på enheden. Den nøjagtige sti er forskellig mellem platforme (Android, iOS, web) og mellem enheder.

Under kørsel udfylder appen automatisk `family_path`. En typisk løst værdi ser således ud:

```
resources/familyMedia/Phuong_Person_Test
```

Da stien er platformsspecifik og bestemmes ved opstart, kan den ikke hårdkodes i formularen. `pulldata('app-api', 'family_path')` er den eneste pålidelige måde at hente den på.

---

## Sådan bruges det i stier

Når `family_path` er defineret, kan du bygge en fuld filsti med `concat()`:

```
concat(${family_path}, '/file.db::tableName')
```

Suffikset `::tableName` fjernes, når appen åbner filen; tabelnavnet bruges kun inde i din SQL-forespørgsel.

---

## Hvor family_path bruges

`family_path` er påkrævet i sti-argumentet, hver gang du refererer til en bundled fil:

- **Lokal databasesøgning** — `db_path`-argumentet i `search-autocomplete-noedit-v2('rawquery', ...)` skal bygges med `concat(${family_path}, ...)`. Se [Lokal databasesøgning](local-database-search) for fulde brugsoplysninger.
- **`pulldata` rawquery** — ethvert `pulldata('rawquery', ...)`-kald, der læser fra en `.db`-fil, bruger det samme `concat()`-mønster.
- **`search()` med en lokal fil** — dynamiske søge-appearances, der indlæses fra en bundled CSV- eller DB-fil, afhænger også af `family_path` for filreferencen.

---

## Placering i formularen

`family_path` skal vises **før det første felt, der refererer til det**. Den anbefalede position er umiddelbart efter meta-gruppen:

| type | name | label | calculation |
|---|---|---|---|
| begin_group | meta | | |
| deviceid | deviceid | | |
| start | start | | |
| end | end | | |
| end_group | | | |
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |
| select_one | province | Province | *(rawquery appearance, der refererer til `${family_path}`)* |

<Callout type="warning">
Hvis `family_path` mangler i formularen eller er placeret efter det første `rawquery` / `search()`-felt, der refererer til det, vil alle opslag mod bundled filer lydløst returnere tomme. Der er ingen fejlmeddelelse — autocomplete viser blot ingen resultater.
</Callout>

---

## Flere databasefiler

En enkelt formular kan bruge flere `.db`-filer. Hver sti konstrueres uafhængigt med `concat()`:

```
concat(${family_path}, '/locations.db::externalData')
concat(${family_path}, '/health_facilities.db::facilities')
concat(${family_path}, '/household_list.db::households')
```

Definer `family_path` én gang; referer til den i så mange felter som nødvendigt.

---

## Verifikation under udvikling

Tilføj et midlertidigt `note`-felt under `family_path` for at inspicere den løste værdi på enheden:

| type | name | label | calculation |
|---|---|---|---|
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |
| note | family_path_check | `Sti: ${family_path}` | |

Noten vil vise den faktiske løste sti under test. Fjern den før udrulning af den endelige formular.
