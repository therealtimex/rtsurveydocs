title: "Kald API"
description: "Kald API lader din undersøgelse hente data fra en ekstern webtjeneste og bruge svaret til at udfylde felter eller validere svar."
---

**Kald API**-funktionen lader et spørgeskemafelt foretage en HTTP-anmodning til en ekstern tjeneste og bruge svaret til at udfylde en beregnet værdi eller validere brugerinput. Dette muliggør realtidsopslag, ID-bekræftelse, stregkodeopslag og enhver anden server-side kontrol under dataindsamling.

Der er to funktioner:

-   `callapi()` — henter en værdi fra en API og gemmer den i et `calculate`- eller `text`-felt
-   `callapi-verify()` — kalder en API og blokerer progression, hvis svaret ikke stemmer overens med den forventede værdi (bruges i `constraint`)

---

## `callapi()` — Hent og gem et API-svar

### Syntaks

Placer `callapi()` i **`calculation`**-kolonnen i et `calculate`- eller `text`-felt:

```
callapi(method, url, allowed_auto, max_retry, no_overwrite, extract_expr, timeout, lifetime, response_q, call_type, post_body)
```

### Parametre

| #  | Parameter      | Beskrivelse                                                                       |
|----|----------------|-----------------------------------------------------------------------------------|
| 1  | `method`       | HTTP-metode: `'GET'` eller `'POST'`                                               |
| 2  | `url`          | API-slutpunkt URL                                                                 |
| 3  | `allowed_auto` | `1` for automatisk at kalde, når feltet nås; `0` for at kræve en manuel udløserknap |
| 4  | `max_retry`    | Maksimalt antal genforsøg ved fejl                                                 |
| 5  | `no_overwrite` | `1` for at beholde den eksisterende værdi, hvis feltet allerede har en; `0` for altid at overskrive |
| 6  | `extract_expr` | JSONPath-udtryk for at udtrække den ønskede værdi fra svaret (f.eks. `$.data.name`) |
| 7  | `timeout`      | Anmodnings-timeout i millisekunder                                                |
| 8  | `lifetime`     | Hvor længe (ms) det cachede svar forbliver gyldigt, før der hentes igen            |
| 9  | `response_q`   | Navn på et felt til at gemme den rå HTTP-svarkode (f.eks. `${response_status}`)     |
| 10 | `call_type`    | *(Valgfrit)* Speciel kaldstilstand: `'lazy-upload'` eller `'lazy-upload-multiple'` |
| 11 | `post_body`    | *(Valgfrit)* POST body-streng. Referer til formularfelter med `##fieldname##`      |

### Eksempel: GET-anmodning for at slå en husstand op efter ID

| type    | name         | label           | appearance | calculation                                                                                                           |
|---------|--------------|-----------------|------------|-----------------------------------------------------------------------------------------------------------------------|
| text    | household_id | Husstands-ID    |            |                                                                                                                       |
| calculate | hh_name      |                 | `callapi`    | `callapi('GET', concat('https://api.example.com/households/', ${household_id}), 1, 3, 0, '$.name', 10000, 0, '')` |
| note    | hh_display   | Husstand: `${hh_name}` |            |                                                                                                                       |

### Eksempel: POST-anmodning med en JSON-krop

```
callapi('POST', 'https://api.example.com/lookup', 1, 2, 0, '$.result.value', 15000, 0, '', '', '{"id": "##household_id##"}')
```

I `post_body` skal du bruge `##fieldname##` til at injicere den aktuelle værdi af et hvilket som helst formularfelt.

### Udseende: `callapi`

Tilføj `callapi` til `appearance`-kolonnen i feltet for at aktivere API-kaldsintegrationen:

| type      | name       | label | appearance | calculation             |
|-----------|------------|-------|------------|-------------------------|
| calculate | api_result |       | callapi    | `callapi('GET', ...)` |

Når `allowed_auto` er `0`, viser rtSurvey en **"Hent"-knap**, som indsamleren tapper manuelt.

## `callapi-verify()` — Valider en værdi mod en API

`callapi-verify()` blokerer indsendelse af et felt, indtil en API bekræfter, at den indtastede værdi er gyldig. Brug den i **`constraint`**-kolonnen.

### Syntaks

```
callapi-verify(method, url, extract_expr, match_expr, timeout, constraint_mode, post_body, message)
```

### Parametre

| # | Parameter       | Beskrivelse                                                                                                                              |
|---|-----------------|------------------------------------------------------------------------------------------------------------------------------------------|
| 1 | `method`        | HTTP-metode: `'GET'` eller `'POST'`                                                                                                      |
| 2 | `url`           | Verifikations-API-slutpunkt                                                                                                              |
| 3 | `extract_expr`  | JSONPath for at udtrække den forventede værdi fra svaret                                                                                |
| 4 | `match_expr`    | Udtryk, der sammenligner den udtrukne værdi med feltværdien (f.eks. `$.status = 'valid'`)                                                 |
| 5 | `timeout`       | Anmodnings-timeout i millisekunder                                                                                                       |
| 6 | `constraint_mode` | `'soft'` kun for en advarsel; `'hard'` for at blokere progression                                                                       |
| 7 | `post_body`     | *(Valgfrit)* POST body med `##fieldname##`-erstatninger                                                                                  |
| 8 | `message`       | *(Valgfrit)* Fejlmeddelelse. Understøtter flere sprog: `<en>Invalid!</en><vi>Không hợp lệ!</vi>`                                       |

### Eksempel: Bekræft en stregkode mod et aktivregister

| type    | name       | label               | appearance     | constraint                                                                                                                                                 | constraint_message             |
|---------|------------|---------------------|----------------|------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------|
| barcode | asset_code | Scan aktivets stregkode | callapi-verify | `callapi-verify('POST', 'https://api.example.com/assets/verify', '$.valid', ". = 'true'", 10000, 'hard', '{"code": "##asset_code##"}')` | Aktiv ikke fundet i register |

### Udseende: `callapi-verify(...)`

`appearance`-kolonnen på et felt med `callapi-verify()` i `constraint` skal indeholde `callapi-verify(params)` eller `callapi-verify(dynamicParams)` for at signalere til rtSurvey, at dette felt bruger API-verifikation.

## Brug af App API-data sammen med callapi

Kombiner `callapi()` med `pulldata('app-api', 'user.token')` for at injicere den godkendte brugers token i din API-anmodning:

```
callapi('POST', 'https://api.example.com/data', 1, 2, 0, '$.value', 10000, 0, '', '',
  concat('{"token":"', pulldata('app-api','user.token'), '","id":"##item_id##"}'))
```

## Bedste praksis

1.  Indstil altid en rimelig `timeout` (5000–15000 ms) – brug ikke 0 eller meget høje værdier.
2.  Indstil `allowed_auto=0` for verifikationer, som indsamleren bevidst skal udløse (f.eks. ID-kontroller).
3.  Indstil `no_overwrite=1`, når feltet muligvis skal redigeres senere, og du ikke ønsker, at genhentning skal overskrive manuelle korrektioner.
4.  Brug `extract_expr` med en specifik JSONPath i stedet for at stole på rå svartekst.
5.  Test API-kald i offline-tilstand – callapi vil mislykkes elegant og vise en fejl, men formularen skal stadig kunne udfyldes for ikke-kritiske felter.

## Begrænsninger

-   Kræver netværksforbindelse på tidspunktet for opkaldet – opkald mislykkes, når enheden er offline.
-   API-svar skal være JSON – XML- eller almindelige tekstsvar kræver yderligere parsing.
-   Høj opkaldsfrekvens (f.eks. et API-kald pr. gentagelsesinstans) kan bremse formularnavigationen.
