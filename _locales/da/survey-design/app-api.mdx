AppAPI giver brugere mulighed for at indlæse system metadata fra appen ved hjælp af forskellige metoder i FormEngine og DMView. Den giver adgang til forskellige datanøgler til hentning af specifik information fra appen.

I xlsform kan du bruge `pulldata()`-funktionen med følgende syntaks:

<Callout>pulldata('app-api', 'data-key')</Callout>

-   `'app-api'`: Dette nøgleord informerer FormEngine om at hente data fra App API.
-   `'data-key'`: Dette er nøglen til de data, du vil hente fra App API.
-   Hvis datanøglen er ugyldig eller ikke understøttet, returnerer beregningen "n/a".

Her er de understøttede datanøgler, som du kan bruge med App-API:

`osPlatform`: Returnerer det aktuelle OS-navn (Android eller iOS) og OS-versionen. Webplatforme returnerer en tom værdi.

`appPlatform`: Returnerer app-platformnavnet, som er `rtSurvey`.

`appVersion`: Returnerer appens versionsnavn.

`getDisplayWidth`: Returnerer enhedens skærmbredde i pixels.

`getDisplayHeight`: Returnerer enhedens skærmhøjde i pixels.

`getScreenSize`: Returnerer enhedens skærmstørrelse i tommer.

`projectCode`: Returnerer den aktuelle projektkode for det sted, brugeren logger ind på.

`projectURL`: Returnerer den aktuelle projekt-URL for det sted, brugeren logger ind på. Standard/fallback-værdien er en tom tekst ("").

`startingPoint`: Returnerer stien til det punkt, der starter formularen. Se "Formulars startpunkt" for flere detaljer.

`serverTime`: Returnerer den bedst tilgængelige tilnærmelse af dato og tid på serveren.

`user.[attribute]`: Returnerer de aktuelle brugerattributter baseret på den angivne attributnøgle. Se tabellen "Brugerattributter" for tilgængelige attributnøgler.

Kombiner nedenstående attributnøgler med "user." i `pulldata()`-parametrene for at hente de aktuelle brugeroplysninger. Brug f.eks. `user.username`, `user.email` osv.

| Attribute Key | Beskrivelse                          |
|---------------|--------------------------------------|
| username      | Brugernavn på brugeren               |
| name          | Brugerens fulde navn                 |
| staffCode     | Brugerens staff-kode                 |
| phone         | Brugerens telefonnummer              |
| email         | Brugerens e-mailadresse              |
| description   | Beskrivelsestekst i brugerinformation |
| organization_id | Organisations-ID brugeren tilhører    |
| organization_name | Organisationsnavn brugeren tilhører  |
| team_id       | Team-ID brugeren tilhører            |
| supervisor_id | ID på brugerens supervisor           |
| is_supervisor | 1 hvis brugeren er supervisor, 0 hvis ikke |

`instancePath`: Returnerer den aktuelle instansmappesti.

`appLanguage`: Returnerer den aktuelle app-sprogindstilling i appens indstillinger (f.eks. vi, en).

`openArgs.[attribute]`: Returnerer open-form-argumentet, der er sendt fra handlingsknappen (act_fill_form, act_get_instance). Standard/fallback-værdien er en tom tekst ("").

`primaryAppColor`: Henter appens primærfarve.

## Eksempler på brug

### Gem indsamlerens brugernavn og organisation

| type      | name             | label | calculation                           |
|-----------|------------------|-------|---------------------------------------|
| calculate | enumerator_name  |       | `pulldata('app-api', 'user.name')`    |
| calculate | enumerator_org   |       | `pulldata('app-api', 'user.organization_name')` |
| calculate | enumerator_email |       | `pulldata('app-api', 'user.email')`   |

Brug disse i note-etiketter til revisionsformål:
```
note | interviewer_info | Interviewer: ${enumerator_name} (${enumerator_org})
```

### Enheds- og skærmoplysninger

| type      | name            | label | calculation                        |
|-----------|-----------------|-------|------------------------------------|
| calculate | device_platform |       | `pulldata('app-api', 'osPlatform')` |
| calculate | app_ver         |       | `pulldata('app-api', 'appVersion')` |
| calculate | screen_w        |       | `pulldata('app-api', 'getDisplayWidth')` |

Nyttigt til fejlfinding: eksporter `device_platform` og `app_ver` sammen med dine data for at identificere, hvilken enhedsversion der blev brugt til hver indsendelse.

### Servertid i stedet for enhedstid

Enhedsure kan være forkerte. Brug `serverTime` for et mere pålideligt tidsstempel:

| type      | name      | label | calculation                       |
|-----------|-----------|-------|-----------------------------------|
| calculate | server_ts |       | `pulldata('app-api', 'serverTime')` |

### Betinget logik baseret på brugerrolle

Vis en supervisor-only sektion kun for supervisorer:

| type        | name             | label            | relevant                          |
|-------------|------------------|------------------|-----------------------------------|
| calculate   | is_supervisor    |                  | `pulldata('app-api', 'user.is_supervisor')` |
| begin_group | supervisor_section | Supervisor review | `${is_supervisor} = '1'`          |
| text        | supervisor_notes | Supervisor notes |                                   |
| end_group   |                  |                  |                                   |

### Send argumenter fra en handlingsknap

Når formularen startes fra en `act_fill_form` handlingsknap med brugerdefinerede argumenter:

| type      | name           | label | calculation                                 |
|-----------|----------------|-------|---------------------------------------------|
| calculate | passed_hh_id   |       | `pulldata('app-api', 'openArgs.household_id')` |
| calculate | passed_task    |       | `pulldata('app-api', 'openArgs.task_code')`   |

Handlingsknappen skal sende argumenterne med matchende nøgler (f.eks. `household_id`, `task_code`).

### Brug af projektinformation

| type      | name        | label | calculation                       |
|-----------|-------------|-------|-----------------------------------|
| calculate | project     |       | `pulldata('app-api', 'projectCode')` |
| calculate | project_url |       | `pulldata('app-api', 'projectURL')` |

## Bemærkninger

-   Alle `pulldata('app-api', ...)`-kald evalueres, når formularen åbnes, og genudevalueres ikke dynamisk under sessionen (undtagen `serverTime` og `now()`).
-   Hvis en nøgle ikke understøttes, eller data ikke er tilgængelige, returnerer funktionen `'n/a'` (ikke tom streng – test med `!= 'n/a'` snarere end `!= ''`).
-   `openArgs`-værdier er kun tilgængelige, når formularen startes fra en handlingsknap; de returnerer ellers en tom streng.
