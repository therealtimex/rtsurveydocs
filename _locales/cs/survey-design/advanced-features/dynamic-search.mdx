title: "Dynamické vyhledávání"
description: "Dynamické vyhledávání načítá možnosti z externího API v reálném čase během psaní tazatele, což umožňuje práci s rozsáhlými nebo často aktualizovanými datovými sadami."
---

**Dynamické vyhledávání** (také nazývané Search API) umožňuje polím typu `select_one`, `select_multiple` nebo `text` načítat možnosti z externí webové služby **v reálném čase** během psaní tazatele. To je správný přístup v případech, kdy je seznam možností příliš velký na to, aby byl součástí souboru CSV, je často aktualizován nebo pochází z živé databáze.

---

## Vzhled `search-api()`

Dynamické vyhledávání se konfiguruje v sloupci `appearance` pomocí funkce `search-api()`:

```
search-api(method, url, post_body, value_column, display, data_path, save_path)
```

### Parametry

| Parametr | Popis |
|-----------|-------------|
| `method` | Vždy použijte `'POST'` |
| `url` | Koncový bod API (endpoint) pro dotazování |
| `post_body` | Tělo JSON zasílané do API. Použijte `%__input__%` jako zástupný symbol pro aktuální text vyhledávání tazatele |
| `value_column` | Klíč v objektu odpovědi, který se použije jako uložená **hodnota** (value) |
| `display` | Klíč (nebo šablona), který se použije jako **popisek** (label) zobrazený v rozevíracím seznamu. Podporuje zástupné symboly `##key##` a výrazy `@{func}` |
| `data_path` | JSONPath k poli výsledných objektů v odpovědi (např. `$.data`, `$.hits.hits.*._source`) |
| `save_path` | Název, pod kterým se uloží nezpracovaná odpověď pro použití v jiných polích |

## Základní příklad

Vyhledávání zdravotnického zařízení, kde tazatel píše část názvu zařízení:

| type | name | label | appearance |
|------|------|-------|------------|
| select_one | facility | Vyberte zdravotnické zařízení | `search-api('POST', 'https://api.example.com/facilities/search', '{"query": "%__input__%"}', 'id', 'name', '$.results', 'facility_data')` |

API obdrží `{"query": "nair"}` ve chvíli, kdy tazatel napíše „nair“, a vrátí:

```json
{
  "results": [
    {"id": "HF001", "name": "Nairobi Central Clinic"},
    {"id": "HF002", "name": "Nairobi West Hospital"}
  ]
}
```

V rozevíracím seznamu se zobrazí `Nairobi Central Clinic` a `Nairobi West Hospital`; uložená hodnota je `HF001` nebo `HF002`.

---

## Pokročilé formátování zobrazení

### Použití šablon `##key##`

Zobrazení více polí v popisku:

```
search-api('POST', 'https://api.example.com/search', '{"q": "%__input__%"}', 'id', '##name## (##district##)', '$.data', 'res')
```

Zobrazeno jako: `Nairobi Central Clinic (Nairobi)`.

### Použití výrazů `@{func}`

Použití podmíněné logiky v popisku zobrazení:

```
search-api('POST', 'https://api.example.com/search', '{"q": "%__input__%"}', 'id',
  '@{if_else(eq("##status##", "active"), "✓ ##name##", "✗ ##name##")}',
  '$.data', 'res')
```

Aktivní výsledky zobrazí `✓ Clinic Name`; neaktivní zobrazí `✗ Clinic Name`.

---

## Nastavení výchozí hodnoty: `search-default-api()`

Použijte `search-default-api()` za `search-api()` pro předvyplnění pole výchozí volbou načtenou z odděleného volání API (např. při úpravě existujícího záznamu):

```
appearance: search-api(...) search-default-api('POST', 'https://api.example.com/get', '{"id": "##saved_id##"}', 'id', 'name', '$.item')
```

---

## Vlastní oddělovač pro select_multiple: `search-default-separator()`

U polí `select_multiple` určete, jak budou vybrané hodnoty spojeny v uloženém řetězci:

```
appearance: search-api(...) search-default-separator(' || ')
```

Výchozím oddělovačem je mezera.

## Podporované typy otázek

| Typ otázky | Případ použití |
|---------------|----------|
| `select_one` | Jeden výběr z výsledků vyhledávání |
| `select_multiple` | Více výběrů z výsledků vyhledávání |
| `text` | Automatické doplňování – tazatel píše volně, ale může vybrat návrh |

## Použití uložených dat odpovědi

Když tazatel vybere výsledek, rtSurvey uloží celý odpovídající objekt z odpovědi pod názvem `save_path`. Ostatní pole z něj mohou číst dvěma způsoby.

### Metoda 1 – vyhledávání pomocí `pulldata()`

Použijte `pulldata('save_path', 'key')` k načtení pole nejvyšší úrovně z uloženého objektu:

| type | name | label | calculation |
|------|------|-------|-------------|
| select_one | facility | Vyberte zařízení | |
| calculate | facility_district | | `pulldata('facility_data', 'district')` |
| calculate | facility_type | | `pulldata('facility_data', 'type')` |
| calculate | facility_beds | | `pulldata('facility_data', 'beds')` |

Vzhled (appearance) v řádku `select_one` musí obsahovat `search-api(..., 'facility_data')` s odpovídajícím `save_path`.

Pro **vnořená JSON pole** kombinujte s `substr-jsonpath()`:

```
substr-jsonpath(pulldata('facility_data', 'location'), '$.district')
```

## Vyhledávání v lokálním souboru pomocí search()

`search()` provádí offline vyhledávání shody sloupců v přibaleném souboru SQLite `.db` – nevyžaduje připojení k síti ani SQL dotazy. Použijte jej, pokud jsou vaše referenční data součástí formuláře a potřebujete jednoduché vyhledávání ve stylu „najdi všechny řádky, kde se sloupec rovná hodnotě“.

### Signatura

```
search(path, 'matches', 'list_name', ${field})
```

### Parametry

| Parametr | Popis |
|-----------|-------------|
| `path` | Cesta k tabulce SQLite: `concat(${family_path}, '/file.db::table')` |
| `'matches'` | Operátor shody – vrací řádky, kde se sloupec rovná hodnotě |
| `'list_name'` | Název sloupce, se kterým se má provést porovnání |
| `${field}` | Hodnota pro porovnání; obvykle odkaz na pole |

### Příklad

Naplnění pole `select_one` z lokální databáze porovnáním hodnoty `${d307}` se sloupcem `list_name` v tabulce `externalData` v souboru `d307.db`:

| type | name | label | appearance |
|------|------|-------|------------|
| select_one | facility | Vyberte zařízení | `search(concat(${family_path}, '/d307.db::externalData'), 'matches', 'list_name', ${d307})` |

Když se `${d307}` rovná `"HF001"`, `search()` vrátí každý řádek v `externalData`, kde `list_name = 'HF001'` – zcela z přibaleného souboru, bez síťového volání.

### search() vs. automatické doplňování rawquery

| Funkce | `search()` | Automatické doplňování `rawquery` |
|---------|-----------|------------------------|
| SQL dotazy | Ne – pouze shoda sloupců | Ano – plné `SELECT … FROM …` |
| Parametrizovaný vstup | Shoda hodnoty sloupce | Vložený v řetězci SQL |
| Volné zadávání textu | Ano – tazatel může psát volně | Ne – musí vybrat ze seznamu |
| UNION / více tabulek | Nepodporováno | Podporováno |

### Kdy použít kterou možnost

- Použijte **`search()`**, pokud potřebujete přímočarou shodu rovnosti v přibaleném souboru `.db`, formulář musí fungovat offline a chcete povolit volné zadávání textu.
- Použijte **automatické doplňování `rawquery`**, pokud potřebujete flexibilitu SQL (JOIN, UNION, vypočítané sloupce) nebo musíte dotazovat více tabulek a formulář má spolehlivé připojení.

## Osvědčené postupy

1. Zajistěte, aby váš koncový bod API odpovídal do 1–2 sekund – pomalá API způsobují, že vyhledávání působí zasekaně.
2. Použijte `%__input__%` v `post_body`, aby API vracelo pouze odpovídající výsledky, nikoli celou datovou sadu.
3. Indexujte vyhledávací pole na straně serveru (např. Elasticsearch, fulltextový index databáze) pro rychlé odpovědi.
4. Omezte výsledky na 20–50 položek na dotaz – vracení tisíců výsledků popírá účel vyhledávání.
5. Zahrňte do API požadavek na minimální délku vstupu, abyste zabránili spouštění širokých dotazů při zadání jediného znaku.

## Omezení

- Dynamické vyhledávání vyžaduje síťové připojení – nefunguje offline.
- Zástupný symbol `%__input__%` je vložen tak, jak je; na straně serveru vstupy ošetřete, abyste zabránili útokům typu injection.
- Složité zobrazovací výrazy `@{func}` mohou mít omezenou podporu ve všech verzích klientů rtSurvey.
