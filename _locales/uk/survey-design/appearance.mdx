Стовпець `appearance` в rtSurvey дозволяє налаштовувати візуальне представлення та поведінку запитань у ваших опитуваннях. Ця функція покращує досвід користувача та може значно підвищити ефективність збору даних. rtSurvey підтримує стандартні атрибути зовнішнього вигляду XLSForm та розширює їх додатковими опціями.

## Стандартні атрибути зовнішнього вигляду XLSForm

rtSurvey підтримує наступні стандартні атрибути зовнішнього вигляду XLSForm:

| Атрибут зовнішнього вигляду | Типи запитань | Опис |
|-----------------------------|---------------|------|
| multiline | text | Створює багаторядкове текстове поле (найкраще для веб-клієнтів) |
| minimal | select_one, select_multiple | Відображає варіанти у випадаючому меню |
| quick | select_one | Автоматично переходить до наступного запитання після вибору (тільки для мобільних пристроїв) |
| no-calendar | date | Приховує відображення календаря (тільки для мобільних пристроїв) |
| month-year | date | Дозволяє вибирати тільки місяць та рік |
| year | date | Дозволяє вибирати тільки рік |
| horizontal-compact | select_one, select_multiple | Відображає варіанти горизонтально (тільки для веб-версії) |
| horizontal | select_one, select_multiple | Відображає варіанти горизонтально у стовпцях (тільки для веб-версії) |
| likert | select_one | Представляє варіанти як шкалу Лайкерта |
| compact | select_one, select_multiple | Відображає варіанти поруч із мінімальним відступом |
| quickcompact | select_one | Поєднує компактне відображення з автоматичним переходом (тільки для мобільних пристроїв) |
| field-list | groups | Відображає всю групу на одному екрані (тільки для мобільних пристроїв) |
| label | select_one, select_multiple | Показує мітки варіантів без полів введення |
| list-nolabel | select_one, select_multiple | Показує поля введення без міток (використовуйте з `label`) |
| table-list | groups | Відображає запитання у форматі таблиці |
| signature | image | Вмикає захоплення підпису (тільки для мобільних пристроїв) |
| draw | image | Дозволяє малювання від руки (тільки для мобільних пристроїв) |
| map, quick map | select_one, select_one_from_file | Вмикає вибір з об'єктів на карті |

## Найкращі практики використання зовнішнього вигляду

1. **Послідовність**: Використовуйте атрибути зовнішнього вигляду послідовно в усьому опитуванні для забезпечення єдиного вигляду.
2. **Мобільні пристрої проти веб-версії**: Враховуйте, як зовнішній вигляд буде відображатися на різних пристроях та платформах.
3. **Продуктивність**: Будьте обережні з атрибутами зовнішнього вигляду, які можуть уповільнити завантаження форми (наприклад, `table-list` для великих груп).
4. **Досвід користувача**: Вибирайте зовнішній вигляд, який робить введення даних простішим та інтуїтивно зрозумілішим для респондентів.
5. **Тестування**: Завжди тестуйте свою форму на цільових пристроях, щоб переконатися, що зовнішній вигляд працює належним чином.

## Просунуті техніки

### Поєднання зовнішнього вигляду

Деякі атрибути зовнішнього вигляду можна поєднувати для складніших макетів:

```
| type | name | label | appearance |
|------|------|-------|------------|
| select_one options | choice | Виберіть один: | minimal compact |
```

### Динамічний зовнішній вигляд

rtSurvey дозволяє динамічно змінювати зовнішній вигляд на основі логіки форми:

```
| type | name | label | appearance | relevant |
|------|------|-------|------------|----------|
| text | time | Введіть час: | inline-[%H:%M] | ${show_time} = 'yes' |
```

## Особливості для мобільних додатків

- Деякі види зовнішнього вигляду (наприклад, `quick`, `signature`) призначені спеціально для мобільних пристроїв.
- Ретельно протестуйте на Android та iOS, щоб забезпечити послідовну поведінку.

## Розширені атрибути зовнішнього вигляду rtSurvey

На додаток до стандартних атрибутів XLSForm, rtSurvey підтримує наступні специфічні для платформи опції:

### Керування даними та відображенням

| Атрибут зовнішнього вигляду | Типи запитань | Опис |
|-----------------------------|---------------|------|
| `invisible` | будь-який | Приховує поле від перегляду, водночас продовжуючи збирати або обчислювати його значення. Відрізняється від типу `hidden` — поле все одно бере участь у логіці. |
| `displaytitle` | будь-який | Примусово відображає мітку/заголовок поля, навіть якщо зазвичай вони приховуються. |
| `autopull` | select_one, select_multiple | Автоматично отримує зовнішні дані для заповнення варіантів при завантаженні форми або зміні поля-тригера. |
| `floating_hint` | text, integer, decimal | Показує текст підказки як плаваючу мітку над полем введення, а не під ним. |
| `calculate-button` | calculate | Додає видиму кнопку, яка запускає перерахунок поля на вимогу, замість автоматичного обчислення. |

### Групи та навігація

| Атрибут зовнішнього вигляду | Типи запитань | Опис |
|-----------------------------|---------------|------|
| `section` | group | Відображає групу як картку розділу, що згортається. Примітка: тільки для мобільних додатків. |
| `toc-hide` | будь-який | Виключає запитання з панелі навігації за змістом (TOC). |
| `minilog` | begin_repeat | Відображає завершені записи повторів як компактний список міні-журналу, а не розгортає кожен запис у тексті. |

### Поведінка введення

| Атрибут зовнішнього вигляду | Типи запитань | Опис |
|-----------------------------|---------------|------|
| `proper` | text | Автоматично робить першу літеру кожного слова великою під час введення (поведінка як у заголовках). |
| `text-nolabel` | text, integer, decimal | Відображає поле введення без видимої мітки. |
| `inline-1line` | text | Примушує текстове введення відображатися в один рядок, навіть якщо мітка запитання довга. |
| `popup` | будь-який | Відображає поле всередині спливаючого вікна / модального накладання, а не безпосередньо на сторінці. |

### Макет

| Атрибут зовнішнього вигляду | Типи запитань | Опис |
|-----------------------------|---------------|------|
| `1screen` | group | Примушує всю групу відображатися на одному екрані незалежно від розміру групи. |
| `columns(n)` | select_one, select_multiple | Відображає варіанти у `n` стовпцях. Приклад: `columns(3)` показує три стовпці перемикачів. |
| `gridformat<row=R col=C colspan=S align=center>` | будь-який | Розміщує поле в макеті CSS-сітки у рядку `R`, стовпці `C`, охоплюючи `S` стовпців. Використовується з `advanced-extension/grid-layout`. |
| `ignore-simplify` | будь-який | Наказує рендереру форми пропустити автоматичне спрощення або ущільнення макета цього поля. |
| `horizontal(N)` | select_one, select_multiple | Встановлює кожен варіант так, щоб він займав `N` відсотків ширини рядка. Приклад: `horizontal(50)` розміщує два варіанти у рядку. |
| `scroll-view(N%)` | group, repeat | Обмежує контейнер максимальною висотою `N%` від вікна перегляду (або батьківського елемента), додаючи смугу прокрутки, коли вміст переповнюється. Приклад: `scroll-view(60%)`. |

### Віджети

| Атрибут зовнішнього вигляду | Типи запитань | Опис |
|-----------------------------|---------------|------|
| `likert` | select_one | Представляє варіанти як рядок шкали Лайкерта (вже є у стандартній таблиці вище; підтверджено підтримку). |
| `distress` | select_one | Відображає варіанти як візуальний віджет шкали психологічного дистресу Кесслера (K10) з емоційними іконками. |
| `rating_box-fill-{c1}-{c2}-{c3}-{c4}-{c5}` | select_one | Відображає варіанти як стилізовані поля оцінювання з п'ятьма колірними слотами. `c1` = межа зовнішнього контейнера, `c2` = межа невідміченого поля, `c3` = межа та заповнення відміченого поля, `c4` = колір тексту невідміченого поля, `c5` = колір тексту відміченого поля. Приклад: `rating_box-fill-grey-blue-green-black-white`. |
| `tagging-choices-noshow-v2-{c1}-{c2}-{c3}-{c4}-{c5}` | select_multiple | Відображає варіанти як кольорові теги-чіпи. П'ять колірних слотів відповідають тому самому порядку, що і в `rating_box-fill`. Вибрані варіанти підсвічуються; невибрані варіанти приховуються з підсумкового перегляду. |

### Інтеграція API

| Атрибут зовнішнього вигляду | Типи запитань | Опис |
|-----------------------------|---------------|------|
| `callapi` | text, integer, decimal, select_one | Вмикає інтеграцію викликів API для цього поля. Стовпець обчислення має містити вираз `callapi()`. Див. [Call API](advanced-features/call-api). |
| `callapi-verify(params)` | text, integer, decimal | Запускає виклик верифікації API з використанням статичних параметрів. Форма блокує прогрес, доки API не підтвердить значення. |
| `callapi-verify(dynamicParams)` | text, integer, decimal | Те саме, що `callapi-verify`, але з параметрами, отриманими з значень інших полів під час виконання. |

### Перемикач мов

| Атрибут зовнішнього вигляду | Типи запитань | Опис |
|-----------------------------|---------------|------|
| `change_language-{colors} default('lang')` | note, text | Відображає віджет перемикача мов, стилізований згідно з наданими кодами кольорів. Токен `default('lang')` встановлює початкову мову (наприклад, `default('en')`); він перезаписується на `rtDefault('lang')` внутрішньо під час парсингу. Приклад: `change_language-blue-white default('vi')`. |

### Формат дати/часу в тексті

Для полів `date`, `time` та `datetime` ви можете вказати власний формат відображення за допомогою рядка формату, доданого до атрибута зовнішнього вигляду:

```
inline-[%d/%m/%Y]
inline-1line-[%d/%m/%Y %H:%M]
```

Токени формату такі самі, як у функціях `format-date()` та `format-date-time()`. Див. [Функції — Функції дати та часу](operators-and-functions/functions#date-and-time-functions).

Приклад:

| type | name | label | appearance |
|------|------|-------|------------|
| datetime | event_time | Дата та час події | inline-[%d/%m/%Y %I:%M %p] |
| date | birth_date | Дата народження | inline-[%d/%m/%Y] |

### Макет кнопок у тексті — `display{}` та `results{}`

Для типів запитань, які відображаються як іконка-кнопка в тексті (`date`, `time`, `datetime`, `image`, `audio`, `video`, `file`, `barcode`, `geopoint`), два модифікатори зовнішнього вигляду керують положенням кнопки та поведінкою після захоплення.

#### `display{...}` — положення кнопки до захоплення

```
display{<align>, <size>, <color>}
```

| Параметр | Значення | За замовчуванням |
|----------|----------|-----------------|
| Align | `left`, `right`, `top`, `center`, `bottom` | `right` |
| Size | `small`, `medium`, `large` | `small` |
| Color | hex, наприклад `#FF5500` | основний колір теми |
| Flag | `inline-icon` | примусовий режим іконки |

| Значення Align | Макет |
|----------------|-------|
| `right` | Кнопка праворуч від мітки |
| `left` | Кнопка ліворуч від мітки |
| `top` | Кнопка над міткою, центрована по всій ширині |
| `center` / `bottom` | Кнопка під міткою, центрована по всій ширині |

#### `results{...}` — макет та видимість після захоплення

Успадковує налаштування `display{}`. Використовуйте для переміщення кнопки або приховування елементів після того, як значення було захоплено.

```
results{<align>, hide(<element>)}
```

| Значення `hide` | Ефект |
|---|---|
| `hide(capture)` | Приховує кнопку захоплення, як тільки файл/значення з'являється |
| `hide(review)` | Приховує мініатюру перегляду / кнопку відтворення |
| `hide(filename)` | Приховує ім'я файлу, що показується після завантаження |
| `hide(camera)` | Приховує кнопку спуску камери після захоплення |
| `hide(scanner)` | Приховує кнопку сканування штрих-коду після того, як значення відскановано |
| `hide(value)` | Приховує текст відсканованого значення (штрих-код / geopoint) |

Віджет автоматично перемикається з макета `display{}` на `results{}` у момент захоплення значення.

**Приклади:**

```
inline display{right}                                    → іконка праворуч від мітки
inline display{left, large}                              → велика іконка ліворуч
inline display{center, large, #FF5500}                   → велика помаранчева іконка під міткою
inline display{right} results{left}                      → іконка переміщується ліворуч після захоплення
inline display{right} results{hide(capture)}             → іконка зникає після захоплення
inline display{center} results{hide(capture), hide(filename)}
```

## Відомі обмеження

- Складні види зовнішнього вигляду можуть відображатися не однаково на всіх платформах.
- Деякі розширені види зовнішнього вигляду rtSurvey можуть не підтримуватися в офлайн-режимі.

## Усунення несправностей зовнішнього вигляду

1. **Зовнішній вигляд не застосовано**: Перевірте наявність друкарських помилок у стовпці appearance.
2. **Непослідовний рендеринг**: Перевірте сумісність із типом запитання та платформою.
3. **Проблеми з продуктивністю**: Подумайте про спрощення складних видів зовнішнього вигляду, особливо для великих опитувань.
