**Пошук у локальній базі даних** дозволяє полям `select_one` або `text` запитувати файл SQLite `.db`, який входить до медіа-пакету форми — повністю в автономному режимі, без звернення до сервера. Це правильний підхід, якщо ваш список варіантів великий і статичний (наприклад, національний список сіл, медичних установ або адміністративних кордонів), а зв'язок не може бути гарантований.

| Підхід | Джерело даних | Потрібне підключення |
|---|---|---|
| Пошук у локальній базі даних (`rawquery`) | Вбудований файл `.db` (SQLite) | Ні |
| `search-api()` | Віддалений REST API | Так |
| `search()` | Вбудований CSV-файл | Ні |

---

## Варіанти відображення (Appearance)

Поле автозаповнення налаштовується через колонку `appearance`. Доступні три варіанти:

| Варіант | Примітки |
|---|---|
| `search-autocomplete-noedit(...)` | Стандартне автозаповнення — інтерв'юер повинен вибрати зі списку; введення довільного тексту не зберігається |
| `search-autocomplete-noedit-v2(...)` | Рекомендований варіант — така сама поведінка, але використовується оновлений рушій рендерингу з кращою продуктивністю на великих наборах результатів |
| `search(...)` | Просте зіставлення на основі вбудованого CSV-файлу; **не** підтримує чистий SQL — наведено тут лише для порівняння |

<Callout type="info">
`search-autocomplete-noedit` — це псевдонім; під час парсингу додаток замінює його внутрішнім ім'ям функції `searchAutocompleteNoedit`. Використовуйте будь-яке написання у вашій XLS-формі; обидва працюють.
</Callout>

## Джерело даних `rawquery`

Щоб запустити SQL-запит до файлу `.db`, передайте `'rawquery'` як перший аргумент функції appearance. Повна сигнатура:

```
search-autocomplete-noedit-v2(
  'rawquery',
  <db_path>,
  '[display_col]',
  'value_col',
  'SELECT ...',
  param1, param2, ...
)
```

### Параметри

| Позиція | Параметр | Опис |
|---|---|---|
| 1 | `'rawquery'` | Літеральний рядок — вказує додатку виконувати SQL безпосередньо |
| 2 | `db_path` | Шлях до файлу SQLite у форматі `<dir>/<file>.db::tableName`. Суфікс `::tableName` відсікається під час відкриття файлу; ім'я таблиці використовується всередині вашого SQL-запиту |
| 3 | `'[display_col]'` | Колонка для відображення у випадаючому списку. Квадратні дужки `[ ]`, що оточують ім'я, відсікаються під час виконання |
| 4 | `'value_col'` | Колонка, значення якої зберігається, коли інтерв'юер робить вибір |
| 5 | `'SELECT ...'` | Будь-який допустимий оператор SQLite SELECT. `SELECT DISTINCT` впроваджується автоматично, якщо `DISTINCT` ще не присутній |
| 6+ | `param1, ...` | Необов'язково. Значення, прив'язані до плейсхолдерів `?` в SQL по порядку. Якщо SQL містить `?`, але параметри не вказані, поле повертає порожнє значення (вбудований захист від відсутніх аргументів) |

### Угода `db_path`

Файл бази даних знаходиться всередині вбудованого медіа-каталогу форми. Під час виконання `pulldata('app-api', 'family_path')` повертає шлях до цього каталогу. Див. [family_path](family-path) для отримання детальної інформації про налаштування. Стандартний шаблон:

```
concat(${family_path}, '/mydata.db::tableName')
```

Коли додаток відкриває файл, він відсікає частину `::tableName` і використовує чистий шлях до файлу. Ім'я таблиці з'являється тільки всередині вашого SQL-запиту.

## Базовий приклад — пошук провінції

Випадаючий список провінцій тільки для читання, що працює на базі вбудованого файлу `vnxa3.db`:

| type | name | label | appearance | calculation |
|---|---|---|---|---|
| calculate | family_path | | | `pulldata('app-api', 'family_path')` |
| select_one | province | Провінція | `search-autocomplete-noedit-v2('rawquery', concat(${family_path}, '/vnxa3.db::externalData'), '[provv]', 'provid', 'SELECT provv, provid FROM externalData WHERE rta_filter = "1"')` | |

Колонка `appearance` (розгорнута для зручності читання):

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[provv]', 'provid',
  'SELECT provv, provid FROM externalData WHERE rta_filter = "1"')
```

- Мітка, що відображається, береться з колонки `provv`.
- Збережене значення береться з колонки `provid`.
- Показуються тільки рядки, де `rta_filter = "1"`.

## Параметризовані запити

Використовуйте плейсхолдери `?` в SQL і передавайте відповідні посилання на поля як додаткові аргументи (починаючи з 6-ї позиції). Це стандартний шаблон для каскадних виборів — наприклад, завантаження районів, що належать раніше обраній провінції.

<Callout type="warning">
Якщо ваш SQL містить хоча б один знак `?` і аргументи параметрів не вказані, поле повертає порожній набір результатів. Це запобігає появі застарілих або неактуальних даних до того, як буде зроблено батьківський вибір.
</Callout>

### Приклад каскаду районів

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[distv]', 'distid',
  'SELECT distv, distid FROM externalData
   WHERE provid = ? AND rta_filter = "1"',
  ${province})
```

Значення `${province}` прив'язується до першого знака `?`. Поле залишається порожнім, поки інтерв'юер не вибере провінцію.

### Приклад із двома параметрами — каскад комун

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[commv]', 'commid',
  'SELECT commv, commid FROM externalData
   WHERE provid = ? AND distid = ? AND rta_filter = "1"',
  ${province}, ${district})
```

Параметри прив'язуються позиційно: `${province}` → перший `?`, `${district}` → другий `?`.

## UNION SELECT для спеціальних значень

Впроваджуйте синтетичні рядки — такі як «Не знаю» або «Відмова від відповіді» — безпосередньо в SQL за допомогою `UNION SELECT`:

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[provv]', 'provid',
  'SELECT provv, provid FROM externalData WHERE rta_filter = "1"
   UNION SELECT "<i>Не знаю</i>", "888"')
```

Угоди, що використовуються у формах RTSurvey:

| Код | Значення |
|---|---|
| `888` | Не знаю |
| `999` | Відмова від відповіді |

HTML-теги, такі як `<i>`, у рядку відображення рендеряться додатком — ви можете використовувати їх для візуального виділення спеціальних опцій.

## Багатомовне відображення

Зберігайте мовні мітки в окремих колонках (наприклад, `label_vi`, `label_en`) і вибирайте відповідну на основі поля мови у вашій формі:

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[label_vi]', 'provid',
  'SELECT label_vi, label_en, provid FROM externalData
   WHERE rta_filter = "1"')
```

Щоб динамічно перемикати колонки на основі поля `${language}`, використовуйте вираз `if()` у параметрі колонки відображення для перемикання між мовними колонками:

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  if(${language} = 'vi', '[label_vi]', '[label_en]'),
  'provid',
  'SELECT label_vi, label_en, provid FROM externalData
   WHERE rta_filter = "1"')
```

<Callout type="info">
Параметр колонки відображення обчислюється перед запуском запиту. В SQL-рушій передається тільки ім'я колонки (без дужок); дужки є косметичними маркерами, що відсікаються під час парсингу.
</Callout>

## Перевірка реального вибору

Якщо поле допускає спеціальні значення, такі як 888 или 999, звичайної перевірки `required = yes` недостатньо — вона виконується, навіть якщо інтерв'юер вибирає «Не знаю». Використовуйте обмеження `selected-at(., 0) != -997`, щоб переконатися, що збережене значення є реальним вибором, а не внутрішнім маркером «нічого не вибрано» `-997`:

| колонка | значення |
|---|---|
| constraint | `selected-at(., 0) != -997` |
| constraint_message | Будь ласка, виберіть коректний варіант |

Значення `-997` — це внутрішній код, який RTSurvey зберігає, коли жоден елемент не був обраний зі списку автозаповнення. Вибір 888 або 999 все одно є свідомим вибором і проходить цю перевірку.

Щоб додатково вимагати реальне (не спеціальне) значення, розширте обмеження:

```
selected-at(., 0) != -997 and selected-at(., 0) != '888' and selected-at(., 0) != '999'
```

## Порівняння: локальна база даних та інші методи пошуку

| Функція | Автозаповнення `rawquery` | `search-api()` | `search()` CSV | Звичайні CSV-варіанти |
|---|---|---|---|---|
| Джерело даних | Вбудований `.db` (SQLite) | Віддалений REST API | Вбудований CSV | Аркуш Choices |
| Працює офлайн | Так | Ні | Так | Так |
| Підтримка чистого SQL | Так | Ні | Ні | Ні |
| Каскадні фільтри | Так — параметризований `?` | Через тіло запиту | Обмежено | Ні |
| Розмір набору даних | Дуже великий (мільйони рядків) | Необмежений (на стороні сервера) | Середній (десятки тисяч) | Маленький |
| Спеціальні впроваджені рядки | Так — `UNION SELECT` | Ні | Ні | Так (вручну) |
| Складність налаштування | Середня — потрібен вбудований `.db` | Висока — потрібен API-сервер | Низька | Немає |

## Обмеження

- Файл `.db` повинен бути включений до медіа-пакету форми перед розгортанням. Динамічні оновлення бази даних вимагають нового розгортання форми.
- SQL виконується на пристрої «як є». На стороні сервера очищення (sanitization) не проводиться — уникайте створення SQL-запитів на основі довільного текстового введення інтерв'юера.
- Підтримуються тільки оператори `SELECT`. `INSERT`, `UPDATE` та `DELETE` не дозволені.
- Дуже складні запити (великі ланцюжки `UNION`, множинні приєднання) можуть повільно працювати на бюджетних Android-пристроях.
- Варіанти `search-autocomplete-noedit` не дозволяють інтерв'юеру зберегти значення, якого немає в наборі результатів. Якщо потрібне введення довільного тексту, використовуйте окреме поле `text`.
- `SELECT DISTINCT` впроваджується автоматично тільки в тому випадку, якщо `DISTINCT` відсутній у запиті. Якщо ви напишете `SELECT DISTINCT` явно, воно не буде дублюватися.
