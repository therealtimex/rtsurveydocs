---

**Динамічний пошук** (також відомий як Search API) дозволяє полю типу `select_one`, `select_multiple` або `text` завантажувати варіанти вибору з віддаленого веб-сервісу **під час виконання**, коли реєстратор вводить текст. Це правильний підхід, коли ваш список варіантів занадто великий для включення у CSV-файл, часто оновлюється або походить з «живої» бази даних.

---

## Вигляд (appearance) `search-api()`

Динамічний пошук налаштовується через стовпець `appearance` за допомогою функції `search-api()`:

```
search-api(method, url, post_body, value_column, display, data_path, save_path)
```

### Параметри

| Параметр | Опис |
|-----------|-------------|
| `method` | Завжди використовуйте `'POST'` |
| `url` | Кінцева точка API для запиту |
| `post_body` | Тіло JSON, що надсилається до API. Використовуйте `%__input__%` як заповнювач для поточного тексту пошуку реєстратора |
| `value_column` | Ключ в об'єкті відповіді, який буде використовуватися як збережене **значення** |
| `display` | Ключ (або шаблон), який буде використовуватися як **мітка**, що відображається у випадаючому списку. Підтримує заповнювачі `##key##` та вирази `@{func}` |
| `data_path` | JSONPath до масиву об'єктів результатів у відповіді (наприклад, `$.data`, `$.hits.hits.*._source`) |
| `save_path` | Ім'я, під яким зберігається необроблена відповідь для використання іншими полями |

---

## Базовий приклад

Пошук закладу охорони здоров'я, де реєстратор вводить частину назви закладу:

| type | name | label | appearance |
|------|------|-------|------------|
| select_one | facility | Оберіть заклад охорони здоров'я | `search-api('POST', 'https://api.example.com/facilities/search', '{"query": "%__input__%"}', 'id', 'name', '$.results', 'facility_data')` |

API отримує `{"query": "nair"}`, коли реєстратор вводить "nair", і повертає:

```json
{
  "results": [
    {"id": "HF001", "name": "Nairobi Central Clinic"},
    {"id": "HF002", "name": "Nairobi West Hospital"}
  ]
}
```

Випадаючий список відображає `Nairobi Central Clinic` та `Nairobi West Hospital`; збережене значення — `HF001` або `HF002`.

## Розширене форматування відображення

### Використання шаблонів `##key##`

Відображення кількох полів у мітці:

```
search-api('POST', 'https://api.example.com/search', '{"q": "%__input__%"}', 'id', '##name## (##district##)', '$.data', 'res')
```

Відображається як: `Nairobi Central Clinic (Nairobi)`.

### Використання виразів `@{func}`

Застосування умовної логіки у мітці відображення:

```
search-api('POST', 'https://api.example.com/search', '{"q": "%__input__%"}', 'id',
  '@{if_else(eq("##status##", "active"), "✓ ##name##", "✗ ##name##")}',
  '$.data', 'res')
```

Активні результати відображають `✓ Clinic Name`; неактивні — `✗ Clinic Name`.

## Встановлення значення за замовчуванням: `search-default-api()`

Використовуйте `search-default-api()` після `search-api()`, щоб попередньо заповнити поле вибором за замовчуванням, завантаженим з окремого виклику API (наприклад, при редагуванні існуючого запису):

```
appearance: search-api(...) search-default-api('POST', 'https://api.example.com/get', '{"id": "##saved_id##"}', 'id', 'name', '$.item')
```

---

## Спеціальний роздільник для select_multiple: `search-default-separator()`

Для полів `select_multiple` вкажіть, як кілька вибраних значень з'єднуються у збереженому рядку:

```
appearance: search-api(...) search-default-separator(' || ')
```

Роздільник за замовчуванням — пробіл.

## Підтримувані типи запитань

| Тип запитання | Варіант використання |
|---------------|----------|
| `select_one` | Одиночний вибір із результатів пошуку |
| `select_multiple` | Множинний вибір із результатів пошуку |
| `text` | Автозаповнення — реєстратор вводить текст вільно, але може вибрати пропозицію |

## Використання збережених даних відповіді

Коли реєстратор вибирає результат, rtSurvey зберігає повний відповідний об'єкт із відповіді під ім'ям `save_path`. Інші поля можуть читати з нього двома способами.

### Метод 1 — пошук `pulldata()`

Використовуйте `pulldata('save_path', 'key')`, щоб прочитати поле верхнього рівня зі збереженого об'єкта:

| type | name | label | calculation |
|------|------|-------|-------------|
| select_one | facility | Оберіть заклад | |
| calculate | facility_district | | `pulldata('facility_data', 'district')` |
| calculate | facility_type | | `pulldata('facility_data', 'type')` |
| calculate | facility_beds | | `pulldata('facility_data', 'beds')` |

Вигляд (appearance) у рядку `select_one` повинен включати `search-api(..., 'facility_data')` з відповідним `save_path`.

Для **вкладених полів JSON** комбінуйте з `substr-jsonpath()`:

```
substr-jsonpath(pulldata('facility_data', 'location'), '$.district')
```

## Пошук у локальних файлах за допомогою `search()`

`search()` виконує офлайн-пошук за рівністю стовпців у вбудованому файлі SQLite `.db` — мережеве з'єднання та SQL-запити не потрібні. Використовуйте його, коли ваші довідкові дані постачаються разом із формою і вам потрібен простий пошук «знайти всі рядки, де стовпець дорівнює значенню».

### Сигнатура

```
search(path, 'matches', 'list_name', ${field})
```

### Параметри

| Параметр | Опис |
|-----------|-------------|
| `path` | Шлях до таблиці SQLite: `concat(${family_path}, '/file.db::table')` |
| `'matches'` | Оператор відповідності — повертає рядки, де стовпець дорівнює значенню |
| `'list_name'` | Назва стовпця для порівняння |
| `${field}` | Значення для порівняння; зазвичай посилання на поле |

### Приклад

Заповнення `select_one` з локальної бази даних шляхом порівняння значення `${d307}` зі стовпцем `list_name` у таблиці `externalData` файлу `d307.db`:

| type | name | label | appearance |
|------|------|-------|------------|
| select_one | facility | Оберіть заклад | `search(concat(${family_path}, '/d307.db::externalData'), 'matches', 'list_name', ${d307})` |

Коли `${d307}` дорівнює `"HF001"`, `search()` повертає кожен рядок у `externalData`, де `list_name = 'HF001'` — повністю із вбудованого файлу, без мережевого виклику.

### `search()` проти автозаповнення `rawquery`

| Функція | `search()` | Автозаповнення `rawquery` |
|---------|-----------|------------------------|
| SQL-запити | Ні — лише рівність стовпців | Так — повний `SELECT … FROM …` |
| Параметризоване введення | Відповідність значенню стовпця | Вбудовано в рядок SQL |
| Введення довільного тексту | Так — реєстратор може вводити вільно | Ні — потрібно вибрати зі списку |
| UNION / кілька таблиць | Не підтримується | Підтримується |

### Коли використовувати кожен з них

- Використовуйте **`search()`**, коли вам потрібна проста відповідність за рівністю у вбудованому файлі `.db`, форма повинна працювати офлайн, і ви хочете дозволити введення довільного тексту.
- Використовуйте **автозаповнення `rawquery`**, коли вам потрібна гнучкість SQL (JOIN, UNION, обчислювані стовпці) або потрібно робити запити до кількох таблиць, а форма має надійне з'єднання.

## Кращі практики

1. Переконайтеся, що ваша кінцева точка API відповідає протягом 1–2 секунд — повільні API роблять пошук менш зручним.
2. Використовуйте `%__input__%` у `post_body`, щоб API повертав лише результати, що відповідають запиту, а не весь набір даних.
3. Індексуйте поле пошуку на стороні сервера (наприклад, Elasticsearch, повнотекстовий індекс бази даних) для швидких відповідей.
4. Обмежуйте результати до 20–50 елементів на запит — повернення тисяч результатів нівелює мету пошуку.
5. Включіть вимогу щодо мінімальної довжини вводу в API, щоб уникнути запуску широких запитів при введенні одного символу.

## Обмеження

- Динамічний пошук потребує підключення до мережі — він не працює офлайн.
- Заповнювач `%__input__%` вставляється як є; очищуйте вхідні дані на стороні сервера, щоб запобігти ін'єкціям.
- Складні вирази відображення `@{func}` можуть мати обмежену підтримку в різних версіях клієнта rtSurvey.
