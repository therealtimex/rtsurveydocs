`family_path` — це розрахункове поле (calculate), яке містить шлях до каталогу медіафайлів форми. Кожна форма, яка виконує пошук у локальній базі даних за допомогою `rawquery`, `pulldata` або `search()`, повинна містити це поле — без нього шляхи до файлів неможливо розпізнати, і пошук просто повертатиме порожній результат.

---

## Розрахункове поле (calculate)

Додайте цей рядок у верхній частині вашої сторінки survey, після будь-яких мета-полів і перед першим питанням, яке використовує файл бази даних:

| type | name | label | calculation |
|---|---|---|---|
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |

Поле не зберігає видимого значення і не потребує мітки (label). Це неявна передумова для всіх конструкцій шляхів, які слідують далі.

---

## Чому це потрібно

RTSurvey групує медіафайли форми — бази даних SQLite, зображення, аудіокліпи — у каталозі для кожної форми на пристрої. Точний шлях відрізняється залежно від платформи (Android, iOS, веб) та пристрою.

Під час виконання додаток автоматично заповнює `family_path`. Типове розпізнане значення виглядає так:

```
resources/familyMedia/Phuong_Person_Test
```

Оскільки шлях залежить від платформи та визначається під час запуску, його не можна жорстко прописати у формі. `pulldata('app-api', 'family_path')` — єдиний надійний спосіб його отримати.

---

## Як використовувати це у шляхах

Після визначення `family_path` побудуйте повний шлях до файлу за допомогою `concat()`:

```
concat(${family_path}, '/file.db::tableName')
```

Суфікс `::tableName` видаляється, коли додаток відкриває файл; назва таблиці використовується лише у вашому SQL-запиті.

---

## Де використовується family_path

`family_path` обов’язковий в аргументі шляху щоразу, коли ви посилаєтеся на вбудований файл:

- **Пошук у локальній базі даних** — аргумент `db_path` функції `search-autocomplete-noedit-v2('rawquery', ...)` має бути побудований за допомогою `concat(${family_path}, ...)`. Дивіться [Пошук у локальній базі даних](local-database-search) для отримання повної інформації про використання.
- **`pulldata` rawquery** — будь-який виклик `pulldata('rawquery', ...)`, який читає з файлу `.db`, використовує той самий шаблон `concat()`.
- **`search()` із локальним файлом** — параметри вигляду (appearance) динамічного пошуку, які завантажуються з вбудованого файлу CSV або DB, також покладаються на `family_path` для посилання на файл.

---

## Розміщення у формі

`family_path` має з’явитися **перед першим полем, яке на нього посилається**. Рекомендоване місце — одразу після мета-групи:

| type | name | label | calculation |
|---|---|---|---|
| begin_group | meta | | |
| deviceid | deviceid | | |
| start | start | | |
| end | end | | |
| end_group | | | |
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |
| select_one | province | Province | *(appearance rawquery з посиланням на `${family_path}`)* |

<Callout type="warning">
Якщо `family_path` відсутній у формі або розміщений після першого поля `rawquery` / `search()`, яке на нього посилається, усі пошуки у вбудованих файлах просто повертатимуть порожній результат. Повідомлення про помилку не з’явиться — автозаповнення просто не покаже результатів.
</Callout>

---

## Кілька файлів бази даних

Одна форма може використовувати кілька файлів `.db`. Кожен шлях будується незалежно за допомогою `concat()`:

```
concat(${family_path}, '/locations.db::externalData')
concat(${family_path}, '/health_facilities.db::facilities')
concat(${family_path}, '/household_list.db::households')
```

Визначте `family_path` один раз; посилайтеся на нього у стількох полях, скільки потрібно.

---

## Перевірка під час розробки

Додайте тимчасове поле `note` під `family_path`, щоб перевірити розпізнане значення на пристрої:

| type | name | label | calculation |
|---|---|---|---|
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |
| note | family_path_check | `Path: ${family_path}` | |

Нотатка відображатиме фактичний розпізнаний шлях під час тестування. Видаліть її перед розгортанням остаточної форми.
