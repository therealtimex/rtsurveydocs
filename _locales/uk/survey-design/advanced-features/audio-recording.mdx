Аудіозапис дозволяє формі непомітно або відкрито фіксувати звук під час певного розділу опитування. Це корисно для запису інтерв'ю, фонового звуку під час польових спостережень або усних відповідей, які доповнюють структуровані дані.

## Як це працює

Аудіозапис керується двома полями типу `text`, які виступають у ролі **маркерів**:

- Поле з властивістю `audio-start` починає запис, коли інтерв'юер доходить до нього.
- Поле з властивістю `audio-end` зупиняє запис і зберігає аудіофайл у подані дані (submission).

Обидва поля-маркери мають тип `text`. Зазвичай вони приховані від інтерв'юера (за допомогою `relevant = false` або розміщення в неінтерактивній позиції), хоча можуть бути і видимими. Записане аудіо додається доsubmission як файл, пов'язаний із полем `audio-end`.

## Базовий приклад

| type | name | label | appearance |
|------|------|-------|------------|
| text | audio_s_a1 | | `audio-start` |
| text | q_name | Ім'я респондента | |
| text | q_occupation | Род занять | |
| integer | q_age | Вік | |
| text | audio_e_a1 | | `audio-end` |

Додаток починає запис, коли інтерв'юер доходить до `audio_s_a1`, і зупиняє, коли він доходить до `audio_e_a1`. Усі запитання між двома маркерами записуються.

---

## Непомітний запис: `audio-start invisible`

За замовчуванням мобільний додаток відображає індикатор запису під час фіксації звуку. Додавання `invisible` до властивості appearance приховує цей індикатор, тому запис відбувається без видимих ознак для респондента.

| type | name | label | appearance |
|------|------|-------|------------|
| text | audio_s_a1 | | `audio-start invisible` |
| text | q_consent | Ви згодні на участь? | |
| text | q_feedback | Ваш відгук | |
| text | audio_e_a1 | | `audio-end` |

Використовуйте `invisible` лише тоді, коли вимоги щодо розкриття інформації були задоволені іншими засобами (наприклад, окремим полем письмової згоди перед розділом із записом).

## Правила іменування

У робочих формах використовується послідовна схема іменування полів-маркерів:

```
audio_s_{section}{n}   — маркер початку
audio_e_{section}{n}   — маркер завершення
```

Де `{section}` — це коротка мітка для розділу форми, а `{n}` — порядковий номер у цьому розділі.

| Field name | Role | Meaning |
|------------|------|---------|
| `audio_s_a1` | Start | Перший запис у розділі А |
| `audio_e_a1` | End | Завершення першого запису в розділі А |
| `audio_s_b1` | Start | Перший запис у розділі B |
| `audio_e_b1` | End | Завершення першого запису в розділі B |
| `audio_s_a2` | Start | Другий запис у розділі А |
| `audio_e_a2` | End | Завершення другого запису в розділі А |

Дотримання цієї конвенції полегшує ідентифікацію меж запису під час перегляду визначень форм та даних подання.

## Зберігання та отримання

Коли інтерв'юер доходить до поля `audio-end`, додаток завершує створення аудіофайлу та додає його до submission. Файл:

- Зберігається як аудіо-вкладення у submission, пов'язане з назвою поля `audio-end`.
- Доступний у переглядачі подань rtSurvey разом з іншими медіа-вкладеннями.
- Доступний для завантаження через стандартний експорт даних — аудіофайли відображаються у стовпці медіа, що відповідає назві поля `audio-end`.

Формат файлу та бітрейт залежать від пристрою та версії додатка.

---

## Кілька розділів запису

Форма може містити кілька розділів запису, що не перекриваються. Кожна пара маркерів `audio-start` / `audio-end` має бути повністю завершеною — розділи не повинні переплітатися.

| type | name | label | appearance |
|------|------|-------|------------|
| text | audio_s_a1 | | `audio-start` |
| text | q_intro | Вступ | |
| text | audio_e_a1 | | `audio-end` |
| note | section_break | — | |
| text | audio_s_b1 | | `audio-start invisible` |
| text | q_detail | Деталі | |
| text | audio_e_b1 | | `audio-end` |

Кожен розділ створює окремий аудіофайл, прикріплений до відповідного поля `audio-end`.

---

## Обмеження

- **Тільки для мобільного додатка.** Ця функція не підтримується у веб-формах. `audio-start` та `audio-end` ігноруються у браузері.
- **Без вкладеності.** Розділи запису не можуть перекриватися. Початок нового запису до того, як буде досягнуто попередній маркер `audio-end`, не підтримується.
- **Тип поля має бути `text`.** Використання `audio-start` або `audio-end` для будь-якого іншого типу запитання не підтримується.
- **Розмір завантаження.** Довгі записи створюють великі файли. Враховуйте обмеження розміру submission та умови мережі в польових умовах.
- **Без паузи під час запису.** Запис триває безперервно від маркера початку до маркера завершення; механізму призупинення та відновлення в межах одного розділу не існує.
