يتيح **البحث الديناميكي** (المعروف أيضاً باسم واجهة برمجة تطبيقات البحث Search API) لحقل من نوع `select_one` أو `select_multiple` أو `text` تحميل خياراته من خدمة ويب عن بُعد **أثناء التشغيل** (at runtime) بينما يكتب جامع البيانات. هذا هو النهج الصحيح عندما تكون قائمة الخيارات كبيرة جداً بحيث لا يمكن حزمها في ملف CSV، أو عندما تُحدث بشكل متكرر، أو تأتي من قاعدة بيانات مباشرة.

---

## مظهر `search-api()`

يتم تكوين البحث الديناميكي من خلال عمود `appearance` باستخدام وظيفة `search-api()`:

```
search-api(method, url, post_body, value_column, display, data_path, save_path)
```

### المعاملات (Parameters)

| المعامل | الوصف |
|-----------|-------------|
| `method` | استخدم دائماً `'POST'` |
| `url` | نقطة نهاية واجهة برمجة التطبيقات (API endpoint) المطلوب الاستعلام عنها |
| `post_body` | جسم JSON المرسل إلى واجهة برمجة التطبيقات. استخدم `%__input__%` كعنصر نائب لنص البحث الحالي لجامع البيانات |
| `value_column` | المفتاح في كائن الاستجابة لاستخدامه كـ **القيمة** (value) المخزنة |
| `display` | المفتاح (أو القالب) لاستخدامه كـ **تسمية** (label) معروضة في القائمة المنسدلة. يدعم العناصر النائبة `##key##` وتعبيرات `@{func}` |
| `data_path` | مسار JSONPath إلى مصفوفة كائنات النتائج في الاستجابة (مثلاً، `$.data` أو `$.hits.hits.*._source`) |
| `save_path` | اسم يتم بموجبه حفظ الاستجابة الخام لاستخدامها من قبل حقول أخرى |

## مثال أساسي

البحث عن منشأة صحية حيث يكتب جامع البيانات جزءاً من اسم المنشأة:

| type | name | label | appearance |
|------|------|-------|------------|
| select_one | facility | اختر المنشأة الصحية | `search-api('POST', 'https://api.example.com/facilities/search', '{"query": "%__input__%"}', 'id', 'name', '$.results', 'facility_data')` |

تتلقى واجهة برمجة التطبيقات `{"query": "nair"}` عندما يكتب جامع البيانات "nair" وتُرجع:

```json
{
  "results": [
    {"id": "HF001", "name": "Nairobi Central Clinic"},
    {"id": "HF002", "name": "Nairobi West Hospital"}
  ]
}
```

تُظهر القائمة المنسدلة `Nairobi Central Clinic` و `Nairobi West Hospital`؛ والقيمة المخزنة هي `HF001` أو `HF002`.

## تنسيق العرض المتقدم

### استخدام قوالب `##key##`

عرض حقول متعددة في التسمية:

```
search-api('POST', 'https://api.example.com/search', '{"q": "%__input__%"}', 'id', '##name## (##district##)', '$.data', 'res')
```

تُعرض كـ: `Nairobi Central Clinic (Nairobi)`.

### استخدام تعبيرات `@{func}`

تطبيق المنطق الشرطي في تسمية العرض:

```
search-api('POST', 'https://api.example.com/search', '{"q": "%__input__%"}', 'id',
  '@{if_else(eq("##status##", "active"), "✓ ##name##", "✗ ##name##")}',
  '$.data', 'res')
```

تُظهر النتائج النشطة `✓ Clinic Name`؛ وتُظهر غير النشطة `✗ Clinic Name`.

## تعيين قيمة افتراضية: `search-default-api()`

استخدم `search-default-api()` بعد `search-api()` لملء الحقل مسبقاً بخيار افتراضي يتم تحميله من مكالمة واجهة برمجة تطبيقات منفصلة (على سبيل المثال، عند تحرير سجل موجود):

```
appearance: search-api(...) search-default-api('POST', 'https://api.example.com/get', '{"id": "##saved_id##"}', 'id', 'name', '$.item')
```

---

## فاصل مخصص لـ select_multiple: `search-default-separator()`

لحقول `select_multiple` حدد كيفية دمج القيم المتعددة المختارة في السلسلة المخزنة:

```
appearance: search-api(...) search-default-separator(' || ')
```

الفاصل الافتراضي هو مسافة.

## أنواع الأسئلة المدعومة

| نوع السؤال | حالة الاستخدام |
|---------------|----------|
| `select_one` | اختيار واحد من نتائج البحث |
| `select_multiple` | اختيارات متعددة من نتائج البحث |
| `text` | الإكمال التلقائي — يكتب جامع البيانات بحرية ولكن يمكنه اختيار اقتراح |

## استخدام بيانات الاستجابة المحفوظة

عندما يختار جامع البيانات نتيجة، يحفظ rtSurvey الكائن المطابق الكامل من الاستجابة تحت اسم `save_path`. يمكن للحقول الأخرى القراءة منه بطريقتين.

### الطريقة 1 — البحث باستخدام `pulldata()`

استخدم `pulldata('save_path', 'key')` لقراءة حقل من المستوى الأعلى من الكائن المحفوظ:

| type | name | label | calculation |
|------|------|-------|-------------|
| select_one | facility | اختر المنشأة | |
| calculate | facility_district | | `pulldata('facility_data', 'district')` |
| calculate | facility_type | | `pulldata('facility_data', 'type')` |
| calculate | facility_beds | | `pulldata('facility_data', 'beds')` |

يجب أن يتضمن المظهر في صف `select_one` وظيفة `search-api(..., 'facility_data')` مع `save_path` المطابق.

لـ **حقول JSON المتداخلة** ادمج مع `substr-jsonpath()`:

```
substr-jsonpath(pulldata('facility_data', 'location'), '$.district')
```

## البحث في ملف محلي باستخدام search()

تؤدي وظيفة `search()` عمليات بحث غير متصلة بالإنترنت (offline) وتعتمد على مساواة الأعمدة مقابل ملف SQLite `.db` محزم — لا يلزم وجود اتصال بالشبكة ولا استعلامات SQL. استخدمها عندما تكون بياناتك المرجعية معبأة مع النموذج وتحتاج إلى بحث بسيط عن "العثور على جميع الصفوف حيث يساوي العمود القيمة".

### الصيغة (Signature)

```
search(path, 'matches', 'list_name', ${field})
```

### المعاملات (Parameters)

| المعامل | الوصف |
|-----------|-------------|
| `path` | المسار إلى جدول SQLite: `concat(${family_path}, '/file.db::table')` |
| `'matches'` | عامل المطابقة — يُرجع الصفوف حيث يساوي العمود القيمة |
| `'list_name'` | اسم العمود المراد المطابقة معه |
| `${field}` | القيمة المراد مطابقتها؛ عادة ما تكون مرجعاً لحقل |

### مثال

ملء `select_one` من قاعدة بيانات محلية عن طريق مطابقة قيمة `${d307}` مع عمود `list_name` في جدول `externalData` بملف `d307.db`:

| type | name | label | appearance |
|------|------|-------|------------|
| select_one | facility | اختر المنشأة | `search(concat(${family_path}, '/d307.db::externalData'), 'matches', 'list_name', ${d307})` |

عندما تساوي `${d307}` القيمة `"HF001"`، تُرجع `search()` كل صف في `externalData` حيث `list_name = 'HF001'` — بالكامل من الملف المحزم، دون مكالمة شبكة.

### search() مقابل الإكمال التلقائي rawquery

| الميزة | `search()` | الإكمال التلقائي `rawquery` |
|---------|-----------|------------------------|
| استعلامات SQL | لا — مساواة العمود فقط | نعم — استعلام `SELECT … FROM …` كامل |
| إدخال معلمات (Parameterized) | مطابقة قيمة العمود | مدمجة في سلسلة SQL |
| إدخال نص حر | نعم — يمكن لجامع البيانات الكتابة بحرية | لا — يجب الاختيار من قائمة |
| UNION / جداول متعددة | غير مدعوم | مدعوم |

### متى تستخدم كل منهما

- استخدم **`search()`** عندما تحتاج إلى مطابقة مساواة مباشرة مقابل ملف `.db` محزم، ويجب أن يعمل النموذج دون اتصال بالإنترنت، وتريد السماح بإدخال نص حر.
- استخدم **الإكمال التلقائي `rawquery`** عندما تحتاج إلى مرونة SQL (مثل JOINs و UNIONs والأعمدة المحسوبة) أو يجب عليك الاستعلام عبر جداول متعددة، ويكون للنموذج اتصال موثوق.

## أفضل الممارسات

1. تأكد من أن نقطة نهاية واجهة برمجة التطبيقات الخاصة بك تستجيب في غضون ثانية إلى ثانية ونصف — واجهات برمجة التطبيقات البطيئة تجعل البحث يبدو غير مستجيب.
2. استخدم `%__input__%` في `post_body` بحيث تُرجع واجهة برمجة التطبيقات النتائج المطابقة فقط، وليس مجموعة البيانات بأكملها.
3. قم بفهرسة حقل البحث من جانب الخادم (مثل Elasticsearch أو فهرس النص الكامل لقاعدة البيانات) للحصول على استجابات سريعة.
4. حدد النتائج بـ 20-50 عنصراً لكل استعلام — إرجاع آلاف النتائج يهزم الغرض من البحث.
5. قم بتضمين متطلب الحد الأدنى لطول الإدخال في واجهة برمجة التطبيقات لتجنب إطلاق استعلامات واسعة النطاق على إدخالات من حرف واحد.

## القيود

- يتطلب البحث الديناميكي اتصالاً بالشبكة — فهو لا يعمل دون اتصال بالإنترنت.
- يتم حقن العنصر النائب `%__input__%` كما هو؛ قم بتنقية المدخلات من جانب الخادم لمنع هجمات الحقن.
- قد يكون لتعبيرات العرض المعقدة `@{func}` دعم محدود عبر جميع إصدارات عملاء rtSurvey.
