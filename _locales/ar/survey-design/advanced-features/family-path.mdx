import { Callout } from 'nextra/components'

`family_path` هو حقل حساب اصطلاحي يحمل المسار إلى دليل الوسائط المجمع للنموذج. يجب أن يتضمن كل نموذج يقوم بعمليات البحث في قاعدة البيانات المحلية باستخدام `rawquery` أو `pulldata` أو `search()` هذا الحقل — بدونه، لا يمكن حل مسارات الملفات وترجع عمليات البحث بصمت نتائج فارغة.

---

## حقل الحساب (calculate)

أضف هذا الصف بالقرب من أعلى ورقة الاستبيان (survey)، بعد أي حقول وصفية (meta) وقبل السؤال الأول الذي يستخدم ملف قاعدة بيانات:

| type | name | label | calculation |
|---|---|---|---|
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |

لا يخزن الحقل أي قيمة مرئية ولا يتطلب تسمية (label). إنه شرط مسبق صامت لكل عمليات بناء المسارات التي تتبع.

---

## لماذا هو مطلوب

يقوم RTSurvey بتجميع وسائط النموذج — قواعد بيانات SQLite، الصور، المقاطع الصوتية — داخل دليل خاص بكل نموذج على الجهاز. يختلف المسار الدقيق بين الأنظمة الأساسية (Android، iOS، الويب) وبين الأجهزة.

في وقت التشغيل، يقوم التطبيق بملء `family_path` تلقائيًا. تبدو القيمة المحلولة النموذجية كما يلي:

```
resources/familyMedia/Phuong_Person_Test
```

نظرًا لأن المسار خاص بالنظام الأساسي ويتم تحديده في وقت الإطلاق، فلا يمكن ترميزه بشكل ثابت في النموذج. `pulldata('app-api', 'family_path')` هي الطريقة الوحيدة الموثوقة لاسترداده.

---

## كيفية استخدامه في المسارات

بمجرد تعريف `family_path` ، قم ببناء مسار ملف كامل باستخدام `concat()`:

```
concat(${family_path}, '/file.db::tableName')
```

يتم تجريد اللاحقة `::tableName` عندما يفتح التطبيق الملف؛ يتم استخدام اسم الجدول فقط داخل استعلام SQL الخاص بك.

---

## أين يتم استخدام family_path

يعد `family_path` مطلوبًا في وسيط المسار كلما أشرت إلى ملف مجمع:

- **البحث في قاعدة البيانات المحلية** — يجب بناء وسيط `db_path` الخاص بـ `search-autocomplete-noedit-v2('rawquery', ...)` باستخدام `concat(${family_path}, ...)`. راجع [البحث في قاعدة البيانات المحلية](local-database-search) للحصول على تفاصيل الاستخدام الكاملة.
- **`pulldata` rawquery** — أي استدعاء لـ `pulldata('rawquery', ...)` يقرأ من ملف `.db` يستخدم نفس نمط `concat()`.
- **`search()` مع ملف محلي** — تعتمد مظاهر البحث الديناميكي التي يتم تحميلها من ملف CSV أو DB مجمع أيضًا على `family_path` لمرجع الملف.

---

## الموضع في النموذج

يجب أن يظهر `family_path` **قبل الحقل الأول الذي يشير إليه**. الموضع الموصى به هو مباشرة بعد المجموعة الوصفية (meta):

| type | name | label | calculation |
|---|---|---|---|
| begin_group | meta | | |
| deviceid | deviceid | | |
| start | start | | |
| end | end | | |
| end_group | | | |
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |
| select_one | province | Province | *(rawquery appearance referencing `${family_path}`)* |

<Callout type="warning">
إذا كان `family_path` مفقودًا من النموذج، أو تم وضعه بعد أول حقل `rawquery` / `search()` يشير إليه، فسترجع جميع عمليات البحث في الملفات المجمعة بصمت نتائج فارغة. لا توجد رسالة خطأ — ببساطة لا يظهر الإكمال التلقائي أي نتائج.
</Callout>

---

## ملفات قاعدة بيانات متعددة

يمكن لنموذج واحد استخدام عدة ملفات `.db`. يتم بناء كل مسار بشكل مستقل باستخدام `concat()`:

```
concat(${family_path}, '/locations.db::externalData')
concat(${family_path}, '/health_facilities.db::facilities')
concat(${family_path}, '/household_list.db::households')
```

قم بتعريف `family_path` مرة واحدة؛ وأشر إليه في أكبر عدد ممكن من الحقول حسب الحاجة.

## التحقق أثناء التطوير

أضف حقل `note` مؤقتًا أسفل `family_path` لفحص القيمة المحلولة على الجهاز:

| type | name | label | calculation |
|---|---|---|---|
| calculate | `family_path` | | `pulldata('app-api', 'family_path')` |
| note | family_path_check | `Path: ${family_path}` | |

ستعرض الملاحظة المسار المحلول الفعلي أثناء الاختبار. قم بإزالتها قبل نشر النموذج النهائي.
