**البحث في قاعدة البيانات المحلية** يتيح لحقل `select_one` أو `text` الاستعلام عن ملف SQLite `.db` المضمن مع حزمة وسائط النموذج — بالكامل دون اتصال بالإنترنت، وبدون رحلة ذهاب وإياب إلى الخادم. هذا هو النهج الصحيح عندما تكون قائمة الاختيارات كبيرة وثابتة (مثل قائمة وطنية للقرى، أو المرافق الصحية، أو الحدود الإدارية) ولا يمكن ضمان الاتصال.

| النهج | مصدر البيانات | يتطلب اتصالاً |
|---|---|---|
| البحث في قاعدة البيانات المحلية (`rawquery`) | ملف `.db` مضمن (SQLite) | لا |
| `search-api()` | REST API عن بعد | نعم |
| `search()` | ملف CSV مضمن | لا |

---

## متغيرات المظهر

يتم تكوين حقل الإكمال التلقائي من خلال عمود `appearance`. تتوفر ثلاثة متغيرات:

| المتغير | ملاحظات |
|---|---|
| `search-autocomplete-noedit(...)` | الإكمال التلقائي القياسي — يجب على العداد الاختيار من القائمة؛ لا يتم حفظ الإدخال النصي الحر |
| `search-autocomplete-noedit-v2(...)` | المتغير الموصى به — نفس السلوك ولكنه يستخدم محرك عرض محدثًا مع أداء أفضل لمجموعات النتائج الكبيرة |
| `search(...)` | مطابقة بسيطة تعتمد على الملف مقابل ملف CSV مضمن؛ **لا** يدعم SQL الخام — مدرج هنا للمقارنة فقط |

<Callout type="info">
`search-autocomplete-noedit` هو اسم مستعار — في وقت التحليل، يستبدله التطبيق باسم الوظيفة الداخلية `searchAutocompleteNoedit`. استخدم أيًا من الهجاءين في XLSForm الخاص بك؛ كلاهما يعمل.
</Callout>

## مصدر بيانات `rawquery`

لتشغيل استعلام SQL مقابل ملف `.db` مرر `'rawquery'` كوسيط أول لوظيفة المظهر. التوقيع الكامل هو:

```
search-autocomplete-noedit-v2(
  'rawquery',
  <db_path>,
  '[display_col]',
  'value_col',
  'SELECT ...',
  param1, param2, ...
)
```

### المعلمات

| الموضع | المعلمة | الوصف |
|---|---|---|
| 1 | `'rawquery'` | سلسلة نصية حرفية — تخبر التطبيق بتنفيذ SQL مباشرة |
| 2 | `db_path` | المسار إلى ملف SQLite، بصيغة `<dir>/<file>.db::tableName`. يتم تجريد اللاحقة `::tableName` عند فتح الملف؛ يتم استخدام اسم الجدول داخل SQL الخاص بك |
| 3 | `'[display_col]'` | العمود الذي سيتم عرضه في القائمة المنسدلة. يتم تجريد الأقواس المحيطة `[ ]` في وقت التشغيل |
| 4 | `'value_col'` | العمود الذي يتم تخزين قيمته عندما يقوم العداد بإجراء اختيار |
| 5 | `'SELECT ...'` | أي عبارة SQLite SELECT صالحة. يتم حقن `SELECT DISTINCT` تلقائيًا إذا لم يكن `DISTINCT` موجودًا بالفعل |
| 6+ | `param1, ...` | اختياري. القيم المرتبطة بالعناصر النائبة `?` في SQL، بالترتيب. إذا كان SQL يحتوي على `?` ولكن لم يتم توفير معلمات، فسيقوم الحقل بإرجاع نتيجة فارغة (حماية مدمجة ضد الوسائط المفقودة) |

### اصطلاح `db_path`

يعيش ملف قاعدة البيانات داخل دليل الوسائط المضمن للنموذج. في وقت التشغيل، يقوم `pulldata('app-api', 'family_path')` بإرجاع مسار الدليل هذا. راجع [family_path](family-path) للحصول على تفاصيل الإعداد. النمط القياسي هو:

```
concat(${family_path}, '/mydata.db::tableName')
```

عندما يفتح التطبيق الملف فإنه يجرد جزء `::tableName` ويستخدم مسار الملف العاري. يظهر اسم الجدول فقط داخل SQL الخاص بك.

## مثال أساسي — البحث عن المقاطعة

قائمة منسدلة للمقاطعات للقراءة فقط مدعومة بملف `vnxa3.db` مضمن:

| type | name | label | appearance | calculation |
|---|---|---|---|---|
| calculate | family_path | | | `pulldata('app-api', 'family_path')` |
| select_one | province | Province | `search-autocomplete-noedit-v2('rawquery', concat(${family_path}, '/vnxa3.db::externalData'), '[provv]', 'provid', 'SELECT provv, provid FROM externalData WHERE rta_filter = "1"')` | |

عمود `appearance` (موسع لسهولة القراءة):

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[provv]', 'provid',
  'SELECT provv, provid FROM externalData WHERE rta_filter = "1"')
```

- التسمية المعروضة تأتي من عمود `provv`.
- القيمة المخزنة تأتي من عمود `provid`.
- يتم عرض الصفوف التي يكون فيها `rta_filter = "1"` فقط.

## الاستعلامات ذات المعلمات

استخدم العناصر النائبة `?` في SQL الخاص بك ومرر مراجع الحقول المقابلة كوسائط إضافية (من الموضع 6 فصاعدًا). هذا هو النمط القياسي للاختيارات المتتالية — على سبيل المثال، تحميل المناطق التي تنتمي إلى المقاطعة المختارة مسبقًا.

<Callout type="warning">
إذا كان SQL الخاص بك يحتوي على `?` واحد على الأقل ولم يتم توفير وسائط المعلمات، فسيقوم الحقل بإرجاع مجموعة نتائج فارغة. هذا يمنع ظهور بيانات قديمة أو غير محددة النطاق قبل إجراء اختيار أصلي.
</Callout>

### مثال على تسلسل المناطق

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[distv]', 'distid',
  'SELECT distv, distid FROM externalData
   WHERE provid = ? AND rta_filter = "1"',
  ${province})
```

قيمة `${province}` مرتبطة بأول `?`. يكون الحقل فارغًا حتى يختار العداد مقاطعة.

### مثال بمعلمتين — تسلسل البلديات

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[commv]', 'commid',
  'SELECT commv, commid FROM externalData
   WHERE provid = ? AND distid = ? AND rta_filter = "1"',
  ${province}, ${district})
```

المعلمات مرتبطة بالموضع: `${province}` ← أول `?` و`${district}` ← ثاني `?`.

## UNION SELECT للقيم الخاصة

حقن صفوف اصطناعية — مثل "لا أعرف" أو "رفض الإجابة" — مباشرة في SQL باستخدام `UNION SELECT`:

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[provv]', 'provid',
  'SELECT provv, provid FROM externalData WHERE rta_filter = "1"
   UNION SELECT "<i>Không biết</i>", "888"')
```

الاصطلاحات المستخدمة في نماذج RTSurvey:

| الرمز | المعنى |
|---|---|
| `888` | لا أعرف |
| `999` | رفض الإجابة |

يتم عرض علامات HTML مثل `<i>` في سلسلة العرض بواسطة التطبيق — يمكنك استخدامها لتمييز الخيارات الخاصة بصريًا.

## عرض متعدد اللغات

قم بتخزين التسميات الخاصة باللغة في أعمدة منفصلة (مثل `label_vi` و`label_en`) وحدد العمود المناسب بناءً على حقل اللغة في نموذجك:

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[label_vi]', 'provid',
  'SELECT label_vi, label_en, provid FROM externalData
   WHERE rta_filter = "1"')
```

للتبديل بين الأعمدة ديناميكيًا بناءً على حقل `${language}` استخدم تعبير `if()` في معلمة عمود العرض للتبديل بين أعمدة اللغة:

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  if(${language} = 'vi', '[label_vi]', '[label_en]'),
  'provid',
  'SELECT label_vi, label_en, provid FROM externalData
   WHERE rta_filter = "1"')
```

<Callout type="info">
يتم تقييم معلمة عمود العرض قبل تشغيل الاستعلام. يتم تمرير اسم العمود فقط (بدون أقواس) إلى محرك SQL؛ الأقواس هي علامات تجميلية يتم تجريدها في وقت التحليل.
</Callout>

## التحقق من اختيار حقيقي

عندما يسمح الحقل بقيم خاصة مثل 888 أو 999، فإن فحص `required = yes` البسيط يكون غير كافٍ — حيث يتم استيفاؤه حتى لو اختار العداد "لا أعرف". استخدم قيد `selected-at(., 0) != -997` للتحقق من أن القيمة المخزنة هي اختيار حقيقي وليست علامة "لم يتم اختيار شيء" الداخلية `-997`:

| column | value |
|---|---|
| constraint | `selected-at(., 0) != -997` |
| constraint_message | يرجى تحديد خيار صالح |

القيمة `-997` هي الرمز الداخلي الذي يخزنه RTSurvey عندما لا يتم اختيار أي عنصر من قائمة الإكمال التلقائي. لا يزال اختيار 888 أو 999 اختيارًا متعمدًا ويجتاز هذا الفحص.

للمطالبة بشكل إضافي بقيمة حقيقية (غير خاصة)، قم بتوسيع القيد:

```
selected-at(., 0) != -997 and selected-at(., 0) != '888' and selected-at(., 0) != '999'
```

## المقارنة: قاعدة البيانات المحلية مقابل طرق البحث الأخرى

| الميزة | إكمال تلقائي `rawquery` | `search-api()` | `search()` CSV | خيارات CSV عادية |
|---|---|---|---|---|
| مصدر البيانات | ملف `.db` مضمن (SQLite) | REST API عن بعد | ملف CSV مضمن | ورقة الاختيارات |
| يعمل دون اتصال | نعم | لا | نعم | نعم |
| يدعم SQL الخام | نعم | لا | لا | لا |
| عوامل التصفية المتتالية | نعم — `?` بمعلمات | عبر نص الطلب | محدود | لا |
| حجم مجموعة البيانات | كبير جدًا (ملايين الصفوف) | غير محدود (من جانب الخادم) | متوسط (عشرات الآلاف) | صغير |
| صفوف محقونة خاصة | نعم — `UNION SELECT` | لا | لا | نعم (يدويًا) |
| تعقيد الإعداد | متوسط — يتطلب ملف `.db` مضمنًا | عالٍ — يتطلب خادم API | منخفض | لا يوجد |

## القيود

- يجب تضمين ملف `.db` داخل حزمة وسائط النموذج قبل النشر. تتطلب التحديثات الديناميكية لقاعدة البيانات نشر نموذج جديد.
- يتم تنفيذ SQL كما هو على الجهاز. لا يوجد تطهير من جانب الخادم — تجنب بناء SQL من إدخال العداد النصي الحر.
- يتم دعم عبارات `SELECT` فقط. لا يُسمح بـ `INSERT` و`UPDATE` و`DELETE`.
- قد تكون الاستعلامات المعقدة للغاية (سلاسل `UNION` الكبيرة، وعمليات الانضمام المتعددة) بطيئة في أجهزة Android منخفضة المواصفات.
- متغيرات `search-autocomplete-noedit` لا تسمح للعداد بحفظ قيمة ليست في مجموعة النتائج. إذا كان الإدخال النصي الحر مطلوبًا، فاستخدم حقل `text` منفصلًا.
- يتم حقن `SELECT DISTINCT` تلقائيًا فقط عند غياب `DISTINCT` من الاستعلام. إذا كتبت `SELECT DISTINCT` صراحة، فلن يتم مضاعفته.
