import { Callout } from 'nextra/components'

Η **Αναζήτηση σε τοπική βάση δεδομένων** επιτρέπει σε ένα πεδίο `select_one` ή `text` να υποβάλει ερώτημα σε ένα αρχείο SQLite `.db` που είναι ενσωματωμένο στο πακέτο πολυμέσων της φόρμας — εντελώς εκτός σύνδεσης, χωρίς επικοινωνία με τον διακομιστή. Αυτή είναι η σωστή προσέγγιση όταν η λίστα επιλογών σας είναι μεγάλη και στατική (π.χ. ένας εθνικός κατάλογος χωριών, εγκαταστάσεων υγείας ή διοικητικών ορίων) και η συνδεσιμότητα δεν μπορεί να διασφαλιστεί.

| Προσέγγιση | Πηγή δεδομένων | Απαιτεί συνδεσιμότητα |
|---|---|---|
| Αναζήτηση σε τοπική βάση δεδομένων (`rawquery`) | Ενσωματωμένο αρχείο `.db` (SQLite) | Όχι |
| `search-api()` | Απομακρυσμένο REST API | Ναι |
| `search()` | Ενσωματωμένο αρχείο CSV | Όχι |

---

## Παραλλαγές εμφάνισης

Το πεδίο αυτόματης συμπλήρωσης διαμορφώνεται μέσω της στήλης `appearance`. Υπάρχουν τρεις διαθέσιμες παραλλαγές:

| Παραλλαγή | Σημειώσεις |
|---|---|
| `search-autocomplete-noedit(...)` | Τυπική αυτόματη συμπλήρωση — ο απογραφέας πρέπει να επιλέξει από τη λίστα. Η ελεύθερη εισαγωγή κειμένου δεν αποθηκεύεται |
| `search-autocomplete-noedit-v2(...)` | Προτεινόμενη παραλλαγή — ίδια συμπεριφορά, αλλά χρησιμοποιεί μια ενημερωμένη μηχανή απόδοσης με καλύτερη απόδοση σε μεγάλα σύνολα αποτελεσμάτων |
| `search(...)` | Απλή αντιστοίχιση βάσει αρχείου με ένα ενσωματωμένο CSV. **Δεν** υποστηρίζει raw SQL — παρατίθεται εδώ μόνο για σύγκριση |

<Callout type="info">
Το `search-autocomplete-noedit` είναι ένα ψευδώνυμο — κατά το χρόνο ανάλυσης η εφαρμογή το αντικαθιστά με το εσωτερικό όνομα συνάρτησης `searchAutocompleteNoedit`. Χρησιμοποιήστε οποιαδήποτε από τις δύο ορθογραφίες στο XLSForm σας. Και οι δύο λειτουργούν.
</Callout>

## Η πηγή δεδομένων `rawquery`

Για να εκτελέσετε ένα ερώτημα SQL σε ένα αρχείο `.db`, περάστε το `'rawquery'` ως το πρώτο όρισμα της συνάρτησης εμφάνισης. Η πλήρης υπογραφή είναι:

```
search-autocomplete-noedit-v2(
  'rawquery',
  <db_path>,
  '[display_col]',
  'value_col',
  'SELECT ...',
  param1, param2, ...
)
```

### Παράμετροι

| Θέση | Παράμετρος | Περιγραφή |
|---|---|---|
| 1 | `'rawquery'` | Λεκτικό αλφαριθμητικό — λέει στην εφαρμογή να εκτελέσει την SQL απευθείας |
| 2 | `db_path` | Διαδρομή προς το αρχείο SQLite, στη μορφή `<dir>/<file>.db::tableName`. Το επίθεμα `::tableName` αφαιρείται κατά το άνοιγμα του αρχείου. Το όνομα του πίνακα χρησιμοποιείται μέσα στην SQL σας |
| 3 | `'[display_col]'` | Στήλη που θα εμφανίζεται στο αναπτυσσόμενο μενού. Οι περιβάλλουσες αγκύλες `[ ]` αφαιρούνται κατά το χρόνο εκτέλεσης |
| 4 | `'value_col'` | Στήλη της οποίας η τιμή αποθηκεύεται όταν ο απογραφέας κάνει μια επιλογή |
| 5 | `'SELECT ...'` | Οποιαδήποτε έγκυρη δήλωση SQLite SELECT. Το `SELECT DISTINCT` εισάγεται αυτόματα εάν το `DISTINCT` δεν υπάρχει ήδη |
| 6+ | `param1, ...` | Προαιρετικό. Τιμές που συνδέονται με τα σύμβολα κράτησης θέσης `?` στην SQL, με τη σειρά. Εάν η SQL περιέχει `?` αλλά δεν παρέχονται παράμετροι, το πεδίο επιστρέφει κενό (μια ενσωματωμένη προστασία έναντι ελλειπόντων ορισμάτων) |

### Η σύμβαση `db_path`

Το αρχείο της βάσης δεδομένων βρίσκεται μέσα στον κατάλογο ενσωματωμένων πολυμέσων της φόρμας. Κατά το χρόνο εκτέλεσης, η συνάρτηση `pulldata('app-api', 'family_path')` επιστρέφει τη διαδρομή αυτού του καταλόγου. Δείτε το [family_path](family-path) για λεπτομέρειες ρύθμισης. Το τυπικό μοτίβο είναι:

```
concat(${family_path}, '/mydata.db::tableName')
```

Όταν η εφαρμογή ανοίγει το αρχείο, αφαιρεί το τμήμα `::tableName` και χρησιμοποιεί την απλή διαδρομή του αρχείου. Το όνομα του πίνακα εμφανίζεται μόνο μέσα στην SQL σας.

## Βασικό παράδειγμα — αναζήτηση επαρχίας

Ένα αναπτυσσόμενο μενού επαρχιών μόνο για ανάγνωση που υποστηρίζεται από ένα ενσωματωμένο αρχείο `vnxa3.db`:

| type | name | label | appearance | calculation |
|---|---|---|---|---|
| calculate | family_path | | | `pulldata('app-api', 'family_path')` |
| select_one | province | Επαρχία | `search-autocomplete-noedit-v2('rawquery', concat(${family_path}, '/vnxa3.db::externalData'), '[provv]', 'provid', 'SELECT provv, provid FROM externalData WHERE rta_filter = "1"')` | |

Η στήλη `appearance` (αναπτυγμένη για αναγνωσιμότητα):

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[provv]', 'provid',
  'SELECT provv, provid FROM externalData WHERE rta_filter = "1"')
```

- Η εμφανιζόμενη ετικέτα προέρχεται από τη στήλη `provv`.
- Η αποθηκευμένη τιμή προέρχεται από τη στήλη `provid`.
- Εμφανίζονται μόνο οι σειρές όπου `rta_filter = "1"`.

## Ερωτήματα με παραμέτρους

Χρησιμοποιήστε τα σύμβολα κράτησης θέσης `?` στην SQL σας και περάστε τις αντίστοιχες αναφορές πεδίων ως πρόσθετα ορίσματα (από τη θέση 6 και μετά). Αυτό είναι το τυπικό μοτίβο για διαδοχικές επιλογές — π.χ. φόρτωση περιοχών που ανήκουν στην προηγουμένως επιλεγμένη επαρχία.

<Callout type="warning">
Εάν η SQL σας περιέχει τουλάχιστον ένα `?` και δεν παρέχονται ορίσματα παραμέτρων, το πεδίο επιστρέφει ένα κενό σύνολο αποτελεσμάτων. Αυτό εμποδίζει την εμφάνιση παρωχημένων ή μη φιλτραρισμένων δεδομένων πριν γίνει μια γονική επιλογή.
</Callout>

### Παράδειγμα διαδοχικής επιλογής περιοχής

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[distv]', 'distid',
  'SELECT distv, distid FROM externalData
   WHERE provid = ? AND rta_filter = "1"',
  ${province})
```

Η τιμή του `${province}` συνδέεται με το πρώτο `?`. Το πεδίο είναι κενό μέχρι ο απογραφέας να επιλέξει μια επαρχία.

### Παράδειγμα δύο παραμέτρων — διαδοχική επιλογή κοινότητας

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[commv]', 'commid',
  'SELECT commv, commid FROM externalData
   WHERE provid = ? AND distid = ? AND rta_filter = "1"',
  ${province}, ${district})
```

Οι παράμετροι συνδέονται κατά θέση: `${province}` → πρώτο `?`, `${district}` → δεύτερο `?`.

## UNION SELECT για ειδικές τιμές

Εισαγάγετε συνθετικές σειρές — όπως "Δεν γνωρίζω" ή "Άρνηση απάντησης" — απευθείας στην SQL χρησιμοποιώντας το `UNION SELECT`:

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[provv]', 'provid',
  'SELECT provv, provid FROM externalData WHERE rta_filter = "1"
   UNION SELECT "<i>Δεν γνωρίζω</i>", "888"')
```

Συμβάσεις που χρησιμοποιούνται στις φόρμες RTSurvey:

| Κωδικός | Σημασία |
|---|---|
| `888` | Δεν γνωρίζω |
| `999` | Άρνηση απάντησης |

Οι ετικέτες HTML όπως το `<i>` στο αλφαριθμητικό εμφάνισης αποδίδονται από την εφαρμογή — μπορείτε να τις χρησιμοποιήσετε για να διακρίνετε οπτικά τις ειδικές επιλογές.

## Εμφάνιση σε πολλές γλώσσες

Αποθηκεύστε ετικέτες ειδικά για κάθε γλώσσα σε ξεχωριστές στήλες (π.χ. `label_vi`, `label_en`) και επιλέξτε την κατάλληλη με βάση ένα πεδίο γλώσσας στη φόρμα σας:

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  '[label_vi]', 'provid',
  'SELECT label_vi, label_en, provid FROM externalData
   WHERE rta_filter = "1"')
```

Για να αλλάξετε δυναμικά τις στήλες με βάση ένα πεδίο `${language}`, χρησιμοποιήστε μια έκφραση `if()` στην παράμετρο της στήλης εμφάνισης για εναλλαγή μεταξύ των στηλών γλώσσας:

```
search-autocomplete-noedit-v2('rawquery',
  concat(${family_path}, '/vnxa3.db::externalData'),
  if(${language} = 'vi', '[label_vi]', '[label_en]'),
  'provid',
  'SELECT label_vi, label_en, provid FROM externalData
   WHERE rta_filter = "1"')
```

<Callout type="info">
Η παράμετρος της στήλης εμφάνισης αξιολογείται πριν από την εκτέλεση του ερωτήματος. Μόνο το όνομα της στήλης (χωρίς αγκύλες) περνά στη μηχανή SQL. Οι αγκύλες είναι διακοσμητικοί δείκτες που αφαιρούνται κατά το χρόνο ανάλυσης.
</Callout>

## Επικύρωση μιας πραγματικής επιλογής

Όταν το πεδίο επιτρέπει ειδικές τιμές όπως 888 ή 999, ένας απλός έλεγχος `required = yes` είναι ανεπαρκής — ικανοποιείται ακόμα και αν ο απογραφέας επιλέξει "Δεν γνωρίζω". Χρησιμοποιήστε τον περιορισμό `selected-at(., 0) != -997` για να επαληθεύσετε ότι η αποθηκευμένη τιμή είναι μια γνήσια επιλογή και όχι η εσωτερική ένδειξη "τίποτα δεν επιλέχθηκε" `-997`:

| στήλη | τιμή |
|---|---|
| constraint | `selected-at(., 0) != -997` |
| constraint_message | Παρακαλώ επιλέξτε μια έγκυρη επιλογή |

Η τιμή `-997` είναι ο εσωτερικός κωδικός που αποθηκεύει το RTSurvey όταν δεν έχει επιλεγεί κανένα στοιχείο από τη λίστα αυτόματης συμπλήρωσης. Μια επιλογή 888 ή 999 εξακολουθεί να είναι μια σκόπιμη επιλογή και περνά αυτόν τον έλεγχο.

Για να απαιτήσετε επιπλέον μια πραγματική (μη ειδική) τιμή, επεκτείνετε τον περιορισμό:

```
selected-at(., 0) != -997 and selected-at(., 0) != '888' and selected-at(., 0) != '999'
```

## Σύγκριση: τοπική βάση δεδομένων έναντι άλλων μεθόδων αναζήτησης

| Χαρακτηριστικό | Αυτόματη συμπλήρωση `rawquery` | `search-api()` | `search()` CSV | Απλές επιλογές CSV |
|---|---|---|---|---|
| Πηγή δεδομένων | Ενσωματωμένο `.db` (SQLite) | Απομακρυσμένο REST API | Ενσωματωμένο CSV | Φύλλο επιλογών |
| Λειτουργεί εκτός σύνδεσης | Ναι | Όχι | Ναι | Ναι |
| Υποστηρίζει raw SQL | Ναι | Όχι | Όχι | Όχι |
| Διαδοχικά φίλτρα | Ναι — με παραμέτρους `?` | Μέσω του σώματος του αιτήματος | Περιορισμένα | Όχι |
| Μέγεθος συνόλου δεδομένων | Πολύ μεγάλο (εκατομμύρια σειρές) | Απεριόριστο (από την πλευρά του διακομιστή) | Μεσαίο (δεκάδες χιλιάδες) | Μικρό |
| Ειδικές σειρές που εισάγονται | Ναι — `UNION SELECT` | Όχι | Όχι | Ναι (χειροκίνητα) |
| Πολυπλοκότητα ρύθμισης | Μεσαία — απαιτεί ενσωματωμένο `.db` | Υψηλή — απαιτεί διακομιστή API | Χαμηλή | Καμία |

## Περιορισμοί

- Το αρχείο `.db` πρέπει να είναι ενσωματωμένο στο πακέτο πολυμέσων της φόρμας πριν από την ανάπτυξη. Οι δυναμικές ενημερώσεις στη βάση δεδομένων απαιτούν νέα ανάπτυξη της φόρμας.
- Η SQL εκτελείται ως έχει στη συσκευή. Δεν υπάρχει εξυγίανση από την πλευρά του διακομιστή — αποφύγετε την κατασκευή SQL από ελεύθερη εισαγωγή κειμένου του απογραφέα.
- Υποστηρίζονται μόνο δηλώσεις `SELECT`. Δεν επιτρέπονται οι `INSERT`, `UPDATE` και `DELETE`.
- Πολύ περίπλοκα ερωτήματα (μεγάλες αλυσίδες `UNION`, πολλαπλές συνδέσεις) ενδέχεται να είναι αργά σε συσκευές Android χαμηλού επιπέδου.
- Οι παραλλαγές `search-autocomplete-noedit` δεν επιτρέπουν στον απογραφέα να αποθηκεύσει μια τιμή που δεν περιλαμβάνεται στο σύνολο αποτελεσμάτων. Εάν απαιτείται εισαγωγή ελεύθερου κειμένου, χρησιμοποιήστε ένα ξεχωρισρό πεδίο `text`.
- Το `SELECT DISTINCT` εισάγεται αυτόματα μόνο όταν το `DISTINCT` απουσιάζει από το ερώτημα. Εάν γράψετε το `SELECT DISTINCT` ρητά, δεν θα διπλασιαστεί.
