---

**Dynamické vyhľadávanie** (nazývané aj Search API) umožňuje poliam `select_one`, `select_multiple` alebo `text` načítavať možnosti zo vzdialenej webovej služby **počas behu (runtime)**, keď anketár píše. Toto je správny prístup, keď je váš zoznam možností príliš veľký na to, aby bol pribalený v súbore CSV, často sa aktualizuje alebo pochádza zo živej databázy.

---

## Vzhľad `search-api()`

Dynamické vyhľadávanie sa konfiguruje prostredníctvom stĺpca `appearance` pomocou funkcie `search-api()`:

```
search-api(method, url, post_body, value_column, display, data_path, save_path)
```

### Parametre

| Parameter | Popis |
|-----------|-------------|
| `method` | Vždy používajte `'POST'` |
| `url` | Koncový bod API (endpoint) na dopytovanie |
| `post_body` | Telo JSON odoslané do API. Použite `%__input__%` ako zástupný symbol pre aktuálny vyhľadávací text anketára |
| `value_column` | Kľúč v objekte odpovede, ktorý sa má použiť ako uložená **hodnota** (`value`) |
| `display` | Kľúč (alebo šablóna), ktorý sa má použiť ako **štítok** (`label`) zobrazený v rozbaľovacom zozname. Podporuje zástupné symboly `##key##` a výrazy `@{func}` |
| `data_path` | JSONPath k polu (array) výsledných objektov v odpovedi (napr. `$.data`, `$.hits.hits.*._source`) |
| `save_path` | Názov, pod ktorým sa uloží nespracovaná (raw) odpoveď na použitie v iných poliach |

---

## Základný príklad

Vyhľadávanie zdravotníckeho zariadenia, kde anketár píše časť názvu zariadenia:

| type | name | label | appearance |
|------|------|-------|------------|
| select_one | facility | Vyberte zdravotnícke zariadenie | `search-api('POST', 'https://api.example.com/facilities/search', '{"query": "%__input__%"}', 'id', 'name', '$.results', 'facility_data')` |

API dostane `{"query": "nair"}`, keď anketár napíše „nair“, a vráti:

```json
{
  "results": [
    {"id": "HF001", "name": "Nairobi Central Clinic"},
    {"id": "HF002", "name": "Nairobi West Hospital"}
  ]
}
```

Rozbaľovací zoznam zobrazuje `Nairobi Central Clinic` a `Nairobi West Hospital`; uložená hodnota je `HF001` alebo `HF002`.

---

## Pokročilé formátovanie zobrazenia

### Použitie šablón `##key##`

Zobrazenie viacerých polí v štítku:

```
search-api('POST', 'https://api.example.com/search', '{"q": "%__input__%"}', 'id', '##name## (##district##)', '$.data', 'res')
```

Zobrazené ako: `Nairobi Central Clinic (Nairobi)`.

### Použitie výrazov `@{func}`

Použitie podmienenej logiky v štítku zobrazenia:

```
search-api('POST', 'https://api.example.com/search', '{"q": "%__input__%"}', 'id',
  '@{if_else(eq("##status##", "active"), "✓ ##name##", "✗ ##name##")}',
  '$.data', 'res')
```

Aktívne výsledky zobrazujú `✓ Clinic Name`; neaktívne zobrazujú `✗ Clinic Name`.

---

## Nastavenie predvolenej hodnoty: `search-default-api()`

Použite `search-default-api()` po `search-api()` na predvyplnenie poľa predvolenou voľbou načítanou zo samostatného volania API (napr. pri úprave existujúceho záznamu):

```
appearance: search-api(...) search-default-api('POST', 'https://api.example.com/get', '{"id": "##saved_id##"}', 'id', 'name', '$.item')
```

---

## Vlastný separátor pre select_multiple: `search-default-separator()`

Pre polia `select_multiple` špecifikujte, ako sa viacero vybraných hodnôt spojí v uloženom reťazci:

```
appearance: search-api(...) search-default-separator(' || ')
```

Predvoleným separátorom je medzera.

## Podporované typy otázok

| Typ otázky | Prípad použitia |
|---------------|----------|
| `select_one` | Jeden výber z výsledkov vyhľadávania |
| `select_multiple` | Viacero výberov z výsledkov vyhľadávania |
| `text` | Automatické dopĺňanie — anketár píše voľne, ale môže si vybrať návrh |

## Používanie uložených údajov odpovede

Keď anketár vyberie výsledok, rtSurvey uloží celý zhodný objekt z odpovede pod názvom `save_path`. Ostatné polia z neho môžu čítať dvoma spôsobmi.

### Metóda 1 — vyhľadávanie `pulldata()`

Použite `pulldata('save_path', 'key')` na načítanie poľa najvyššej úrovne z uloženého objektu:

| type | name | label | calculation |
|------|------|-------|-------------|
| select_one | facility | Vyberte zariadenie | |
| calculate | facility_district | | `pulldata('facility_data', 'district')` |
| calculate | facility_type | | `pulldata('facility_data', 'type')` |
| calculate | facility_beds | | `pulldata('facility_data', 'beds')` |

Vlastnosť `appearance` v riadku `select_one` musí obsahovať `search-api(..., 'facility_data')` so zodpovedajúcim `save_path`.

Pre **vnorené polia JSON** skombinujte s `substr-jsonpath()`:

```
substr-jsonpath(pulldata('facility_data', 'location'), '$.district')
```

## Vyhľadávanie v lokálnom súbore pomocou search()

`search()` vykonáva offline vyhľadávanie rovnosti stĺpcov v pribalenom súbore SQLite `.db` — bez sieťového pripojenia a bez potreby SQL dopytov. Použite ho, keď sú vaše referenčné údaje zabalené s formulárom a potrebujete jednoduché vyhľadávanie „nájdi všetky riadky, kde sa stĺpec rovná hodnote“.

### Signatúra

```
search(path, 'matches', 'list_name', ${field})
```

### Parametre

| Parameter | Popis |
|-----------|-------------|
| `path` | Cesta k tabuľke SQLite: `concat(${family_path}, '/file.db::table')` |
| `'matches'` | Operátor zhody — vracia riadky, kde sa stĺpec rovná hodnote |
| `'list_name'` | Názov stĺpca, voči ktorému sa má hľadať zhoda |
| `${field}` | Hodnota, ktorá sa má zhodovať; zvyčajne odkaz na pole |

### Príklad

Naplnenie poľa `select_one` z lokálnej databázy priradením hodnoty `${d307}` k stĺpcu `list_name` v tabuľke `externalData` v `d307.db`:

| type | name | label | appearance |
|------|------|-------|------------|
| select_one | facility | Vyberte zariadenie | `search(concat(${family_path}, '/d307.db::externalData'), 'matches', 'list_name', ${d307})` |

Keď sa `${d307}` rovná `"HF001"`, `search()` vráti každý riadok v `externalData`, kde `list_name = 'HF001'` — úplne z pribaleného súboru, bez sieťového volania.

### search() verzus dopĺňanie rawquery

| Funkcia | `search()` | Dopĺňanie `rawquery` |
|---------|-----------|------------------------|
| SQL dopyty | Nie — iba rovnosť stĺpcov | Áno — úplný `SELECT … FROM …` |
| Parametrizovaný vstup | Zhoda hodnoty stĺpca | Vložené v reťazci SQL |
| Voľný vstup textu | Áno — anketár môže písať voľne | Nie — musí si vybrať zo zoznamu |
| UNION / viacero tabuliek | Nepodporované | Podporované |

### Kedy použiť ktoré

- Použite **`search()`**, keď potrebujete priamu zhodu rovnosti voči pribalenému súboru `.db`, formulár musí fungovať offline a chcete umožniť voľný vstup textu.
- Použite **dopĺňanie `rawquery`**, keď potrebujete flexibilitu SQL (JOINy, UNIONy, vypočítané stĺpce) alebo musíte dopytovať viacero tabuliek a formulár má spoľahlivé pripojenie.

## Najlepšie postupy

1. Zabezpečte, aby váš koncový bod API odpovedal do 1 – 2 sekúnd — pomalé API spôsobujú, že vyhľadávanie pôsobí nereagujúco.
2. Použite `%__input__%` v `post_body`, aby API vracalo iba zhodné výsledky, nie celý súbor údajov.
3. Indexujte vyhľadávacie pole na strane servera (napr. Elasticsearch, full-textový index databázy) pre rýchle odpovede.
4. Obmedzte výsledky na 20 – 50 položiek na dopyt — vrátenie tisícok výsledkov marí účel vyhľadávania.
5. Do API zahrňte požiadavku na minimálnu dĺžku vstupu, aby ste sa vyhli spúšťaniu širokých dopytov pri vstupoch s jedným znakom.

## Obmedzenia

- Dynamické vyhľadávanie vyžaduje sieťové pripojenie — nefunguje offline.
- Zástupný symbol `%__input__%` sa vkladá v pôvodnej podobe; sanujte vstupy na strane servera, aby ste zabránili útokom typu injection.
- Komplexné výrazy zobrazenia `@{func}` môžu mať obmedzenú podporu vo všetkých verziách klienta rtSurvey.
