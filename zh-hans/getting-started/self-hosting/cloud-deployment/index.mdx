部署仓库包含主要云服务商的自动化配置脚本。每个脚本在全新 **Ubuntu 22.04 LTS** 服务器首次启动时运行，执行完全无人值守的设置：

- 安装 Docker 和 Docker Compose
- 为所有内部服务生成安全的随机密码
- 写入 `docker-compose.production.yml` 和 `.env`
- 将 Nginx 配置为反向代理
- 从 Let's Encrypt 获取免费的 TLS 证书（自动重试直到 DNS 解析成功）
- 配置 UFW 防火墙
- 可选部署内嵌 Keycloak SSO 服务器
- 输出包含所有凭据的完整部署摘要

在标准实例上，设置在 **5–10 分钟**内完成。

---

## 选择脚本

根据您的云服务商和 SSO 设置，有多种脚本变体可供选择：

| 脚本 | 服务商 | SSO 模式 | 最适合 |
|--------|----------|----------|----------|
| `digitalocean-droplet-keycloak-embed.sh` | DigitalOcean | 内置 Keycloak | 简单、自包含的 SSO |
| `digitalocean-droplet.sh` | DigitalOcean | Keycloak 或外部 OIDC | 完全控制 |
| `linode-stackscript-keycloak-embed.sh` | Linode | 内置 Keycloak | 基于表单的设置，最简单 |
| `linode-stackscript-oidc.sh` | Linode | 仅外部 OIDC | 现有身份提供商 |
| `linode-stackscript.sh` | Linode | Keycloak 或外部 OIDC | 完全控制 |
| `aws-ec2.sh` | AWS EC2 | Keycloak 或外部 OIDC | AWS 部署 |
| `gcp-compute.sh` | Google Cloud | Keycloak 或外部 OIDC | GCP 部署 |

> **大多数用户推荐：** 使用 `keycloak-embed` 变体。它包含内置 Keycloak 身份服务器，需要配置的字段最少。

## 服务器规格指南

| 使用场景 | RAM | 磁盘 | 示例 |
|----------|-----|------|---------|
| 评估/开发 | 2 GB | 25 GB | DO Basic $18/月, t3.small, e2-small |
| 小型团队（< 50 用户） | 4 GB | 40 GB | DO Basic $24/月, t3.medium, e2-medium |
| 生产环境（> 50 用户） | 8 GB | 80 GB | DO General $48/月, t3.large, n2-standard-2 |

> 内嵌 Keycloak 至少需要 **4 GB RAM**。仅在没有 Keycloak 的情况下进行评估时使用 2 GB。

## DNS 设置

所有脚本都需要一个**将 A 记录指向服务器 IP** 的域名，Let's Encrypt 才能颁发证书。

脚本在设置过程早期会打印您的服务器 IP：

```
============================================================
 Server IP : 139.162.51.85
 Add this DNS A record now if you haven't already:
   myapp.example.com  ->  139.162.51.85
 The script will retry Certbot every 60s until DNS resolves.
============================================================
```

脚本会**自动重试** Let's Encrypt，每 60 秒一次，最长重试 1 小时。只需添加 DNS 记录并等待——无需重启。

> **频率限制：** Let's Encrypt 每个域名每 7 天最多允许 **5 个证书**。避免重复使用相同域名部署和销毁服务器。如果达到限制，脚本将显示 `retry after` 时间戳并立即停止。

## 部署后检查清单

- [ ] 应用可在 `https://your-domain.com` 打开
- [ ] 使用 `admin` 和您配置的密码登录
- [ ] 所有容器健康：`docker compose -f /opt/rtcloud/docker-compose.production.yml ps`
- [ ] Let's Encrypt 续期正常：`certbot renew --dry-run`
- [ ] MySQL 端口 3306 **未**开放：`ufw status`
- [ ] 设置每日数据库备份（参见[维护](../maintenance)）

## 故障排除

### 查看完整设置日志

```bash
# Linode
tail -200 /var/log/stackscript.log

# DigitalOcean / AWS / GCP
tail -200 /var/log/rtcloud-setup.log
```

### Let's Encrypt 频率限制

如果日志中看到 `too many certificates`，您已达到每 7 天 5 个证书的限制。日志会显示确切的重试时间：

```
[SSL] ERROR: Let's Encrypt rate limit hit. retry after 2026-03-15 16:22 UTC.
```

等到该时间后重新部署。

### Keycloak 持续不健康

确保服务器至少有 4 GB RAM，然后检查日志：

```bash
docker logs rtcloud-keycloak --tail 50
free -h
```

### SSL 配置在 certbot 后未应用

如果证书已颁发但 Nginx 仍显示 HTTP，请查看日志中的错误行并手动重新加载 Nginx：

```bash
nginx -t && systemctl reload nginx
```
