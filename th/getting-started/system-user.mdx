# การจัดการผู้ใช้ระบบ

โมดูล **System User** (`/cpms/cpmsSystemUser/admin`) เป็นอินเทอร์เฟซการจัดการที่ครอบคลุมสำหรับควบคุมว่าใครมีสิทธิ์เข้าถึงแพลตฟอร์ม Real-Time Survey (RT-CPMS) และสามารถดำเนินการใดได้บ้าง

![System User Interface](/images/system_user.png)

## แนวทางการจัดการแบบรวมศูนย์

ใน RT-CPMS **ผู้ถามแบบสอบถาม** เป็นเพียงบทบาทเฉพาะที่กำหนดให้กับผู้ใช้ระบบ ไม่มีฐานข้อมูล "ผู้ถามแบบสอบถาม" แยกต่างหาก ไม่ว่าผู้ใช้จะเป็นผู้ดูแลระบบระดับสูงที่ตรวจสอบพอร์ทัลเว็บหรือผู้ถามแบบสอบถามภาคสนามที่เก็บข้อมูลผ่านแอปมือถือ ทั้งหมดได้รับการจัดการภายในกรอบการทำงานแบบรวมเดียวกันนี้

## คุณสมบัติหลัก

### 1. ไดเรกทอรีผู้ใช้และมุมมองกริด
อินเทอร์เฟซหลักแสดงรายการผู้ใช้ทั้งหมดที่เชื่อมต่อกับพื้นที่ทำงานแบบแบ่งหน้า แอตทริบิวต์สำคัญได้แก่:
* **Organization ID & Name**: การจัดกลุ่มผู้ใช้แบบตรรกะภายใต้หน่วยงานองค์กรเฉพาะ (เช่น `rta`, `partner_org`)
* **Role**: ระบุระดับสิทธิ์ของผู้ใช้ (เช่น `Administrator`, `Leadteam`, `Enumerator`)
* **Group**: การกำหนดกลุ่มเชิงพื้นที่หรือตรรกะ (เช่น เขตเฉพาะหรือทีมปฏิบัติการ)
* **Is Synchronized**: ระบุว่าบัญชีถูกรวมเข้ากับระบบ Single Sign-On (SSO) กลางสำเร็จหรือไม่
* **Status**: ตัวบ่งชี้ภาพที่ยืนยันว่าบัญชีเป็น `Active`, `Inactive`, `Deleted` หรือ `Blocked`

**การดำเนินการส่วนกลาง:**
* **Add System User**: สร้างโปรไฟล์รายบุคคลด้วยตนเอง
* **Import System User**: อัปโหลดบัญชีจำนวนมากโดยใช้เทมเพลต Excel คุณสามารถแก้ไขความขัดแย้งโดยใช้โหมด `Skip` หรือ `Replace` และซิงค์โดยตรงกับ SSO
* **Bulk Delete**: รองรับการเลือกหลายรายการสำหรับการลบบัญชีจำนวนมาก

### 2. การควบคุมการเข้าถึงและความปลอดภัย
เมื่อสร้างหรือแก้ไขโปรไฟล์ผู้ใช้ มีฟิลด์ความปลอดภัยและขั้นตอนการทำงานสำคัญหลายรายการ:
* **User Code**: ตัวระบุเฉพาะที่เชื่อมโยงบัญชี CPMS ภายในเครื่องกับที่เก็บ SSO กลาง
* **Change-Device Code**: โทเค็นความปลอดภัยที่แข็งแกร่งซึ่งต้องใช้เมื่อผู้ถามแบบสอบถามต้องเปลี่ยนอุปกรณ์มือถือที่ใช้สำหรับการเก็บข้อมูล
* **Power Level**: ระดับลำดับความสำคัญ/การเข้าถึงแบบละเอียดตั้งแต่ 0 (ต่ำสุด) ถึง 20 (สูงสุด)
* **Supervisory Toggle**: ช่องทำเครื่องหมายที่ยกระดับผู้ใช้มาตรฐานไปยังสถานะการจัดการได้ทันที
* **Workflow Automation**: ตัวเลือก "อนุมัติคำขอแก้ไขโดยอัตโนมัติ" ซึ่งปรับปรุงกระบวนการล้างข้อมูลและการตรวจสอบสำหรับผู้ใช้ที่เชื่อถือได้

### 3. การจัดการโค้ด (การเริ่มต้นใช้งานอัตโนมัติ)
พบใต้แท็บย่อย "Code" ฟีเจอร์นี้จัดการลิงก์การลงทะเบียนและคำเชิญแบบ hash ช่วยให้กระบวนการเริ่มต้นใช้งานสำหรับทีมขนาดใหญ่มีประสิทธิภาพมากขึ้น

* **Registration vs. Invitation**: เลือกว่าผู้ใช้สามารถลงทะเบียนด้วยตนเองโดยใช้ลิงก์ที่แจกจ่ายหรือต้องการคำเชิญจากผู้ดูแลระบบโดยตรง
* **Expiry Dates**: จำกัดการเริ่มต้นใช้งานให้อยู่ในช่วงเวลาเฉพาะ
* **Usage Limits**: จำกัดจำนวนผู้ใช้ที่สามารถเข้าร่วมโดยใช้โค้ดที่สร้างขึ้นเพียงรหัสเดียว
* **Pre-assigned Roles**: ผู้ใช้ที่เข้าร่วมผ่านโค้ดเหล่านี้จะรับบทบาทและระดับอำนาจที่กำหนดไว้ล่วงหน้าโดยอัตโนมัติ เพื่อให้พร้อมทำงานได้ทันทีโดยไม่ต้องมีการแทรกแซงจากผู้ดูแลระบบด้วยตนเอง
