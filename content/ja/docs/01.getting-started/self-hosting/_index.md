Docker Composeを使って独自のインフラでrtCloudを実行します。セルフホスティングにより、データ、ネットワーク、デプロイ環境を完全に所有でき、データ居住要件、エアギャップネットワーク、またはカスタムインフラニーズを持つ組織に最適です。

## rtCloudセルフホスティングとは？

rtCloudセルフホスティングは、rtCloudプラットフォーム全体を任意のLinuxサーバーで実行できるポータブルコンテナスタックにパッケージ化した公式Dockerイメージです。スタックには以下が含まれます：

| サービス | 説明 |
|---------|-------------|
| **rtCloudアプリ** | Apache 2.4 + PHP 7.4 Webアプリケーション（組み込みバックグラウンドキュー（Beanstalkd）、分析サーバー（Shiny）、スケジュールタスクを含む） |
| **MySQL 8.0** | すべてのアプリケーションと調査データのリレーショナルデータベース |
| **Keycloak** *（オプション）* | エンタープライズIDプロバイダー管理用の組み込みシングルサインオンサーバー |

## セルフホスティングを選ぶ場合

以下の場合にセルフホスティングが適切な選択です：

- **データ主権**が必要 — すべてのデータが独自インフラ内に留まる
- 外部クラウドアクセスのない**エアギャップまたは制限されたネットワーク**で運用している
- オンプレミスストレージを義務付ける**コンプライアンス要件**がある（GDPR、HIPAA、政府データポリシー）
- **内部IDプロバイダー**（Active Directory、LDAP、SAML）との統合が必要
- 独自の条件でCPU、RAM、ストレージ割り当てを**カスタマイズ**したい

## アーキテクチャの概要

デプロイは内部ネットワークで接続されたDockerコンテナのセットとして実行されます：

```
┌────────────────────────────────────────┐
│            rtcloud-app                 │
│  Apache 2.4 (port 80)                  │
│  PHP 7.4 application                   │
│  Beanstalkd queue (internal)           │
│  Shiny Server (port 3838)              │
│  Cron scheduler                        │
└─────────────────┬──────────────────────┘
                  │ rtcloud-net (bridge)
┌─────────────────▼──────────────────────┐
│            rtcloud-mysql               │
│  MySQL 8.0 (port 3306, internal only)  │
└────────────────────────────────────────┘
```

SSOが有効な場合、第3のコンテナが並行して実行されます：

```
┌─────────────────────────────────────────┐
│            rtcloud-keycloak             │
│  Keycloak (port 8080, internal only)    │
│  Admin UI (port 9000, internal only)    │
└─────────────────────────────────────────┘
```

すべてのコンテナは隔離されたDockerブリッジネットワーク上で通信します。Webアプリケーションポートと（オプションで）Shiny分析ポートのみがホストに公開されます。
