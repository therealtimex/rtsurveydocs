DigitalOcean uses **User Data** scripts that run automatically on first boot. You fill in the configuration variables at the top of the script, then paste the entire script when creating a Droplet.

> Unlike Linode StackScripts, DigitalOcean has no form UI — you must edit the script directly before pasting.

---

## Embedded Keycloak (Recommended)

Use `digitalocean-droplet-keycloak-embed.sh` for the simplest setup with built-in SSO.

### Step 1 — Fill in the configuration

Open the script and edit the `CONFIGURATION` block at the top:

```bash
# --- Required ---
PROJECT_ID="rtsurvey"                  # Unique identifier for your project (no spaces)
KEYCLOAK_ADMIN_PASSWORD="MyStr0ngPass" # Password for Keycloak admin + app admin login

# --- Docker Hub ---
DOCKER_HUB_USER="rtawebteam"
DOCKER_HUB_PASSWORD="your-token"      # Docker Hub password or access token
RTCLOUD_IMAGE="rtawebteam/rta-smartsurvey:survey-dockerize"

# --- Domain + SSL ---
DOMAIN="myapp.example.com"            # Your domain — DNS A record must point here
PROJECT_URL=""                         # Leave blank unless behind Cloudflare/proxy
LETSENCRYPT_EMAIL="admin@example.com" # Email for Let's Encrypt notifications

# --- Optional ---
STATA_ENABLED="false"
TZ="Asia/Ho_Chi_Minh"
```

| Field | Required | Description |
|-------|----------|-------------|
| `PROJECT_ID` | Yes | Used as database name and Keycloak client ID. Lowercase, no spaces. |
| `KEYCLOAK_ADMIN_PASSWORD` | Yes | Password for both Keycloak admin console and app admin login. |
| `DOCKER_HUB_PASSWORD` | Yes | Docker Hub password or access token to pull the private image. |
| `DOMAIN` | Yes | Your domain name. DNS A record must point to the Droplet IP. |
| `LETSENCRYPT_EMAIL` | Yes | Email address for Let's Encrypt certificate notifications. |
| `PROJECT_URL` | No | Override the public URL. Leave blank to use `DOMAIN`. Useful behind Cloudflare. |

### Step 2 — Create a Droplet

In the [DigitalOcean control panel](https://cloud.digitalocean.com):

1. Click **Create** → **Droplets**
2. Choose **Ubuntu 22.04 LTS** as the image
3. Select **Basic, 4 GB RAM / 2 vCPUs** or larger
4. Scroll to **Advanced Options** → check **Add Initialization scripts**
5. Paste the full script content into the text area
6. Click **Create Droplet**

### Step 3 — Add the DNS record

While the Droplet boots, add an **A record** in your DNS provider:

```
Type  : A
Name  : myapp          (or @ for root domain)
Value : <droplet-ip>
TTL   : 300
```

### Step 4 — Monitor progress

SSH into the Droplet and watch the log:

```bash
ssh root@<droplet-ip>
tail -f /var/log/rtcloud-setup.log
```

The script prints your server IP near the start — add the DNS record as soon as you see it.

### Step 5 — Access the app

When setup completes, the log shows a summary:

```
============================================================
 rtCloud deployment complete! (Embedded Keycloak)
============================================================
 App URL   : https://myapp.example.com
 Admin     : admin / MyStr0ngPass
 Keycloak  : https://myapp.example.com/auth/admin
============================================================
```

Open `https://myapp.example.com` in your browser and log in with `admin` and your password.

## Full Script (Keycloak + External OIDC)

Use `digitalocean-droplet.sh` for full control. This script supports:

- Embedded Keycloak (`EMBED_KEYCLOAK="true"`)
- External OIDC provider (`EMBED_KEYCLOAK="false"`)
- HTTP-only mode (leave `DOMAIN` blank)

Additional configuration fields:

```bash
# --- Admin ---
ADMIN_PASSWORD=""                            # Leave blank to auto-generate
EMBED_KEYCLOAK="true"
KEYCLOAK_ADMIN_PASSWORD="${ADMIN_PASSWORD}"  # Defaults to ADMIN_PASSWORD

# --- External OIDC (when EMBED_KEYCLOAK=false) ---
OIDC_ISSUER_URL=""
OIDC_CLIENT_ID=""
OIDC_CLIENT_SECRET=""

# --- HTTP-only mode (leave DOMAIN blank) ---
DOMAIN=""
APP_PORT="8080"
```

Follow the same steps as above — fill in the config, paste into User Data, create the Droplet.

## After Deployment

### Change a password

SSH into the Droplet, edit `.env`, and restart the affected container:

```bash
nano /opt/rtcloud/.env
docker compose -f /opt/rtcloud/docker-compose.production.yml up -d --force-recreate rtcloud
```

### Update the domain

If you assign a different domain after deployment, update `PROJECT_URL` in `.env`:

```bash
nano /opt/rtcloud/.env   # update PROJECT_URL=
docker compose -f /opt/rtcloud/docker-compose.production.yml up -d --force-recreate rtcloud
```

### View all containers

```bash
docker compose -f /opt/rtcloud/docker-compose.production.yml ps
```
