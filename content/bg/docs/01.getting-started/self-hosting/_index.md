Стартирайте rtCloud на собствена инфраструктура с Docker Compose. Самостоятелното хостване ви дава пълна собственост върху данните, мрежата и средата за разгръщане — идеално за организации с изисквания за съхранение на данни, изолирани мрежи или специфични нужди от инфраструктура.

## Какво е самостоятелно хостване на rtCloud?

Самостоятелното хостване на rtCloud е официален Docker образ, опаковащ цялата платформа rtCloud в преносим контейнерен стек, който можете да стартирате на всеки Linux сървър. Стекът включва:

| Услуга | Описание |
|---------|-------------|
| **Приложение rtCloud** | Уеб приложение Apache 2.4 + PHP 7.4 с вграден фонов опашка (Beanstalkd), аналитичен сървър (Shiny) и планирани задачи |
| **MySQL 8.0** | Релационна база данни за всички данни на приложението и анкетите |
| **Keycloak** *(незадължително)* | Вграден SSO сървър за корпоративно управление на самоличности |

## Кога да се самостоятелно хоства

Самостоятелното хостване е правилният избор, когато:

- Изисквате **суверенитет на данните** — всички данни остават в рамките на вашата инфраструктура
- Работите в **изолирана или ограничена мрежа** без достъп до външен облак
- Имате **изисквания за съответствие** (GDPR, HIPAA, правителствени политики за данни), изискващи локално съхранение
- Трябва да интегрирате с **вътрешен доставчик на самоличност** (Active Directory, LDAP, SAML)
- Искате да **персонализирате ресурсите** — CPU, RAM и разпределение на дисково пространство по ваш избор

## Архитектурен преглед

Разгръщането се изпълнява като набор от Docker контейнери, свързани в изолирана мрежа:

```
┌────────────────────────────────────────┐
│            rtcloud-app                 │
│  Apache 2.4 (port 80)                  │
│  PHP 7.4 application                   │
│  Beanstalkd queue (internal)           │
│  Shiny Server (port 3838)              │
│  Cron scheduler                        │
└─────────────────┬──────────────────────┘
                  │ rtcloud-net (bridge)
┌─────────────────▼──────────────────────┐
│            rtcloud-mysql               │
│  MySQL 8.0 (port 3306, internal only)  │
└────────────────────────────────────────┘
```

Когато SSO е активирано, трети контейнер се изпълнява паралелно:

```
┌─────────────────────────────────────────┐
│            rtcloud-keycloak             │
│  Keycloak (port 8080, internal only)    │
│  Admin UI (port 9000, internal only)    │
└─────────────────────────────────────────┘
```

Всички контейнери комуникират чрез изолирана Docker мрежа тип мост. Само портът на уеб приложението и (по избор) портът на аналитичния сървър Shiny са изложени към хоста.
